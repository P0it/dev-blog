# /project — 포트폴리오 원고 → 실험실 적재

원고 위치 / 붙여넣은 내용: **$ARGUMENTS**

다른 레포의 Claude 세션이 `/portfolio` 스킬로 만든 `portfolio.md` 를 받아
이 레포 규약에 맞게 손질하고 Supabase `projects` 에 적재한다.

**받은 원고를 그대로 밀어 넣지 않는다.** 저쪽 세션은 규약의 옛 버전을 들고 있을 수도 있고,
기획 의도처럼 코드에 안 남는 건 비워 두고 왔을 수도 있다. 여기서 한 번 거른다.

## 절차

### 1. 원고를 확보한다

`$ARGUMENTS` 가 경로면 그걸 쓴다 — **폴더 경로여도 된다.** `portfolio/` 를 통째로
받는 게 정상이고, 그 안의 `portfolio.md` 가 원고다.
내용을 그대로 붙여넣었으면 그걸 쓰되, 그때는 로고·화면 파일이 없다는 뜻이다.
아무것도 없으면 달라고 한다. 레포 안에 `portfolio/` 나 `portfolio.md` 가 굴러다니면 후보다.

### 2. 규약과 대조한다

`skills/portfolio/SKILL.md` 를 읽는다. **기억에 의존하지 않는다** — 규약은 계속 바뀐다.
그다음 원고를 훑으며 아래를 고친다.

**섹션 제목** — 아는 제목이 아니면 그 섹션은 화면에서 밋밋한 글로 떨어진다.
아는 제목은 `화면` `데이터와 API` `구상` `기획` `인터뷰` `유저 플로우` `구조`
`개발 과정` `시행착오` `남은 것` 뿐이다 (`제품 소개` 는 없어졌다 — 아래를 본다). 비슷한 뜻의 제목(`개발 후기`, `회고`)은
맞는 섹션으로 옮기거나, 정말 남길 이유가 있으면 그대로 두되 사용자에게 알린다.

**옛 규약의 흔적**
- `## 기술 선정` 표가 있으면 → 첫 열(또는 `고른 것` 열)의 이름을 프런트매터 `stack` 으로
  옮기고 섹션은 지운다. 고른 이유 중 살릴 만한 건 `## 개발 과정` 으로 녹인다
- `## 유저 플로우` 에 mermaid 가 있으면 → 노드를 `### 단계` 로 풀고, 분기는
  `**갈라짐** 조건 → 결과 / 조건 → 결과` 한 줄로 바꾼다. mermaid 는 `## 구조` 에서만 쓴다
- `logo_emoji` 가 있으면 지운다. 로고는 이미지 아니면 첫 글자 모노그램이다
- `## 데이터와 API` 가 항목마다 `제공처·적재·갱신·주의` 를 문단째 달고 있으면 → 압축한다.
  **`**용도**` 한 줄이 없으면 만들어 준다** (무엇에 쓰는지). `방식`·`갱신` 은 명사 몇 개로
  줄여 칩으로 만들고, 나머지는 한두 줄로 깎아 남긴다 — 접혀 있다가 "자세히" 로 열린다.
  **스크립트·명령어·함수·필드 이름 같은 코드 레벨 서술은 전부 걷어낸다.** 살릴 만한
  삽질이면 `## 시행착오` 케이스로 옮긴다. 카드가 8장을 넘으면 같은 브랜드끼리 합친다.
  이름에서 브랜드가 안 잡히는 항목만 `**아이콘** Naver` 처럼 힌트를 붙인다
- `## 시연` 은 없어진 섹션이다 → 클립을 `## 화면` 으로 옮기고 섹션은 지운다.
  화면 갤러리가 영상도 같은 자리에 그린다
- `## 구조` 의 mermaid 가 `A --> B --> C` 한 줄기이거나 `flowchart TD` 면 → **다시 그린다.**
  사슬은 구조가 아니라 순서고, 그건 `## 개발 과정` 이 이미 맡고 있다. `subgraph` 로
  2~4 덩어리를 나누고, `flowchart LR` 로 눕히고(상자 안쪽만 `direction TB`),
  화살표에 흐르는 것을 한두 단어로 적고, 되돌아오는 흐름은 점선(`-.->`)으로 건다.
  화살표 라벨이 길수록 그림이 옆으로 늘어나 판에 맞추느라 축소된다
- `## 구조` 의 `### 제목` 이 다이어그램의 노드·상자 이름과 다르면 → 이름을 맞춘다.
  화면이 이름으로 짝을 찾아, 설명에 손을 얹으면 그 조각을 켜 준다.
  부연은 `### 쿼리 캐시 — 오프라인 저장소를 겸한다` 처럼 `—` 뒤에 둔다
- `## 구조` 문단이 "왜 그렇게 했는지"를 말하면 → `## 개발 과정` 이나 `## 시행착오` 로
  옮긴다. 구조는 무엇이 무엇과 무엇을 주고받는지, 현재형으로만 쓰는 자리다
- **`## 기획` 이 `소개`·`계기`·`사용자` 로 채워져 있으면 옛 규약이다** → 제목을 `## 인터뷰` 로
  바꾸고, 그 안의 `제약`·`정책` 은 새 `## 기획` 으로 올린다. 인터뷰의 `**문제**` 는
  기획의 `**문제**` 로(사연이 아니라 정의로 고쳐 쓴다), `**사용자**` 는 기획의 `**타겟**` 으로
  올린다 — **인터뷰에서 `사용자` 라벨은 뺐다.** 새 `## 기획` 은 `## 구상` **앞**에 세운다
- `## 요구사항` 은 옛 제목이다 → `## 구상` 으로 바꾼다. 파서는 둘 다 받지만 화면에
  제목이 그대로 나오므로, 새 원고에 옛 이름이 남아 있으면 안 된다.
  이름만 바꾸고 끝내지 말고 아래 "구상이 부푼 경우"까지 같이 적용한다

**`## 제품 소개` 가 들어 있는 경우** — 없어진 섹션이다. **화면에 아예 안 그려지고
흘러가므로 반드시 옮긴다.** 표지에서 한 번, 문답에서 또 한 번 같은 이야기를 하게 돼
접었다. 지금은 `## 인터뷰` 의 첫 줄 `**소개**` 가 그 자리다 ("어떤 서비스인가요?"로 뜬다).
- 소개 문단을 **한두 문장으로 줄여** `## 인터뷰` 맨 위에 `**소개**` 로 올린다.
  현재형이고, 무엇을 넣으면 무엇이 나오는 물건인지가 읽히면 된다
- 만든 동기·불편했던 상황이 섞여 있으면 → `**계기**` 줄로 가른다
- 사용자층 설명이 있으면 → `## 기획` 의 `**타겟**` 줄로
- 기술 이름을 늘어놓았으면 → 버린다. 프런트매터 `stack` 이 그린다
- 옮기고 나면 `## 제품 소개` 제목째 지운다. **본문의 첫 섹션은 `## 화면` 이다**

**기획을 손보는 경우** — `## 기획` 은 만들기 전에 짠 구현 계획이다. 누구를 위한
것이고(`타겟`), 무엇을 넣고 무엇은 안 넣을지(`범위`), 어떤 조건(`제약`)과 규칙(`정책`)으로
굴릴지. `문제` 는 선택이고, 인터뷰 `계기` 가 이미 말하면 뺀다. 라벨 차례가 곧 표의 차례다.
- **`해법` 줄이 있으면 뺀다.** 어떤 방식으로 풀지는 `## 구상`·`## 개발 과정` 이 말한다
- 인터뷰의 `**사용자**` 는 `타겟` 으로 올린다 — 인터뷰에서 그 라벨은 뺐다
- **`접은 안`·`넣지 않은 것` 은 쓰지 않는다** — 안 하기로 한 것은 `범위`, 나중으로 민
  것은 `## 남은 것` 이다. **저울질하다 버린 다른 방법은 `## 개발 과정` 에서
  문장으로 푼다** (언제 왜 갈아탔는지까지 나와야 판단으로 읽힌다)
- `타겟`·`범위` 가 비면 **사용자에게 묻는다** — 코드에 안 남는 값이다
- `**우선순위**` 줄이 있으면 뺀다. 기능이 붙은 순서는 `## 개발 과정` 이 이야기로 말한다
- `범위` 가 여러 줄이면 한 줄로 합친다. 여러 줄이 되는 순간 해명하는 글이 된다
- 답이 없으면 그 줄을 빼고 보고에 적는다. **지어낸 대안을 세워 두고 접었다고 쓰지 않는다**
- 결정만 있고 이유가 없는 줄은 이유를 묻는다. 이유 없는 결정은 취향으로 읽힌다
- 넷에서 여덟 줄이면 넉넉하다. 기획이랄 게 정말 없었으면 섹션을 통째로 뺀다
- 만들다 바뀐 판단이 여기 들어와 있으면 → `## 개발 과정` 으로 옮긴다
- `**넣지 않은 것**`·`**접은 안**` 줄이 들어와 있으면 → 기능 제외는 `범위` 로 합치고,
  대안 검토는 `## 개발 과정` 의 해당 단계에 문장으로 녹인 뒤 그 라벨은 뺀다
- `**가설**` `**성공 기준**` 줄이 들어와 있으면 → 라벨 표에서 뺐다. 저울질한 흔적이면
  `## 개발 과정`, 처리 규칙이면 `정책`, 경계면 `범위` 로 옮기고 그 라벨은 지운다

**인터뷰가 라벨 두어 줄뿐인 경우** — 이 섹션은 만든 사람 문답이다. 라벨이 화면에서
질문으로 바뀌어 문답으로 그려지니, 읽는 사람이 궁금해할 걸 몇 줄 더 채운다.
표준 라벨과 그때 뜨는 질문은 `SKILL.md` 의 표에 있다. **없는 걸 지어내지는 않는다** —
원고·커밋·사용자 답변에 근거가 없으면 사용자에게 묻고, 답이 없으면 그 줄을 뺀다.
- `**소개**` `**계기**` 는 되도록 채운다
- `**배운 것**` `**반응**` 처럼 사람 목소리가 나는 줄이 있으면 글이 산다.
  사용자에게 한 번 물어볼 값어치가 있다
- `**문제**` `**사용자**` `**제약**` `**정책**` 은 여기가 아니라 `## 기획` 이다
  (`사용자` → 기획의 `타겟`, `문제` → 기획의 `문제`)
- `**기간**` `**자랑**` `**지금**` 은 묻지 않는다. 라벨 표에서 뺐다 — 옛 원고에 남아 있으면
  그대로 둬도 그려지지만, 새로 채우지는 않는다
- 여섯~여덟 줄이면 넉넉하다. 열 줄을 넘기면 인터뷰가 아니라 설문지가 된다
- 답이 명사로 끊겨 있으면 문장으로 편다. 질문이 존댓말인데 답이 개조식이면 대화가 안 된다
- 옛 원고의 인터뷰에 `**문제**`·`**사용자**` 가 남아 있으면 → `## 기획` 의 `문제`·`타겟` 으로 올린다

**화면이 없는 경우** — `## 화면` 은 정지 화면 6~10 장을 그리드로 까는 섹션이다.
없이도 글은 성립하니(표지 이미지가 있다) **억지로 만들지 않는다.** 사용자에게 몇 장
받을 수 있는지 한 번 묻고, 없다고 하면 섹션을 빼고 그대로 적재한다.
여기서 앱을 띄워 찍으려 들지 않는다 — 그건 프로젝트 레포를 아는 저쪽 세션의 몫이다.
있는데 부실하면 이렇게 거른다.
- 로그인·빈 상태·에러 화면이 들어와 있으면 뺀다. 이 물건이 뭔지 알려주지 않는다
- **개발 서버 배지가 찍힌 화면은 다시 받는다.** Next.js 의 왼쪽 아래 동그란 `N` 같은 것.
  발행된 화면에는 없으니 그대로 실으면 대충 찍은 티가 난다
- 10 장을 넘으면 줄인다. 주요 흐름이 다 보이면 충분하고, 같은 화면을 상태만 바꿔
  여러 장 늘어놓는 자리가 아니다
- `**설명**` 줄이 없으면 채운다. 그 화면이 **무엇을 하는 자리인지** 한 문장 —
  40자 안쪽, 제목을 되풀이하지 않는다 (`홈 화면입니다` ✗ / `위치를 켜면 주변
  사우나가 거리순으로 깔립니다` ○). 두세 문장짜리 해설이 붙어 있으면 한 줄로 줄이고,
  버리기 아까운 내용은 `## 개발 과정` 의 해당 단계로 녹인다
- **`**설명**` 은 존댓말로 끝낸다 — `~합니다`·`~됩니다`.** 평서체(`~깔린다`)로 들어온
  줄은 고쳐 준다. 이름표 아래에서만 반말이 되면 본문 높임과 어긋나 튄다
- 홈·메인 화면을 맨 앞으로 옮긴다. **첫 장이 목록 카드의 대표 화면이 된다**
- **그림 비율은 손대지 않는다.** 화면 갤러리가 보고 알아서 고른다 — 세로 폰 화면은
  폰 판에(갤러리 한 줄에 세 칸), 가로로 넓은 데스크탑·웹 화면은 줄을 통째로 쓰며
  제 비율로, 스크롤까지 담긴 긴
  캡처는 상세에서 판 안을 위에서 아래로 훑어 내린다(목록 카드는 맨 위만 잘라 세운다).
  **긴 캡처를 잘라 여러 장으로 나누지 않는다**
- **데스크탑 캡처가 1440px 폭으로 찍혀 왔으면 다시 찍어 달라고 한다.** 캡처는 판 안에서
  줄어들어 보이고 그 비율은 *찍은 폭 대비 판 폭*이라, 1440px 은 목록 판(812px)에서
  56% 가 되어 본문이 9px 로 앉는다. 규약 폭은 **1152px** 다(70%)
- **판이 폰인지 브라우저 창인지는 프런트매터 `platform` 이 정한다.** 데스크탑 브라우저
  창으로 찍은 화면인데 이 줄이 없으면 폰 판에 우겨넣어져 좌우가 잘린다 → `platform: web`
  을 적어 준다. 기준은 쓰인 기술이 아니라 **캡처를 무엇으로 찍었는가**다. 웹으로 만들었어도
  폰 화면으로 쓰는 물건이면 `mobile` 이고, 그때는 줄을 안 적어도 된다(기본값)

**섹션 순서** — 화면에 나오는 순서가 곧 원고 순서다. 규약 순서로 맞춘다:
`화면` → `데이터와 API` → `기획` → `구상` → `인터뷰` → `유저 플로우` →
`구조` → `개발 과정` → `시행착오` → `남은 것`.
**`기획` → `구상` → `인터뷰` 순이다** — 문제를 세우고, 그래서 만들기로 한 것을 늘어놓고,
그러게 된 사람 사정으로 좁혀 들어간다. 기능 목록이 문제 정의보다 앞에 서면 안 된다. **본문은 `화면` 으로 연다.** 기술 스택은 `stack` 으로 그 바로 뒤에 자동으로
끼워지고 `데이터와 API` 가 받는다. **`구조` 는 `유저 플로우` 바로 뒤다** — 사람이
움직이는 길 다음에 데이터가 흐르는 길이다.
**`개발 과정` 과 `시행착오` 는 붙여서 뒤쪽에 둔다** — 둘 다 길어서, 앞에 오면
읽는 사람이 얼개를 보기도 전에 지친다.

**구상이 부푼 경우** — 저쪽 세션이 개발 다 끝난 레포를 읽고 쓰기 때문에, 이 섹션이
완성된 기능 목록으로 불어나 있는 일이 잦다. **기획 시점에 알고 있던 것만 남긴다.**
- 항목이 7개 넘으면 거의 회고적으로 채운 것이다. 첫 커밋 즈음의 구상만 남기고 줄인다
- 버그·성능·해결 과정이 항목으로 들어와 있으면 → `## 시행착오` 로 옮긴다
- 개발하다 붙은 기능이 들어와 있으면 → `## 개발 과정` 의 해당 단계로 녹인다
- **체크박스가 붙어 있으면 뗀다.** `- [x]`·`- [ ]` → `- `. 구상은 막연히 떠올린 첫
  그림이라 진척을 말하지 않는다. 못 한 것을 티 내는 말(`아직`, `못 했다`)도 뺀다 —
  그 순간 `## 남은 것` 과 같은 줄이 된다
- 항목이 `## 유저 플로우` 의 단계 제목과 같은 문장이면 → 구상을 한 단계 위로 올려
  다시 쓴다. 구상은 그 물건이 해 주는 일, 플로우는 화면을 거치는 순서다
- 옮기면서 원고에 없던 내용을 지어내지 않는다. 옮길 자리가 마땅찮으면 버리고 보고에 적는다

**남은 것이 할 일 목록인 경우** — 저쪽 세션이 레포를 읽고 쓰기 때문에 여기가 개발자
백로그로 채워져 있는 일이 잦다. **이 물건이 아직 못 해주는 것만 남긴다.**
- 출시·심사·배포·도메인 이야기(`스토어에 못 올렸어요`, `Mac 이 있어야 해요`)는 통째로 뺀다.
  기능 이야기가 아니라 사정 이야기라, 물건이 덜 된 것처럼만 읽힌다
- 코드 레벨 항목(파일·함수·컬럼·패키지 이름, 테스트 커버리지, 리팩터링 계획)은
  **증상 쪽으로 바꿔 쓰거나** 뺀다. 읽는 사람은 이 코드를 모른다
- 걸러내고 3~6줄이면 넉넉하다. 다 빠지면 섹션을 통째로 뺀다

**빠진 것**
- `## 기획` 이 없거나 `타겟` / `범위` 가 비었으면 → **사용자에게 묻는다.**
  기획은 코드에서 못 캔다. 지어내지 않는다
- `## 인터뷰` 가 없거나 `소개` / `계기` 가 비었으면 → 마찬가지로 묻는다.
  `소개` 가 비면 표지 말고는 이 물건이 뭔지 말하는 자리가 없다
- `## 개발 과정` 이 없으면 → 원고의 다른 섹션과 그 프로젝트 레포의 커밋 로그로 초안을 잡되,
  근거가 얇으면 사용자에게 확인받는다
- `stack` 표기가 공식 표기와 다르면 고친다 (`nextjs` → `Next.js`, `postgres` → `PostgreSQL`).
  아이콘을 이름으로 찾기 때문이다

**문체** — 규약의 문체 절대로. 해요체 기본, 개발 일지 톤.
`~했다` 로만 끝나는 문장이 이어지면 손본다. `**라벨** 값` 줄은 예외로 짧게 둔다.
**영어 부사 직역을 걷어낸다** — `조용히`(silently)가 실패·무시·삭제를 꾸미고 있으면
정황을 문장으로 편다("에러도 경고도 없이", "어디에도 표시가 안 났다").
`우아하게`·`공격적으로`·`무겁게`도 같다.

### 3. 파일을 놓는다

**저쪽 레포의 `portfolio/` 폴더를 통째로 `projects/<slug>/` 로 옮긴다.**
slug 는 프런트매터의 것을 쓴다.

```
projects/
  mcp-probe/
    portfolio.md
    logo.png
    screens/01-home.png
```

**경로는 고치지 않는다.** `**파일**` 과 `logo_file` 의 상대경로는 원고 파일 기준인데,
원고가 그 폴더 안에 그대로 있으니 `./screens/01-home.png` 가 알아서 맞는다.
폴더를 풀어헤쳐 파일만 옮기면 그때부터 경로를 일일이 다시 써야 한다 — 그러지 마라.

원고 내용만 붙여받았고 파일이 없으면 `projects/<slug>/portfolio.md` 로 저장하고,
로컬 파일을 가리키는 줄(`logo_file`, `**파일**`)은 지운 뒤 보고에 적는다.
없는 파일을 가리키면 적재가 그 자리에서 실패한다.

이 파일들은 커밋한다. 적재하면 스토리지로 올라가지만, 원고를 다시 push 할 때
로컬 원본이 없으면 그 자리에서 막히기 때문이다. 그래서 영상은 작게 유지한다.

### 4. 적재한다

```
npm run project -- push projects/<slug>/portfolio.md
```

**이미 발행된 프로젝트면 스크립트가 막는다.** 그게 정상이다. 어드민 에디터가
source of truth 라 파일로 덮으면 거기서 고친 내용이 롤백된다.
막혔을 때 `--force` 를 임의로 붙이지 않는다 — 사용자에게 알리고 물어본다.

### 5. 캡처한다

`url` 이 있고 `capture: true` 면:

```
npm run capture:project <slug>
```

배포 안 했거나 `capture: false` 면 건너뛴다.

### 6. 확인하고 보고한다

`npm run dev` 로 띄워 `/lab/<slug>` 를 눈으로 본다. 화면이 옛 HTML 을 내주면
`.next` 를 지우고 다시 띄운다.

보고에는 이렇게 적는다.

- 적재한 slug 와 공개 URL
- 원고에서 **고친 것** — 옮긴 섹션, 바꾼 표기, 지운 옛 규약 흔적
- 기획에 채운 라벨과, 사용자에게 물어야 채워지는 판단
- 여전히 **비어 있는 것** 과 이유
- 사용자가 직접 해야 하는 일 (어드민에서 발행, 로고 파일 추가 등)

## 하지 않는 것

- **발행하지 않는다.** 적재는 `draft` 로 들어간다. 공개는 어드민에서 사용자가 누른다
- 근거 없는 내용을 채워 넣지 않는다. 특히 기획(`타겟`·`범위`), API 호출 제한, 시행착오
- `--force` 를 스스로 붙이지 않는다
