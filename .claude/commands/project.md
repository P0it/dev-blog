# /project — 포트폴리오 원고 → 실험실 적재

원고 위치 / 붙여넣은 내용: **$ARGUMENTS**

다른 레포의 Claude 세션이 `/portfolio` 스킬로 만든 `portfolio.md` 를 받아
이 레포 규약에 맞게 손질하고 Supabase `projects` 에 적재한다.

**받은 원고를 그대로 밀어 넣지 않는다.** 저쪽 세션은 규약의 옛 버전을 들고 있을 수도 있고,
기획 의도처럼 코드에 안 남는 건 비워 두고 왔을 수도 있다. 여기서 한 번 거른다.

## 절차

### 1. 원고를 확보한다

`$ARGUMENTS` 가 파일 경로면 그걸 읽는다. 내용을 그대로 붙여넣었으면 그걸 쓴다.
아무것도 없으면 원고를 달라고 한다. 레포 루트에 `portfolio.md` 가 굴러다니면 그것도 후보다.

### 2. 규약과 대조한다

`skills/portfolio/SKILL.md` 를 읽는다. **기억에 의존하지 않는다** — 규약은 계속 바뀐다.
그다음 원고를 훑으며 아래를 고친다.

**섹션 제목** — 아는 제목이 아니면 그 섹션은 화면에서 밋밋한 글로 떨어진다.
아는 제목은 `제품 소개` `기획` `유저 플로우` `요구사항` `개발 과정` `데이터와 API`
`시연` `구조` `시행착오` `남은 것` 뿐이다. 비슷한 뜻의 제목(`개발 후기`, `회고`)은
맞는 섹션으로 옮기거나, 정말 남길 이유가 있으면 그대로 두되 사용자에게 알린다.

**옛 규약의 흔적**
- `## 기술 선정` 표가 있으면 → 첫 열(또는 `고른 것` 열)의 이름을 프런트매터 `stack` 으로
  옮기고 섹션은 지운다. 고른 이유 중 살릴 만한 건 `## 개발 과정` 으로 녹인다
- `## 유저 플로우` 에 mermaid 가 있으면 → 노드를 `### 단계` 로 풀고, 분기는
  `**갈라짐** 조건 → 결과 / 조건 → 결과` 한 줄로 바꾼다. mermaid 는 `## 구조` 에서만 쓴다
- `logo_emoji` 가 있으면 지운다. 로고는 이미지 아니면 첫 글자 모노그램이다

**빠진 것**
- `## 기획` 이 없거나 `문제` / `사용자` / `넣지 않은 것` 이 비었으면 → **사용자에게 묻는다.**
  기획 의도는 코드에서 못 캔다. 지어내지 않는다
- `## 개발 과정` 이 없으면 → 원고의 다른 섹션과 그 프로젝트 레포의 커밋 로그로 초안을 잡되,
  근거가 얇으면 사용자에게 확인받는다
- `stack` 표기가 공식 표기와 다르면 고친다 (`nextjs` → `Next.js`, `postgres` → `PostgreSQL`).
  아이콘을 이름으로 찾기 때문이다

**문체** — 규약의 문체 절대로. 해요체 기본, 개발 일지 톤.
`~했다` 로만 끝나는 문장이 이어지면 손본다. `**라벨** 값` 줄은 예외로 짧게 둔다.

### 3. 파일을 놓는다

`projects/<slug>.md` 로 저장한다. slug 는 프런트매터의 것을 쓴다.
로고·시연 파일이 딸려 왔으면 `logo_file` / `**파일**` 의 상대경로가 실제로 맞는 자리에
오도록 같이 옮긴다. 없는 파일을 가리키면 적재가 그 자리에서 실패한다.

### 4. 적재한다

```
npm run project -- push projects/<slug>.md
```

**이미 발행된 프로젝트면 스크립트가 막는다.** 그게 정상이다. 어드민 에디터가
source of truth 라 파일로 덮으면 거기서 고친 내용이 롤백된다.
막혔을 때 `--force` 를 임의로 붙이지 않는다 — 사용자에게 알리고 물어본다.

### 5. 캡처한다

`url` 이 있고 `capture: true` 면:

```
npm run capture:project <slug>
```

배포 안 했거나 `capture: false` 면 건너뛴다.

### 6. 확인하고 보고한다

`npm run dev` 로 띄워 `/lab/<slug>` 를 눈으로 본다. 화면이 옛 HTML 을 내주면
`.next` 를 지우고 다시 띄운다.

보고에는 이렇게 적는다.

- 적재한 slug 와 공개 URL
- 원고에서 **고친 것** — 옮긴 섹션, 바꾼 표기, 지운 옛 규약 흔적
- 여전히 **비어 있는 것** 과 이유
- 사용자가 직접 해야 하는 일 (어드민에서 발행, 로고 파일 추가 등)

## 하지 않는 것

- **발행하지 않는다.** 적재는 `draft` 로 들어간다. 공개는 어드민에서 사용자가 누른다
- 근거 없는 내용을 채워 넣지 않는다. 특히 기획 의도, API 호출 제한, 시행착오
- `--force` 를 스스로 붙이지 않는다
