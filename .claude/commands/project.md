# /project — 포트폴리오 원고 → 실험실 적재

원고 위치 / 붙여넣은 내용: **$ARGUMENTS**

다른 레포의 Claude 세션이 `/portfolio` 스킬로 만든 `portfolio.md` 를 받아
이 레포 규약에 맞게 손질하고 Supabase `projects` 에 적재한다.

**받은 원고를 그대로 밀어 넣지 않는다.** 저쪽 세션은 규약의 옛 버전을 들고 있을 수도 있고,
기획 의도처럼 코드에 안 남는 건 비워 두고 왔을 수도 있다. 여기서 한 번 거른다.

## 절차

### 1. 원고를 확보한다

`$ARGUMENTS` 가 경로면 그걸 쓴다 — **폴더 경로여도 된다.** `portfolio/` 를 통째로
받는 게 정상이고, 그 안의 `portfolio.md` 가 원고다.
내용을 그대로 붙여넣었으면 그걸 쓰되, 그때는 로고·화면 파일이 없다는 뜻이다.
아무것도 없으면 달라고 한다. 레포 안에 `portfolio/` 나 `portfolio.md` 가 굴러다니면 후보다.

### 2. 규약과 대조한다

`skills/portfolio/SKILL.md` 를 읽는다. **기억에 의존하지 않는다** — 규약은 계속 바뀐다.
그다음 원고를 훑으며 아래를 고친다.

**섹션 제목** — 아는 제목이 아니면 그 섹션은 화면에서 밋밋한 글로 떨어진다.
아는 제목은 `제품 소개` `기획` `화면` `유저 플로우` `구상` `개발 과정` `데이터와 API`
`시연` `구조` `시행착오` `남은 것` 뿐이다. 비슷한 뜻의 제목(`개발 후기`, `회고`)은
맞는 섹션으로 옮기거나, 정말 남길 이유가 있으면 그대로 두되 사용자에게 알린다.

**옛 규약의 흔적**
- `## 기술 선정` 표가 있으면 → 첫 열(또는 `고른 것` 열)의 이름을 프런트매터 `stack` 으로
  옮기고 섹션은 지운다. 고른 이유 중 살릴 만한 건 `## 개발 과정` 으로 녹인다
- `## 유저 플로우` 에 mermaid 가 있으면 → 노드를 `### 단계` 로 풀고, 분기는
  `**갈라짐** 조건 → 결과 / 조건 → 결과` 한 줄로 바꾼다. mermaid 는 `## 구조` 에서만 쓴다
- `logo_emoji` 가 있으면 지운다. 로고는 이미지 아니면 첫 글자 모노그램이다
- `## 요구사항` 은 옛 제목이다 → `## 구상` 으로 바꾼다. 파서는 둘 다 받지만 화면에
  제목이 그대로 나오므로, 새 원고에 옛 이름이 남아 있으면 안 된다.
  이름만 바꾸고 끝내지 말고 아래 "구상이 부푼 경우"까지 같이 적용한다

**제품 소개와 기획이 겹치는 경우** — 자주 겹친다. 둘 다 "누구의 어떤 불편을 푸는가"로
끌려가기 때문이다. **시제로 가른다** — 소개는 지금 무엇인가(현재형), 기획은 그때 왜
시작했나(과거형).
- 소개에 불편했던 상황이 한 문장 넘게 늘어져 있으면 → 줄이고 `## 기획` 의 `**문제**` 로 몰아준다.
  **문제 서술의 정본은 `## 기획` 이다**
- 소개에 사용자층 설명·만든 동기가 있으면 → `**사용자**` 줄, `## 개발 과정` 으로 옮긴다
- 옮기고 나서 소개가 두 문단 아래로 줄면 그대로 둔다. 억지로 늘리지 않는다
- `## 제품 소개` 는 본문 섹션이 아니라 **표지 아래 리드**로 그려진다. 번호도 목록에도
  안 뜬다. 그래서 본문의 첫 섹션은 `## 기획` 이어야 한다 — 원고에서 소개가 빠져 있으면
  표지 밑이 휑해지니 사용자에게 알린다

**화면이 없는 경우** — `## 화면` 은 정지 화면 3~5 장을 그리드로 까는 섹션이다.
없이도 글은 성립하니(표지 이미지가 있다) **억지로 만들지 않는다.** 사용자에게 몇 장
받을 수 있는지 한 번 묻고, 없다고 하면 섹션을 빼고 그대로 적재한다.
여기서 앱을 띄워 찍으려 들지 않는다 — 그건 프로젝트 레포를 아는 저쪽 세션의 몫이다.
있는데 부실하면 이렇게 거른다.
- 로그인·빈 상태·에러 화면이 들어와 있으면 뺀다. 이 물건이 뭔지 알려주지 않는다
- 6 장을 넘으면 줄인다. 전 화면을 늘어놓는 자리가 아니다
- `## 시연` 과 같은 장면이 겹치면 한쪽만 남긴다 (화면은 한 컷, 시연은 흐름)
- `**설명**` 줄이 붙어 있으면 지운다. 화면 갤러리는 이름표만 그린다.
  버리기 아까운 내용이면 `## 개발 과정` 의 해당 단계로 녹인다
- 홈·메인 화면을 맨 앞으로 옮긴다. **첫 장이 목록 카드의 대표 화면이 된다**

**섹션 순서** — 화면에 나오는 순서가 곧 원고 순서다. 규약 순서로 맞춘다:
`제품 소개`(표지 리드) → `화면` → `기획` → `구상` → `유저 플로우` → `개발 과정` →
`데이터와 API` → `시연` → `구조` → `시행착오` → `남은 것`.
**`구상` 은 `기획` 바로 뒤여야 한다** — 왜 만들려 했는지 다음에 무엇을 만들기로
했는지가 이어져야 한다. **본문은 `화면` 으로 연다.** 기술 스택은 `stack` 으로
그 바로 뒤에 자동으로 끼워진다.

**구상이 부푼 경우** — 저쪽 세션이 개발 다 끝난 레포를 읽고 쓰기 때문에, 이 섹션이
완성된 기능 목록으로 불어나 있는 일이 잦다. **기획 시점에 알고 있던 것만 남긴다.**
- 항목이 7개 넘으면 거의 회고적으로 채운 것이다. 첫 커밋 즈음의 구상만 남기고 줄인다
- 버그·성능·해결 과정이 항목으로 들어와 있으면 → `## 시행착오` 로 옮긴다
- 개발하다 붙은 기능이 들어와 있으면 → `## 개발 과정` 의 해당 단계로 녹인다
- `[ ]` 항목이 `## 남은 것` 과 겹치면 → 구상 쪽을 남기고 남은 것에서 뺀다
- 옮기면서 원고에 없던 내용을 지어내지 않는다. 옮길 자리가 마땅찮으면 버리고 보고에 적는다

**빠진 것**
- `## 기획` 이 없거나 `문제` / `사용자` / `넣지 않은 것` 이 비었으면 → **사용자에게 묻는다.**
  기획 의도는 코드에서 못 캔다. 지어내지 않는다
- `## 개발 과정` 이 없으면 → 원고의 다른 섹션과 그 프로젝트 레포의 커밋 로그로 초안을 잡되,
  근거가 얇으면 사용자에게 확인받는다
- `stack` 표기가 공식 표기와 다르면 고친다 (`nextjs` → `Next.js`, `postgres` → `PostgreSQL`).
  아이콘을 이름으로 찾기 때문이다

**문체** — 규약의 문체 절대로. 해요체 기본, 개발 일지 톤.
`~했다` 로만 끝나는 문장이 이어지면 손본다. `**라벨** 값` 줄은 예외로 짧게 둔다.

### 3. 파일을 놓는다

**저쪽 레포의 `portfolio/` 폴더를 통째로 `projects/<slug>/` 로 옮긴다.**
slug 는 프런트매터의 것을 쓴다.

```
projects/
  mcp-probe/
    portfolio.md
    logo.png
    screens/01-home.png
    demo/flow.mp4
```

**경로는 고치지 않는다.** `**파일**` 과 `logo_file` 의 상대경로는 원고 파일 기준인데,
원고가 그 폴더 안에 그대로 있으니 `./screens/01-home.png` 가 알아서 맞는다.
폴더를 풀어헤쳐 파일만 옮기면 그때부터 경로를 일일이 다시 써야 한다 — 그러지 마라.

원고 내용만 붙여받았고 파일이 없으면 `projects/<slug>/portfolio.md` 로 저장하고,
로컬 파일을 가리키는 줄(`logo_file`, `**파일**`)은 지운 뒤 보고에 적는다.
없는 파일을 가리키면 적재가 그 자리에서 실패한다.

이 파일들은 커밋한다. 적재하면 스토리지로 올라가지만, 원고를 다시 push 할 때
로컬 원본이 없으면 그 자리에서 막히기 때문이다. 그래서 영상은 작게 유지한다.

### 4. 적재한다

```
npm run project -- push projects/<slug>/portfolio.md
```

**이미 발행된 프로젝트면 스크립트가 막는다.** 그게 정상이다. 어드민 에디터가
source of truth 라 파일로 덮으면 거기서 고친 내용이 롤백된다.
막혔을 때 `--force` 를 임의로 붙이지 않는다 — 사용자에게 알리고 물어본다.

### 5. 캡처한다

`url` 이 있고 `capture: true` 면:

```
npm run capture:project <slug>
```

배포 안 했거나 `capture: false` 면 건너뛴다.

### 6. 확인하고 보고한다

`npm run dev` 로 띄워 `/lab/<slug>` 를 눈으로 본다. 화면이 옛 HTML 을 내주면
`.next` 를 지우고 다시 띄운다.

보고에는 이렇게 적는다.

- 적재한 slug 와 공개 URL
- 원고에서 **고친 것** — 옮긴 섹션, 바꾼 표기, 지운 옛 규약 흔적
- 여전히 **비어 있는 것** 과 이유
- 사용자가 직접 해야 하는 일 (어드민에서 발행, 로고 파일 추가 등)

## 하지 않는 것

- **발행하지 않는다.** 적재는 `draft` 로 들어간다. 공개는 어드민에서 사용자가 누른다
- 근거 없는 내용을 채워 넣지 않는다. 특히 기획 의도, API 호출 제한, 시행착오
- `--force` 를 스스로 붙이지 않는다
