# /scene — 아이소메트릭 흐름 장면

입력: **$ARGUMENTS**

입력은 둘 중 하나다.
- **주제 하나** — "RAG 질의 파이프라인", "MCP 연결"
- **시리즈 계획 문서 + 편 번호** — "docs/series/ai-architecture-cheatsheet.md 4편". 그 편의 "한 장에 보일 것"·근거 칸을 출발점으로 쓴다.

이 커맨드는 **그림 한 장**을 만든다. 글 전체(제목·본문·윤문·적재)는 `/study` 절차를 따르고, 그 안에서 대표 그림을 이 형식으로 만들 때 쓴다.
규약은 `POSTING.md` 5-11, 견본은 `auto-drafts/posts/iso-scene-sample.html`. 견본을 먼저 읽는다 — 마크업과 장면 적는 법이 거기 다 있다.

## 1. 요점 한 문장과 비유

- 이 그림이 전할 **요점 한 문장**을 적는다. 예: "모델은 다음 할 일만 말하고 실행은 런타임이 한다."
- 그 요점이 **그림만 봐도 보이는 비유**를 고른다. 묻는 순서:
  1. 누가 움직이고 누가 제자리에 있나? (움직이는 쪽이 일을 하는 쪽으로 읽힌다)
  2. 들고 다니는 것은 무엇이고 단계마다 어떻게 변하나? (두꺼워지는 일지 = 길어지는 대화 기록)
  3. 정거장마다 "거기서 벌어지는 일"이 한 줄로 말해지나? ("일지를 처음부터 읽는 중")
- 비유 후보를 2~3개 적고, 요점이 가장 잘 보이는 하나를 고른다. 다른 편과 같은 비유를 되풀이하지 않는다.
  비유가 안 맞는 곳도 같이 적어 둔다(단계 글에 한 줄로 밝힌다).
- 창고·나무·상자 더미 같은 꾸밈 소재는 넣지 않는다. 장면에 있는 사물은 전부 구성 요소이거나 그 구성 요소가 든 것이다.
- 근거는 공식 문서·스펙으로 다시 확인한다. 예시의 모델·도구는 한 회사로 몰지 않는다.

## 2. 단계 대본

- **예시 요청 하나**를 정하고 그것이 거치는 단계를 5~7개로 적는다. 단계마다: 이름(두세 글자) · 설명 한두 문장 · 누가 어디로 가나 ·
  들고 가는 것 · 거기서 벌어지는 일 · 받아 오는 것.
- 설명은 **왜 그렇게 움직이는지**를 적는다. 그림에 보이는 것("비서가 자문실로 갑니다")만 되풀이하지 않는다.
- 전체 흐름 한 줄(`p.iso-sum`)은 요점 한 문장을 그림의 번호와 엮어 적는다("자문실에는 루프마다 다시 들릅니다(2 · 4 · 6)").

## 3. 장면 적기

- 원고에 `<!--ISO-->` 한 줄을 두고 그 아래에 견본과 같은 마크업을 쓴다. 독자가 읽는 문장은 전부 HTML 에 둔다.
- 정거장은 다섯 개 안팎. **서로 정거장 폭 이상 띄운다.** 가운데에 움직이는 쪽의 자리를 두고 나머지를 둘레에 놓으면 길이 겹치지 않는다.
- 길은 축을 따라 긋는다(x 만 바뀌거나 z 만 바뀌게). 꺾으면 직각. 길이 정거장 바닥 판을 가로지르지 않게 한다.
- 부품은 상자와 사람으로 짓는다. **뒤에 있는 것부터 앞 순서로** 적는다. 색은 이름으로(`blue` `teal` …) — 다크 모드 값이 따로 있다.
  사물 하나는 부품 2~5개면 충분하다. 무엇인지 알아볼 만큼만 짓는다.
- 맡긴 종이가 놓일 자리(`drop`)를 정거장마다 정한다. 창구 위, 발판 앞처럼 오가는 사람이 서는 쪽에 둔다.
- 동작은 `isoScene.trip()` 으로 한 바퀴씩 적는다. 처음(요청 받기)과 끝(답 전하기)만 손으로 적는다.
- 순서 번호(`badges`)는 길 위 빈 곳에 둔다. 이름표와 겹치지 않는지 모바일에서도 본다.

## 3-1. 흐름도가 있는 글(AI 시스템 설계 시리즈)에 넣을 때

- 장면은 머리 바로 아래, 흐름도는 그다음 섹션. 견본은 3편 `auto-drafts/posts/agent-runtime-loop-architecture.html` — 넣은 자리·사이 문장·스크립트 순서를 그대로 본뜬다.
- 흐름도와 **같은 예시 요청·같은 횟수**(모델 호출·도구 실행 수)로 대본을 쓴다. 흐름도의 턴 데이터를 먼저 읽는다.
- 두 그림 사이에 비유를 실제 구성 요소 이름으로 잇는 한두 문장을 쓴다.
- 썸네일을 장면으로 옮긴다(`POSTING.md` 5-11 의 `data-thumb` 줄).
- 장면 스크립트는 흐름도 스크립트보다 앞에 둔다. `<!--ISO-->` 는 본문 `<style>` 앞 한 줄.

## 4. 굽고 확인

```
npm run iso -- auto-drafts/posts/<slug>.html
npm run dev                                   # 이미 떠 있으면 생략
npm run check:page -- <slug> <캡처 폴더>
npm run check:page -- <slug> <캡처 폴더> --dark
```

캡처를 열어 직접 본다:
- 데스크톱·모바일·다크에서 정거장과 이름표가 겹치지 않는가. 이름표가 사람 머리를 가리지 않는가.
- 처음부터 재생해 끝까지 본다. 가는 방향을 보는가, 정거장에서 기다렸다가 결과를 받는가, 종이가 두꺼워지는가.
- 전체 흐름 화면만 보고도 순서가 읽히는가.
- 사물이 무엇인지 이름표 없이도 짐작되는가. 안 되면 부품을 더하기보다 비유를 다시 본다.

## 5. 마무리

- 엔진(`scripts/iso-scene/engine.{js,css}`)을 고쳤으면 견본을 다시 굽고 `check:page` 로 본 뒤 같이 커밋한다. 이미 발행한 글은 다시 구워야 바뀐다.
- 화면 규약을 바꿨으면 `POSTING.md` 5-11 도 같이 고친다. 접은 안은 왜 접었는지까지 남긴다.
- 새로 확인한 레퍼런스는 `docs/visual-references.md` 에 더한다.
