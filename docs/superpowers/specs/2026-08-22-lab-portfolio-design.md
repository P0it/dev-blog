# 실험실(Lab) 포트폴리오 개편 설계

작성일: 2026-08-22

## 배경

`/lab` 은 지금 프로젝트 카드 그리드와, `body_md` 마크다운을 블로그 글처럼 렌더하는 상세
페이지로 되어 있다. 상세가 포스트 레이아웃(`post-layout` + 우측 목차 + `PostBody`)을
그대로 쓰기 때문에 글과 프로젝트가 화면상 구분되지 않는다.

앞으로 개인 프로젝트를 하나씩 포트폴리오로 올린다. 각 프로젝트의 아이디어 도출, 기술 선정,
시행착오는 그 프로젝트 레포의 Claude 세션이 자기 메모리·커밋 로그에서 뽑아 넘긴다.
이 문서는 (1) 그 세션이 무엇을 어떤 형식으로 채워야 하는지, (2) 넘어온 내용을 이 블로그가
어떻게 적재하고 어떤 화면으로 보여주는지를 정한다.

## 목표

- 상세 페이지를 열었을 때 "이게 뭐 하는 물건인가"가 글보다 먼저 보인다
- 프로젝트를 새로 올리는 데 드는 추가 작업이 거의 없다 — 규약대로 쓰면 화면이 완성된다
- 목록 카드는 로고·이름·한 줄로 최소화하고, 나머지는 전부 상세로 내린다
- 스크롤에 따른 연출이 붙되, 프로젝트마다 코드를 새로 쓰지 않는다

## 하지 않는 것

- 3D / 모션그래픽 라이브러리 도입 (번들 비용 대비 효과가 낮다)
- 프로젝트별 커스텀 컴포넌트 (특정 프로젝트를 밀고 싶어질 때 개별 판단)
- 어드민에 프로젝트 관리 화면 추가 (CLI 적재로 충분하다)
- 포스트(`/posts`) 쪽 레이아웃 변경

## 전체 흐름

1. 프로젝트 레포에서 `/portfolio` — 세션이 레포·메모리·커밋 로그를 근거로 `portfolio.md` 생성
2. 그 파일을 이 레포 `projects/<slug>.md` 로 가져온다
3. `npm run project -- push projects/<slug>.md` → Supabase `projects` upsert
4. 배포 URL 이 있으면 `npm run capture:project <slug>` → 스크린샷·스크롤 영상 캡처 후 DB 갱신

로고는 1단계에서 이모지+배경색으로 채우고, 스크린샷·영상은 4단계에서 이 레포가 찍는다.
다른 레포 세션은 텍스트만 책임진다.

## 1. 수집 규약 — `/portfolio` 스킬

원본은 이 레포 `skills/portfolio/SKILL.md` 에 두고 커밋한다. `~/.claude/skills/portfolio`
를 그쪽으로 심볼릭 링크해 유저 스코프로 노출한다 (`npm run setup:skills`). 어느 레포에서든
`/portfolio` 로 뜨면서, 규약 수정 이력은 이 레포에 남는다.

스킬은 self-contained 로 쓴다 — 블로그 레포 사정을 모르는 세션에서도 혼자 돌아가야 한다.

### 출력물

레포 루트에 `portfolio.md` 한 장. 프런트매터 + 본문 마크다운.

```yaml
---
slug: mcp-probe            # 필수, ASCII 케밥
name: MCP Probe            # 필수, 카드에 뜨는 이름
tagline: MCP 서버를 붙여보고 응답을 날것으로 보는 도구   # 필수, 40자 이내
year: "2026"               # 필수
logo_bg: "#1F6FEB"         # 필수, 단색
stack: [Next.js, Cloudflare Workers, TypeScript]
url: https://mcp-probe.pages.dev   # 스킴 포함 절대 URL. 배포 없으면 빈 값
host: cloudflare                   # vercel | cloudflare | local | none
status: 운영중              # 운영중 | 실험중 | 중단
capture: true              # 공개 URL 스크롤 캡처 허용 여부
---
```

### 본문 섹션

`##` 제목은 글자 그대로 지킨다. UI 가 이 제목으로 섹션을 갈라 렌더러를 고르기 때문이다.

| 섹션 | 내용 | 형식 제약 |
|---|---|---|
| `## 화면` | 정지 화면 6~10 장 그리드 (판 + 이름표 + 한 줄 설명) | `### 이름` + `**파일**` + `**설명**`. 짧은 영상도 같은 자리에 넣는다. **판 모양은 프런트매터 `platform` 이 정하고**(아래 2-1), 그 안에서 그림 비율은 렌더러가 판별한다 — 폰 판에서 가로 화면은 두 칸, 스크롤까지 담긴 긴 캡처는 상세에서만 판 안을 훑어 내린다(손 얹은 한 장만). **목록 카드는 움직이지 않고 맨 위만 잘라 세운다**. 판을 누르면 원본을 확대 창에서 본다 |
| `## 데이터와 API` | 붙인 외부 데이터·서비스 | `### 이름` 단위. `**용도**` 한 줄 필수(카드에 서는 유일한 문장이라 여기서 승부한다), `**링크**` 는 카드에, **나머지 라벨은 전부 확대 창**. 라벨 이름·순서는 원고가 정한다. 코드 레벨 서술 금지 |
| `## 구상` | 기획 시점에 만들려던 것 (개발 중 붙은 건 제외) | `- [x]` / `- [ ]` 체크리스트, 항목당 한 줄 |
| `## 기획` | 만든 사람 인터뷰. 이 물건이 뭔지도 여기서 말한다 | `**라벨** 값` 줄. 라벨이 화면에서 질문으로 바뀐다(`소개`→"어떤 서비스인가요?"). `소개`·`계기`·`사용자` 를 되도록, 여섯~여덟 줄 |
| `## 유저 플로우` | 사람이 움직이는 동선 | `### 단계` 목록 + 선택적 `**갈라짐** 조건 → 결과 / …`. mermaid 안 씀 |
| `## 구조` | 계층과 그 사이로 오가는 것 | mermaid 블록 1개(subgraph 로 경계·라벨 붙은 화살표) + 노드·subgraph 이름과 같은 `### 제목` 설명. **이름을 맞춰 쓴다** — 맞으면 툴팁으로 그림 위에 붙고, 안 맞으면 그림 아래 카드로 떨어진다 |
| `## 개발 과정` | 생각이 흘러간 순서. 막힌 지점과 그때 붙인 것 | `### 단계` 단위 서술 + 선택적 `**붙인 것** 이름, 이름` |
| `## 시행착오` | 삽질 케이스 | `### 케이스 제목` 단위, 각각 **증상 / 시도 / 결론** 세 문단 |
| `## 남은 것` | 다음 작업, 알려진 한계 | 짧은 목록 |

기술 스택은 본문에 쓰지 않는다. 프런트매터 `stack` 배열이 유일한 소스이고,
상세 화면이 `## 기술 스택` 섹션을 스스로 끼워 넣는다. 옛 원고가 본문에 표를 갖고
있으면 그쪽 이름을 쓴다(하위 호환).

### 스킬이 추가로 지시하는 것

- **문체 규칙** — 개발 일지·회고록 톤. 해요체를 기본으로 하고 합니다체를 섞는다.
  "~했다" 로만 끝나는 문장을 잇지 않는다. 다른 세션이 쓴 글이 그대로 올라오므로
  이게 없으면 톤이 제각각으로 깨진다. `**라벨** 값` 줄만 예외로 짧게 끊는다.
- **시행착오 선별 기준** — 해결까지 두 번 이상 방향을 튼 것만. 오타 수정·단순 버그는 제외.
  근거는 커밋 로그, 이슈, 세션 메모리에서 찾는다.
- **모르는 건 지어내지 않는다** — 채우지 못한 필드는 사용자에게 묻거나, 보고에 명시한다.

## 2. 데이터 모델

### 마이그레이션 `db/migrations/0013_project_portfolio.sql`

`projects` 에 추가:

| 컬럼 | 타입 | 용도 |
|---|---|---|
| `tagline` | text | 카드 한 줄 |
| `logo_emoji` | text | (미사용) 초기 설계의 흔적. 화면은 이모지를 쓰지 않는다 |
| `logo_bg` | text | 로고 타일 배경색 |
| `logo_url` | text | 실제 로고 이미지. 있으면 이모지보다 우선 |
| `status` | text | 운영중 / 실험중 / 중단 |
| `platform` | text | 화면을 올릴 판 — `mobile`(폰) / `web`(브라우저 창). 기본 `mobile` (`0015_project_platform.sql`) |
| `hero_media` | text | 스크롤 영상 URL (mp4) |
| `hero_poster` | text | 영상 첫 프레임 · 대표 스크린샷 URL |
| `shots` | text[] | 추가 스크린샷 |

제거: `description`, `plan`, `build_note`, `thumb_kind`. `Project` 타입의 `k` 필드도 함께 뺀다.
카드에서 빠지고 본문 섹션이 대체한다. 남겨두면 같은 내용이 두 군데로 갈라져 산다.
`tagline` 백필은 기존 `description` 에서 가져오고, 그 다음 컬럼을 드롭한다.

`src/lib/types.ts` 의 `Project` 와 `queries.ts` 의 `rowToProject` 를 같이 고친다.
`host` 타입은 지금 `"vercel" | "cloudflare"` 뿐이라 `"local" | "none"` 을 더한다.
기존 `url` 값은 도메인만 들어있으므로 `https://` 를 붙여 백필한다.

프런트매터의 `capture` 는 DB 컬럼이 아니다. `capture-project.mjs` 가 `projects/<slug>.md` 를
읽어 판단하는 값이라 `push` 는 이 키를 무시한다.

### 2-1. 화면 판 `platform` — 폰이냐 브라우저 창이냐

판을 그림 비율만 보고 고르던 것을 원고가 정하게 바꿨다(`0015`).

**왜 비율로는 안 되나.** 폰 판은 390×844(비율 0.46), 가로 판정은 1.1 이었다. 그
사이(0.46~1.1)에 **데스크탑 전체 페이지 캡처**가 통째로 들어온다 — 1440×2300 이면
비율 0.63 이라 "넓지도 아주 길지도" 않아서 폰 판에 `object-fit: cover` 로 우겨넣어지고
좌우가 잘린다. 절대 폭으로 가르려 해도 폰 캡처 3배율(1170px)과 데스크탑 1배율(1440px)이
붙어 있어 못 가른다.

**기준은 쓰인 기술이 아니라 캡처를 무엇으로 찍었는가다.** 사우나우·데일리 브리핑도
Next.js 웹앱이지만 화면은 폰으로 찍혀 있으니 `mobile` 이다. 기본값이 `mobile` 이라
이 컬럼이 생기기 전에 올린 프로젝트는 서 있던 모습 그대로 남는다.

| | 폰 (`mobile`) | 브라우저 창 (`web`) |
|---|---|---|
| 판 비율 | 390 / 844 | 16 / 10 |
| 목록 카드 | 한 칸 (248×536) | **세 칸** (812×507) |
| 상세 갤러리 | 한 칸, 가로 캡처만 두 칸 | 늘 두 칸 |
| 긴 캡처 | 상세만 훑어 내림, 목록은 맨 위 고정 | 같음 (판 비율만 다름) |
| 확대 창 | 세로 캡처는 실기기 폭(420px)에 세움 | 판 폭을 다 씀 |

**목록 카드가 세 칸인 이유.** 두 칸(530×331)은 옆에 선 폰 판(536)보다 200px 낮아
한 줄이 어긋나고, 1440px 화면을 37%로 줄여 글씨가 점이 된다. 세 칸이면 폰 판과
키가 맞고 축소율도 56%로 올라간다. 열 수가 줄어드는 좁은 폭에서는 두 칸(≥640px),
한 칸(<640px)으로 내린다.

**목록 카드는 움직이지 않는다.** 한때는 긴 캡처를 판 안에서 천천히 훑어 내렸다 —
잘라 두면 맨 위 한 뼘만 보여 목록에서 뭐가 뭔지 모른다고 봤다. 접었다. 카드 넷이
제각기 다른 속도로 흐르니 목록이 가만히 있질 않았고, 어디를 봐야 할지는 오히려 더
흐려졌다. 카드 하나가 답할 것은 "어떻게 생긴 물건인가" 하나뿐이고 그건 머리 한 판이면
대개 말이 된다. 훑어 내리기는 상세 갤러리에만 남았다.

**웹 판에서는 가로 판정을 하지 않는다.** 이미 두 칸을 쓰고 누워 있는데 또 "넓다"를
따지면, 살짝 세로로 긴 캡처가 넓다와 길다에 동시에 걸려 판이 오락가락한다.

판 비율은 CSS 에 못박지 않고 렌더러가 `--shot-ar` 로 넣는다. 한 곳에 박아 두면
웹 프로젝트가 폰 판에 갇힌다.

### 스토리지

`project-media` 버킷 신설. public, 상한 50MB, `video/mp4` · `image/webp` · `image/png` ·
`image/svg+xml` 허용. `scripts/setup-storage.mjs` 를 버킷 목록 순회 구조로 바꿔
`post-images` 와 함께 처리한다.

## 3. 목록 화면 `/lab`

`ProjectCard` 를 재작성한다. 로고 타일 / 이름 / 연한 한 줄, 그게 전부다.

```
┌─────────────────┐
│                 │   로고 타일 — logo_bg 단색 위에
│       🔌        │   이모지(또는 logo_url) 크게, 정사각
│                 │
├─────────────────┤
│ MCP Probe       │   이름
│ MCP 서버 붙여보고 │   tagline — 작고 연하게, 2줄에서 잘림
│ 응답을 날것으로   │
└─────────────────┘
```

제거: `Thumb` 다이어그램, 기획/구현 2줄, 스택 칩, 배포 URL, "자세히" 화살표,
페이지 하단 안내 문단. `.lab-grid` 는 카드가 작아지는 만큼 열 수를 늘린다.

`Thumb` 컴포넌트 자체는 포스트 쪽에서 계속 쓰므로 지우지 않는다.

### 로고 타일 — 확장자로 두 갈래

`logo_url` 이 **SVG** 면 마크만 그린 그림이다. 배경은 `logo_bg` 가 맡으므로 타일
안쪽에 여백을 두고 앉힌다(`64%`, `contain`).

`logo_url` 이 **래스터(png·jpg·webp)** 면 이미 완성된 앱 아이콘이다. 제 배경과
아이콘 규격의 안전 여백(가로세로 약 2/3)을 그림 안에 품고 있어서, 타일에서 또
줄여 넣으면 정작 마크가 타일의 3분의 1도 안 되게 앉는다. 그래서 타일을 가득
채우고(`cover`) 안전 여백만큼만 살짝 밀어 올린다(`scale(1.18)`). 더 키우면
아이콘이 타일 밖으로 밀려 나가 마크 가장자리가 잘린다. 넘치는 가장자리는
아이콘 제 배경뿐이고 `logo_bg` 를 같은 색으로 잡아 두므로 이음매가 보이지 않는다.

갈림은 `ProjectMark` 가 확장자를 보고 `is-icon` 클래스로 표시한다. 래스터 로고를
새로 넣을 때 `logo_bg` 를 **아이콘 배경과 같은 색**으로 맞추는 게 전제다.

## 4. 상세 화면 `/lab/[slug]`

포스트 레이아웃에서 완전히 떼어낸다. `post-layout` · 우측 목차 · `PostBody` 를 쓰지 않는다.

### 히어로

화면폭을 꽉 채우는 **정지 화면**. `hero_poster` 이미지, 없으면 `logo_bg` 단색 위에 로고.
움직이는 배경은 제목을 읽는 데 방해가 되므로 쓰지 않는다. 그 위에 제목,
tagline, `연도 · 스택 · 배포처 · status` 한 줄.

### 바로가기 링크

프로젝트로 들어가는 링크는 프런트매터 `url` 하나다. 여러 개를 받지 않는다.

버튼은 히어로 우상단 고정. 주소를 그대로 찍지 않고 **"바로가기"** 라벨 + 화살표 아이콘으로
묶는다. 지금 `ProjectDetailView` 는 `mcp-probe.pages.dev` 같은 도메인을 모노 폰트로 노출하는데,
도메인 문자열은 방문자에게 정보가 아니고 길이도 제각각이라 히어로 정렬을 흔든다.
호스트는 옆 메타 줄의 `배포처` 가 이미 말해준다.

`url` 은 스킴을 포함한 절대 URL 로 받고, `https://` 를 코드에서 붙이지 않는다. `url` 이 비면
버튼을 통째로 렌더하지 않는다.

**같은 링크를 목차 레일 아래에 한 번 더 세운다.** 히어로 우상단 버튼은 표지 장식처럼 읽히는
데다 스크롤하면 화면 밖으로 나가버려서, 본문을 다 읽고 "그래서 이거 어디서 보나"에 답이
없었다. 레일은 sticky 라 읽는 내내 따라온다. 목차 항목으로 오해되지 않게 실선 한 줄로
가르고, 점·번호 없이 테두리 있는 알약 버튼으로 그린다. 이건 원고가 켜고 끄는 게 아니라
`url` 이 있는 **모든 프로젝트에 자동으로** 붙는다. 레일이 접히는 900px 아래에서는 레일만
사라지고 버튼은 본문 맨 위에 가로로 꽉 차게 남는다.

라벨은 프로젝트를 안 가리고 **"사이트 체험하기"** 하나로 고정한다. 데모 페이지를 가리키는
링크라도 라벨을 갈지 않는다 — 열린 사이트가 자기 입으로 데모라고 말하므로, 버튼에서 미리
갈라 봐야 원고마다 라벨이 제각각이 될 뿐이다.

### 좌측 섹션 레일

sticky. 점 + 라벨로 섹션 목록을 표시하고, 스크롤 위치에 따라 현재 섹션이 채워진다.
IntersectionObserver 를 쓰는 클라이언트 컴포넌트. 포스트의 우측 목차와 위치·형태를
일부러 다르게 둬서 인상을 가른다.

### 섹션별 렌더러

`body_md` 를 `##` 기준으로 쪼개고, 제목이 아는 이름이면 전용 렌더러로 보낸다.

| 섹션 | 렌더링 | 움직임 |
|---|---|---|
| 화면 | 판 그리드(`platform` 이 폰이냐 브라우저 창이냐를 정한다 — 2-1). 판 아래 이름표 + 한 줄 설명. 영상도 같은 자리에 그린다. 판에 올리면 우상단에 확대 표시가 뜨고, 누르면 원본을 확대 창에서 본다(좌우 화살표·←→ 키로 옆 화면으로 넘어간다). 그리드의 판은 실제 화면보다 훨씬 작아 글씨가 안 읽힌다 — 원본을 보는 길이 없으면 목업 전시로 끝난다. **확대 창에서 세로 캡처는 실기기 폭(420px)에 세운다** — 폰 캡처 원본은 2·3배 밀도라(780×1688 = 390pt 화면의 두 배) 판 폭까지 늘리면 글씨가 기기에서 보던 것의 세 배로 부풀어 확대가 아니라 뭉개짐이 된다. 넘치는 길이는 스크롤로 받고, 가로 캡처만 판 폭을 다 쓴다 | 카드 스태거 |
| 기술 스택 | 브랜드 아이콘 + 이름 칩 나열 | 진입 시 페이드업 |
| 데이터와 API | 3열 압축 카드. 브랜드 로고 + 이름 + 용도 한 줄 + 링크까지만. 나머지 라벨은 **올리면 카드 아래로 이어 붙어 나오는 판**에서 라벨-값으로 읽는다. 그 판은 흐름 밖(`absolute`)이라 이웃을 **밀지 않고 덮는다** — 레이아웃은 그대로다. 손가락·키보드에는 hover 가 없으니 "자세히" 버튼으로도 같은 판을 여닫는다. **접은 안 셋** — ①칩: `방식`·`갱신` 값이 죄다 한 문장 이상이라 칩 안에서 잘려 아무 정보도 주지 못했다 ②제자리 펼침: 그리드 한 줄의 높이는 가장 큰 칸이 정하므로 카드 하나를 펼치면 옆 카드가 같이 늘어나 빈 상자가 됐다 ③확대 창(모달): 훑어 내리며 가볍게 보는 자리인데 화면이 전환되는 느낌이라 흐름이 끊겼다 | 카드 스태거. 열린 카드가 이웃 위로 올라오고 아래 모서리를 펴 판과 한 덩어리가 된다 |
| 구상 | `- [x]` 파싱 → 체크 카드 2열 그리드 | 카드 스태거 페이드인, 체크 표시가 그려지듯 |
| 기획 | 라벨을 질문으로 세운 인터뷰 문답 | 진입 시 페이드업 |
| 유저 플로우 | 번호 카드를 **세로로** 쌓고 사이를 점선+아래 화살표로 잇는다. 갈림길이 있는 카드만 900px 위에서 오른쪽 열을 연다 | 카드 스태거 |
| 구조 | 다이어그램을 본문 폭 판에 크게(`fontSize` 16, 확대 18). **판을 다 쓴다** — 자연 폭에 멈추면 노드 몇 개짜리 그림이 판 한가운데 우표만 하게 앉아 아무것도 안 읽힌다. 그림은 벡터라 키워도 안 흐려지므로 `Mermaid` 에 `fill` 을 주고 판 폭까지 늘린다. (판의 `.mermaid-figure` 에 `margin: 0 auto` 를 주면 세로 flex 안에서 stretch 가 꺼져 300px 로 주저앉는다 — `width: 100%` 로 못 박는다.) 선 색은 카드 테두리(`--lab-line`)가 아니라 다이어그램 전용 토큰(`--lab-diag-node`·`--lab-diag-edge`·`--lab-diag-cluster`)을 쓴다. 10% 짜리 테두리색을 쓰면 화살표가 배경에 묻힌다. 노드 색·선 굵기는 `.lab-arch-skin` 이 판과 확대 창 양쪽에 똑같이 입힌다. 판 머리줄에 "크게 보기", 아래에 범례(실선=보내는 것, 점선=되돌아오는 것)만. **계층 이름 태그와 설명 카드의 소속 칩은 접었다** — 그림이 이미 덩어리를 상자로 그려 놓아 같은 말을 태그로 또 하는 꼴이었다 | **포인터**로 잇는다 — 노드나 덩어리(subgraph)에 올리면 그 설명이 그 자리에 툴팁으로 뜬다. 스크롤 동기화와 sticky 는 쓰지 않는다. **설명 카드는 그림에 짝이 없는 것만 남긴다** — 노드 라벨·subgraph 제목과 이름이 맞는 설명은 툴팁이 이미 말하므로, 아래에 또 깔면 같은 문장을 두 번 읽힌다 |
| 개발 과정 | 세로 타임라인. 단계마다 서술 + `붙인 것` 칩 | 카드 스태거 |
| 시행착오 | `###` 케이스별 접이식 카드 | 펼칠 때 증상→시도→결론 |
| 남은 것 | 담백한 목록 | 없음 |

**확대 창은 구조도와 화면이 한 컴포넌트를 쓴다** — `LabModal`
(`src/components/project/LabModal.tsx`). 데이터와 API 카드는 쓰지 않는다(위 참고). 화면을 덮는 판은 반드시 `body` 로 빼서 그린다.
섹션 안에 두면 조상 요소의 `transform` 하나에 `position: fixed` 가 그 요소 안으로 갇힌다.
Escape·배경 클릭·뒤 페이지 스크롤 잠금이 여기 한 곳에 있다.

모르는 `##` 제목은 기본 마크다운으로 떨어뜨린다. 규약을 어겨도 페이지는 깨지지 않는다.

`## 시연` 은 폐지됐다. 클립은 `## 화면` 이 같이 그린다. 옛 원고가 들어와도 깨지지
않도록 렌더러(`Demos`)만 남겨 두었고, `/project` 가 적재 때 `## 화면` 으로 옮긴다.

### 가로 스크롤을 두지 않는다

한 섹션만 좌우로 밀어야 하면, 읽던 손이 거기서 조작을 바꿔야 한다. 휠만 있는
마우스는 아예 못 넘기고, 오른쪽에 늘 잘린 카드가 남아 다 봤다는 확신도 안 생긴다.
유저 플로우를 가로 레일에서 세로로 되돌린 이유다.

섹션을 붙박아 두고(sticky) 세로 스크롤로 가로를 미는 방식도 후보였지만 접었다 —
한 화면에 들어갈 카드 여섯 장을 서너 화면으로 늘리는 셈이고, 좌측 섹션 레일도
그만큼 한 섹션에 붙잡힌다.

같은 이유로 **붙박이 판도 쓰지 않는다.** 판이 화면에 고정된 채 설명이 그 뒤를
지나가면 글이 판에 가린다. 그림과 글을 잇는 일은 스크롤이 아니라 포인터에 맡긴다.

### 연출 구현 방침

- CSS scroll-driven animation(`animation-timeline: view()`) + IntersectionObserver 로 처리.
  라이브러리를 늘리지 않는다. JS 스크롤 핸들러보다 부드럽고, 미지원 브라우저에서는
  애니메이션만 빠지고 내용은 그대로 보인다.
- `prefers-reduced-motion: reduce` 를 존중해 전 연출을 끈다.
- 붙박이(sticky) 연출은 본문에 쓰지 않는다. 판이 고정된 채 글이 그 뒤를 지나가면
  읽던 문단이 판에 가린다. 좌측 섹션 레일만 예외다.
- 가로 스크롤도 두지 않는다. 좁아지면 세로로 눕히고, 그림은 "크게 보기"로 편다.

## 4.5 비주얼 디렉션 — 계측기

실험실만 포스트와 다른 옷을 입는다. "실험실"이라는 이름을 그대로 밀어, 계측기·계기판의
어휘(모노 라벨, 격자 바탕, 코너 마커, 상태 LED)를 쓴다. 기존 토큰(Pretendard ·
Wanted Sans · JetBrains Mono · 민트 액센트) 위에 얹으며, 새 폰트나 새 색을 도입하지 않는다.

### 핵심 규칙 — 크롬에만 계측기, 본문은 읽기 우선

계측기 톤을 본문까지 밀면 모노스페이스·낮은 대비·촘촘한 자간이 겹쳐 가독성이 무너진다.
경계를 명확히 가른다.

| 영역 | 처리 |
|---|---|
| 히어로 HUD, 좌측 레일, 섹션 헤더, 상태 표시, 수치·라벨 | 계측기 — JetBrains Mono, 대문자, letter-spacing 0.18em, 8~9px |
| 본문 문장, 카드 내용, 표 셀, 시행착오 서술 | 읽기 우선 — Pretendard 13~14px, 행간 1.8, 최대 44em, 대비 최대 |

**모노스페이스는 라벨·수치·상태에만 쓰고 문장에는 절대 쓰지 않는다.**
시행착오 카드에서도 `증상 / 시도 / 결론` 라벨만 모노고, 내용은 본문 활자다.

### 격자와 서피스

- 24px 격자는 **페이지 바탕에만** 깐다. 라이트는 4.5% 회색, 다크는 4.5% 흰색
- 카드 · 비교표 · 다이어그램 패널 · 시행착오 카드는 **불투명 서피스**로 덮는다.
  라이트 `#FFFFFF`, 다크는 바탕보다 한 단 밝은 서피스. 격자가 글자 뒤로 비치면 안 된다
- 컴포넌트에는 옅은 그림자를 줘 격자 위에 얹힌 느낌을 만든다
- 격자를 그대로 두는 곳은 히어로 미디어 주변과 좌측 레일뿐

### 색

민트(`--mint-600` 라이트 / `--mint-500` 다크)는 **화면당 서너 곳까지만** 쓴다.
고른 기술 셀, 점등된 다이어그램 노드, 펼친 시행착오 카드, 상태 LED.
그 이상 쓰면 계기판이 아니라 크리스마스 트리가 된다.

### 테마

라이트를 기준 화면으로 설계하고 다크는 토큰 교체만으로 같은 구조가 나오게 한다.
색상값을 컴포넌트에 직접 박지 않고 `--line` · `--panel` · `--mint` 같은 실험실 전용
CSS 변수로 한 번 감싼 뒤, 라이트/다크에서 그 변수만 재정의한다.

### 히어로 연출

풀블리드 HUD 방식. 미디어가 폭을 꽉 채우고 아래쪽으로 페이지 배경색에 녹아들며
(그라데이션 베일), 그 위에 이름 · tagline · 메타 한 줄이 계기판처럼 얹힌다.
메타 줄은 `상태 LED · 연도 · 스택 · 배포처` 순서로 모노 라벨. 영상 위 주사선 질감은
불투명도 5% 이하로만 준다. 바로가기 버튼은 4장의 규칙을 따른다.

**표지 아래 리드 문단(`## 제품 소개`)은 접었다.** 표지에서 한 번, `## 기획` 에서 또 한 번
이 물건이 뭔지를 말하게 돼 같은 이야기가 두 번 실렸다. 지금은 기획의 첫 문답
(`**소개**` -> "어떤 서비스인가요?")이 그 자리를 대신하고, 본문은 `## 화면` 으로 연다.
옛 원고에 그 섹션이 남아 있으면 그리지 않고 흘린다.

## 5. 스크립트

| 스크립트 | 하는 일 |
|---|---|
| `scripts/project.mjs` | `push` / `pull`. `draft.mjs` 와 같은 구조, 대상 테이블만 `projects` |
| `scripts/capture-project.mjs` | Playwright 로 배포 URL 을 열어 ① 전체 스크린샷 ② 위→아래 스크롤 8초 mp4 녹화 → `project-media` 업로드 → `hero_media` · `hero_poster` 갱신 |
| `scripts/setup-skills.mjs` | `~/.claude/skills/portfolio` 심볼릭 링크 생성 |
| `scripts/setup-storage.mjs` | `project-media` 버킷 추가 (기존 파일 수정) |

`playwright` 를 devDependency 로 추가한다. MCP 브라우저는 대화용이라 스크립트에서 못 쓴다.

`package.json` 스크립트: `project`, `capture:project`, `setup:skills`.

## 6. 검증

- `project-sections.ts` 에 `node:test` 단위 테스트를 붙인다. 이 설계에서 가장 부서지기 쉬운
  지점이 "규약을 어긴 마크다운이 들어왔을 때"라서, 섹션 누락·표 열 수 불일치·mermaid 없음·
  `###` 구조 파괴 같은 케이스가 모두 `raw` 로 안전하게 떨어지는지 본다.
- 나머지는 `npm run build` 통과 + 실제 화면 확인.
- 기존 4개 프로젝트(`news-briefing`, `hyunwoo-blog`, `mcp-probe`, `routines-notebook`)의
  `body_md` 를 새 템플릿으로 옮겨 첫 검증 대상으로 삼는다.
