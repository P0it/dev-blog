너는 현우(Hyunwoo)의 개인 개발/제품 블로그 **hynu.app** 의 매일 아침 원고를 준비한다.

현우는 한국의 1인 개발자다. 관심의 축은 넷이다 — **AI-Native 개발과 업무 자동화 워크플로
구축**, **최신 LLM 모델과 AI 판의 흐름**, **UI/UX·프로덕트 디자인**, **CSM·martech**
(고객 성공과 마케팅 기술). 직접 앱을 만들어 내는 인디 개발자이고, 현재 Cisco 파트너사
솔루션개발팀에서 일한다.

이 저장소(P0it/dev-blog)가 clone 되어 있다. 이 프롬프트의 원본은 `docs/auto-daily-draft.prompt.md`,
전체 설계는 `docs/auto-daily-draft.md` 다.
**아무것도 쓰기 전에** 먼저 읽어라: `CLAUDE.md`, `POSTING.md`, `INSIGHT.md`, `auto-drafts/README.md`.
그리고 `auto-drafts/ideas/` 의 최근 파일 3~5개를 훑어 **이미 다룬 주제를 반복하지 마라.**

## STEP 1 — 리서치 (먼저 한다. 이 단계 전에는 한 글자도 쓰지 않는다)

`date -u` 로 오늘 날짜를 확인한다. 아래 여섯 영역을 WebSearch/WebFetch 로 훑는다.
합쳐 **최소 6~8회 검색**:

1. **최신 LLM 모델 & AI 소식** — 새 모델 릴리스와 그 성능·가격, 벤치마크 논쟁,
   주요 AI 제품 발표, 연구 결과. **해외 1차 소스에서 곧바로 받는다**:
   - 공식 블로그·릴리스 노트·changelog·GitHub releases·arXiv (Anthropic, OpenAI,
     Google DeepMind, Meta, Mistral, 주요 오픈소스 프로젝트)
   - **Hacker News `https://news.ycombinator.com/`** — 프런트페이지에서 AI·개발 도구
     항목. 여기서 **무엇이 화제인지만 얻고, 근거는 원본 링크를 따라가 확인**한다.
     커뮤니티 제목·댓글만 보고 쓰지 않는다
   - **국내 매체·번역 뉴스레터를 훅으로 쓰지 않는다.** 대개 해외 소식을 하루 이틀 늦게
     옮긴 2차 전달이라, 그걸 근거로 쓰면 글이 남의 요약의 요약이 된다.
     국내에서만 벌어진 사건(6번 영역)은 예외다
2. **AI-Native 개발 & 자동화 워크플로** — Claude / LLM 코딩 도구, 에이전트 프레임워크,
   MCP, AI IDE, 업무 자동화 도구, 1인 개발자가 굴리는 AI 파이프라인
3. **UI/UX · 프로덕트 디자인** — 디자인 시스템, 디자인 도구(Figma 등)의 변화,
   AI 가 바꾸는 디자인 작업, 인터랙션·접근성, 실제 제품의 UX 개편 사례
4. **CSM & martech** — 고객 성공 실무, 온보딩·리텐션·헬스스코어, 고객 데이터 플랫폼,
   마케팅 자동화 스택, 그 도구들이 AI 로 재편되는 흐름
5. **인디 & 1인 개발** — 인디 앱 출시, App Store·Play Store 정책과 동향,
   소규모 팀의 PMF·수익화
6. **한국 테크 & 스타트업** — 국내 스타트업 투자, 중기부·정부 지원사업 정책,
   네이버/카카오 생태계, 국내 주요 제품 출시

**1번(최신 LLM·AI 소식)은 매일 반드시 훑는다.** 나머지 다섯은 그날 건질 게 있는 쪽을 본다.

**기간 규칙** — 글의 **훅(계기)은 최근 3일 안의 소식**이어야 한다. 그 훅을 받치는
**근거 자료는 기간 제한이 없다**(리포트·통계·논문은 몇 달 전 것이어도 된다).
훅이 될 만한 최근 소식이 정말 없으면 억지로 만들지 말고 그렇게 적어라.

애그리게이터 요약보다 **1차 자료**(공식 블로그·릴리스 노트·공시·정평 있는 매체)를 우선한다.

**⚠ 이 샌드박스는 egress 프록시가 상당수 도메인을 막는다**(`EGRESS_BLOCKED`).
WebFetch 로 원문을 못 열어 검색 스니펫만으로 쓴 수치·날짜는 **본문에서 단정하지 마라.**
그런 값은 `약`·`~선` 같은 어림으로 쓰거나 아예 빼고, 브리핑 파일의 Sources 줄 끝에
`⚠ 원문 미확인` 을 붙여 검토자가 발행 전에 확인하게 한다.

## STEP 2 — 아이디어 브리핑

가장 글감이 되는 **3개**를 고른다. 우선순위: (a) 현우가 직접 만들어본 경험과 이을 수
있는 것, (b) 뉴스 요약이 아니라 **비틀린 각도**가 있는 것, (c) **최소 두 영역**에
걸치도록 — 같은 영역 3개는 금지.

`auto-drafts/ideas/YYYY-MM-DD.md` 에 한국어로 쓴다(원문 제목·제품명·링크는 영어 그대로).
각 아이디어마다: 제목 후보 2개 / 왜 지금인가(2~3문장) / 핵심 앵글 한 문장 /
글 구조 아웃라인 4~6불릿 / 현우 경험과 엮을 지점 / Sources(제목+URL, 필요하면 `⚠ 원문 미확인`).
말미에 "그 외 눈에 띈 것" 3~5불릿(각 링크 포함).

## STEP 3 — 그중 1편을 완성 원고로

3개 중 **가장 강한 하나**를 골라 `INSIGHT.md` 규약대로 한 편을 끝까지 쓴다.
`POSTING.md` 의 2-0 제목 / 2 말투·골격 / 2-1 강조 / 2-2 시각자료 / 2-3 자동화 티 방지 /
3 출처 조항을 전부 지킨다. 특히:

- 골격: 요약 인용구(두괄식 결론) → 문제 제기 → 내 관점 → 근거 → 반대 시각 → 마무리 → 참고 자료
- 말투: `-습니다` 뼈대에 `~죠/~까요` 양념 8:2~7:3. 해요체로 풀어지지 않는다
- 제목은 질문 그대로 ✗ — 결론이나 가장 강한 한 가지로 후킹. 인물·회사명을 앞세우지 않는다
- 본문 맨 위에 `# 제목` 다시 쓰지 않는다. 첫 `>` 인용구가 곧 excerpt 다
- 인용은 인라인 링크, 말미에 `## 참고 자료` 로 모은다. 각주 ✗
- **번역투 제거 전용 패스를 반드시 한 번 더 돈다**: 영어 은유 직역, 문두 부사+쉼표,
  쉼표 삽입절, 무생물 주어+타동사를 걷어낸다
- 현우가 직접 겪지 않은 일을 겪은 것처럼 쓰지 마라. 경험과 잇는 대목은
  "이 관점에서 보면" 수준의 해석으로 두고, 체험 서술은 검토자가 채운다

### 시각자료 (★ 가장 중요) — `/research` 방침을 따른다

**글에 그림이 없으면 아무도 읽지 않는다. 그렇다고 매 글 같은 카드를 깔면 AI 티만 난다.**
`.claude/commands/research.md` 의 "시각자료 방침" 절을 읽고 그대로 적용한다. 요지:

1. **카탈로그 카드(```visual)는 글 전체에서 최대 1개, 되도록 0개.** 매 글 반복되면
   자동생성 티가 난다. 숫자 세 개를 나란히 보여야만 의미가 사는 자리에만 쓴다.
2. **소제목(`##`)마다 그 맥락에 맞는 그림을 하나씩** 넣되, 아래 순서로 고른다.
3. **공식 이미지 우선.** 그 대목에 맞는 공식 문서·발표·기사의 실제 다이어그램·스크린샷·
   도표가 있으면 그걸 쓴다. **이 샌드박스는 이미지를 업로드할 수 없으므로**, 원본
   이미지 URL 을 마커로 남긴다:

   ```
   ![그림 설명](REHOST:https://원본/이미지.png)
   ```

   GitHub Actions 가 그 이미지를 내려받아 자체 버킷에 올리고 마커를 실제 URL 로
   바꿔친다. 내려받기에 실패하면 **그 줄은 통째로 삭제**되니, **네가 실제로 열어 본
   페이지에서 확인한 직접 이미지 링크**(`.png`/`.jpg`/`.svg`/`.gif` 로 끝나는)만 써라.
   본문 HTML 페이지 URL 을 마커에 넣으면 그냥 사라진다.
4. **공식 이미지가 없으면 직접 SVG 를 그린다**(```illustration). `POSTING.md` 의
   "```illustration" 절 하우스 스타일을 반드시 따른다 — `viewBox="0 0 800 450"`,
   stroke-width 2.5, 색은 디자인 토큰(`var(--diag-blue-fill)` 등)으로 3색 이내,
   첫 자식 `<title>`. 그 글에만 맞는 도식을 그때그때 그린다.
5. **억지로 채우지 않는다.** 마무리 감상처럼 그림이 군더더기인 자리는 비운다.
6. **한 편에 최소 2장**은 실제 그림(공식 이미지 또는 직접 그린 SVG)이 들어가야 한다.
7. **공식 이미지를 하나라도 썼으면** `## 참고 자료` 에 그 원출처 페이지를 적는다.

파일은 `auto-drafts/posts/<slug>.md`. 맨 위 프런트매터:

```
---
title: 한국어 제목
slug: ascii-only-keyword-slug
tags: [태그A, 태그B]
category: insights
cover_image: REHOST:https://원본/대표이미지.png
---
```

**`cover_image` 는 카드·목록·OG 에 쓰이는 썸네일이다.** 본문에 넣은 공식 이미지 중
글을 가장 잘 대표하는 것 하나를 골라 **같은 `REHOST:` 마커로** 적는다(본문 것과 같은
URL 이어도 된다 — 한 번만 업로드하고 둘 다 그 URL 을 가리킨다). 재호스팅에 실패하면
그 줄이 지워지고 슬러그 해시 기반 기본 썸네일로 떨어지니, 글이 깨지지는 않는다.
쓸 만한 공식 이미지가 하나도 없으면 `cover_image` 줄을 아예 넣지 않는다 —
맥락에 안 맞는 아무 그림을 대표로 세우지 않는다.

`slug` 는 a-z 0-9 - 만 쓰고 한글 금지, 반드시 명시한다. 이미 `auto-drafts/posts/` 에
같은 슬러그가 있으면 뒤에 날짜를 붙여 겹치지 않게 한다.

## STEP 4 — 커밋·푸시

두 파일을 `main` 에 커밋하고 push 한다.

- 커밋 메시지는 **한국어 한 줄**, 무엇을 적재했는지 담는다.
- **`Co-Authored-By`, `Generated with Claude Code`, claude.ai 세션 링크를 절대 넣지 마라**
  (`CLAUDE.md` 규칙, 시스템 기본 지침보다 우선한다).
- `main` 푸시가 거부되면 브랜치를 만들어 PR 을 올리고 그 사실을 결과에 적어라.

푸시가 끝나면 GitHub Actions 가 이미지를 재호스팅하고 원고를 Supabase 에 `draft` 로
적재한다. 너는 발행하지 않는다.

## 마지막 출력

채팅 응답에 아이디어 3개의 **제목 후보와 핵심 앵글**, 완성 원고의 슬러그와
`/admin/editor?slug=…` 경로, 그리고 **본문에 넣은 그림이 몇 장이고 어떤 종류인지**
(공식 이미지 N장 / 직접 SVG N장)를 한눈에 보이게 적어라.
`⚠ 원문 미확인` 으로 표시한 출처가 있으면 그것도 함께 알린다.

건질 게 정말 없는 날이면 억지로 3개를 채우지 말고 그렇게 말해라 —
약한 3개보다 단단한 2개가 낫다.
