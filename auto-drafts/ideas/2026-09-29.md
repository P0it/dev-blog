## 1. 새 모델로 올리는 작업이 모델 ID 한 줄에서 끝나지 않는다 ⭐ 완성 원고로 선택

**제목 후보**

- `Sonnet 5.5 업그레이드는 모델 ID 한 줄이 아니다` ← 채택
- `모델 ID 를 바꾼 뒤 400 을 돌려받는 다섯 가지`
- `Claude Sonnet 5.5 로 올리기 전에 확인할 것`

**왜 지금인가**

Claude Sonnet 5.5 가 2026년 9월 28일에 공개됐다. 가격은 Sonnet 5 와 같은
`$2 / $10` per MTok 이고 컨텍스트도 1M 그대로인데, 공식 문서가 "Sonnet 5 에서 이미
돌아가던 코드를 깨뜨리는 변경 다섯 가지"를 첫 화면에 나열해 뒀다. 릴리스 노트가
성능이 아니라 깨지는 요청부터 적어 두는 일은 드물다.

**핵심 앵글 한 문장**

모델 교체를 모델 ID 한 줄 치환으로 다루는 습관이 Sonnet 5.5 에서 400 다섯 개와
에러 없는 빈 화면 하나로 돌아온다.

**글 구조 아웃라인**

- 9월 28일 공개 사양 — 1M 컨텍스트, 128K 출력, `$2 / $10`, 지식 컷오프 2026년 6월,
  Anthropic 이 밝힌 "30% 이상 빠르고 작업당 비용은 최대 30% 적다"
- 400 을 돌려주는 다섯 가지를 표로 — `thinking: disabled`, 강제 `tool_choice`,
  편집된 대화의 thinking 블록, `computer_20251124`, 허용되지 않는 advisor 짝
- 그중 가장 넓게 걸리는 강제 `tool_choice` 를 따로 — `any`·`tool` 이 둘 다 막혔고
  token counting 엔드포인트도 같은 검사를 한다는 점, 대체가 `auto` + `strict: true`
- 에러가 나지 않는 여섯 번째 변경 — 도구 호출 사이 설명이 progress update
  `thinking` 블록으로 오고 기본 `display` 에서 텍스트가 비어 있다
- effort 는 재보정됐다는 문장 — 같은 `high` 가 Sonnet 5 와 같은 양을 생각하지 않는다
- 1인 개발자 관점에서 이 변경들을 읽는 법

**현우 경험과 엮을 지점**

혼자 만든 파이프라인에서 모델 교체는 보통 환경변수 한 줄이다. 그 한 줄 뒤에
검증 절차가 붙어 있지 않으면 400 은 그나마 눈에 띄고, 에러 없이 비어 오는 쪽은
한참 뒤에 발견된다. 체험 서술은 검토자가 채운다.

## 2. 승인 프롬프트에 세 번째 답이 생기고 상태줄에 달러 금액이 붙었다

**제목 후보**

- `에이전트 승인 창에 생긴 세 번째 답`
- `상태줄에 달러 금액이 붙은 Claude Code 2.1.284`

**왜 지금인가**

같은 날(2026-09-28) 나온 Claude Code v2.1.284 가 auto mode 의 승인 질문에
`Yes, but ask again next time` 을 더했다. 예·아니오 두 칸이던 자리에 "이번만 허용"이
들어간 것이다. 같은 릴리스가 `/usage` 와 상태줄에 `$271.40 / $500.00 spent this month`
같은 달러 금액을 표시하기 시작했다.

**핵심 앵글 한 문장**

에이전트의 권한과 비용은 설정 파일에서 화면으로 옮겨 오는 중이고, 승인 UI 의
선택지 개수가 그 이동을 가장 정직하게 보여 준다.

**글 구조 아웃라인**

- 두 칸짜리 승인 질문이 만들어 내는 실제 행동 — 매번 묻지 않게 하려고 영구 허용을
  누르는 쪽으로 기운다
- 세 번째 답이 바꾸는 것 — 이번 읽기만 허용하고 다음 읽기는 다시 묻는다
- 같은 릴리스의 상태줄 변경, `rate_limits.spend_limit` 에 더해진 `used_usd`·`limit_usd`·`period`
- 게이트웨이가 같은 버전 이상일 때만 표시된다는 조건
- UI 설계 관점 — 허용·거부 두 칸 사이에 "범위가 좁은 허용"을 넣는 패턴

**현우 경험과 엮을 지점**

개인 프로젝트에서 자동 승인을 한 번 켜 두면 그대로 두게 된다. 선택지 하나를
더하는 것이 문구를 고치는 것보다 행동을 크게 바꾼다는 관점에서 볼 수 있다.

- `Claude Code changelog`(v2.1.283 · 2026-09-25, `availableModelsMatch`·`deniedModels`) — https://code.claude.com/docs/en/changelog

## 3. 통제 계층을 모델 바깥에 두는 쪽으로 정리됐다

**제목 후보**

- `에이전트를 막는 코드가 모델 밖에 있어야 하는 까닭`
- `자격증명을 에이전트에게 주지 않는 설계`

**왜 지금인가**

2026년 9월 28일 Anthropic 이 NVIDIA 와 함께 Claude Managed Agents 를
Open Agent Safety Platform 과 엮는다고 발표했다. 자격증명을 별도 금고에 두고
에이전트가 직접 접근하지 않게 하며, 정책 집행은 모델 계층과 분리된
OpenShell(Apache 2.0)이 맡는다는 구성이다.

**핵심 앵글 한 문장**

프롬프트로 금지 사항을 쌓는 방식과 런타임이 동작을 차단하는 방식은 비용도
검증 방법도 다르고, 이번 발표는 후자를 기본으로 놓는다.

**글 구조 아웃라인**

- 발표가 나눈 두 계층 — 모델이 판단하는 부분과 런타임이 집행하는 부분
- 자격증명 금고 방식이 실제로 줄이는 사고 유형
- 감사 기록·샌드박스·다중 에이전트 조율이 한 묶음으로 묶여 나온 맥락
- 사례로 언급된 Notion·Rakuten·Asana 의 도입 형태
- 1인 개발자 규모에서 이 구조의 최소판은 무엇인지

**현우 경험과 엮을 지점**

혼자 굴리는 자동화에도 토큰과 키가 들어간다. 프롬프트에 "이건 하지 마라"를
적는 것과 실행 단계에서 막는 것을 나눠 보는 관점으로 읽을 수 있다.

**Sources**

- `Giving companies more control over their AI agents, with NVIDIA`(2026-09-28) — https://claude.com/blog/giving-companies-more-control-over-their-ai-agents-with-nvidia
