## 1. 표준을 읽기 시작했는데 기본값은 여전히 대체다 ⭐ 완성 원고로 선택

**제목 후보**

- `Claude Code가 AGENTS.md를 읽는 조건`
- `AGENTS.md 지원에 붙은 단서 한 줄`

**왜 지금인가**

Claude Code 2.1.277 의 CHANGELOG 첫 줄이 `Added AGENTS.md support: in projects without
CLAUDE.md, Claude Code reads AGENTS.md instead` 다. 저장소 커밋 기록을 보면 이 항목이 붙은
CHANGELOG 갱신은 9월 17~18일에 몰려 있다. AGENTS.md 지원 요청(issue #6235)은 2025년 8월 21일에
열려 1년 넘게 닫히지 않았고, 8월까지만 해도 해설 글들이 "Claude Code 는 AGENTS.md 를 읽지
않는다"로 정리하던 항목이다. 그게 이번 주에 닫혔다.

**핵심 앵글 한 문장**

Claude Code 가 AGENTS.md 를 읽기 시작했지만 기본값은 두 파일을 합치는 것이 아니라 CLAUDE.md
가 하나라도 있으면 AGENTS.md 를 건너뛰는 대체 규칙이고, 그 판정에 상위 디렉터리와
`CLAUDE.local.md` 까지 들어간다.

**글 구조 아웃라인**

- 2.1.277 에 한 줄로 들어온 변경과 1년 넘게 열려 있던 요청 #6235
- 공식 문서의 3행 판정 표 — AGENTS.md 만 있을 때 / 둘 다 있을 때 / import 가 있을 때
- 판정에 들어가는 파일과 안 들어가는 파일. `CLAUDE.local.md` 하나가 AGENTS.md 를 밀어낸다
- `/config` 의 **Project instructions** 네 값과 `settings.json` 의 `pluginConfigs` 설정
- 지원이 안 붙는 세션(Bedrock·텔레메트리 비활성·업그레이드 직후 첫 세션·훅 차단)
- 심볼릭 링크·`SessionStart` 훅 같은 기존 우회를 걷는 법

**현우 경험과 엮을 지점**

이 블로그 저장소에도 루트에 `CLAUDE.md` 가 있다. 그래서 이번 변경으로 달라지는 게 없는데,
"지원됨"이라는 말만 보고 AGENTS.md 를 옆에 두면 읽히지 않는다. 여러 도구를 오가며 규약 파일을
관리해 본 관점에서 해석을 얹을 수 있다.

## 2. 새 화면 자세가 먼저 오고 기기는 10월에 온다

**제목 후보**

- `iPhone Duo 시뮬레이터가 먼저 도착한 이유`
- `화면이 하나 더 늘어난 다음의 레이아웃 작업`

**왜 지금인가**

9월 18일 Apple 개발자 뉴스에 iPhone Duo 대응 자료가 한꺼번에 올라왔다. Xcode 27.1 베타,
Apple Design Resources 의 Figma·Sketch 디자인 킷, 세계 각지 워크숍 신청이다. 기기 자체는
10월 23일에 나오고 iOS 27.1 을 싣는다. Xcode 27.1 이 더하는 건 SDK 와 **새 자세(pose)와
방향을 지원하는 시뮬레이터**다. 기기가 없는 동안 레이아웃을 맞출 수단부터 먼저 푼 셈이다.

**핵심 앵글 한 문장**

한 화면을 전제로 짠 레이아웃이 자세마다 달라지는 기기가 한 달 뒤에 나오는데, 1인 개발자가
지금 확인할 수 있는 것은 시뮬레이터의 자세 전환과 디자인 킷의 규격뿐이다.

**글 구조 아웃라인**

- 9월 18일 공지의 세 가지 — Xcode 27.1 베타, 디자인 킷, 워크숍
- 10월 23일 출시와 iOS 27.1 이라는 일정. 27.2 베타와 번호가 엇갈리는 지점
- 자세·방향이 늘어난다는 것이 레이아웃에 요구하는 것
- 디자인 킷이 Figma·Sketch 로 나온다는 것의 실무적 의미
- 1인 개발자가 지금 할 수 있는 확인과 미룰 수 있는 확인

**현우 경험과 엮을 지점**

직접 앱을 만들어 App Store 에 올리는 입장에서, 기기 없이 대응해야 하는 기간이 한 달 있다.
그 기간에 무엇을 붙잡을지 고르는 관점으로 읽을 수 있다.

## 3. 고객 데이터의 완성도를 점수로 매기기 시작했다

**제목 후보**

- `CRM이 컨텍스트 점수를 매기기 시작했다`
- `Breeze Assistant가 에이전트를 배정하는 순서`

**왜 지금인가**

HubSpot 이 9월 16일 Fall '26 Spotlight 를 발표했다. 질문에 답하던 Breeze Assistant 가 요청을
받아 적합한 에이전트에 일을 배정하는 쪽으로 바뀌었고, 통화·메일·미팅을 스스로 기록하는
Smart CRM 이 붙었다. 눈에 띄는 건 **Context Home** 이다. 회사·팀·고객 컨텍스트가 얼마나
채워져 있는지를 점수로 보여 준다고 한다. AI 코딩 도구 쪽에서 규약 파일과 컨텍스트 관리로
부르던 문제가 CRM 화면에 지표로 올라온 모습이다.

**핵심 앵글 한 문장**

에이전트를 쓰는 쪽의 병목이 모델이 아니라 입력 데이터라는 진단이 CSM·마케팅 도구에서는
"컨텍스트 완성도 점수"라는 화면으로 먼저 제품화되고 있다.

**글 구조 아웃라인**

- 9월 16일 Fall '26 Spotlight 의 구성 — Breeze Assistant, Smart CRM, Growth Context
- Context Home 이 점수로 보여 준다는 것의 의미
- 같은 진단이 코딩 에이전트 쪽에서는 규약 파일·컨텍스트 엔지니어링으로 불린 흐름
- HubSpot 이 제시한 3.6배·3.2배·2배 수치를 어디까지 받아들일지
- 도구가 점수를 매길 때 팀이 실제로 하게 되는 일

**현우 경험과 엮을 지점**

CSM·martech 와 AI 워크플로를 같이 보는 자리에서, 데이터 정비를 지표화하는 제품이 팀의 일을
어떻게 바꾸는지 해석을 얹을 수 있다. 체험 서술은 검토 단계에서 채운다.
