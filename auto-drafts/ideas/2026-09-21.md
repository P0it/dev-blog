## 1. 고정해 둔 커밋과 실제로 체크아웃된 커밋을 아무도 맞춰 보지 않았다 ⭐ 완성 원고로 선택

**제목 후보**

- `플러그인에 고정한 커밋 SHA를 믿어도 될까요?`
- `Plugin4Shell이 지나간 커밋 핀`

**왜 지금인가**

AIR Security 가 9월 17일 Plugin4Shell 을 공개했다. Claude Code·OpenAI Codex·GitHub
Copilot·Gemini CLI 네 도구가 플러그인을 설치할 때 쓰는 커밋 SHA 고정이 실제로는 고정이
아니었다는 내용이다(⚠ 원문 미확인). 마침 Claude Code 문서는 `sha` 필드를 두고 "고정된
커밋을 직접 fetch 하고 checkout 한다"고 적어 두었는데, **체크아웃 결과가 그 해시와 같은지를
확인하는 단계가 규약에 없다.** 플러그인·스킬을 CI 에 물려 자동으로 갱신하는 쪽이 늘어난
시점이라, 고정값을 적어 두기만 하고 대조는 안 하는 구조가 그대로 남아 있다.

**핵심 앵글 한 문장**

40자 SHA 를 적는 것은 의도를 적는 일이지 검증이 아니며, 고정값과 체크아웃된 HEAD 를
맞춰 보는 한 줄이 빠지면 같은 이름의 ref 하나로 다른 코드가 조용히 들어앉는다.

**글 구조 아웃라인**

- `marketplace.json` 의 `sha` 필드가 약속하는 것 — 40자 전체 해시, `ref` 보다 우선
- git 에서 이름이 겹칠 때 무엇이 먼저 읽히는지 — `$GIT_DIR/<refname>` 이 `refs/heads/` 보다 앞
- 샌드박스 재현: 같은 서버에서 A(핀 SHA 를 직접 fetch)와 B(전체 fetch 후 `FETCH_HEAD`
  체크아웃)가 서로 다른 커밋·다른 파일 내용으로 끝난다. 에러는 나지 않는다
- 막는 방법은 한 줄 — 체크아웃 뒤 `git rev-parse HEAD` 를 고정값과 문자열 비교
- 패치 시점: Claude Code 2.1.179 는 **2026-06-16**, Codex 0.146.0 은 **2026-07-29** 에
  npm 에 올라갔다. 공개보다 석 달·일곱 주 앞선다(레지스트리에서 직접 확인)
- 아직 패치가 없다고 알려진 쪽과, "폐기됐다"는 Gemini CLI 가 9월 20일까지 nightly 를
  계속 올리고 있다는 관측
- 해석: 이번 건의 실질은 취약점 대응이 아니라 **설치본 버전 확인**이다

**현우 경험과 엮을 지점**

이 블로그 저장소도 `.claude/commands/` 와 GitHub Actions 로 에이전트 파이프라인을 굴려
둔 쪽이다. 플러그인 마켓플레이스를 직접 붙이지는 않았지만, 고정값을 적어 두는 것과
적힌 값이 실제로 쓰였는지 확인하는 것이 다른 일이라는 지점은 Actions 의 액션 핀,
`package-lock.json`, 컨테이너 이미지 태그까지 그대로 옮겨 붙는다. 체험 서술은 검토
단계에서 채우는 것이 낫다.

## 2. 접히는 화면이 먼저 오고 디자인 킷이 같은 날 함께 왔다

**제목 후보**

- `iPhone Duo 디자인 킷에 먼저 들어 있는 것`
- `화면이 접히면 레이아웃은 어디서 갈라질까요?`

**왜 지금인가**

Apple 이 9월 18일 iPhone Duo 대응 자료를 한 번에 풀었다. Xcode 27.1 beta, Apple Design
Resources 의 **Figma·Sketch 디자인 킷**, 그리고 전 세계 워크숍 신청이 같은 공지에 들어
있다. 기기 발표와 디자인 킷 배포가 붙어 있다는 게 이번 공지의 성격이다 — 개발자가
시뮬레이터를 켜기 전에 디자이너가 먼저 열어 볼 파일이 나왔다. 1인 개발자에게는 둘이
같은 사람이라 순서가 더 뚜렷하게 보인다.

**핵심 앵글 한 문장**

접히는 기기 대응은 해상도 하나를 더 지원하는 일이 아니라 한 앱이 화면 구성이 바뀌는
동안 상태를 유지하도록 레이아웃을 다시 설계하는 일이고, Apple 은 그 설계를 코드보다
디자인 파일 쪽에서 먼저 열게 배포했다.

**글 구조 아웃라인**

- 9월 18일 공지에 함께 들어 있던 네 가지 — Xcode 27.1 beta, 디자인 킷, 워크숍, 대응 문서
- Apple 이 준비 항목으로 지목한 것: 동적 리사이즈, 다중 디스플레이와 scene, 적응형
  레이아웃, 카메라 경험
- 디자인 킷이 Figma·Sketch 두 포맷으로 나온다는 점의 의미 — 디자인 시스템 쪽 작업 순서
- 1인 개발자 관점: 대응 비용이 화면 수가 아니라 상태 보존에서 나온다
- 반대 해석도 함께 — 기기 판매량이 붙기 전까지는 대응이 선투자다

**현우 경험과 엮을 지점**

UI/UX 와 구현을 한 사람이 오가는 작업 방식에서, 디자인 킷이 먼저 나오는 배포 순서가
실제 작업 순서와 맞는지 짚을 수 있다. 이 블로그의 `/lab` 화면 규약처럼 화면을 고치면
규약도 같이 고쳐야 하는 구조와 같은 문제다. 실제 대응 경험 서술은 검토자가 채운다.

## 3. 1인 구독에 좌석이 기본값으로 켜졌다

**제목 후보**

- `내 구독에 좌석이 생겼습니다, 기본값으로`
- `App Store 구독을 팀 단위로 파는 길`

**왜 지금인가**

9월 16일 Apple 공지가 두 가지를 한꺼번에 알렸다. 하나는 Bundles 와 Suites — 여러 구독을
Apple In-App Purchase 하나로 묶어 파는 방식이고, 다른 하나는 **multiseat 구매가 App Store
Connect 에서 오늘부터 기본 활성화**라는 내용이다. Volume Purchasing 은 10월 22일, Group
Purchases 는 올겨울에 열린다. 개발자가 신청해서 켜는 기능이 아니라 이미 켜져 있고, 끄려면
직접 꺼야 한다. 훅 기준으로 사흘을 살짝 넘긴 소식이라 그 점은 감안해야 한다.

**핵심 앵글 한 문장**

개인 구독으로 설계한 앱에 조직 구매 경로가 기본값으로 열리면서, 결제 화면을 바꾸지
않은 채로 B2B 고객이 들어올 수 있는 상태가 됐다.

**글 구조 아웃라인**

- 기본 활성화라는 말의 뜻 — 개발자가 한 일이 없어도 이미 켜져 있다
- Volume Purchasing(Apple Business·School Manager, 디바이스 관리로 좌석 배정)과
  Group Purchases(구매자가 좌석을 사고 Apple 이 초대 흐름을 처리)의 차이
- 좌석이 붙으면 달라지는 것 — 1인 구독 기준으로 잡아 둔 한도·온보딩·헬스스코어
- StoreKit 2 전제, Bundles 와 Suites 의 신청 절차
- CSM 관점: 조달 절차 없이 들어오는 소규모 팀 고객은 리텐션 지표를 다르게 읽어야 한다

**현우 경험과 엮을 지점**

CSM·martech 축과 인디 수익화가 만나는 자리다. 개인 앱을 만들어 온 쪽에서 보면 좌석
단위 과금은 가격표가 아니라 온보딩 설계 문제고, 그 관점은 회사에서 다루는 고객 성공
지표와 이어 붙는다. 다만 실제로 구독 앱을 굴려 본 서술은 검토 단계에서 채운다.
