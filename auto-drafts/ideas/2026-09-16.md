## 1. 거부 의사를 적는 자리와 그 의사가 집행되는 자리가 다르다 ⭐ 완성 원고로 선택

**제목 후보**

1. `검색은 열어 두고 AI 학습만 막겠다는 robots.txt 는 누구에게 통하나`
2. `AI 학습을 거부한 robots.txt 가 검색 노출까지 가져가는 지점`
3. `ai-train=no 가 기본으로 박힌 380만 도메인, 그 한 줄이 닿지 않는 곳`

POSTING.md 2-0 으로 셋을 견줬다. 2번은 결론("검색 노출까지 가져간다")을 제목에서 다
말해 버려 본문에 남는 게 없다. 3번은 수치가 세지만 쉼표로 토막을 병치한 형태라
9월 14일 원고(`RubyGems에 2,000개를 올린 에이전트 떼, 끝내 오지 않은 연락 한 통`)와
골격이 겹친다. 1번은 검색어(robots.txt·AI 학습)가 앞쪽에 있고 한 호흡으로 흐르며,
"누구에게 통하나"의 답은 본문에만 있다. 직전 원고가 한 문장형 명사구
(`DeepSeek의 V4-Pro 라우팅 철회가 드러낸 모델 ID의 유효기간`)였으므로 이번엔 질문형으로
골격을 바꿨다. → **1번 채택**

**왜 지금인가**

Cloudflare 가 7월 1일에 예고한 AI 크롤러 기본값 변경이 **오늘(9월 15일) 발효**한다고
보도들이 전한다. 광고가 붙은 페이지에서 Training·Agent 용도의 크롤링은 기본 차단,
Search 는 기본 허용이다. 적용 대상은 새로 온보딩하는 도메인, 신규 고객, 그리고 기존
무료 요금제 고객이다. 같은 날 managed robots.txt 쪽 기본값도 정리되는데, 이미 약
380만 도메인이 `search=yes, ai-train=no` 를 켜 둔 상태라고 한다.

발표 자체는 7월이라 3일 창 밖이지만, **시행일이 오늘**이라 사건이 일어난 날은 오늘이다.
9월 15일 브리핑의 Android 개발자 인증 건(시행일이 2주 앞이라 훅으로 쓰지 않았다)과는
이 점에서 다르다.

**핵심 앵글 한 문장**

사이트가 robots.txt 에 "학습은 거부, 검색은 허용"을 적어도 그 구분이 실제로 서려면
크롤러 쪽이 먼저 user agent 를 용도별로 나눠 둬야 하고, Google·Apple·Microsoft 처럼
하나로 겸하는 곳에서는 학습을 거부하는 순간 검색 노출까지 함께 걸린다.

**글 구조 아웃라인**

- 9월 15일에 바뀐 기본값 — 무엇이 기본 차단이 되고 무엇이 남는가, 적용 대상은 누구인가
- Content Signals 의 세 칸(search·ai-input·ai-train)과 그 칸이 robots.txt 에 적히는 방식.
  이건 선언이지 집행이 아니라는 점
- user agent 하나가 색인과 학습을 겸할 때 생기는 일 — 사이트 주인이 고를 수 없는 구간
- Agent 칸은 미래의 학습이 아니라 지금 읽고 있는 사람의 요청이라는 점
- 봇 비중 수치가 측정마다 30%대에서 50%대까지 갈리는 이유(무엇을 세느냐가 다르다)
- 반대 시각: 인프라 한 곳이 웹 전체의 기본값을 쥐는 문제
- 개인 블로그가 지금 정할 것 — ai-train 과 ai-input 은 다른 칸이다

**현우 경험과 엮을 지점**

hynu.app 을 직접 굴리는 입장에서 이 기본값은 남의 일이 아니다. 다만 "내 블로그는
이렇게 설정해 뒀다"는 체험 서술은 넣지 않았다. 배포 환경이 Cloudflare 인지 아닌지를
클라우드 세션이 모르기 때문이다. 원고에서는 "이 관점에서 보면" 수준의 해석으로 두고,
실제 설정과 유입 데이터는 검토 단계에서 채운다.

## 2. 에이전트가 게이트웨이에 자기 요청이 무엇인지 스스로 적어 보내기 시작했다

**제목 후보**

1. `Claude Code 가 게이트웨이로 흘려보내기 시작한 헤더 다섯 줄`
2. `요청이 어떤 종류인지 클라이언트가 먼저 말할 때 바뀌는 라우팅`

**왜 지금인가**

Claude Code 2.1.273 이 9월 15일에 나왔다. 변경 목록에 LLM 게이트웨이용 요청 헤더
다섯 개가 들어왔다 — `x-claude-code-request-class`, `x-claude-code-agent-type`,
`x-claude-code-prev-tool-durations`, `x-claude-code-compaction`,
`x-claude-code-context-compacted`. 기본값은 꺼져 있고
`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` 로 켠다. 하루 전 2.1.271 에는 Bash·PowerShell·
Monitor 에 명령 단위 `allowed_domains` 가 붙었고, `modelPricing` 에 사내 정산용
`multiplier`(1~10)가 들어왔다. 이 변경 목록은 `code.claude.com` 원문으로 확인했다.

7월 28일 MCP 스펙이 메서드·툴 이름을 HTTP 헤더로 올려 게이트웨이가 패킷을 뜯지 않고
라우팅하게 바꾼 것과 방향이 같다. 게이트웨이가 요청을 추측하던 자리를 클라이언트의
선언이 대신한다.

**핵심 앵글 한 문장**

에이전트 트래픽의 라우팅·정산·관측이 게이트웨이의 추론에서 클라이언트의 자기 신고로
옮겨 가고 있고, 그 신고를 믿을 수 있느냐가 다음 문제다.

**글 구조 아웃라인**

- 2.1.273 이 추가한 헤더 다섯 개가 각각 무엇을 알려 주는가
- 게이트웨이가 지금까지 이걸 어떻게 알아냈나 — 본문 파싱과 추정
- MCP 2026-07-28 의 header-based routing 과 같은 방향
- `modelPricing` multiplier 가 말해 주는 것: 사내 정산이 요건으로 올라왔다
- 자기 신고 기반 라우팅의 한계 — opt-in 이고, 헤더는 클라이언트가 적는다

**현우 경험과 엮을 지점**

게이트웨이를 앞에 두고 여러 에이전트를 돌리는 구성이면 바로 켜 볼 값이다. 실제로 켜
보고 비용이 어떻게 갈렸는지는 검토 단계에서 채운다.

## 3. 무료로 50배를 주는 대신 가져가는 것이 빌드 세션이다

**제목 후보**

1. `Bolt Forge 가 무료 사용량 50배와 맞바꾸는 것`
2. `상용 모델의 91%까지 온 오픈 웨이트, 그 격차를 메우는 연료`

**왜 지금인가**

Bolt.new 가 9월 14일 Forge 를 리서치 프리뷰로 열었다. 10월 14일까지 무료이고
개인 Pro 플랜에 최대 50배 사용량을 얹어 준다. 기본 모델은 GLM 5.3 Flash 와 GLM 5.3,
실험 옵션으로 Kimi K3 와 DeepSeek V4 Pro 가 붙는다. 대신 Forge 세션은 익명화하고
시크릿을 제거한 뒤 Arcee AI 와 함께 오픈 웨이트 모델 학습에 쓴다고 밝혔다. 자체
지표인 Bolt Build Index 로는 오픈 모델 쪽이 92.2, 최상위 유료 모델이 101.0 이다.

**핵심 앵글 한 문장**

오픈 웨이트 모델의 남은 격차를 메우는 연료가 공개 코퍼스가 아니라 사용자의 빌드
세션으로 옮겨 가고 있고, 무료 사용량은 그 데이터의 가격표다.

**글 구조 아웃라인**

- 9월 14일에 열린 Forge 의 조건 — 무료 기간, 사용량, 모델 구성
- 세션을 학습에 쓴다는 약관이 실제로 가져가는 것(프롬프트·실패한 시도·수정 과정)
- 상용 모델과의 격차를 자체 지표로 91% 라고 말하는 방식, 그 숫자의 한계
- 1인 개발자에게 이 교환이 유리한 경우와 아닌 경우

**현우 경험과 엮을 지점**

앱을 혼자 만들며 코딩 에이전트를 상시로 쓰는 입장에서는 무료 사용량이 곧 실험 횟수다.
다만 클라이언트 작업물이 섞인 저장소라면 계산이 달라진다. 이 대목은 해석으로만 두고
실제 판단은 검토 단계에서 채운다.
