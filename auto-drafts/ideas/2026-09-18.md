## 1. 기기에서 돌린 세션인데 기록은 서버에 남는다 ⭐ 완성 원고로 선택

**제목 후보**

- `내 Claude 세션은 회사가 어디까지 볼 수 있을까요?`
- `확장 업데이트 없이 늘어난 Claude 감사 범위`

**왜 지금인가**

9월 18일 Claude 플랫폼 릴리스 노트에 한 줄이 붙었다. Compliance API 의 로컬 세션
엔드포인트가 **Claude in Chrome 세션의 transcript 까지 돌려준다**는 내용이다(beta,
Enterprise 한정). 눈에 띄는 건 방식이다. 문서는 "새 키도, 스코프도, 설정도, 클라이언트
업데이트도 필요 없다"고 적어 뒀다. 확장 프로그램에 새 버전이 나가지도, 관리자가 켤
스위치가 생기지도 않았는데 조회 가능한 범위만 넓어졌다.

**핵심 앵글 한 문장**

로컬 세션은 기기에서 돌지만 기록은 기기에서 걷지 않는다 — 요청이 Claude API 에 닿는
순간 서버에서 남기 때문에, 감사 경계를 정하는 건 어느 기기에서 돌렸느냐가 아니라
그 요청이 어느 경로로 나갔느냐다.

**글 구조 아웃라인**

- 도입: Claude Code 를 회사 노트북 터미널에서 돌릴 때 이 기록이 어디에 남는지 묻는 장면
- 로컬 세션의 수집 방식 — 기기에는 아무것도 설치하지 않고, API 에 닿은 호출을 서버가 기록
- 9월 18일에 붙은 `claude_in_chrome` 과 `product_surface` 목록(Cowork·Claude Code·
  Claude Science·Microsoft 365 add-in·Chrome 확장)
- transcript 에 남는 것과 빠지는 것 — thinking 블록 제외, system prompt 는 마커로 대체,
  이미지는 `[image content not shown]`, 마스킹은 없음, `CLAUDE.md` 는 일반 user 콘텐츠
- 로컬 세션 · 원격 세션 · OpenTelemetry 비교 표(전달 방식·보존·도구 결과 절단 한도)
- 목록에서 빠지는 경로 — Console API 키, Bedrock·Vertex·Foundry, Claude Code 클라우드 세션,
  HIPAA readiness, ZDR(404). 여기가 경계의 실제 지도다
- 기본 6년 보존과 조직 커스텀 기간의 비대칭(기간을 늘려도 이미 만료된 내용은 돌아오지 않는다)

**현우 경험과 엮을 지점**

회사 노트북에서 Claude Code 를 돌리고, 개인 작업은 클라우드 세션으로 돌리는 사람의
구분이 이 문서의 경계선과 정확히 겹친다. 자기 저장소의 `CLAUDE.md` 를 손보는 사람에게는
"그 파일이 transcript 에 일반 user 메시지로 들어간다"는 줄이 특히 걸린다. 체험 서술은
검토자가 채우는 것을 전제로, 본문에서는 "이 관점에서 보면" 수준으로 둔다.

## 2. 광고를 누르면 브랜드의 에이전트와 대화가 시작된다

**제목 후보**

- `ChatGPT 광고가 말을 걸어오기 시작한 날`
- `Sponsored Agents 와 같은 날 열린 HubSpot 연결`

**왜 지금인가**

9월 16일 OpenAI 가 ChatGPT 광고에 **Sponsored Agents** 테스트를 열었다. 광고를 누른
사용자가 광고주의 에이전트와 라벨이 붙은 별도 대화를 시작하고, 그 대화는 ChatGPT 자신의
답변·원래 대화와 섞이지 않는다고 한다. 같은 발표에 HubSpot(첫 CRM 파트너)과
Shopify(첫 커머스 파트너) 연결이 함께 실렸다. 그리고 공교롭게도 HubSpot 은 같은 날
Fall '26 Spotlight 로 Breeze Assistant 를 내놨다.

**핵심 앵글 한 문장**

고객 접점의 양 끝이 같은 날 에이전트로 채워졌다 — 들어오는 쪽(광고)은 대화하는
에이전트가 되고, 받는 쪽(CRM)은 지시를 받아 일을 맡는 에이전트가 되면서, 사람이 읽던
랜딩 페이지와 사람이 쓰던 CRM 화면이 동시에 한 칸씩 뒤로 밀린다.

**글 구조 아웃라인**

- 훅: 광고를 누르면 페이지가 아니라 대화가 열린다는 변화
- Sponsored Agents 의 구조 — 라벨 표시, 원래 대화와의 분리, 광고주 쪽 에이전트
- 광고 운영 도구가 자연어로 옮겨 간 것(Ads Manager 플러그인)
- HubSpot·Shopify 연결이 뜻하는 것 — 광고 계정과 CRM·스토어가 붙는 지점
- 같은 날 HubSpot Breeze Assistant 발표를 겹쳐 보기
- 1인 개발자·작은 팀 관점: 랜딩 페이지 전환율이 아니라 "우리 제품을 대신 설명할 에이전트"
  를 무엇으로 채울 것인가

**현우 경험과 엮을 지점**

CSM·martech 축에 그대로 걸린다. 인디 앱을 알리는 통로가 검색·랜딩에서 대화로 옮겨 가면
제품 설명 문서가 사람용이 아니라 에이전트용으로 다시 쓰여야 한다는 해석까지 이을 수 있다.

## 3. 어디에 맡길지 고르게 하던 화면을 지웠다

**제목 후보**

- `Cowork 를 지우고 Claude 가 대신 고르게 한 이유`
- `모드 선택을 없앤 Claude 의 새 화면`

**왜 지금인가**

9월 16일 Anthropic 이 Claude Cowork 를 별도 제품에서 떼어 Claude 본체 대화 안으로
합쳤다. 함께 나온 Claude Docs·Claude Slides 는 beta 이고, Pro·Max 플랜부터 웹·데스크톱·
모바일에 먼저 들어간다고 한다. 발표문에 인용된 이유가 제품 디자인 이야기 그 자체다 —
"사람들은 둘 다 썼고, 불편했던 건 이 일이 어디에 속하는지 정하는 일이었다."

**핵심 앵글 한 문장**

사용자에게 모드를 고르게 하던 UI 를 지우고 그 판단을 모델에 넘긴 결정이라, 잘 고르면
화면이 줄고 잘못 고르면 사용자가 되돌릴 손잡이가 사라지는 맞거래가 남는다.

**글 구조 아웃라인**

- 훅: 같은 일을 어디서 시작하느냐를 사용자가 정하게 했던 화면의 소멸
- 무엇이 합쳐졌나 — Cowork·Design 이 대화 안으로, Docs·Slides 신설
- 모드 스위치를 지운 제품 디자인의 계보(탭·모드 → 자동 판단)
- 판단을 모델에 넘길 때 남는 문제 — 되돌릴 손잡이, 예측 가능성, 비용 감각
- 롤아웃 순서(Pro·Max 먼저, Team·Free 나중, Enterprise 는 30일 전 고지)가 말해 주는 것

**현우 경험과 엮을 지점**

UI/UX 축. 1인 개발자가 만드는 앱에서도 "모드를 남길 것인가, 자동으로 판단할 것인가"는
매번 부딪히는 선택이라 그 관점에서 해석을 얹을 수 있다.
