## 1. 화면을 플러그인에 열어 준 다음 릴리스가 고친 게 전부 화면 실패였다 ⭐ 완성 원고로 선택

**제목 후보**

- `모드가 그린 Box 하나에 Claude Code 가 꺼지던 이유`
- `화면을 플러그인에 열어 준 Claude Code 가 2.1.289 에서 고친 곳`
- `모드 하나가 세션 전체를 끝낼 수 있던 구조`

**왜 지금인가**

10월 1일 2.1.287 이 Claude Mods 를 열어 플러그인이 터미널 화면을 직접 그리게 됐습니다.
그 이틀 뒤 올라온 2.1.289(10월 3일) 의 수정 목록은 상당수가 같은 종류입니다 — 모드가 화면을
그리다 실패하면 세션이 통째로 끝나거나 실행 중에 멈췄다는 것입니다. 확장 지점을 열자마자
렌더러가 공유 고장 구역이 됐고, 그 답으로 고른 설계가 영역별 격리라는 게 목록에 그대로 드러납니다.

**핵심 앵글 한 문장**

UI 렌더 루프를 서드파티 코드에 열면 렌더러가 공유 고장 구역이 되고, 해결책은 설치 시점 검증이
아니라 영역마다 대체로 그려 줄 주인을 두는 것이다.

**글 구조 아웃라인**

- 10월 3일 2.1.289 수정 목록에 같은 종류의 화면 실패가 몰려 있다
- 모드가 그릴 수 있는 곳(Pane, 프롬프트 위 band, toast, 전사 로그 줄, 상태 줄)과 Claude Code
  가 이미 그리는 곳(메시지·도구 호출 줄·스피너)을 모드가 다시 그릴 수 있다
- 한 모드의 그림이 실패하면 세션 전체가 끝나던 구조 — 높이 없는 영역, 터미널이 모르는
  borderStyle, 비동기로 던진 화면 핸들러
- 검증에 걸린 그림을 엔진이 자기 것으로 바꿔 그리는 처리와 `ui.fault`
- 모드를 설치하는 쪽과 만드는 쪽에 남는 차이

**현우 경험과 엮을 지점**

플러그인·훅으로 자기 작업 흐름을 손보는 1인 개발자 관점에서, 확장 지점을 열 때 "검증"과
"격리" 중 어디에 비용을 쓰는지가 이 릴리스에 그대로 적혀 있습니다. 체험 서술은 검토 단계에서.

## 2. 에이전트 점수가 재던 하네스를 이제 사용자가 고쳐 쓴다

**제목 후보**

- `코딩 에이전트 점수가 재고 있던 것`
- `같은 모델 같은 하네스로 20점이 흔들리는 리더보드`

**왜 지금인가**

코딩 에이전트 벤치마크를 두고 "측정 대상에 하네스가 포함된다"는 지적이 쌓여 왔습니다.
TerminalBench 쪽에서는 과제 분포를 고정해도 성공률이 20퍼센트포인트 이상 흔들린다는 관찰이,
SWE-bench 쪽에서는 20만 회 넘는 실행에서 오케스트레이션·컨테이너 할당·평가 시드가 통과율을
움직였다는 보고가 있습니다. 그런데 10월 1~3일 사이 Claude Code 는 그 하네스의 안쪽을
사용자가 설치한 코드에 열었습니다. 도구 호출을 막고 다시 쓰고 권한 응답을 대신하는 모드가
깔린 세션은 공개된 점수가 측정한 그 하네스가 아닙니다.

**핵심 앵글 한 문장**

공개된 코딩 에이전트 점수는 특정 하네스 구성의 점수이고, 그 하네스가 사용자마다 달라지기
시작한 지금 리더보드 숫자는 아무도 그대로 돌리지 않는 설정을 가리킨다.

**글 구조 아웃라인**

- 하네스가 측정 대상에 들어간다는 지적과 그 변동 폭
- 모드가 바꿀 수 있는 것: 도구 호출 차단·재작성·재시도, 권한 승인과 거부, 출력에서 비밀 제거
- 그래서 "내 Claude Code 점수"라는 말이 성립하지 않는 이유
- 반대 시각 — 그래도 상대 비교에는 쓸 수 있다
- 1인 개발자가 도구를 고를 때 실제로 봐야 하는 것

**현우 경험과 엮을 지점**

도구 선택을 벤치마크로 하지 않고 자기 작업 흐름에서 재 보는 쪽이 맞다는 결론으로 이어집니다.

## 3. 자율 저니를 파는 달에 나온 유일한 조사 숫자는 보조 모드 80.6% 였다

**제목 후보**

- `에이전트를 깔아 둔 마케팅 조직 90.3%, 운영에 올린 곳은`
- `자율 저니를 사고도 보조 모드로 쓰는 이유`

**왜 지금인가**

10월 첫 주에 올라온 마테크 발표는 대체로 자율 에이전트 이야기입니다 — 10Fold 가 10월 1일
MetricsMatter 5.0, Clay 와 Marketbridge 가 200여 벤더 데이터를 묶어 계정을 조사·우선순위·접촉까지
자율로 돌리는 공동 솔루션을 내놨습니다. 그런데 이 판에서 인용되는 조사 숫자는 반대쪽을
가리킵니다. chiefmartec·MartechTribe 조사에서 마케팅·마테크 리더의 90.3% 가 스택 어딘가에
에이전트를 쓰지만 운영에 완전히 올린 곳은 23.3% 이고, 80.6% 는 보조 모드로만 둡니다.

**핵심 앵글 한 문장**

파는 쪽은 자율을 팔고 사는 쪽은 제안함을 쓰고 있어, CSM·마테크 도구의 다음 경쟁은 자율성
자체가 아니라 보조 모드에서 운영으로 넘어가는 승인 구조에서 갈린다.

**글 구조 아웃라인**

- 10월 첫 주 발표들이 공통으로 내세운 자율 저니
- 같은 판의 조사 숫자: 90.3% 도입, 23.3% 운영, 80.6% 보조 모드
- 보조 모드에 머무는 이유로 지목되는 것들(승인 경로, 책임 소재, 데이터 범위)
- 고객 성공 쪽에서 이 간격이 특히 비싼 이유
- 작은 팀이 먼저 만들 수 있는 승인 구조

**현우 경험과 엮을 지점**

CSM 업무를 자동화해 본 관점에서 "자율"보다 "승인 한 단계"가 실제 도입을 결정한다는 해석.
