## 1. 규격은 Final 이 됐는데 받아 읽는 쪽이 아직 셋뿐이다 ⭐ 완성 원고로 선택

**제목 후보**

- `MCP로 오는 스킬을 호스트가 아직 못 읽는 이유`
- `스킬을 MCP 서버에서 받아 오기 전에 볼 것`

**왜 지금인가**

Agent Skills 를 MCP 로 주고받는 규격(SEP-2640)이 9월 13일 Final 로 병합됐다. 확장 저장소
`modelcontextprotocol/ext-skills` 가 9월 16일 문서 사이트를 띄웠고 9월 18일에 저장소 정리와
CODEOWNERS 교체가 끝났다. 그런데 **서빙하는 서버는 이미 v1 인데 받아 읽는 호스트는 공식
매트릭스 14곳 중 세 곳이고 그 셋도 전부 Partial** 이다. 공식 SDK 네 개는 아직 전부 PR
단계다. 스킬을 폴더에 넣어 쓰던 방식에서 "서버가 보내 주는 스킬"로 넘어가는 길목이
지금 어디까지 깔렸는지가 이번 주에 확인 가능한 상태가 됐다.

**핵심 앵글 한 문장**

스킬을 MCP 로 받는다는 것은 원격 서버가 쓴 지시문을 내 모델 컨텍스트에 넣는 일이라,
규격이 호스트에 요구한 것은 파서가 아니라 승인·출처·이름 충돌·캐시 격리를 다루는 구조이고
그래서 서버보다 호스트가 늦는다.

**글 구조 아웃라인**

- SEP-2640 이 Final 이 된 9월 13일과 확장 저장소의 현재 상태(기준 리비전 `2026-07-28`,
  Resources 기반, 메서드 세 개)
- `skills/list`·`skills/get` 이 돌려주는 `Skill` 엔트리 — frontmatter 원문 그대로,
  파일 전체 매니페스트(`digest`·`size`), `"dynamic"` 값, 512개·16MiB 한도
- 지금 서빙하는 서버와 읽는 호스트를 표로 대조 — Hugging Face `hf-mcp-server` v1,
  커뮤니티 서버 v1, `github-mcp-server` 프로토타입 / 호스트는 ChatGPT·fast-agent·
  MCP Inspector 셋 다 Partial / SDK 넷은 PR
- 호스트가 늦는 이유는 파싱이 아니라 보안 요구 — 원격 툴 호출보다 높은 위험 등급,
  출처 태깅 의무, 같은 이름 로컬 스킬을 가리면 안 됨, `allowed-tools` 무시,
  승인은 `resources` 집합에 묶이고 집합이 바뀌면 철회, 캐시는 파일 스킬 탐색 경로 밖
- digest 는 신뢰 근거가 아니라는 규격의 단서와, 그래서 남는 것이 무엇인지
- 내 도구가 어느 쪽인지 확인하는 법(서버 capabilities 의 `extensions` 필드, 공식 클라이언트
  매트릭스, Inspector CLI 의 skill verification)

**현우 경험과 엮을 지점**

이 저장소도 `skills/portfolio/SKILL.md` 를 두고 `~/.claude/skills` 로 심볼릭 링크를 걸어
머신 사이를 맞추고 있다. 규약을 레포 하나에 두고 여러 머신이 그걸 당겨 가는 구조는
"서버가 스킬을 보내 준다"는 이번 규격이 풀려는 문제와 같은 자리에 있다. 이 관점에서 보면
링크로 맞추던 일이 프로토콜로 올라간 셈인데, 받는 쪽이 아직 없다는 것이 이 글의 요지다.
체험 서술은 검토자가 채운다.

## 2. 시행일이 아흐레 남은 안드로이드 개발자 확인

**제목 후보**

- `APK를 20대까지만 돌릴 수 있는 무료 계정`
- `9월 30일부터 설치가 막히는 앱의 조건`

**왜 지금인가**

Android 개발자 확인 제도가 **2026년 9월 30일** 브라질·인도네시아·싱가포르·태국에서 참여
스토어를 대상으로 먼저 시행된다. 나머지 지역은 2027년이다. 확인되지 않은 개발자의 앱은
해당 지역 인증 기기에서 설치가 막히고, 받으려는 사용자는 개발자 모드와 24시간 대기,
생체 인증을 거치는 별도 흐름을 타야 한다. 국내 1인 개발자에게 당장 걸리는 날짜는 아니지만
2027년 전역 적용의 조건이 지금 문서에 다 적혀 있다.

**핵심 앵글 한 문장**

배포처를 Play 스토어로 좁혀 놓았더라도 확인 계정의 종류에 따라 배포 가능한 기기 수가
20대에서 무제한으로 갈리므로, 취미 배포와 상용 배포의 경계가 계정 선택 시점에 정해진다.

**글 구조 아웃라인**

- 9월 30일에 무엇이 바뀌는지와 대상 지역·대상 스토어
- 계정 두 종류 — Full Distribution(정부 발급 신분증, 25달러 1회)과
  Limited Distribution(신분증 없음, 무료, 기기 20대)
- 한 방향으로만 가능한 전환(Limited → Full 은 되고 반대는 안 됨)과 그 이유
- 확인되지 않은 앱을 설치하는 쪽의 경로 — 개발자 모드·24시간 대기·생체 인증
- `adb` 설치와 관리형 기업 배포는 영향을 받지 않는다는 예외
- 2027년 전역 적용 전에 1인 개발자가 지금 정리해 둘 것

**현우 경험과 엮을 지점**

인디 앱을 내는 쪽에서 보면 이 제도는 심사 규정이 아니라 **배포 신원 등록**이라 성격이 다르다.
Play Console 에 이미 앱이 있으면 자동 등록되는 구간과 그렇지 않은 구간이 갈리는 대목을
검토자가 자기 배포 상황에 대 보면 글이 구체해진다.

**Sources**

- [Android developer verification — Android Developers](https://developer.android.com/developer-verification) — 시행 일자·지역·참여 스토어, 원문 확인
- [Developer verification FAQ — Android Developers](https://developer.android.com/developer-verification/guides/faq) — 계정 종류·요금·20대 한도·Advanced Flow·`adb` 예외, 원문 확인
- [Google Play 개발자 정책 안내](https://support.google.com/googleplay/android-developer/answer/17134731) — 정책 공지 페이지, 링크만 확인

## 3. 업무 플러그인 저장소가 115개로 불었다

**제목 후보**

- `직무 플러그인 11개로 시작한 저장소의 현재`
- `SaaS 회사들이 플러그인을 직접 올리기 시작했다`

**왜 지금인가**

`anthropics/knowledge-work-plugins` 는 영업·고객지원·마케팅 같은 직무 플러그인을 모아 둔
공개 저장소인데, 지금 마켓플레이스 파일에 등록된 플러그인이 **115개**다. 9월 17일에
Chronograph GP·LP, 9월 18일에 Wingspan 이 들어왔고 Qodo·Airwallex 의 메타데이터가 같은 날
갱신됐다. 9월 21일 커밋은 각 플러그인 README 의 설치 명령을 고친 것이다. 직무 플러그인을
Anthropic 이 만들어 채우던 저장소에 **SaaS 회사들이 자기 플러그인을 직접 올리는 구조**로
성격이 옮겨 가는 중이다.

**핵심 앵글 한 문장**

고객 데이터가 있는 SaaS 쪽이 커넥터를 넘어 업무 절차까지 플러그인으로 배포하기 시작하면
업무 도구의 진입점이 각 제품 화면에서 에이전트 쪽으로 옮겨 간다.

**글 구조 아웃라인**

- 직무 플러그인 11개(영업·고객지원·마케팅·법무·재무·데이터 등)와 그 구성
  (`commands/` 와 `skills/`, `.mcp.json` 커넥터)
- 지금 115개까지 늘어난 목록에서 파트너 이름이 차지하는 비중
- 봇이 매일 올리는 의존성 갱신 커밋이 뜻하는 것 — 플러그인이 관리 대상 소프트웨어가 됐다
- 고객지원·마케팅 플러그인이 붙잡는 커넥터(Intercom·HubSpot·Klaviyo·Guru)와
  CS 실무에서 겹치는 지점
- 같은 절차를 자기 회사 맥락으로 고쳐 쓰는 경로

**현우 경험과 엮을 지점**

CSM·martech 축과 정확히 겹친다. 고객지원 플러그인이 티켓 분류·응대 초안·에스컬레이션을
스킬로 담고 있어, 헬스스코어나 온보딩 절차를 같은 형식으로 옮겨 적을 수 있는지 검토자가
자기 업무 기준으로 가늠해 볼 수 있다.
