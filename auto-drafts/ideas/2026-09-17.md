## 1. 요약을 대화 안에서 만들던 것을 대화 밖으로 꺼냈다 ⭐ 완성 원고로 선택

**제목 후보**

1. `컨텍스트 압축은 더 이상 대화를 멈추지 않는다`
2. `컨텍스트 압축을 언제 할지 직접 고르게 된 Claude API`
3. `요약 요청 하나가 usage에 0 토큰으로 찍히는 이유`

POSTING.md 2-0 으로 셋을 견줬다. 3번은 반전이 가장 세지만 "무엇에 대한 글인지"가
제목에 없어 검색으로 닿을 통로가 사라진다(2-0 "주장만 있고 대상이 없는 제목 ✗").
2번은 검색어가 앞에 있고 무난하지만, 9월 15일 원고
(`DeepSeek의 V4-Pro 라우팅 철회가 드러낸 모델 ID의 유효기간`)와 같은 명사구 골격이다.
1번은 단정 평서라 최근 세 편(질문형·명사구·쉼표 병치)과 골격이 겹치지 않고,
검색어(컨텍스트 압축)가 앞에 있으며 "그럼 어떻게 안 멈추나"의 답은 본문에만 있다.
→ **1번 채택**

**왜 지금인가**

9월 14일 Claude Platform 릴리스 노트에 `compact-2026-09-04` 베타가 올라왔다.
지금까지의 압축은 한 가지였다. 입력 토큰이 임계치(기본 15만, 최소 5만)에 닿으면
API 가 요청 도중에 요약을 만들고 그 뒤로 응답을 이어 가는 방식이다. 새 베타는
최상위 `compaction` 파라미터를 보내 **요약만 받는 별도 요청**을 만든다. 응답에는
답변이 없고 서명이 붙은 `compaction` 블록 하나만 온다. 그 블록을 나중에 원래
메시지들 자리에 끼워 넣는다.

**핵심 앵글 한 문장**

요약을 만드는 순간이 요청 안에서 요청 밖으로 나오면서, 언제 압축할지와 무엇을 원문
그대로 남길지가 API 의 판단에서 애플리케이션의 결정으로 넘어왔다.

**글 구조 아웃라인**

- 긴 세션을 돌리면 겪는 장면 — 요약이 만들어지는 동안 그 요청이 길어진다
- 기존 방식(threshold compaction): 임계치에 닿으면 요청 중간에 요약, 블록은 요약한
  메시지들 **뒤에** 붙는다
- 새 방식(on-demand): 별도 요청으로 요약만 받고, 서명된 블록이 요약한 메시지들을
  **대체**한다. 앞에 원본이 남아 있으면 400(`compaction_block_misplaced`)
- 이렇게 해서 얻는 세 가지 — 시점 선택 / 백그라운드 실행 / 최근 턴 원문 보존(keep-tail),
  그리고 preserved thinking 이 걸린 모델에서 그 턴의 thinking 이 살아남는 조건
- 비용 계측이 어긋나는 지점 — 요약 호출도 과금·레이트리밋 대상인데 최상위
  `input_tokens`/`output_tokens` 는 0 으로 온다. `usage.iterations` 를 합산해야 한다
- 요약이 들고 가지 못하는 것 — 이미지·문서·`container_upload`·가져온 URL 은 블록이
  대체하는 순간 사라진다. 다시 올려야 한다
- 같은 주 Claude Code 2.1.273(9월 15일)이 게이트웨이용 `x-claude-code-compaction`·
  `x-claude-code-context-compacted` 헤더를 붙인 것과 같은 방향으로 읽힌다

**현우 경험과 엮을 지점**

이 블로그의 원고 자체가 매일 아침 클라우드 세션 한 번으로 만들어진다. 리서치로
컨텍스트를 채우고 원고를 쓰는 긴 세션이라 압축은 남의 일이 아니다. 다만 직접
겪은 서술은 검토자가 채우는 것을 전제로, 본문에서는 "1인 개발자가 에이전트를
길게 돌릴 때 이 선택지가 무엇을 바꾸는가" 수준의 해석으로 둔다.

## 2. 다른 개발자의 앱까지 하나의 구독으로 묶을 수 있게 됐다

**제목 후보**

1. `남의 앱과 구독을 묶어 파는 길이 열린 App Store`
2. `App Store 구독 번들, 같은 개발자 계정이라는 조건이 빠졌다`

**왜 지금인가**

9월 16일 Apple 개발자 뉴스가 iOS 27 의 Bundles·Suites 를 안내했다. Bundles 는 여러
구독을 하나의 인앱 결제로 묶는데, 한 앱 안에서도, 같은 개발자의 여러 앱에서도,
**서로 다른 개발자의 앱에 걸쳐서도** 묶을 수 있다고 적혀 있다. Suites 는 한 개발자의
여러 앱에 하나의 구독이 걸리는 형태다. 같은 날 multiseat 구매도 App Store Connect 에서
기본 활성화됐고, Volume Purchasing 은 10월 22일, Group Purchases 는 올겨울이다.

**핵심 앵글 한 문장**

앱 하나로 버티던 1인 개발자에게 처음으로 "남과 묶어서 파는" 유통 경로가 생겼다.

**글 구조 아웃라인**

- 1인 개발자가 구독을 팔 때 부딪히는 벽 — 앱 하나의 가치로 월 구독을 정당화해야 한다
- Bundles 와 Suites 가 각각 무엇인지, 어떤 조합이 가능한지
- 구매 경험은 App Store 가 제공한다 — 번들에 든 앱 목록이 그 화면에 뜬다
- 다른 개발자와 묶을 때 실제로 남는 질문 — 수익 배분·해지·환불은 문서가 어디까지
  말하는지, 신청 폼을 거쳐야 한다는 점
- multiseat(Volume Purchasing·Group Purchases)이 함께 열린 의미 — 개인 구독만 팔던
  앱이 조직 단위 판매로 갈 수 있다
- StoreKit 2 전제라는 준비 사항

**현우 경험과 엮을 지점**

인디 앱을 직접 내는 입장에서 "혼자 만든 앱 하나의 구독을 어떻게 정당화하는가"는
늘 걸리는 문제다. 다만 실제 번들 신청·정산 경험은 없으므로 해석 수준으로 둔다.

## 3. 추적 동의 화면이 나라마다 갈라진다

**제목 후보**

1. `독일·프랑스에서는 다른 문구로 물어야 하는 추적 동의`
2. `ATT 프롬프트가 EU 안에서 두 벌로 갈린 이유`

**왜 지금인가**

같은 9월 16일, Apple 이 유럽 경쟁당국과의 합의에 따라 App Tracking Transparency
시스템 프롬프트의 **대체 버전**을 EU 에 도입한다고 공지했다. iOS 27.2·iPadOS 27.2
부터다. EU 전체에서는 선택이지만 **독일·프랑스·이탈리아·폴란드·루마니아에 배포되는
앱은 대체 버전만** 쓸 수 있다. 추적 허가를 언제 받아야 하는지는 그대로다.

**핵심 앵글 한 문장**

동의를 묻는 문장 한 벌이 나라 경계로 갈리면서, 옵트인율을 하나의 숫자로 보던 전제가
깨진다.

**글 구조 아웃라인**

- ATT 가 도입된 뒤 모바일 마케팅이 옵트인율이라는 단일 지표에 기대 온 배경
- 이번 변경의 사실관계 — 대체 프롬프트, 적용 버전, 다섯 나라의 강제 적용
- 규제가 바꾼 것은 권한 규칙이 아니라 **묻는 화면**이라는 점
- 화면 문구가 달라지면 무엇이 흔들리는가 — 국가별 옵트인율 비교, 어트리뷰션 기준선,
  A/B 테스트의 대조군
- 1인 개발자가 지금 할 수 있는 준비 — 국가별로 지표를 쪼개 보관하는 것

**현우 경험과 엮을 지점**

martech 관심축과 정확히 맞물린다. 동의 UI 는 UX 문제이면서 동시에 측정 문제다.
다만 실제 앱의 국가별 옵트인율 데이터는 검토자가 가진 것이라 본문에서는 구조만 짚는다.
