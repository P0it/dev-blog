## 1. 서브에이전트가 부모보다 먼저 압축하도록 프런트매터가 열렸다 ⭐ 완성 원고로 선택

**제목 후보**

- `서브에이전트에 일을 넘긴 뒤 따로 도는 컨텍스트 창` ← 채택 (명사구 단독. 직전 두 글이 질문형·단정 평서였어서 골격을 바꿨다)
- `서브에이전트 컨텍스트 창이 부모와 따로 도는 이유`
- `autoCompactWindow, 서브에이전트를 먼저 접는 한 줄`

**왜 지금인가**

2026년 10월 9일 Claude Code 2.1.296 이 `autoCompactWindow` 를 서브에이전트 프런트매터와
`--agents` 정의에 추가했습니다. 공식 설명은 "서브에이전트가 메인 대화의 창보다 먼저
auto-compact 할 수 있도록" 입니다. 같은 릴리스에 `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` 도
들어왔고, 하루 전 2.1.295 는 서브에이전트가 `skills` 필드로 미리 싣는 스킬을 32개까지로 묶었습니다.
사흘 사이 서브에이전트에만 걸리는 예산 손잡이가 셋 늘어난 셈입니다.

**핵심 앵글 한 문장**

서브에이전트에 일을 넘기는 이유는 보통 메인 창을 아끼려는 것인데, 정작 서브에이전트 안쪽
창은 부모와 다른 모델·다른 크기·다른 압축 시점으로 돌아간다 — 그 세 가지가 공식 문서에
각각 어디에 적혀 있는지 맞춰 보고, 10월 9일에 열린 손잡이가 그중 무엇을 덮는지 가린다.

**글 구조 아웃라인**

- 서브에이전트에 조사를 맡겨 두고 메인 창을 아꼈다는 장면에서 출발 → 그럼 서브에이전트
  안쪽 창은 어떻게 차는지 질문 → 부모와 따로 돈다는 직답
- 창 크기부터 다르다: 서브에이전트의 컨텍스트 창은 **자기 모델 기준**으로 잡힌다(부모 기준이 아니다).
  모델은 호출 인자 → 프런트매터 `model`(`inherit`) → `CLAUDE_CODE_SUBAGENT_MODEL` → 메인 대화 모델
  순으로 결정된다
- 압축 시점: 창을 따로 정하지 않으면 모델의 컨텍스트 한도에서 압축하고, 네이티브 1M 모델은
  약 967K 선에서 미리 압축한다. 클라우드 세션은 한도에 가까워지면 압축한다
- 10월 9일에 더해진 것: 그 창을 서브에이전트 프런트매터에 한 줄로 적을 수 있다.
  기존에 창을 정하던 네 자리(`/autocompact`·설정 키·`--autocompact`·환경변수)와 우선순위를 표로 대조
- 압축이 되살리는 것과 못 되살리는 것: CLAUDE.md·오토 메모리는 디스크에서 다시 주입되지만,
  스킬 본문은 스킬당 5,000 토큰·합계 25,000 토큰으로 묶이고 오래된 것부터 버려진다.
  스킬 32개를 미리 실은 서브에이전트가 한 번 압축되면 무엇이 남는지는 이 두 규칙을 겹쳐 보면 보인다
- 무인 실행에서 확인할 것으로 맺는다 — 서브에이전트 기록의 `compact_boundary`·`preTokens`

**현우 경험과 엮을 지점**

이 블로그의 매일 아침 원고가 도는 클라우드 세션이 정확히 "서브에이전트에 조사를 넘기고
메인 창을 아끼는" 구조입니다. 클라우드 세션은 한도에 가까워지면 압축한다는 항목이 그대로
걸리는 자리라, 어느 창이 먼저 차는지를 따져 본 관점으로 이을 수 있습니다. 체험 서술은
검토 단계에서 채웁니다.

**Sources**

- [Claude Code changelog 2.1.296 (2026-10-09)](https://code.claude.com/docs/en/changelog) — `autoCompactWindow`, `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`
- [Claude Code changelog 2.1.295 (2026-10-08)](https://code.claude.com/docs/en/changelog) — 서브에이전트 스킬 미리 싣기 32개 상한
- [Subagents — Claude Code](https://code.claude.com/docs/en/sub-agents) — 프런트매터 18개 필드, 모델 결정 순서, 자기 모델 기준 창, `compact_boundary`
- [Model configuration — Claude Code](https://code.claude.com/docs/en/model-config) — 창을 정하는 네 자리와 우선순위, 967K 기본 압축

## 2. 같은 도구 설명이 로딩 방식에 따라 네 배 다른 길이로 잘린다

**제목 후보**

- `MCP 도구 설명이 잘리는 글자 수가 두 개인 이유`
- `4,096자와 16,384자로 갈린 MCP 설명 예산`

**왜 지금인가**

MCP 서버를 만드는 쪽이 쓴 도구 설명과 서버 instructions 는 Claude Code 가 모델에 보낼 때
글자 수로 자릅니다. 그 기본값이 10월 8~9일 이틀에 걸쳐 두 번 바뀌었습니다. 2.1.295 는
tool search 로 모델이 불러오는 설명을 2,048자에서 16,384자로 늘렸고, 다음 날 2.1.296 은
처음부터 올려 보내는 설명과 서버 instructions 의 기본 상한을 2,048자에서 4,096자로 바꿨습니다.
같은 문장이 올라가는 경로에 따라 네 배 다른 지점에서 잘립니다.

**핵심 앵글 한 문장**

MCP 서버 제작자가 쓴 설명은 길이 제한이 하나가 아니라 로딩 경로마다 다르고, 어느 쪽으로
붙을지는 `alwaysLoad`·`ENABLE_TOOL_SEARCH` 가 정하므로 설명을 쓸 때 전제가 달라진다.

**글 구조 아웃라인**

- 도구 설명을 길게 써 넣었는데 모델이 그 뒷부분을 모르는 장면에서 출발
- 두 경로를 가른다: 처음부터 올려 보내는 길(기본 4,096자, `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`
  로 조정, v2.1.280 이상)과 tool search 로 필요할 때 불러오는 길(16,384자)
- 어느 쪽으로 붙을지 정하는 것들: 도구 `_meta` 의 `anthropic/alwaysLoad`, 서버 설정의
  `alwaysLoad`, `ENABLE_TOOL_SEARCH` 의 `auto:N` 임계값(정의 합계가 창의 10% 넘으면 미루기)
- 그래서 설명을 쓰는 요령이 갈린다 — 중요한 내용을 앞에 두라는 공식 권고의 근거가 이 상한
- ⚠ 검토 전 확인할 것: `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` 문서와 MCP 문서는 오늘 기준
  기본값을 아직 2,048자로 적어 두었다. changelog 와 문서 중 어느 쪽이 현재 동작인지
  발행 전에 실제 버전에서 확인이 필요하다

**현우 경험과 엮을 지점**

직접 만든 MCP 서버를 Claude Code 에 붙여 두고 쓰는 입장에서, 서버 코드를 고치지 않았는데
클라이언트 기본값이 바뀌어 모델이 읽는 범위가 달라지는 대목입니다.

**Sources**

- [Claude Code changelog 2.1.296 · 2.1.295](https://code.claude.com/docs/en/changelog) — 4,096자·16,384자 변경 두 줄
- [MCP — Claude Code](https://code.claude.com/docs/en/mcp) — tool search, `alwaysLoad`, `ENABLE_TOOL_SEARCH` 표
- [Environment variables — Claude Code](https://code.claude.com/docs/en/env-vars) — `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`

## 3. 한국 App Store 연령 등급이 이번 달부터 한 칸 올라간다

**제목 후보**

- `가벼운 비속어 한 줄로 12+ 가 되는 한국 App Store`
- `GRAC 등급번호로 되돌릴 수 있게 된 App Store 연령 등급`

**왜 지금인가**

Apple 이 2026년 8월 12일에 공지한 한국 연령 등급 변경이 **이번 달부터** 적용됩니다.
"Infrequent profanity and crude humor" 와 "Infrequent mature or suggestive themes" 두 콘텐츠
설명자가 All 에서 12+ 로 올라갑니다. 같은 공지에서 GRAC 등급분류번호(RCN)를 다음 버전 제출에
넣으면 한국 App Store 등급을 All·12+·15+·19+ 중 하나로 직접 지정할 수 있게 됐습니다.
**훅이 최근 3일 안의 소식은 아닙니다** — 계기는 공지가 아니라 적용 시점이 이번 달이라는 쪽입니다.

**핵심 앵글 한 문장**

연령 등급 질문지에서 무심코 고른 설명자 하나가 한국 스토어에서만 등급을 한 칸 올려
노출 범위를 바꾸고, 그 되돌림 수단은 Apple 이 아니라 GRAC 등급번호 쪽에 있다.

**글 구조 아웃라인**

- 같은 앱이 한국 스토어에서만 12+ 로 보이는 장면에서 출발
- 올라간 설명자 둘이 무엇인지, 질문지의 어느 답이 거기에 걸리는지
- GRAC RCN 으로 지정하는 경로와 그 전제(공식 등급을 이미 받아 둔 앱이어야 한다)
- 1인 개발자 입장의 실무 — 다음 버전 제출 전에 질문지를 다시 보는 순서로 맺는다

**현우 경험과 엮을 지점**

직접 앱을 내는 1인 개발자에게 바로 걸리는 변경입니다. 다만 현우의 앱이 실제로 어느 설명자에
걸렸는지는 세션이 알 수 없어, 체험 서술은 검토 단계에서 채웁니다.

**Sources**

- [Latest News — Apple Developer](https://developer.apple.com/news/) — 2026년 8월 12일 "Updates to age ratings for the Republic of Korea" 항목에서 원문 확인. 항목 고유 URL 은 찾지 못해 목록 페이지를 적는다
- GRAC 등급분류번호로 지정할 수 있는 카테고리가 Games·Entertainment 로 제한된다는 서술은 2차 보도에만 있었다 ⚠ 원문 미확인
