## 1. 은퇴 공지를 하루 앞두고 되돌렸고, 되돌리지 않았으면 에러 없이 다른 모델이 답할 뻔했다 ⭐ 완성 원고로 선택

**제목 후보**

1. `DeepSeek의 V4-Pro 라우팅 철회가 드러낸 모델 ID의 유효기간`
2. `모델 은퇴 공지에서 통보 기간보다 먼저 확인해야 하는 한 줄`
3. `은퇴한 모델에 요청이 갔을 때 에러가 나느냐로 갈리는 운영 비용`

세 후보를 POSTING.md 2-0 으로 견줬다. 2번은 대상이 없어 검색 통로가 약하고, 3번은
결론("에러가 나느냐")을 제목에서 다 말해 버린다. 1번은 검색어(DeepSeek·V4-Pro)가 앞에
오고 한 문장으로 흐르며 "유효기간"이 무엇인지는 본문에만 있다. 직전 글이 쉼표 두 토막
(`RubyGems에 2,000개를 올린 에이전트 떼, 끝내 오지 않은 연락 한 통`)이었으므로 이번엔
한 문장형 명사구로 잡았다. → **1번 채택**

**왜 지금인가**

DeepSeek 는 9월 10일 V4.1-Flash 를 내면서 9월 14일 04:00 UTC 부터 `deepseek-v4-pro` 로
들어오는 요청 전부를 V4.1-Flash 로 넘기고 요금도 Flash 기준으로 받겠다고 공지했다.
그리고 그 날짜에 이르러 계획을 접었다. 사용자 요구를 이유로 V4-Pro 를 API 에서 계속
제공하고 청구도 그대로 두겠다고 밝혔다. 하루 차이로 없던 일이 됐지만, 공지가 실제로
말한 것은 "모델을 내린다"가 아니라 "같은 모델 ID 에 다른 모델이 답하게 한다"였다.

**핵심 앵글 한 문장**

모델 은퇴에서 개발자가 실제로 다치는 지점은 통보 기간의 길이가 아니라 은퇴 이후 그
모델 ID 로 간 요청이 에러로 끊기느냐 200 을 받고 다른 모델의 답을 가져오느냐다.

**글 구조 아웃라인**

- 9월 14일에 되돌려진 DeepSeek 의 V4-Pro 라우팅 공지 — 무엇을 하겠다고 했고 무엇을 접었나
- 은퇴가 에러로 끝나지 않는 경우: xAI 가 5월 15일에 여덟 개를 정리하면서 옛 슬러그를
  살려 둔 채 grok-4.3 로 넘긴 사례. 로그에는 실패가 남지 않고 응답 품질과 요금만 달라진다
- Anthropic 문서가 같은 자리에서 적어 둔 두 줄: 최소 60일 통보, 그리고 "retired 모델에
  대한 요청은 실패한다". 모델 ID 가 전부 pinned snapshot 이라는 설명도 같은 문서에 있다
- 세 공급자를 통보 기간·은퇴 후 동작·요금 기준으로 견주는 표
- 반대 시각: 용량과 안전을 이유로 옛 모델을 계속 세워 두기 어렵다는 공급자 쪽 설명
- 1인 개발자가 지금 확인할 것 — 호출하는 ID 가 스냅샷인지 별칭인지, 은퇴 후 동작이
  문서 어디에 적혀 있는지

**현우 경험과 엮을 지점**

앱을 혼자 만들고 자동화 파이프라인을 API 위에 얹어 두는 입장에서는, 모델 교체가
에러로 오는 편이 낫다. 에러는 알림으로 잡히지만 품질 저하는 사용자가 먼저 발견한다.
다만 이 대목은 "이 관점에서 보면" 수준의 해석으로 두고, 실제로 겪은 사례는 검토
단계에서 채운다.

## 2. 한도를 영구히 25% 올린다는 공지가 어제까지 쓰던 양보다 적다

**제목 후보**

1. `Claude Code 주간 한도가 25% 오르고도 어제보다 줄어든 계산`
2. `임시 부스트를 기준선으로 삼은 파이프라인이 9월 14일에 만나는 것`

**왜 지금인가**

Anthropic 은 9월 14일부터 Pro·Max·Team·좌석 기반 Enterprise 의 Claude Code 주간
한도를 영구히 25% 올린다고 밝혔다. 그런데 5월부터 여러 차례 연장해 온 임시 50%
부스트가 9월 13일에 끝난다. 두 날짜를 붙여 놓으면 "영구 인상" 다음 날 실제로 쓸 수
있는 양은 직전보다 17% 안팎 줄어든다. 기준선을 프로모션에 맞춰 둔 사람에게는 인상
공지가 감축 공지다.

**핵심 앵글 한 문장**

한도 공지는 퍼센트가 아니라 기준선이 무엇인지를 먼저 봐야 하고, 프로모션 기간의 양을
정상 용량으로 여기고 설계한 에이전트 파이프라인은 프로모션이 끝나는 날 설계가 깨진다.

**글 구조 아웃라인**

- 9월 13일에 끝나는 임시 50% 부스트와 9월 14일에 시작하는 영구 25% 인상
- 두 수를 같은 축에 놓으면 나오는 감소분, 그리고 공지가 그 비교를 하지 않는 이유
- 주간 한도와 5시간 한도는 다른 장치라 체감이 갈린다
- 개인 요금제 위에서 상시 에이전트를 돌리는 설계가 프로모션에 기대 있었을 때 생기는 일
- 정리 — 한도를 용량 계획의 입력값으로 적어 두는 쪽과 그때그때 쓰는 쪽

**현우 경험과 엮을 지점**

이 블로그의 매일 아침 초안 루틴도 한도를 쓰는 상시 작업이다. 프로모션이 아니라 영구
한도를 기준으로 작업량을 잡아야 한다는 정도로만 해석을 얹고, 실제 소진량 경험은 검토
단계에서 채운다.

## 3. 설치가 막히는 날짜는 정해졌는데, 그 문서의 계기는 6월에 멈춰 있다

**제목 후보**

1. `9월 30일에 네 나라에서 먼저 닫히는 Android 앱 설치`
2. `무료 계정 20대라는 숫자가 말해 주는 Android 개발자 인증의 경계선`

**왜 지금인가 (훅 기간 주의)**

**이 아이디어는 최근 3일 안의 새 소식이 아니다.** 발표는 6월이고, 9월 12~15일 창에서는
새 공지가 없었다. 다만 시행일이 9월 30일이라 2주 앞이고, 개인 개발자가 지금 움직여야
하는 항목이라 브리핑에 남긴다. 그대로 쓰면 규약의 기간 규칙을 어기므로, 쓸 거면
발행 전에 새 공지가 붙었는지 확인해야 한다.

Google 문서 기준으로 9월 30일부터 브라질·인도네시아·싱가포르·태국의 인증
기기(Android 7 이상)에서는 참여 스토어를 통해 설치되는 앱의 개발자가 등록돼 있어야
한다. Google Play 뿐 아니라 Galaxy Store·OPPO·HONOR·V-Appstore·GetApps 등이 포함된다.
학생·취미 개발자용 무료 계정은 신분증과 등록비 없이 최대 20대까지 배포할 수 있다.

**핵심 앵글 한 문장**

배포 경계가 스토어 심사에서 개발자 신원으로 옮겨 가면서, 1인 개발자에게는 "어디에
올리느냐"보다 "등록돼 있느냐"가 먼저 걸리는 관문이 됐다.

**글 구조 아웃라인**

- 9월 30일·네 나라·참여 스토어 목록으로 좁혀 보는 실제 적용 범위
- 표준 계정과 무료 제한 배포 계정(20대)의 경계
- adb 와 advanced flow 가 남겨 둔 설치 통로
- 2027년 전역 확대 예고가 인디 배포에 남기는 것
