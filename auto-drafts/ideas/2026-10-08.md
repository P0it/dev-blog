# 2026-10-08 아이디어 브리핑

## 1. 1M 컨텍스트를 열어 두고 요금만 프롬프트 길이로 받는 모델이 나왔다 ⭐ 완성 원고로 선택

**제목 후보**
- `Haiku 5.5 에서 90% 인하가 끝나는 10만 토큰`
- `10만 토큰을 넘기면 5배가 되는 Haiku 5.5 요금표`

**왜 지금인가**
Anthropic 이 2026년 10월 7일 Claude Haiku 5.5 를 공개했습니다. 발표문은 "가장 싸고
빠른 소형 모델"이라고 적었고 평균 75% 저렴하다고 밝혔는데, 같은 발표문 각주와 공식
요금표에는 조건이 둘 붙어 있습니다. 90% 인하는 **프롬프트 10만 토큰 이하**에서만이고,
이 모델은 Claude 4.6 이후 모델 중 **1M 컨텍스트 전체를 표준 요금으로 주지 않는 유일한
예외**입니다. 같은 날 Claude Code 2.1.293 이 이 모델을 API 기본 Haiku 로 올렸습니다.

**핵심 앵글 한 문장**
10만 토큰 경계를 넘기면 프롬프트 일부가 아니라 요청 전체가 5배 요율로 넘어가고,
새 토크나이저가 같은 텍스트를 약 30% 더 많은 토큰으로 세기 때문에 그 경계는
글자 수 기준으로 생각보다 일찍 온다.

**글 구조 아웃라인**
- 발표문이 내건 숫자 세 개(평균 75%, 10만 이하 90%, 10만 초과 50%)를 공식 요금표와 나란히 놓는다
- 경계가 프롬프트 전체에 적용된다는 것 — 입력뿐 아니라 출력 단가까지 5배로 같이 올라간다
- 토크나이저가 약 30% 더 세는 효과를 경계에 곱한다 → 구 토크나이저 기준 약 7만 7천 토큰 분량에서 이미 경계
- 글자 수 기준으로 환산한 실질 인하율(약 87% / 약 35%)을 직접 계산해 제시
- 반대 시각: Haiku 가 겨냥한 분류·요약 작업은 애초에 10만 밑이고, 성능 차이도 크다(Terminal-Bench 4.0 39.2% vs 0.0%)
- 에이전트 파이프라인에서 이 경계를 설계 변수로 다루는 법(compaction·캐싱·서브에이전트 분리)

**현우 경험과 엮을 지점**
컨텍스트가 대화를 거치며 계속 누적되는 코딩 에이전트·자동화 파이프라인을 직접 돌리는
입장에서 보면, 요금이 "토큰당 단가"가 아니라 "요청 길이 구간"으로 매겨지는 건 설계가
바뀌는 변수입니다. 체험 서술은 검토 단계에서 채웁니다.

## 2. 에이전트에게 웹을 열어 줄 때 도메인 목록이 검색 결과까지 묶는다

**제목 후보**
- `allowed_hosts 가 web_search 결과까지 걸러내기 시작했다`
- `에이전트에 웹을 열어 줄 때 도메인 목록이 닿는 범위`

**왜 지금인가**
10월 7일 Claude Managed Agents 의 `limited` networking 규칙이 바뀌어, `allowed_hosts`
가 이제 `web_search` 와 `web_fetch` 도구에도 적용됩니다. 목록에 없는 호스트로 `web_fetch`
를 부르면 `url_not_allowed` 결과가 돌아오고, `web_search` 는 그 호스트의 결과를 빼고
돌려줍니다. 같은 날 검증 규칙도 함께 들어가, 활성화된 웹 도구의 `allowed_domains` 에
`allowed_hosts` 범위를 벗어난 항목이 있으면 세션 생성·수정이 400 으로 떨어집니다.

**핵심 앵글 한 문장**
에이전트의 네트워크 제한은 "못 받아오는 것"에서 끝나지 않고 "검색 결과에서 사라지는 것"
까지 포함되므로, 조사 품질이 조용히 깎이는 게 아니라 설정에서 미리 드러나야 한다.

**글 구조 아웃라인**
- `limited` networking 에서 `allowed_hosts` 가 적용되는 범위가 어디까지 넓어졌는지
- `url_not_allowed` 와 검색 결과 누락의 차이 — 하나는 에러로 보이고 하나는 그냥 적게 온다
- `allowed_domains` 와 `allowed_hosts` 의 포함 관계 검증이 400 으로 떨어지는 조건
- `*.` 접두 없이는 정확히 한 호스트만 일치한다는 규칙
- 폐쇄망·사내 규정 아래서 에이전트에 리서치를 맡길 때 설계 순서

**현우 경험과 엮을 지점**
클라우드 루틴으로 리서치를 돌려 본 관점에서 보면, 막힌 도메인이 에러로 보이는 경우와
결과가 그냥 적게 오는 경우는 디버깅 난이도가 전혀 다릅니다.

## 3. 디자인 에이전트가 베타를 벗으면서 과금 대상으로 들어갔다

**제목 후보**
- `Figma 에이전트가 베타를 벗고 AI 크레딧을 쓰기 시작했다`
- `무료 베타가 끝난 디자인 에이전트의 다음 단계`

**왜 지금인가**
Figma 가 10월 6일 release notes 에서 Figma agent 의 베타를 끝냈다고 적었습니다.
지연 시간 개선, 채팅 안에서 Figma 파일 검색, 디자인 라이브러리 맥락을 에이전트에
알려 주는 guidelines 설정이 같이 들어갔고, 같은 날부터 **AI 크레딧을 소비**합니다.
베타 기간 무료로 쓰던 기능이 사용량 과금으로 넘어가는 전형적인 전환점입니다.

**핵심 앵글 한 문장**
디자인 도구의 에이전트가 "기능"에서 "사용량 단위로 값을 매기는 자원"으로 바뀌면,
디자인 조직의 비용 구조도 토큰 과금과 같은 모양을 띠게 된다.

**글 구조 아웃라인**
- Figma agent 가 베타를 벗으면서 같이 바뀐 것(지연 시간·파일 검색·guidelines)
- AI 크레딧 과금으로 넘어간 시점과 그 의미
- guidelines 로 디자인 시스템 맥락을 먹이는 방식 — 토큰·변수·컴포넌트를 지목하는 구조
- 디자인 작업이 사용량으로 계량되기 시작할 때 생기는 문제(실험 비용, 팀 단위 배분)

**현우 경험과 엮을 지점**
UI/UX 를 직접 그리면서 코드까지 붙이는 1인 개발 입장에서는, 디자인 단계의 에이전트
비용과 개발 단계의 토큰 비용이 한 주머니에서 나갑니다.
