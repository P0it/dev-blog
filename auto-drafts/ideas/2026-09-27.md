## 1. 확장을 유통하는 창구가 열린 날, 확장의 값이 사용자 화면에 숫자로 붙었다 ⭐ 완성 원고로 선택

**제목 후보**
- `안 쓰는 Claude 플러그인이 매 턴 쓰는 토큰` ← 채택
- `Claude 플러그인 디렉터리가 설치 전에 붙이는 숫자`
- `플러그인 설명문을 줄이면 스킬이 호출되지 않습니다`

**왜 지금인가**
Anthropic 이 9월 25일 플러그인 디렉터리 제출 포털을 열었습니다. 유료 플랜을 쓰는 사람이면
파트너 프로그램 심사 없이 바로 제출할 수 있습니다. 제출하면 자동 검증과 보안 스캔이
돌고 새 등록은 사람이 한 번 읽은 뒤 올라갑니다. 발표문은 플러그인을 "Claude 의 서드파티 확장을
만드는 주된 방법"이라고 못 적어 두었습니다. 같은 주에 공식 문서 쪽에서는 반대 방향의
숫자가 붙었습니다 — 공식 마켓플레이스의 플러그인 목록은 설치 전에 **Context cost** 를
보여 줍니다. 설치한 플러그인은 14일과 10세션 동안 안 쓰이면 **Not used recently** 로
내려갑니다. 유통 창구가 열린 날에 확장의 값이 토큰으로 계산되어 사용자 눈앞에 왔습니다.

**핵심 앵글 한 문장**
플러그인을 설치하면 그 플러그인의 스킬·에이전트·커맨드 이름과 설명이 매 턴 컨텍스트에
들어갑니다. 그래서 만드는 쪽이 줄여야 하는 것은 기능이 아니라 설명문이고 그 설명문을 줄이면
스킬이 호출되지 않는 반대 문제가 생깁니다.

**글 구조 아웃라인**
- 9월 25일 제출 포털이 연 것과 발표문이 적어 둔 세 가지(자동 검증·검토 상태·게시 시점 선택)
- 활성화한 플러그인이 매 턴 컨텍스트에 넣는 것과 넣지 않는 것(훅은 하네스 쪽, MCP 스키마는 런타임)
- `claude plugin details` 의 `Always-on` 줄을 읽는 법과 구성요소별 비용 표
- 설명문을 줄이면 always-on 이 내려가지만 스킬 트리거가 약해지는 대가, 그래서 eval 로 확인하라는 문서의 지시
- 설치 전 Context cost(2,000 토큰 이상이면 강조 표시)와 설치 뒤 Not used recently 의 조건
- 검증과 보안 스캔이 실제로 걸러내는 것들(버전 고정, 자격증명, README 40단어, LICENSE)
- 확장을 하나 더 붙일 때 따져 볼 것

**현우 경험과 엮을 지점**
스킬과 커맨드를 직접 만들어 여러 머신에 동기화해 쓰고 있으면, 늘려 둔 확장이 언제부터
부담이 되는지를 이미 겪었을 것입니다. 이 관점에서 보면 공식 문서가 always-on 을 "모든
사용자가 지고 가는 숫자"라고 적어 둔 대목은 개인 설정에도 그대로 적용됩니다. (체험 서술은
검토 단계에서 채워 넣는 것을 전제로 합니다.)

## 2. 에이전트를 봇으로 붙이지 않고 멤버로 등록하는 팀 채팅

**제목 후보**
- `에이전트에게 계정을 주는 팀 채팅`
- `Slack 위에 얹지 않고 처음부터 다시 만든 이유`

**왜 지금인가**
Ando 가 9월 24일 스텔스에서 나오면서 시드 2,000만 달러를 발표했습니다(Accel, Index
Ventures, Emergence Capital). 팀 메신저인데 에이전트를 워크스페이스의 정식 멤버로 두는
구조라고 설명합니다 — 에이전트가 채널과 스레드에 신분과 권한을 갖고 들어와 맥락을 이어
가고 Jams 라는 실시간 대화에도 참여합니다. 특정 모델에 묶이지 않아 Codex·Claude 등
이미 쓰는 하네스를 그대로 붙인다고 합니다. 에이전트를 기존 메신저의 봇 연동으로 붙이는
방식과 무엇이 다른지가 이 제품의 주장 전부입니다. ⚠ 원문 미확인

**핵심 앵글 한 문장**
에이전트를 봇으로 붙일 때 빠지는 것은 대화 참여 기능이 아닙니다. 신분과 권한과 지속되는
맥락입니다. 그 셋을 메신저 바깥에서 채우려 하면 결국 사람이 맥락을 옮겨 붙이는 일을 합니다.

**글 구조 아웃라인**
- 봇 연동으로 에이전트를 붙였을 때 실제로 남는 작업(맥락 복사, 권한 대행, 결과 옮기기)
- 멤버로 등록한다는 말이 기술적으로 요구하는 것 — 계정, 권한 범위, 감사 로그
- 여러 하네스를 섞어 쓰는 팀이 겪는 신분 문제
- 1인 개발자에게 이 구조가 의미가 있는지, 혼자 쓰는 워크스페이스에서 남는 값
- 반대 시각 — 메신저를 갈아타는 비용은 기능 차이보다 크다

**현우 경험과 엮을 지점**
여러 에이전트를 동시에 띄워 작업을 나눠 본 적이 있으면, 결과를 사람이 모아 옮기는 단계가
가장 오래 걸린다는 점을 확인했을 것입니다. 이 제품의 주장은 그 단계를 메신저 안으로
가져오겠다는 것입니다.

## 3. 이벤트 플랫폼이 결제와 참가자까지 어시스턴트에 읽고 쓰게 열었다

**제목 후보**
- `MCP 서버를 공짜로 끼워 주는 SaaS 가 여는 범위`
- `참가자와 결제까지 어시스턴트가 쓰게 된 이벤트 플랫폼`

**왜 지금인가**
Eventtia 가 9월 25일 자체 MCP 서버를 공개했습니다. 모든 플랜에 추가 비용 없이 포함됩니다.
연결에 5분이 안 걸리며 코드가 필요 없다고 설명합니다. 문제는 열어 주는 범위입니다 —
이벤트, 참가자, 세션, 연사, 체크인, 결제에 읽기와 쓰기가 함께 열립니다. 같은 주 마테크
쪽에서 Later 가 YouTube Creator Partnerships API 연동을, Attentive 가 Lifecycle
Intelligence 를 내놓은 것과 묶어 보면, 벤더들이 9월 24~25일에 한 일은 기능 추가보다
자기 데이터를 어시스턴트 쪽으로 내보내는 작업이었습니다. ⚠ 원문 미확인

**핵심 앵글 한 문장**
MCP 서버를 무료로 끼워 주는 벤더가 늘어날 때 고객이 실제로 결정해야 하는 것은 연결
여부가 아닙니다. 쓰기 권한의 범위입니다. 지금 그 범위는 벤더가 정해서 내놓습니다.

**글 구조 아웃라인**
- 5분·무료·노코드라는 세 문구가 가리키는 도입 경로
- 읽기와 쓰기를 한 덩어리로 여는 설계에서 결제·체크인이 함께 들어간다는 점
- CS·마케팅 실무에서 어시스턴트가 잘못 쓰면 되돌리기 어려운 동작 목록
- 고객 쪽에서 확인할 것 — 권한 분리, 감사 로그, 승인 단계
- 9월 24~25일 마테크 발표들을 같은 기준으로 견주기

**현우 경험과 엮을 지점**
CSM·martech 쪽 도구를 붙여 본 관점에서 보면, 연동의 값은 항목 개수보다 되돌릴 수 없는
동작을 누가 승인하는지에서 달라집니다. 무료로 끼워 주는 MCP 서버는 그 승인 단계를 고객이
직접 만들도록 남겨 둡니다.
