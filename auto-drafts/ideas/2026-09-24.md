## 1. 설정을 짧게 쓰면 구버전이 파일 전체를 건너뛴다 ⭐ 완성 원고로 선택

**제목 후보**
- `Claude Code 설정을 구버전이 통째로 건너뛰는 한 줄`
- `커밋에서 Claude 이름을 지우는 설정의 두 가지 형태`

**왜 지금인가**
9월 23일 Claude Code v2.1.281 이 `settings.json` 에 `"attribution": false` 를 더했습니다.
커밋 트레일러와 PR 본문 문구를 한 줄로 전부 끄는 값입니다. 그런데 같은 변경 항목에
경고가 함께 적혀 있습니다. 구버전 CLI 는 이 값이 든 설정 파일을 건너뛰므로, 버전이
섞인 곳에서 공유하는 파일에는 객체 형태를 유지하라는 것입니다.

**핵심 앵글 한 문장**
공유 `settings.json` 에 짧게 쓴 값 하나가 구버전 CLI 에서 그 파일의 모든 키를 무효로
만들고, `-p` 헤드리스 실행에서는 그 사실을 알리는 화면조차 뜨지 않습니다.

**글 구조 아웃라인**
- 9월 23일 v2.1.281 변경 항목과 거기 붙은 경고 한 줄
- 원래 형태는 객체였다 — `attribution.commit`·`attribution.pr`·`attribution.sessionUrl`
  셋을 각각 비워야 했고, 공식 settings reference 는 9월 24일 현재도 객체 형태만 적고 있다
- Claude Code 가 설정 파일을 거부하는 방식은 세 가지로 갈린다: 잘못된 JSON·스키마가
  거부한 값(Settings Error, 파일 단위) / 개별 항목만 실패(Settings Warning, 그 값만)
  / managed settings(나머지는 계속 적용)
- `-p` 실행에는 대화 상자가 없다. 무엇이 버려졌는지는 `claude doctor` 로만 확인된다
- 그래서 공유 파일에는 객체 형태, 개인 `~/.claude/settings.json` 에만 짧은 형태
- 설정 스키마를 넓힐 때 "키를 더하는 것"과 "기존 키의 값 타입을 넓히는 것"의 비용이 다르다

**현우 경험과 엮을 지점**
이 저장소의 `CLAUDE.md` 첫 절이 정확히 같은 일을 산문으로 하고 있습니다 — 커밋 메시지에
`Co-Authored-By`·Claude attribution 문구·claude.ai 세션 링크를 넣지 말라는 규칙이고,
시스템 기본 지침보다 우선한다고 못을 박아 뒀습니다. 설정 키 하나로 내려갈 수 있는 일을
문서가 대신해 온 셈이라, 이 관점에서 보면 "규칙을 문서에 적을 것인가 설정에 적을
것인가"를 다시 볼 만합니다. 실제로 어느 쪽을 택할지는 검토자가 채웁니다.

## 2. 천장이 아니라 기본값이 올라간 9월 22일

**제목 후보**
- `아무것도 고르지 않은 사용자가 9월 22일에 받은 모델`
- `기본 모델이 Sonnet에서 Opus로 바뀐 날`

**왜 지금인가**
9월 22일 하루에 세 가지가 겹쳤습니다. Anthropic 이 Claude Opus 5.5 를 공개했고, 같은 날
Claude Code v2.1.280 이 Pro·Team Standard 요금제의 기본 모델을 Sonnet 에서 Opus 로
바꿨습니다. 같은 날 OpenAI 는 GPT-6 Sol 과 Luna 를 내면서 GPT-5.6 계열보다 API 단가를
절반 수준으로 낮췄다고 밝혔습니다.

**핵심 앵글 한 문장**
이날 움직인 것은 최상위 모델의 성능이 아니라 아무것도 고르지 않은 사용자가 받게 되는
기본값이고, 1인 개발자의 월 비용은 대개 그 기본값에서 정해집니다.

**글 구조 아웃라인**
- 9월 22일에 겹친 세 가지 변경을 날짜와 버전으로 정리한다
- Pro·Team Standard 기본 모델 변경이 실제로 바꾸는 것 — 고르지 않는 사용자의 토큰 단가
- 같은 릴리스가 `/effort` 저장값을 신규 모델에 더는 적용하지 않도록 바꿨다는 점
  (Opus 5.5 는 각 모델의 기본값에서 시작한다)
- OpenAI 쪽은 싼 티어에 상위 모델의 학습 방법을 내렸다고 밝혔다 `⚠ 원문 미확인`
- 기본값이 올라가면 "고르는 법"을 아는 것의 값어치가 줄어드는가

**현우 경험과 엮을 지점**
9월 23일 원고가 Opus 5.5 단가표를 이미 다뤘으므로, 이 글은 단가가 아니라 기본값 쪽만
보는 것으로 범위를 좁혀야 겹치지 않습니다.

## 3. OG 이미지를 만들던 코드가 원격 코드 실행 통로였다

**제목 후보**
- `OG 이미지를 만드는 코드에 열려 있던 통로`
- `같은 next/og 코드가 런타임에 따라 갈린 이유`

**왜 지금인가**
9월 22일 Next.js 가 16.3.6 과 15.5.26 을 보안 릴리스로 냈습니다. `next/og` 의
`ImageResponse` 에서 원격 코드 실행이 가능한 결함이고(CVE-2026-94545, CVSS 9.5),
영향 범위는 16.2.0 이상 16.3.6 미만입니다. 사용자가 넘긴 값을 SVG 내용·속성·스타일에
그대로 넣어 이미지를 만들 때 발생합니다.

**핵심 앵글 한 문장**
글 제목을 URL 파라미터로 받아 썸네일을 굽는 블로그가 곧 이 결함의 전형적인 사용 패턴이고,
같은 코드라도 Edge 런타임이면 해당되지 않고 Node 런타임이면 해당됩니다.

**글 구조 아웃라인**
- 9월 22일 릴리스와 권고문의 사실관계(버전·CVE·점수·영향 범위)
- 취약한 패턴은 특별한 코드가 아니라 OG 이미지 생성의 표준 사용법에 가깝다
- 런타임이 경계였다는 점 — Edge `ImageResponse` 는 영향 없음
- 1인 개발자에게 이 결함의 의미: 패치 주체가 자신뿐이고, 캐러티드 버전 범위를
  `package-lock.json` 에서 직접 확인해야 한다
- 당장 올릴 수 없으면 사용자 입력을 SVG 에 넣지 않는 쪽으로 먼저 막는다

**현우 경험과 엮을 지점**
이 저장소가 바로 해당 범위 안에 있습니다. `package.json` 이 `"next": "^16.2.6"` 이고
`package-lock.json` 에 실제로 고정된 값은 **16.2.10** 이라, 16.2.0 이상 16.3.6 미만이라는
영향 범위에 그대로 들어갑니다. `chore/next-16-upgrade` 브랜치도 따로 있습니다. 다만 이
블로그의 썸네일이 어떤 경로로 만들어지는지, 실제로 사용자 입력이 SVG 로 들어가는지는
검토자가 확인해야 합니다.
