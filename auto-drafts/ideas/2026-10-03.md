## 1. 자격증 17만 장을 발급해 둔 회사가 1억 달러를 들여 1만 명을 다시 수련시킨다 ⭐ 완성 원고로 선택

**제목 후보**
- `Claude 자격증 17만 장은 왜 부족했나`
- `Anthropic이 1만 명을 의사처럼 수련시키는 방식`

**왜 지금인가**
10월 2일 Anthropic 이 Claude Frontier Academy 를 발표했다. 1억 달러를 걸고 2027년 말까지
Frontier Deployed Engineer 1만 명을 길러내겠다는 계획이다. 같은 발표문 끝에 기존 Claude
Partner Network 실적이 적혀 있는데, 46,000개 회사에서 Claude 자격증 175,000장 이상이 이미
발급됐고 Basecamp 수료자는 4,000명 가까이 된다.

**핵심 앵글 한 문장**
자격증 17만 장이 이미 깔린 상태에서 인재가 "가장 시급한 문제"로 남았다는 건, 모자란 것이
Claude 사용 지식이 아니라 업무 절차를 읽어 배치까지 끌고 가는 판단이라는 뜻이다.

**글 구조 아웃라인**
- 10월 2일 발표의 사실 관계 — 1억 달러, 1만 명, 2027년 말, 첫 코호트 8개 조직, 지명제
- 같은 발표문이 적어 둔 기존 실적 — 46,000개 회사·자격증 175,000장·Basecamp 4,000명
- 의사 수련 모델을 그대로 가져온 FDE 레지던시의 단계와 두 개의 배지
- Accenture 측 발언 — 시험하는 것은 기술이 아니라 모의 배치에서의 판단이다
- 반론 — Anthropic 은 자격증 과정을 부정하지 않았고, 첫 코호트 명단은 컨설팅사 위주다
- 1인 개발자 관점에서 남는 것

**현우 경험과 엮을 지점**
FDE 역할 설명(적합한 유스케이스 선정 → 보안 검토 → 핸드오버까지 혼자 끌고 가기)은 1인
개발자가 평소 하는 일과 겹친다. 조직 안에서 희소한 역량이 혼자 만드는 쪽에서는 기본값인
셈인데, 체험 서술은 검토 단계에서 채운다.

## 2. 작년에 박아 둔 모델 ID 에 만료일이 붙었다

**제목 후보**
- `Sonnet 4.5 에 붙은 11월 30일`
- `모델 ID 를 고정해 둔 쪽이 11월에 해야 하는 일`

**왜 지금인가**
9월 30일 Claude API 릴리스 노트에 `claude-sonnet-4-5-20250929` 의 은퇴 일자가 2026년
11월 30일로 공지됐다. 9월 28일에 나온 Sonnet 5.5 가 권고 이전 대상인데, 같은 문서가
Sonnet 5 대비 400 을 돌려주는 변경을 다섯 가지 적어 두고 있다.

**핵심 앵글 한 문장**
날짜를 박아 모델을 고정하는 방식이 재현성은 지켜 주지만, 그 핀에는 1년 남짓한 수명이
붙어 있어서 이전 비용이 아니라 이전 일정이 실제 부담이 된다.

**글 구조 아웃라인**
- 9월 30일 공지의 내용 — 대상 모델 ID 와 11월 30일
- 날짜 박힌 모델 ID 를 쓰는 이유와 그 수명
- 권고 이전 대상인 Sonnet 5.5 가 요구하는 변경과 에러 없이 지나가는 변경
- 소규모 팀이 이전 일정을 잡는 기준
- 반대 시각 — 별칭(`claude-sonnet-5-5`)으로 두면 날짜는 신경 쓸 필요가 없다

**현우 경험과 엮을 지점**
`.env` 에 모델 ID 를 박아 두고 돌리는 개인 파이프라인이라면 공지 자체를 못 보고 넘어가기
쉽다. 해석은 "이 관점에서 보면" 수준으로 두고 실제 운영 경험은 검토 단계에서 얹는다.

**Sources**
- Claude API release notes (2026-09-30 Sonnet 4.5 deprecation, 2026-09-28 Sonnet 5.5) — https://platform.claude.com/docs/en/release-notes/api

## 3. 공개된 도입 성과가 전부 사용량 숫자다

**제목 후보**
- `Barclays 가 공개한 숫자에 없는 것`
- `헬스스코어를 사용량으로 짜면 보이지 않는 것`

**왜 지금인가**
10월 1일 Anthropic 이 Barclays 사례를 공개했다. 적힌 숫자는 Colleague Knowledge Assistant
이용자 16,000명, 누적 검색 100만 건 이상, Global Markets 의 하루 이메일 처리 12만 건,
2026년 말까지 개발자 50% 적용 목표다. 전부 얼마나 쓰였는지를 재는 숫자다.

**핵심 앵글 한 문장**
도입 사례가 내놓는 지표가 사용량에 쏠려 있는 것은 성과를 숨기려는 게 아니라 조직 단위에서
성과를 사용량만큼 깔끔하게 뽑기 어렵기 때문이고, 고객 성공 지표를 짜는 쪽이 같은 함정에
빠진다.

**글 구조 아웃라인**
- 10월 1일 공개된 Barclays 숫자 네 개를 그대로 정리
- 사용량 지표와 성과 지표의 차이, 그리고 사용량이 먼저 나오는 이유
- 헬스스코어를 로그인·검색 횟수로 짜 둔 팀에서 생기는 어긋남
- 사용량 지표를 성과로 잇는 중간 지표를 무엇으로 둘지
- 반대 시각 — 초기 도입 단계에서는 사용량이 가장 정직한 선행 지표다

**현우 경험과 엮을 지점**
CSM 쪽 관심 축과 바로 붙는다. 다만 Barclays 내부 사정은 알 수 없으니 공개 숫자가 어떤
종류인지까지만 말하고 평가는 하지 않는다.

**Sources**
- Barclays scales Claude to upgrade operations and improve client experience — https://www.anthropic.com/news/barclays-scales-claude
