## 1. 에이전트가 직접 쓴 프로그램이 에이전트 1,000대를 돌린다 ⭐ 완성 원고로 선택

**제목 후보**

- `에이전트 1,000대의 순서는 모델이 쓴 스크립트가 정한다` ← 채택 (단정 평서, 직전 글이 질문형이라 골격을 바꿨다)
- `워크플로 스크립트 안에서 Date.now() 가 막히는 이유`
- `에이전트 1,000대의 계획을 들고 있는 JavaScript 한 장`

**왜 지금인가**

2026년 10월 9일 Claude Managed Agents 에 **dynamic workflows** 가 베타로 들어갔습니다. 에이전트가
워크플로를 직접 작성하고, 서버가 그 프로그램을 백그라운드 워크플로 런으로 실행합니다. 같은 기능이
Claude Code 에는 이미 들어가 있어서, 이번 주에 **같은 기능이 두 표면에 모두 서게 됐습니다.** 그런데
정작 그 프로그램을 읽는 방법이 두 쪽에서 다릅니다 — CLI 는 런마다 스크립트를 파일로 남기고
`/workflows` 에서 커맨드로 저장까지 되는데, API 쪽 문서는 "워크플로의 코드는 보이지 않는다"고 적어 뒀습니다.

**핵심 앵글 한 문장**

오케스트레이션이 모델이 쓴 프로그램으로 옮겨 가면 확인할 대상이 대화 로그에서 그 스크립트와 런타임
제약으로 바뀌는데, Claude Code 는 그 스크립트를 파일로 내주고 Managed Agents 는 내주지 않는다 —
두 표면의 한도와 확인 수단을 공식 문서의 문장으로 하나씩 가린다.

**글 구조 아웃라인**

- 10월 9일 API 릴리스 노트가 켠 것과, `multiagent_20261001` + `workflows: enabled` 설정
- 워크플로 런의 세 층(런 → 페이즈 → 에이전트 스레드)과 공식 다이어그램 한 장
- 계획이 어디에 있나 — 서브에이전트는 모델 컨텍스트, 워크플로는 스크립트 변수
- 한도 대조표: 동시 16대 / 64대, 런당 1,000대, 수명 24시간, 세션당 런 10개
- 스크립트를 읽을 수 있는 쪽과 물어봐야 하는 쪽
- 재실행이 같은 순서를 반복하게 만드는 제약(`Date.now()`·`Math.random()` 금지, 결과 캐시)
- 무인으로 돌리기 전에 확인할 것(예산, 두 번 불려도 안전한 도구, 사이즈 가이드라인)

**현우 경험과 엮을 지점**

이 블로그의 원고가 매일 아침 클라우드 세션에서 생성되는 구조 자체가 "사람 없이 도는 파이프라인"이라,
오케스트레이션을 모델에게 맡겼을 때 **무엇을 로그로 남겨야 하는가**라는 질문과 바로 닿습니다. 다만
현우가 dynamic workflows 를 직접 돌려본 기록은 없으므로, 원고에서는 "이 관점에서 보면" 수준의 해석으로 두고
체험 서술은 검토자가 채운다.

## 2. 차트를 그려 주는 쪽이 아니라 쿼리를 보여 주는 쪽으로 간 대시보드

**제목 후보**

- `숫자를 누르면 쿼리가 나오는 대시보드`
- `영상 모델 없이 만드는 설명 영상`

**왜 지금인가**

2026년 10월 8일 Claude Dashboards 와 Claude Motion 이 베타로 공개됐고, Docs·Slides·Design 은 베타를
벗어나 Free 플랜까지 내려왔습니다. 눈에 걸리는 건 두 가지입니다. 대시보드는 숫자를 누르면 그 숫자를 만든
쿼리를 보여 주고 차트마다 마지막 갱신 시각을 띄웁니다. Motion 은 영상 생성 모델을 쓰지 않고 텍스트·차트·
도형을 움직이는 **코드**를 내놓습니다. 생성 결과를 믿게 만드는 방식이 "더 그럴듯한 출력"이 아니라
"근거를 열어 보여 주기"로 가고 있습니다. 독립 사이트 `claude.ai/design` 은 12월 14일에 닫힙니다.

**핵심 앵글 한 문장**

AI 가 만든 시각자료를 업무에 쓸 수 있게 만드는 건 품질이 아니라 검산 경로이고, Dashboards 의 쿼리 노출과
Motion 의 코드 출력이 같은 설계를 두 번 보여 준다.

**글 구조 아웃라인**

- 10월 8일에 공개된 것과 각 플랜에서 켜지는 방식(Enterprise 는 Organization settings 에서 수동)
- 대시보드가 붙는 데이터 쪽(Redshift·BigQuery·ClickHouse·Databricks·Snowflake·Salesforce)
- 숫자 → 쿼리, 차트 → 갱신 시각. 검산 경로가 UI 에 들어간 의미
- Motion 이 영상 모델을 쓰지 않는다고 밝힌 대목과 그 결과물(MP4 로 내보내기 전까지 코드)
- 내보내는 쪽 목록(Grafana·Hex·Mixpanel·Omni·PostHog·Sigma, Looker·Tableau 는 예정)
- Design 이 대화 안으로 들어오고 독립 사이트가 닫히는 일정

**현우 경험과 엮을 지점**

CSM·martech 쪽 지표를 다루는 사람에게 "이 숫자 어디서 나왔냐"는 질문이 가장 자주 오는 질문이라,
쿼리를 바로 까 주는 대시보드는 도입 저항이 낮습니다. 리텐션·헬스스코어를 직접 설계해 본 관점에서
검산 경로를 평가하는 대목은 검토자가 채운다.

**Sources**

- Build live dashboards and animate explainers with Claude, 2026-10-08 — https://claude.com/resources/articles/dashboards-and-motion

## 3. 접히는 화면에 맞춘 스크린샷이 2027년 4월부터 필수가 된다

**제목 후보**

- `2027년 4월부터 심사에 필요해지는 스크린샷`
- `접히는 iPhone 에 맞춰 바뀐 App Store 자산 규격`

**왜 지금인가**

Apple 이 2026년 10월 5일 개발자 공지로 iPhone Duo 최적화 앱 제출을 열었습니다. 기기는 10월 23일에
판매를 시작합니다. 공지가 못 박은 일정은 하나입니다 — **2027년 4월부터 App Store Connect 에 제출하는
모든 앱과 게임은 iPhone Duo 스크린샷을 포함해야 합니다.** 신규 앱만이 아니라 제출 자체에 걸리는 조건입니다.
제품 페이지 헤더와 검색 결과 자산이라는 새 자산 종류도 같이 생겼습니다.
(10월 5일 공지라 이번 회차 3일 범위에서는 벗어납니다.)

**핵심 앵글 한 문장**

새 폼팩터가 1인 개발자에게 주는 실제 작업은 레이아웃 대응이 아니라 **스토어 자산 규격과 그 마감일**이고,
Apple 공지가 밝힌 범위와 커뮤니티가 떠드는 수치는 구분해서 읽어야 한다.

**글 구조 아웃라인**

- 10월 5일 공지의 세 덩어리(Xcode 27.1 재컴파일, 제품 페이지 자산, 제출)
- Device Hub 로 모든 자세·방향에서 확인하라고 적은 대목
- 새로 생긴 자산 종류(제품 페이지 헤더, 검색 결과 자산)와 App Store Connect 미리보기 도구
- 2027년 4월 마감이 1인 개발자의 유지보수 일정에 들어오는 방식
- 2차 매체가 적은 픽셀 규격·검은 여백 이야기는 Apple 공지에 없다 — 규격 페이지에서 확인할 몫

**현우 경험과 엮을 지점**

직접 앱을 내 본 사람에게 스토어 자산은 기능 개발과 따로 쌓이는 일거리입니다. 자산 규격 변경이 릴리스
일정에 어떻게 끼어드는지는 겪어 본 쪽이 더 잘 적을 수 있어, 그 대목은 검토자가 채운다.

**Sources**

- Prepare and submit your apps for iPhone Duo, Apple Developer News, 2026-10-05 — https://developer.apple.com/news/?id=kkphp5qo
- Screenshot specifications (App Store Connect) — https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications ⚠ 원문 미확인
- 픽셀 규격·검은 여백·사전 주문 일자를 적은 2차 매체(서로 날짜가 엇갈린다) ⚠ 원문 미확인 — 본문에 쓰지 않는 쪽을 권한다
