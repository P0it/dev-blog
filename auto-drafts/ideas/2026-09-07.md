## 1. SaaS를 안 샀다는 32%, 그런데 소프트웨어 지출은 늘었다 ⭐ 완성 원고로 선택

**제목 후보**
- `SaaS 안 사고 직접 만든다는 32%, 지출은 15% 늘었다`
- `이탈은 갱신 회의가 아니라 조달 밖에서 시작된다`

**왜 지금인가**
McKinsey가 8월 25일 State of AI 2026 조사를 냈습니다. 응답자 32%가 agentic coding 도구로
내부에서 만들 수 있어 소프트웨어 구매를 접었다고 답했고, 기술 업종은 39%까지 올라갑니다.
같은 방향의 수치가 2월 Retool 보고서에도 있는데(35%가 이미 SaaS 하나를 자체 제작으로 교체),
정작 Gartner의 7월 27일 전망은 2026년 소프트웨어 지출을 두 자릿수 성장으로 올려 잡았습니다.
두 숫자가 정면으로 부딪히는 지금이 이 질문을 던질 자리입니다.

**핵심 앵글**
줄어든 건 구매가 아니라 **결재선을 타는 구매**다 — Retool 응답자의 자체 제작 중 60%가
공식 조달 밖(shadow IT)에서 일어났고, 그래서 SaaS 이탈은 갱신 협상 테이블에 오르기 전에
이미 시작된다.

**아웃라인**
- 32%·35%라는 숫자와, 그 숫자가 곧 "SaaS 종말"로 읽히는 현재의 해석
- 같은 해 소프트웨어 지출 전망은 오히려 상향됐다는 반대 방향의 사실
- 두 숫자가 함께 참일 수 있는 유일한 설명 — 구매의 경계가 조달 밖으로 이동했다
- shadow IT 60%가 뜻하는 것: 벤더는 이탈을 관측조차 못 한다
- McKinsey의 EBIT 37% 정체 — 만드는 속도와 손익이 아직 연결되지 않았다
- 반대 시각: "그냥 진짜 대체다, TCO가 답이다"에 대한 응답
- CSM 관점의 시사점 — 로그인·티켓·NPS로는 안 잡히는 이탈

**현우 경험과 엮을 지점**
- B2B 엔터프라이즈 솔루션개발팀에서 고객사가 "이건 우리가 만들면 되지 않나"라고 말할 때
  실제로 무슨 일이 벌어지는지 (검토자가 체험 서술 보강)
- 1인 개발자로 직접 만들어 본 사람으로서, "만들 수 있다"와 "몇 년 굴릴 수 있다"의 거리
- CSM 전환 중인 입장에서 갱신 지표가 놓치는 신호

## 2. 1인 개발 앱이 이번 가을 기업 구매팀 앞에 선다

**제목 후보**
- `App Store가 결제는 대신해도 갱신은 대신 못 한다`
- `이번 가을, 인디 앱에 조달 창구가 열린다`

**왜 지금인가**
Apple이 6월 8일 발표한 App Store 개편에서 Volume Purchasing과 Retention Messaging의
출시 시점을 "이번 가을"로 못 박았습니다. 지금이 그 가을입니다. Volume Purchasing은
Apple School Manager·Apple Business Manager를 통해 구독을 기업·교육 구매자에게 파는
경로고, Retention Messaging은 해지를 누른 순간 개발자가 메시지와 오퍼를 띄우는 기능입니다.
1인 개발자가 처음으로 조달 채널과 리텐션 훅을 동시에 손에 쥐게 됩니다.

**핵심 앵글**
Apple이 열어 준 건 결제 경로지 고객 관계가 아니다 — B2B 구매가 시작되는 순간
인디 개발자에게 없던 요구(보안 검토·인보이스·관리자 콘솔·갱신 협상)가 함께 도착한다.

**아웃라인**
- 이번 가을 켜지는 것: Volume Purchasing, Retention Messaging, App Store Bundles
- 인디 개발자에게 이게 왜 다른 종류의 문인지 — 소비자 결제와 조달의 차이
- Retention Messaging은 해지 버튼 앞의 마지막 한 화면, 즉 축소판 CS다
- App Store가 대신해 주는 것과 끝내 대신 못 해 주는 것
- 1인 규모에서 B2B 고객을 받는다는 것의 실제 비용

**현우 경험과 엮을 지점**
- B2B 소프트웨어 판매·도입 과정을 안에서 본 사람이, 같은 절차를 1인 개발자 규모로
  옮겨 놓으면 무엇이 남는지 (검토자가 체험 서술 보강)
- CSM 관점에서 Retention Messaging은 "해지 방어"가 아니라 "이유 수집" 채널로 읽힌다

## 3. 매출 없는 AI 시제품이 9월부터 공공조달 심사대에 오른다

**제목 후보**
- `수의계약 6년, AI 제품 심사가 따로 열렸다`
- `상업 실적 없는 AI 시제품에 조달 문이 열린 이유`

**왜 지금인가**
조달청의 AI 제품 전용 평가트랙이 9월부터 시행됩니다. 그동안 AI 제품도 일반 심사 기준으로
평가받아 혁신성을 인정받기 어렵다는 지적이 있었고, 이번 개편으로 전용 트랙이 생기면서

**핵심 앵글**
매출 실적이 없어도 심사대에 오를 수 있게 된 대신, 심사 기준이 AI 모델의 신뢰성·데이터

- 왜 지금 바뀌었나 — 일반 심사에서 AI 제품이 떨어지던 이유
- 새 심사 기준이 요구하는 것(신뢰성·보안·개인정보)은 소규모 팀에 무엇을 의미하나

- 9월 4차 지정이 첫 시험대인 이유

**현우 경험과 엮을 지점**
- 국내 B2B에서 공공 레퍼런스 한 건이 이후 영업에 어떻게 작동하는지 (검토자가 체험 보강)

## 1. 에이전트를 저장소 파일로 선언하는 `ant apply` ⭐ 완성 원고로 선택

**제목 후보**
- `에이전트 도입을 막는 건 모델이 아니라 형상관리입니다`
- `콘솔에서 만든 에이전트는 코드로 데려올 수 없다`

**왜 지금인가**
`ant` CLI 1.30.0 이 9월 3일 나오면서 `ant apply` 가 들어왔습니다. 에이전트·환경·스킬·
메모리 스토어·배포를 저장소 파일로 적고 Claude API 리소스와 맞추는 명령입니다. 다음 날
9월 4일 1.31.0 이 조직 컴플라이언스 설정 관련 타입을 추가했고, 9월 5일 Claude Code 는
정책·스킬 진단 쪽을 손봤습니다. 사흘 사이에 같은 방향의 커밋이 세 번 나온 셈입니다 —
에이전트를 **관리 대상 자산**으로 다루는 쪽입니다.

**핵심 앵글**
에이전트가 회사 안으로 못 들어간 이유는 모델 성능이 아니라 변경 이력을 댈 수 없다는
데 있었고, `claude-lock.json` 의 해시 두 개(`hash`·`remote_hash`)가 그 답을 파일 하나로
만들었다. 대신 **콘솔에서 클릭으로 만든 에이전트는 흡수되지 않는다** — GUI 로 시작한
에이전트에는 운영으로 가는 승격 경로가 자동으로 붙지 않는다.

**아웃라인**
- 무엇이 파일이 되는가: `agents/` 마크다운, `environments/`·`memory_stores/` YAML,
  `deployments/` 마크다운, 스킬은 `SKILL.md` 디렉터리. 파일끼리는 ID 가 아니라 상대 경로
- `claude-lock.json` 의 두 해시가 양방향 변경을 잡는 구조. 밖에서 바뀌면 `refusing to apply`
- 엔터프라이즈에서 막히는 지점은 벤치마크가 아니라 승인·감사·롤백이라는 관점
- CI 규약(PR 은 `--dry-run`, 병합 후 `--yes`, WIF 인증, 락파일 조직 불일치 시 거부)
- 콘솔 리소스는 adopt 불가 — 같은 정의를 apply 하면 에이전트가 하나 더 생긴다
- 반대 시각: Gartner 의 agentic 프로젝트 취소 전망, 그리고 Managed Agents 가 stateful
  이라 ZDR·HIPAA BAA 대상이 아니라는 공식 문서의 한 줄
- 마무리: 저장소에 무엇이 들어 있는지가 곧 그 조직의 에이전트 현황이다

## 2. 스킬이 마크다운 한 장짜리 유통 단위가 됐다

**제목 후보**
- `플러그인은 심사를 받았고 스킬은 받지 않는다`
- `마크다운 한 장이 배포 단위가 된 해`

**왜 지금인가**
Claude Code 가 9월 5일 업데이트에서 스킬 진단 쪽을 정리했습니다. 앞선 버전에서 들어온
`/skill-doctor` 는 **로드됐지만 안 쓰이는 스킬과 그 컨텍스트 비용**을 보여 줍니다.
같은 흐름의 반대편에서 Figma 는 에이전트용 스킬을 커뮤니티에 유통시키기 시작했습니다 —
50개가 넘는 커뮤니티 스킬 라이브러리, 파일 맥락에서 스킬 만들기, 커뮤니티에 발행하고
리믹스하기. 그리고 `ant apply` 는 스킬을 GitHub URL 로 참조해 커밋에 고정해 가져옵니다.
유통 경로·제작 경로·정리 도구가 한 달 안에 같이 서 있습니다.

**핵심 앵글**
플러그인은 코드였고 스토어 심사를 거쳤다. 스킬은 산문이고 심사가 없다 — 유통 비용이
0 이 된 대신 **로드 비용**이 생겼고, 그래서 스킬 스토어와 스킬 청소 도구가 같은 시기에
나왔다. 다음 병목은 "좋은 스킬을 어디서 구하나"가 아니라 "지금 몇 장이 켜져 있나"다.

**아웃라인**
- SKILL.md 라는 형식이 도구를 건너 공통 포맷이 된 경과
- 디자인 쪽까지 온 것 — Figma 커뮤니티 스킬 라이브러리와 발행·리믹스
- 유통이 쉬워지면 생기는 비용: 켜 두기만 한 스킬이 매 턴 컨텍스트를 먹는다
- `/skill-doctor` 가 등장한 자리 — 컨텍스트를 예산으로 다루기 시작한 신호
- `ant apply` 의 GitHub URL 참조와 커밋 고정, `--upgrade` 로만 갱신되는 설계
- 심사 없는 유통의 위험: 산문이 곧 실행 지시라는 점
- 프로덕트 디자인 관점의 시사점 — 스킬은 기능이 아니라 문서 형태의 워크플로다

**현우 경험과 엮을 지점**
- 이 블로그 저장소가 슬래시 커맨드·스킬 원본을 md 로 두고 머신 간 동기화하는 구조라,
  "스킬을 파일로 관리한다"는 주장을 자기 저장소로 보여 줄 수 있다
- 디자인 시스템을 다뤄 본 관점에서, 컴포넌트 라이브러리가 겪은 확산·정리 주기와 겹쳐 읽기

## 3. 마케팅 스택이 사람 대신 에이전트에게 열리고 있다

**제목 후보**
- `마케터의 클릭이 지표에서 사라진다`
- `이제 제품의 표면은 화면이 아니라 엔드포인트다`

**왜 지금인가**
MarTech Conference 가 9월 2일 열렸고, 9월 3일 martech.org 는 콘텐츠 운영의 다음이
agentic 시스템이라는 인터뷰를 실었습니다. 훅으로는 조금 약하지만, 그 아래 깔린 사실은
단단합니다 — HubSpot 은 올해 4월 MCP 서버를 정식 공개하고 5월에 UI 와 API 의 완전
동등성을 약속했고, Braze 는 7월 23일 원격 MCP 서버를 냈습니다. 벤더들이 제품 표면을
화면에서 엔드포인트로 옮기는 중입니다.

**핵심 앵글**
"AI 기능을 붙였다"와 "에이전트가 우리 제품을 운전할 수 있다"는 다른 일이다. 후자는
UI 기능 목록이 아니라 API 동등성으로 판정된다 — 그리고 그 순간 CSM 이 보던
사용량 지표(로그인·클릭·세션)는 고객 건강도를 대변하지 못하게 된다.

**아웃라인**
- 벤더들이 붙이고 있는 것은 챗봇이 아니라 MCP 엔드포인트라는 사실
- API 동등성 약속이 왜 마케팅 문구가 아니라 제품 결정인가
- 에이전트가 운전하면 사라지는 것: 화면 사용량이라는 대리 지표
- 그럼 무엇으로 건강도를 보나 — 실행된 작업, 도달한 결과 쪽으로 옮겨 가는 흐름
- 반대 시각: 툴 노출이 곧 자동화가 아니다, 권한·감사 없이 열면 사고가 난다
- 1인 개발자에게 주는 시사점 — 작은 제품일수록 MCP 표면 하나가 통합 목록을 대신한다

**현우 경험과 엮을 지점**
- CSM·martech 를 보는 입장에서 헬스스코어가 실제로 무엇으로 계산되는지 (검토자가 체험 보강)
- B2B 도입 심사에서 "API 로 다 되나요"가 어느 단계에서 나오는 질문인지
