## 1. 에이전트에 웹을 열어 주는 허용 목록이 세 개이고 같은 문자열이 다르게 읽힌다 ⭐ 완성 원고로 선택

**제목 후보**

- `에이전트 허용 도메인에 와일드카드가 필요할까요?` ← 채택 (질문형. 직전 두 글이 명사구·단정 평서였어서 골격을 바꿨습니다)
- `allowed_hosts 와 allowed_domains 가 같은 줄을 다르게 읽는 이유`
- `허용 목록에 example.com 만 적으면 막히는 요청`

**왜 지금인가**

Claude Managed Agents 는 10월 7~8일에 웹 도구의 경계를 두 번 좁혔습니다. `limited` 네트워킹
환경의 `allowed_hosts` 가 사이트를 직접 열지 않는 `web_search`·`web_fetch` 에까지 적용되고,
`allowed_domains` 에 `allowed_hosts` 밖의 항목이 있으면 세션 생성이 400 으로 떨어집니다.
같은 날 `web_fetch` 는 **세션에 이미 등장한 URL 만** 가져오도록 바뀌었습니다.
그런데 이 두 목록의 매칭 규칙이 서로 반대입니다. 여기에 Claude Code 샌드박스의
`network.allowedDomains` 까지 더하면 허용 목록이 세 벌이고, 세 곳의 와일드카드 규칙이 다 다릅니다.

**핵심 앵글 한 문장**

에이전트에 웹을 열어 줄 때 적는 허용 목록은 한 벌이 아니라 세 벌이고, `example.com` 이라는
같은 한 줄이 어떤 목록에서는 서브도메인까지 열고 어떤 목록에서는 그 호스트 하나만 열며
`*.example.com` 은 한쪽에서 필수이고 다른 쪽에서는 거절되므로, 세 목록의 매칭 규칙을
맞춰 보지 않으면 세션이 400 으로 거절되거나 열어 준 줄 알았던 호스트가 막힌다.

**글 구조 아웃라인**

- 허용 목록에 `example.com` 한 줄을 적어 두고 열었다고 생각한 장면에서 출발 →
  와일드카드가 필요한지 질문 → "목록에 따라 다르다" 는 직답
- 도구 쪽 `allowed_domains`: 적은 도메인이 그 호스트와 **모든 서브도메인**을 덮는다.
  `example.com` 이 `docs.example.com` 을 덮고, 반대로 `docs.example.com` 은 `example.com` 을 못 덮는다.
  `www.` 도 서브도메인이라 `www.example.com` 은 `example.com` 을 못 덮는다.
  **와일드카드는 거절된다** — `*.example.com` 을 적으면 `example.com` 으로 고치라는 에러
- 환경 쪽 `allowed_hosts`: 맨 호스트명은 **그 호스트 하나만** 맞는다. `example.com` 은
  `www.example.com` 과 안 맞는다. `*.example.com` 은 모든 서브도메인과 맞지만 `example.com` 자신은 아니다.
  **여기서는 와일드카드가 유일한 방법**이다
- 두 목록이 만나는 지점에서 세션이 거절된다: 도구의 `docs.example.com` 은
  `allowed_hosts: ["example.com"]` 안에 없고, `["docs.example.com"]` 이나 `["*.example.com"]` 에는 있다
- 세 번째 목록 — Claude Code 샌드박스의 `network.allowedDomains` 는 `*.npmjs.org` 처럼 와일드카드를
  쓰고, 비어 있으면 첫 요청에서 승인을 묻는다(`strictAllowlist` 면 묻지 않고 막는다). 세 목록을 표로 대조
- 호스트가 맞아도 막히는 두 경우: 프록시 환경변수를 안 읽는 도구(`ssh`·DB 드라이버)와
  TCP 가 아닌 트래픽(UDP·QUIC·`ping`), 그리고 `web_fetch` 의 출처 규칙 —
  모델 자기 출력·시스템 프롬프트·첨부 문서·`bash` 출력에만 있는 URL 은 `url_not_in_prior_context`
- 에러 코드로 어디서 막혔는지 가리는 법으로 맺는다 — 생성 시 400,
  런타임 `url_not_allowed`, 출처 규칙 `url_not_in_prior_context`, 샌드박스 403

**현우 경험과 엮을 지점**

이 블로그의 매일 아침 원고를 쓰는 클라우드 세션이 정확히 이 구조 안에서 돌고, 이번 회차에
열린 도메인이 다섯 곳뿐이라 리서치 범위가 그대로 줄었습니다. 허용 목록을 좁히면 안전해지는
대신 에이전트가 할 수 있는 일도 같이 줄어든다는 대목을 이 관점에서 이을 수 있습니다.
체험 서술은 검토 단계에서 채웁니다.

## 2. AI 가 코드를 쓰는 동안 개발자 공고는 오히려 늘었다

**제목 후보**

- `개발자 공고를 15% 밀어 올린 쪽은 주니어가 아니었다`
- `AI 가 코드를 쓰는데 개발자 공고가 느는 이유`

**왜 지금인가**

CNBC 가 **2026년 10월 11일** 에 미국 소프트웨어 개발 직군 공고가 2025년 2월 이후 약 15% 올랐다고
보도했습니다. 전체 고용 시장과 반대 방향입니다. 같은 기사에서 2025년 5월~2026년 5월 증가분의
약 71% 가 시니어 직군이고, 증가분의 약 37% 가 제목에 AI 가 들어간 공고였다고 적었습니다.
팬데믹 이전 대비로는 여전히 27.5% 아래라는 Indeed Hiring Lab 수치도 함께 실렸습니다.
**이 회차에서 3일 창 안에 들어온 유일한 항목**입니다.

**핵심 앵글 한 문장**

AI 코딩 도구가 개발자 수요를 줄였다는 통념과 달리 공고는 늘었는데, 늘어난 쪽이 시니어와
AI 직함에 몰려 있다는 점에서 이 수치는 수요 회복이 아니라 **진입 구간이 좁아지는 신호**로 읽힌다.

**글 구조 아웃라인**

- "AI 가 코드를 쓰면 개발자를 덜 뽑는다" 는 예상에서 출발 → 공고는 늘었다는 직답
- 늘어난 폭과 기준선을 같이 놓는다 — 2025년 2월 대비 약 15% 증가, 팬데믹 이전 대비로는 여전히 아래
- 증가분의 구성: 시니어 약 71%, AI 직함 약 37%
- 그래서 무엇이 달라졌나 — 총량이 아니라 분포가 움직였다는 해석
- 1인 개발자·이직 준비자 입장에서 확인할 것으로 맺는다
- ⚠ **발행 전 반드시 확인**: 이 글의 수치는 전부 검색 스니펫에서 받은 것이고 원문을 열지 못했습니다.
  본문에 수치를 단정해 쓰지 말고, CNBC 원문과 Indeed Hiring Lab 원글을 직접 확인한 뒤 확정하십시오.
  FRED 의 같은 계열 지수는 2026-10-02 에 78.33 으로, 기사의 27.5% 와 계산이 맞지 않습니다

**현우 경험과 엮을 지점**

Cisco 파트너사 솔루션개발팀에서 일하면서 개인 앱을 내는 입장은 기사가 말하는 "시니어 +
AI 직함" 쪽에 걸칩니다. 다만 채용 시장에 대한 체험 서술은 세션이 알 수 없어 검토 단계에서 채웁니다.

## 3. 10월 15일이 Haiku 4.5 가 은퇴할 수 있는 첫날인데 공지가 없다

**제목 후보**

- `Haiku 4.5 옆에 적힌 10월 15일이 은퇴일이 아닌 이유`
- `모델 표의 "not sooner than" 을 일정으로 읽으면 안 되는 까닭`

**왜 지금인가**

Anthropic 의 model deprecations 표에서 `claude-haiku-4-5-20251001` 의 상태는 **Active** 이고
tentative retirement date 는 **2026년 10월 15일** 입니다. 사흘 뒤입니다. 그런데 Deprecated 칸은
비어 있고 deprecation history 에 Haiku 4.5 항목이 없습니다. 같은 문서가 공개 모델에는
**최소 60일 전 통보**를 적어 뒀으니, 공지가 없는 지금 10월 15일에 은퇴하는 일은 일어날 수 없습니다.
대체 모델인 Haiku 5.5 는 10월 7일에 나왔고 Claude Code 2.1.293 이 그날 기본 모델로 바꿨습니다.

**핵심 앵글 한 문장**

모델 표의 "not sooner than" 날짜는 일정이 아니라 **하한선**이고, 실제로 움직이는 시계는
deprecation 공지가 뜬 날부터 60일이므로, 모델 ID 를 고정해 둔 쪽이 봐야 하는 칸은
retirement date 가 아니라 Deprecated 칸이다.

**글 구조 아웃라인**

- 표에서 사흘 뒤 날짜를 보고 교체를 서두르는 장면에서 출발 → 그날 은퇴하지 않는다는 직답
- 표의 네 상태(Active·Legacy·Deprecated·Retired)와 "not sooner than" 이 뜻하는 것
- 실제 사례로 대조: Sonnet 4.5 는 9월 30일 공지 → 11월 30일 은퇴로 61일이 잡혔다
- 그럼 Haiku 4.5 는 — Active, 공지 없음, 대체 모델은 이미 나와 기본값까지 바뀌었다
- 파이프라인에서 확인할 것으로 맺는다
- ⚠ 겹침 주의: 9/15 브리핑과 `deepseek-v4-pro-routing-model-id.md` 가 통보 기간·은퇴 후 동작을
  이미 다뤘습니다. 이 글로 가려면 Haiku 4.5 한 건에 좁히고 그 글과 겹치는 설명은 걷어내십시오

**현우 경험과 엮을 지점**

API 위에 자동화 파이프라인을 올려 둔 입장에서 모델 ID 를 고정했는지 별칭으로 뒀는지에 따라
확인할 칸이 달라집니다. 해석 수준으로 두고 체험 서술은 검토 단계에서 채웁니다.

## 그 외 눈에 띈 것

- **`web_fetch` 의 멀티에이전트 교집합 규칙** — 서브에이전트로 넘길 때 `allowed_domains` 는
  모든 목록이 덮는 호스트만 통과하고 `blocked_domains` 는 합집합으로 더해집니다. 교집합이
  비면 도구는 남아 있는데 모든 호출이 `url_not_allowed` 로 실패합니다 —
  https://platform.claude.com/docs/en/managed-agents/tools-web-restrictions
- **호스트 단위 허용의 한계를 문서가 직접 경고한다** — 허용은 호스트 단위이고 동작 단위가
  아니라서, 허용된 호스트로 `git push` 나 패키지 배포까지 나갈 수 있습니다. 프롬프트 인젝션이
  성공하면 그 호스트로 파일이 빠져나갈 수 있다고 적혀 있습니다 —
  https://platform.claude.com/docs/en/managed-agents/environments
- **Compliance API 가 Claude Docs 문서를 Word 로 내려받는다**(10/8, 베타) — 통합 Claude 경험의
  대화까지 반환 범위에 들어왔습니다 — https://platform.claude.com/docs/en/release-notes/api
- **Claude Code 샌드박스에서 자격증명 마스킹에는 TLS 종료가 필요하다** — `mask` 항목을 쓰려면
  `network.tlsTerminate` 를 켜야 하고, 켜지 않으면 센티널이 그대로 서버에 도달해 인증이 실패합니다.
  `claude doctor` 가 경고로 알려 줍니다 — https://code.claude.com/docs/en/sandboxing
- **Figma 가 10월 9일 Sightlines 3호를 냈다** — AI 도입의 초점을 속도에서 품질로 옮긴다는 내용으로
  검색 결과에 잡혔지만 `figma.com` 이 차단이라 원문을 열지 못했습니다 ⚠ 원문 미확인

## 1. UTF-8 이 아닌 파일을 고치면 한글이 전부 물음표로 바뀐다 ⭐ 완성 원고로 선택

**제목 후보**

- `한글 주석 한 줄에 파일이 깨지는 이유` ← 채택
- `UTF-8 이 아닌 파일을 고칠 때 사라지는 글자`
- `바이트는 글자가 아니다`

채택 이유: 앞선 HTML 학습 페이지 글 세 편이 `온도를 올리면 AI는 왜 엉뚱한 말을 할까요`,
`RAG는 AI가 모르는 우리 회사 규정을 어떻게 답할까요`, `Self-Attention은 "그것"이 무엇을
가리키는지 어떻게 알까요` 로 **세 편 연속 질문형**입니다. 같은 날 1회차 원고도
`~할까요?` 였습니다. `POSTING.md` 2-0 의 "질문형이 잘 읽힌다고 전부 `~까요?` 로 끝내면
그게 자동화 티다" 에 정확히 걸리는 자리라, 이번은 **짧은 명사구**로 골격을 바꿨습니다.
`한글 주석`·`깨지는` 이 독자가 실제로 검색창에 치는 말이라 검색 통로도 앞쪽에 있습니다.

**훅이 된 소식**

2026년 10월 9일 Claude Code 2.1.296 이 이 한 줄을 고쳤습니다 — "Fixed Edit and
NotebookEdit replacing every non-ASCII character in files that are not valid UTF-8
(Windows-1252, Shift-JIS, GBK); such edits are now refused". 에이전트가 UTF-8 이 아닌
파일을 고치면 **ASCII 가 아닌 모든 글자가 교체 문자로 바뀌어 저장되고 있었고**, 이제는
그런 편집을 거부합니다. 같은 릴리스에 유니코드 줄 구분자(U+2028, U+2029)가 든 텍스트가
기록에서 사라지던 버그 두 건도 같이 올라와 있습니다.

**설명할 원리와 이 글이 답할 질문**

바이트와 글자는 다른 것이고, 그 사이를 잇는 것은 **약속(인코딩)** 하나뿐이다.
이 글이 답할 질문: *왜 한글 주석 한 줄이 들어간 순간에만 파일이 깨지고, 한 번 깨진
글자는 왜 되돌릴 수 없는가.*

핵심은 세 겹입니다.
1. **ASCII 구간은 어느 인코딩에서나 바이트가 똑같다.** `print(x)` 는 UTF-8·CP949·
   Shift-JIS·GBK·Windows-1252 에서 전부 `70 72 69 6E 74 28 78 29` 입니다. 그래서 영문
   코드만 있는 파일은 인코딩을 틀려도 멀쩡해 보입니다 — 깨짐이 **한글·일본어 주석이
   들어간 자리에서만** 드러나는 이유입니다.
2. **같은 글자가 인코딩마다 다른 바이트다.** `한` 은 UTF-8 에서 3바이트 `ED 95 9C`,
   CP949 에서 2바이트 `C7 D1` 입니다.
3. **틀린 약속으로 읽으면 실패하거나, 더 나쁘게는 엉뚱한 글자로 성공한다.** CP949 로 쓴
   `한글` 의 네 바이트 `C7 D1 B1 DB` 를 UTF-8 로 읽으면, `C7` 은 깨져서 교체 문자가 되고
   `D1 B1` 은 **키릴 문자 `ѱ`(U+0471)로 멀쩡히 성공**하고 `DB` 가 또 깨집니다. 깨짐이 늘
   눈에 보이는 게 아니라는 대목입니다.

그리고 **왜 되돌릴 수 없는가** — 교체 문자()를 UTF-8 로 다시 저장하면 `EF BF BD` 라는
실제 바이트가 됩니다. 원래 `C7` 이 무엇이었는지는 파일 어디에도 남지 않습니다. 읽기는
추측이지만 쓰기는 확정이라, 추측한 결과를 저장한 순간 원본이 사라집니다.

**대표 인터랙션 아이디어 한 줄**

바이트 띠 하나를 고정해 놓고 **디코더(약속)만 바꿔 끼우는** 장치 — 같은
`C7 D1 B1 DB` 가 CP949 에서는 `한글`, UTF-8 에서는 `ѱ`, Windows-1252 에서는
`ÇÑ±Û` 로 다시 그려지고, 바이트 칸에 마우스를 올리면 그 바이트의 8비트와 UTF-8 선행
비트 패턴이 같이 보인다.

**글 구조 아웃라인**

- 첫 화면: 훅이 된 10월 9일 수정 한두 문장 → 바로 대표 인터랙션(디코더 바꿔 끼우기)
- 바이트가 무엇인지부터: 숫자 하나가 0~255, 파일은 그 숫자의 줄
- 약속 표(인코딩)가 있어야 숫자가 글자가 된다 → 일상 비유: 같은 좌석 번호가 다른 공연장
  배치도에서 다른 자리를 가리킨다. 비유가 안 맞는 부분 한 줄
- ASCII 구간이 왜 전부 같은지: 작은 표로 `print(x)` 바이트 대조 → 깨짐이 한글에서만
  드러나는 이유
- UTF-8 의 구조: 1~4바이트, 선행 바이트의 비트 패턴이 길이를 알려 준다(작은 숫자와
  모양으로, 수식 없이)
- 틀린 디코더의 세 결말: 실패 / 교체 문자 / **엉뚱한 글자로 성공**
- 되돌릴 수 없는 이유: 읽기(추측) vs 쓰기(확정), `EF BF BD` 가 파일에 박히는 자리
- 2026년의 자리: 그래서 에이전트가 편집을 거부하는 쪽으로 바뀌었다 + U+2028 두 건
- 참고 자료

## 2. 터미널로 상태를 알리는 규격이 생기고, 같은 통로로 쓰레기 문자가 새던 버그가 같이 고쳐졌다

**훅이 된 소식**

2.1.295(10월 8일)가 **Program Status Protocol(OSC 7501)** 지원을 넣었습니다 — 터미널이
이 규격을 구현하면 Claude Code 가 작업 중인지, 사용자를 기다리는지, 끝났는지를 표시할 수
있습니다. 바로 다음 릴리스 2.1.296(10월 9일)은 MATE Terminal 같은 구형 VTE 터미널에서
복사 후 `52;c;…` 이스케이프 시퀀스가 화면에 그대로 찍히던 버그를 고쳤습니다.

**설명할 원리와 이 글이 답할 질문**

터미널에는 글자와 명령이 **같은 한 줄기 바이트로 섞여** 흐른다. 그 둘을 가르는 것은
ESC 로 시작하는 약속뿐이다. 이 글이 답할 질문: *화면에 글자를 찍는 통로와 "커서를 옮겨라"
같은 명령을 보내는 통로가 하나인데, 터미널은 그 둘을 어떻게 구분하는가.* 구분이 어긋나면
명령이 글자로 찍히고(`52;c;` 사고), 반대로 글자가 명령으로 실행되면 보안 문제가 됩니다.

**대표 인터랙션 아이디어 한 줄**

바이트 줄에 ESC 를 직접 끼워 넣어 보는 장치 — ESC 를 넣으면 뒤따르는 글자가 화면에서
사라지고 커서가 움직이고, ESC 를 빼면 `[1;31m` 같은 글자가 그대로 보인다.

## 3. 이름이 `constructor` 인 설정 하나가 사라지는 일이 2년째 반복된다

**훅이 된 소식**

2.1.296 에 두 건이 같이 올라왔습니다 — 이름이 `constructor` 같은 마켓플레이스를 더하면
내부 오류가 나던 문제(이제 명확히 거부), 그리고 **이름이 `constructor` 나 `prototype` 인
플러그인 시크릿이 다음 저장에서 삭제되던 문제**입니다.

**설명할 원리와 이 글이 답할 질문**

JavaScript 에서 객체를 사전처럼 쓰면, 넣지 않은 키가 이미 들어 있는 것처럼 보인다.
이 글이 답할 질문: *왜 `constructor` 라는 이름만 특별히 사고를 내는가.*
변경이력을 거슬러 보면 같은 계열 버그가 여러 번 반복됩니다 — 스킬 이름, 훅 매처 이름
(`__proto__`), SDK MCP 도구 이름, 권한 규칙 이름(`toString`)에서 각각 한 번씩입니다.
원리는 하나(프로토타입 체인)인데 사전으로 쓰는 자리마다 새로 터지는 구조입니다.

**대표 인터랙션 아이디어 한 줄**

빈 사전에 키를 넣어 보는 장치 — `banana` 를 조회하면 비어 있다고 나오는데
`constructor` 를 조회하면 넣지 않은 값이 나오고, "사전을 깨끗한 통으로 바꾸기"
(`Object.create(null)`·`Map`) 토글을 켜면 그 칸이 비워진다.

**Sources**

- [Claude Code changelog](https://code.claude.com/docs/en/changelog) — 2.1.296 의 두 건.
  원문 확인
- [anthropics/claude-code CHANGELOG.md](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)
  — 같은 계열 과거 항목(스킬 이름, `__proto__` 훅 매처, SDK MCP 도구 이름, `toString`
  권한 규칙)을 원본 텍스트에서 확인

**왜 1번에 밀렸나**: 재미있는 주제지만 JavaScript 객체 모델을 먼저 깔아야 해서,
그 언어를 모르는 독자에게는 디딤돌이 한 겹 더 필요합니다.
