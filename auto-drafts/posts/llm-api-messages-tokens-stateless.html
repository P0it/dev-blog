ChatGPT는 방금 한 말을 어떻게 기억할까요?

채팅 앱에 "내 이름은 민지야"라고 쓰고 조금 뒤에 "내 이름이 뭐였지?"라고 물으면 "민지님이요"라는 답이 옵니다. 앞에서 한 말을 기억하는 것처럼 보입니다. 그런데 LLM은 대화를 기억하지 못합니다. 그렇다면 이 답은 어떻게 나왔을까요? 앱이 LLM에 보내는 요청을 하나 열어 보겠습니다.

채팅 앱과 LLM 사이에는 무엇이 오가나요?

앱이 내 말을 요청에 담아 보내고, LLM은 답 하나를 돌려줍니다.

ChatGPT나 Claude 앱에 글을 쓰면 앱이 그 글을 LLM API로 보냅니다. API는 다른 프로그램에 일을 시킬 때 쓰는 정해진 요청 형식입니다. LLM은 요청을 읽고 답을 만들어 돌려줍니다. 앱은 그 답을 화면에 보여 줍니다.

그림 가운데의 앱은 개발자가 짠 프로그램입니다. 이 글은 도구를 쓰지 않는 가장 단순한 경우, 곧 챗봇을 다룹니다. 도구를 붙여 Agent를 만들어도 앱과 LLM이 주고받는 요청의 모양은 같습니다.

그럼 두 번째 말을 보낼 때는 어떨까요? 이번에도 새로 쓴 한 줄만 보낼 것 같지만 앱은 앞의 대화를 함께 묶어서 보냅니다.

LLM이 "민지님"이라고 답할 수 있었던 것은 요청 안에 첫 번째 말이 다시 들어 있었기 때문입니다. 앱이 왜 이렇게 묶어 보내는지는 아래에서 요청 하나를 열어 보면서 봅니다.

요청에는 무엇이 들어가나요?

모델 이름, 답 길이 한도, 그리고 지금까지의 대화를 담은 메시지 목록입니다.

앱이 보내는 요청 (Claude API)
{ "model": "claude-sonnet-5-5", "max_tokens": 1024, "system": "너는 친절한 비서다.", "messages": [ { "role": "user", "content": "내 이름은 민지야." }, { "role": "assistant", "content": "반가워요, 민지님!" }, { "role": "user", "content": "내 이름이 뭐였지?" } ] }

messages는 대화를 순서대로 담은 메시지 목록입니다. 칸마다 누가 한 말인지 적는 role이 붙습니다. user는 사용자의 말이고 assistant는 LLM이 앞서 한 답입니다.

system은 개발자가 LLM에게 주는 지시입니다. 말투와 역할, 지켜야 할 규칙을 여기에 적습니다. Claude API는 system을 메시지 목록 밖의 칸으로 받습니다. OpenAI API는 목록 맨 앞에 role이 system(최신 모델은 developer)인 칸으로 받습니다.

max_tokens는 답 길이의 한도입니다. Claude API에서는 꼭 넣어야 하는 값이고, 한도에 닿으면 답이 문장 중간에서 잘립니다.

LLM이 이번 요청에서 볼 수 있는 것은 이 요청에 담긴 글이 전부입니다.

그럼 LLM은 앞에서 한 말을 어떻게 기억하나요?

기억하지 않습니다. 앱이 지난 대화를 매번 다시 보냅니다.

LLM API는 요청 하나를 받아 답 하나를 돌려주면 그 요청을 잊습니다. 이렇게 앞선 요청을 기억하지 않는 성질을 stateless라고 합니다. 대화를 기억하는 것은 앱입니다.

앱은 대화 기록을 들고 있다가 새 말이 오면 기록 끝에 붙여 전체를 보냅니다. LLM의 답이 오면 그 답도 기록에 붙입니다. 답을 기록에 붙이는 일을 빠뜨리면 LLM은 다음 요청에서 자기가 앞에서 무슨 말을 했는지 모릅니다.

OpenAI의 Responses API처럼 서버가 대화를 저장해 주는 방식도 있습니다. 앱은 이전 응답 번호만 보내면 됩니다. 이때도 서버가 지난 대화를 다시 모델 입력에 넣는 것은 같아서 그만큼의 토큰은 똑같이 계산됩니다.

토큰은 무엇이고 왜 세나요?

LLM이 글을 읽고 쓰는 단위입니다. 요금과 길이 한도가 모두 토큰으로 정해집니다.

토큰(token)은 단어와 비슷하거나 조금 작은 글 조각입니다. 같은 글이라도 모델마다 나누는 방식이 달라서 토큰 수가 다릅니다. 같은 뜻이라도 한국어는 영어보다 토큰을 더 쓰는 편입니다.

돌아온 응답 (줄임)
{ "content": [{ "type": "text", "text": "민지님이라고 하셨어요." }], "stop_reason": "end_turn", "usage": { "input_tokens": 47, "output_tokens": 10 } }

응답에는 이번 요청에 쓴 토큰 수가 함께 옵니다. Claude API는 usage의 input_tokens(보낸 토큰)와 output_tokens(받은 토큰)로 알려 줍니다. 요금은 두 값에 각각 단가를 곱해서 매깁니다. 받은 토큰의 단가가 보통 몇 배 비쌉니다.

보내기 전에 미리 세어 보고 싶으면 토큰 세기 API를 씁니다. Claude API에는 count_tokens가 있고, OpenAI는 tiktoken 라이브러리로 셀 수 있습니다.

대화가 길어지면 무엇이 달라지나요?

보내는 토큰이 매번 늘어서 비용과 대기 시간이 함께 늘어납니다.

앱은 대화 전체를 매번 보내기 때문에, 세 번째 질문을 할 때는 첫 질문과 답까지 다시 보내고 그 토큰값을 또 냅니다. 열 번 주고받으면 첫 질문을 열 번 보내게 됩니다. 대화가 길수록 비싸고 느려지는 이유는 매번 처음부터 다시 보내기 때문입니다.

모델이 한 번에 받을 수 있는 양에도 한도가 있습니다. 이 한도를 context window라고 합니다. 보낸 토큰과 받을 토큰을 합쳐 이 안에 들어와야 합니다. 넘치면 요청이 거절되므로 긴 대화는 오래된 부분을 덜어 내거나 요약해서 보냅니다.

매번 같은 앞부분을 다시 보내는 비용은 prompt caching으로 줄일 수 있습니다. 앞에서 보낸 부분을 서버가 잠시 저장해 두고 다시 계산하지 않는 기능입니다. 요청을 여러 번 이어서 보내는 Agent에서 특히 효과가 큽니다.

답이 한 글자씩 나오는 건 왜 그런가요?

LLM이 토큰을 만들 때마다 앱이 받아서 바로 보여 주기 때문입니다. 이것을 스트리밍이라고 합니다.

LLM은 답을 토큰 하나씩 만듭니다. 스트리밍을 켜지 않으면 앱은 답이 다 만들어질 때까지 기다렸다가 한 번에 받습니다. 답이 길면 몇 초 동안 빈 화면이 이어집니다.

스트리밍을 켜면 API가 토큰이 만들어지는 대로 조각을 이어서 보내 줍니다. 조각은 SSE(Server-Sent Events)로 옵니다. 서버가 연결을 열어 둔 채 작은 이벤트를 차례로 흘려보내는 웹 표준입니다. 첫 글자가 보이는 시간은 크게 줄지만 답 전체가 끝나는 시간은 그대로입니다.

코드로 쓰면 어떻게 되나요?

대화 기록 목록 하나와 반복문 하나면 됩니다.

import anthropic

client = anthropic.Anthropic()  # ANTHROPIC_API_KEY 환경 변수를 읽는다

# ① 대화 기록
history = []

while True:
    question = input("나: ")
    if not question:
        break
    # ② 내 말을 기록에 붙인다
    history.append({"role": "user", "content": question})
    # ③ 기록 전체를 보내고 답을 조각으로 받는다
    with client.messages.stream(
        model="claude-sonnet-5-5",
        max_tokens=1024,
        system="너는 친절한 비서다.",
        messages=history,
    ) as stream:
        for text in stream.text_stream:
            print(text, end="", flush=True)
        reply = stream.get_final_message()

    # ④ LLM의 답도 기록에 붙인다
    history.append({"role": "assistant", "content": reply.content})
    # ⑤ 이번 요청에 쓴 토큰
    print(f"\n[보냄 {reply.usage.input_tokens} · 받음 {reply.usage.output_tokens}]")
$ python chat.py
나: 내 이름은 민지야.
반가워요, 민지님! 무엇을 도와드릴까요?
[보냄 21 · 받음 14]
나: 내 이름이 뭐였지?
민지님이라고 하셨어요.
[보냄 47 · 받음 10]
  1. 앱이 들고 있는 대화 기록입니다. 이 목록이 위 그림의 메시지 목록이고, LLM 대신 대화를 기억합니다.
  2. 사용자의 말을 기록 끝에 붙입니다. 이 줄 대신 새 질문만 담은 목록을 보내면 그림 아래쪽처럼 LLM이 앞의 대화를 모릅니다.
  3. stream으로 부르면 토큰이 만들어지는 대로 text_stream에서 조각이 나옵니다. 다 받은 뒤 get_final_message로 전체 응답을 얻습니다.
  4. LLM의 답도 기록에 붙입니다. 빠뜨리면 다음 질문에서 LLM은 자기가 한 말을 모릅니다.
  5. 두 번째 요청에서 보낸 토큰이 21에서 47로 늘었습니다. 첫 질문과 답을 다시 실어 보냈기 때문입니다. 실제 코드에서는 stop_reason이 max_tokens인지도 확인해 잘린 답을 알려 줍니다.

코드는 anthropic 2.14 기준이고 출력은 예시입니다. OpenAI SDK로 쓰면 client.chat.completions.create(..., stream=True)로 부르고 system 지시는 메시지 목록 맨 앞 칸에 넣습니다. OpenAI는 새 프로젝트에 Responses API를 권합니다.
