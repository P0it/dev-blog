Agent를 하나 더 두면 정말 나아질까요?

Agent에게 "경쟁사 다섯 곳의 요금제를 조사해서 비교표로 만들어 줘"라고 맡겼더니, 세 번째 회사를 조사할 즈음 대화가 검색 결과로 가득 차서 첫 회사 내용을 놓치기 시작합니다. 회사마다 조사 Agent를 따로 두면 나아질까요? 여러 Agent가 함께 일하는 구조와, 그 전에 먼저 따져 볼 단순한 방법들을 봅니다.

Agent 하나로 큰 일을 맡기면 무엇이 문제인가요?

모든 중간 결과가 한 대화에 쌓여 context window를 채우고 LLM이 앞의 내용을 놓칩니다.

Agent 하나에 큰 일을 맡기면 검색 결과와 읽은 문서가 전부 한 대화에 쌓입니다. 대화가 길어질수록 비용이 늘고 LLM이 앞의 내용을 놓치기 쉽습니다. 다섯 회사를 조사하는 동안 쌓인 수만 토큰 가운데 비교표에 실제로 필요한 것은 회사마다 몇 줄뿐입니다.

일을 나눠 다른 Agent에게 맡기면 각자 자기 몫의 자료만 봅니다. 조사를 마친 Agent는 요약만 돌려주고 총괄 Agent는 요약 다섯 개로 비교표를 만듭니다. 이렇게 Agent마다 대화를 따로 두는 것을 컨텍스트 격리라고 합니다.

여러 Agent는 어떻게 함께 일하나요?

총괄 Agent가 일을 나눠 맡기고 하위 Agent가 각자 일한 뒤 요약만 돌려줍니다.

가장 흔한 구조는 총괄(orchestrator)과 하위 Agent(subagent)입니다. 총괄 Agent는 일을 나누고 하위 Agent에게 맡긴 뒤 결과를 합칩니다. 하위 Agent는 맡은 일만 하고 요약을 돌려줍니다. 총괄 Agent 입장에서 하위 Agent는 도구 하나와 같습니다. 부탁을 보내면 결과가 돌아옵니다.

서로 기다릴 필요가 없는 일이면 하위 Agent를 동시에 돌려 시간도 줄입니다. Anthropic의 조사 시스템은 이 구조로 Agent 하나일 때보다 조사 품질이 크게 올랐다고 밝혔습니다. 대신 토큰은 일반 채팅의 15배쯤 썼다고 합니다.

그럼 항상 여러 Agent로 나누는 게 좋은가요?

아닙니다. 비용과 지연이 크게 늘어서 나눠야 할 이유가 분명할 때만 씁니다.

여러 Agent는 비쌉니다. 하위 Agent마다 지시와 도구 목록을 따로 보내고 각자 여러 번 반복합니다. 총괄 Agent도 계획과 합치기에 LLM을 부릅니다. 하위 Agent끼리 서로의 결과를 모르니 같은 자료를 두 번 찾기도 하고 서로 다른 결론을 내기도 합니다.

나누기 좋은 일은 이런 일입니다. 서로 독립적으로 할 수 있는 일, 자료가 많아 한 대화에 담기 어려운 일, 결과의 가치가 비용보다 큰 일입니다. 작업 순서가 정해져 있거나 서로 긴밀히 맞춰야 하는 일은 Agent 하나가 낫습니다. 코드 수정처럼 파일 하나를 여럿이 함께 고쳐야 하는 일이 그렇습니다.

Agent를 늘리기 전에 따져 볼 방법은 없나요?

순서가 정해진 일은 워크플로로 충분할 때가 많습니다. Anthropic은 다섯 가지 패턴을 먼저 권합니다.

패턴하는 일예
이어 붙이기한 단계의 출력을 다음 단계의 입력으로초안 → 번역 → 말투 검사
길 나누기입력을 분류해 알맞은 처리로 보냄문의를 환불·배송·기타로
동시에 하기나눈 일을 함께 돌리고 합침문서 다섯 개 동시 요약
총괄과 일꾼LLM이 일을 나누고 맡김여러 파일 고치기, 조사
쓰고 고치기한 LLM이 쓰고 다른 LLM이 평가해 다시번역 다듬기

Anthropic은 "가장 단순한 방법으로 시작하고 필요할 때만 복잡하게" 하라고 권합니다. 위 다섯 가지 가운데 앞의 세 가지는 순서를 코드가 정하는 워크플로이고 네 번째가 여러 Agent에 가장 가깝습니다. 길을 정할 수 있는 일은 LangGraph 같은 그래프로 코드가 정하게 하고, 나눌 방법을 미리 알 수 없을 때만 LLM에게 나누기를 맡깁니다.

코드로 쓰면 어떻게 되나요?

하위 Agent를 도구 함수 하나로 감싸서 총괄 Agent에게 줍니다.

from langchain.agents import create_agent
from langchain.tools import tool

# ① 하위 Agent: 검색 도구만 가진 조사 담당
researcher = create_agent(
    model="anthropic:claude-haiku-5-5",
    tools=[web_search, read_page],
    system_prompt="맡은 회사의 요금제를 조사해 10줄 이내로 요약한다. "
                  "출처 주소를 함께 적는다.",
)

# ② 하위 Agent 를 도구로 감싼다. 요약만 돌려준다
@tool
def research(company: str) -> str:
    """회사 하나의 요금제를 조사해 요약을 돌려준다. 회사마다 따로 부른다."""
    out = researcher.invoke(
        {"messages": [{"role": "user", "content": f"{company} 요금제 조사"}]})
    return out["messages"][-1].content       # 검색 결과는 버리고 요약만

# ③ 총괄 Agent: 조사 도구 하나로 나누고 합친다
lead = create_agent(
    model="anthropic:claude-sonnet-5-5",
    tools=[research],
    system_prompt="조사가 필요한 회사마다 research 를 부르고, "
                  "결과를 모아 비교표를 만든다.",
)
  1. 하위 Agent는 맡은 일에 필요한 도구만 받습니다. 일이 단순하면 값싼 모델을 써서 비용을 줄입니다.
  2. 하위 Agent의 대화 전체 대신 마지막 답(요약)만 돌려줍니다. 컨텍스트 격리가 일어나는 곳이 이 한 줄입니다.
  3. 총괄 Agent는 하위 Agent를 도구로 봅니다. LLM이 한 응답에 research 부탁을 여러 개 담으면 LangChain이 동시에 실행합니다.

web_search·read_page는 예시라 줄였습니다. 하위 Agent에게 넘기는 지시가 가장 중요합니다. 무엇을, 어디까지, 어떤 형식으로 돌려줄지 적지 않으면 하위 Agent끼리 같은 일을 하거나 총괄 Agent가 합치기 어려운 결과를 돌려줍니다.
