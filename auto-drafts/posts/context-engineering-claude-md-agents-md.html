컨텍스트 창이 남았는데 에이전트가 규칙을 잊는 이유

아침 아홉 시, 코딩 에이전트(coding agent)에게 "테스트는 pnpm test 로 돌려 줘"라고 말했습니다. 오후 세 시가 되자 에이전트가 npm test 를 돌립니다. 둘은 이름이 비슷한 다른 패키지 관리 도구(남이 만든 코드 묶음을 설치하는 프로그램)라 프로젝트가 정한 쪽을 써야 합니다. Claude Code 공식 문서에도 대화가 길어지면 앞에서 한 지시를 놓칠 수 있다고 적혀 있습니다.

에이전트가 한 번에 받아 읽는 글 전체를 컨텍스트 창(context window)이라고 합니다. 책상과 비슷합니다. 책상 넓이는 모델(글을 읽고 답을 만드는 AI 본체)이 글을 읽는 조각인 토큰(token)으로 재고 토큰 하나는 단어보다 조금 작습니다. 아래 띠가 하루 동안 이 책상에 쌓이는 것입니다. ▶ 로 다시 쌓아 보고 다 쌓이면 세 방법으로 치워 보세요.

모델은 답할 때마다 책상 위 전부를 다시 읽습니다

에이전트가 파일 하나를 읽으면 터미널(명령을 글자로 치고 결과를 글자로 받는 창)에는 Read auth.ts 한 줄만 뜹니다. 모델 쪽에는 그 파일 내용 2,400 토큰이 통째로 들어갑니다.

책상에 올라가는 것은 다섯 가지입니다. 에이전트를 만든 회사가 넣는 기본 지시인 시스템 프롬프트(system prompt), 쓸 수 있는 도구의 설명, CLAUDE.md 같은 안내 파일, 사람과 주고받은 대화, 그리고 파일 내용·명령 출력 같은 도구 결과(tool result)입니다. 대부분은 화면에 거의 보이지 않습니다.

책상과 다른 점도 있습니다. 사람은 필요한 자료만 집어 봅니다. 모델은 답을 한 번 만들 때마다 책상 위 전부를 처음부터 입력으로 받습니다. 그래서 쌓인 양이 곧 매 턴의 계산량과 비용이 됩니다. 턴은 사람이 한 번 말하고 에이전트가 한 번 답하는 한 차례입니다.

이미 계산한 앞부분을 저장해 두고 다시 쓰는 캐시(cache)는 Prefill·Decode·KV Cache 글에 따로 정리했습니다.

많이 쌓을수록 흐려지는 컨텍스트 부패

한도까지 자리가 남아 있어도 쌓인 양만큼 성능은 떨어집니다. 이 현상을 컨텍스트 부패(context rot)라고 부릅니다. 오래 둔 음식이 상하듯 쌓인 글이 답을 흐린다는 뜻입니다.

Anthropic 은 원인을 이렇게 설명합니다. 모델 안에서는 모든 토큰이 다른 모든 토큰과 관계를 계산합니다. 이 계산을 주의(attention)라고 합니다. 토큰이 n 개면 관계는 n² 개입니다. 자기 자신과의 관계까지 넣고 A→B 와 B→A 를 따로 세서 n × n 입니다. 점을 늘려 보면 관계가 얼마나 빨리 늘어나는지 보입니다.

Anthropic 은 주의를 정해진 예산에 비유합니다. 토큰이 늘수록 예산이 얇게 퍼져서 정말 봐야 할 토큰에 가는 몫이 줄어듭니다. 그림에서 점점 가늘어지는 선이 그 몫입니다.

창이 100만 토큰이면 괜찮지 않나요?

최근 Claude 모델은 100만 토큰 창을 기본으로 쓰고 Claude Code 는 약 96만 7천 토큰에서 자동으로 정리를 시작합니다. 그래도 흐려지는 문제는 사라지지 않습니다. 모델이 배운 글도 대부분 짧아서 멀리 떨어진 토큰끼리 잇는 연습이 부족하다고 Anthropic 은 설명합니다.

가운데 둔 정보를 가장 자주 놓칩니다

같은 내용이라도 책상 어디에 놓였는지에 따라 결과가 달라집니다. Stanford 등의 연구진이 2023년 발표한 Lost in the Middle 실험은 문서 20장 가운데 한 장에만 답을 넣고 그 정답 문서의 위치만 바꿔 가며 질문했습니다. 아래 값은 OpenAI 의 모델 GPT-3.5-Turbo 결과입니다. 정답 문서를 직접 옮겨 보세요.

👆 정답 문서(파랑)를 어디에 둘지 골라 보세요. 막대를 눌러도 됩니다.

정답 문서를 10번째에 두면 정답률은 53.8% 입니다. 문서를 하나도 주지 않았을 때(56.1%)보다 낮습니다.

GPT-3.5-Turbo, 문서 20장 질의응답. 논문 부록 표 6의 측정값이고 다섯 자리만 쟀습니다 — Liu 외, Lost in the Middle, TACL 2024.

정답이 맨 앞에 있으면 75.8%, 맨 끝이면 63.2%, 가운데면 53.8% 였습니다. 시험 볼 때 오픈북을 펼쳐도 앞쪽 목차와 마지막 요약만 보고 가운데 페이지를 놓치는 것과 비슷합니다. 다만 사람은 다시 넘겨 보면 되지만 모델은 한 번 읽은 입력 안에서 답을 내야 합니다.

맨 위 하루 띠에서 아침 규칙은 책상 맨 앞쪽에 있었습니다. 이 실험대로라면 잘 보여야 할 자리입니다. 그런데도 잊힌 건 위치보다 쌓인 길이 탓으로, 앞에서 본 컨텍스트 부패입니다.

왜 U자가 될까요? 요즘 모델도 그럴까요?

연구진도 원인을 다 밝히지는 못했습니다. 점 잇기 그림에서 모든 점이 서로 이어져 있었듯 주의는 구조상 어느 자리의 토큰이든 똑같이 볼 수 있습니다. 그래서 연구진은 이 U자 모양이 뜻밖이라고 적었습니다. 사람이 목록의 처음과 끝을 잘 기억하는 현상과 닮았다고 덧붙였습니다.

이 실험은 2023년 모델로 했습니다. Chroma 의 2025년 실험에서는 바늘(찾을 문장)의 위치를 11곳으로 바꿔도 뚜렷한 차이가 나지 않았고 대신 입력 길이와 헷갈리는 비슷한 문장(distractor) 수가 성능을 끌어내렸습니다. 위치 효과는 모델마다 다르지만 길게 쌓을수록 흐려진다는 결과는 두 연구가 같습니다.

프롬프트 엔지니어링에서 컨텍스트 엔지니어링으로

지시문 한 편을 잘 쓰는 일을 프롬프트 엔지니어링(prompt engineering)이라고 합니다. 에이전트는 한 번 묻고 끝나지 않고 도구를 수십 번 부르며 책상을 계속 채웁니다. 그래서 Anthropic 은 2025년 9월 매 턴 책상에 무엇을 올릴지 고르고 관리하는 일을 컨텍스트 엔지니어링(context engineering)이라고 따로 불렀습니다.

목표는 한 문장입니다. 원하는 결과가 나올 가능성을 가장 높이는, 가장 작은 토큰 묶음을 찾는 것입니다. 꼭 필요한 정보만 담긴 토큰을 Anthropic 은 고신호(high-signal) 토큰이라고 부릅니다. 수학여행 가방을 쌀 때 가방 크기보다 무엇을 넣을지가 중요한 것과 비슷합니다. 가방은 한 번 싸면 끝이지만 컨텍스트는 도구를 부를 때마다 다시 골라야 한다는 점이 다릅니다.

CLAUDE.md 에는 지우면 실수할 줄만

CLAUDE.md 는 Claude Code 가 세션을 시작할 때마다 읽는 프로젝트 안내 파일입니다. 매번 책상 맨 처음에 깔리니 뭐든 적어 두고 싶어집니다. 공식 문서의 기준은 반대입니다. 줄마다 "이 줄을 지우면 Claude 가 실수할까?"를 묻고, 아니면 지우라고 합니다. 파일이 부풀면 정작 중요한 규칙이 묻혀서 무시되기 때문입니다.

문서는 CLAUDE.md 를 200줄 아래로 유지하라고 권하고 지시는 확인할 수 있을 만큼 구체적으로 쓰라고 합니다. "코드를 깔끔하게"보다 "들여쓰기는 공백 두 칸"이 낫다는 식입니다. 서로 어긋나는 두 지시가 있으면 Claude 가 아무거나 하나를 고를 수 있다는 경고도 있습니다.

절대 어기면 안 되는 규칙은 훅(hook)으로 옮깁니다. 훅은 정해진 순간에 스크립트를 자동으로 실행하는 장치라서 모델의 판단과 상관없이 매번 돌아갑니다. 한 줄이 계속 무시될 때는 그 줄에만 "IMPORTANT" 같은 강조를 붙입니다.

AGENTS.md, 여러 에이전트가 같이 읽는 안내서

CLAUDE.md 는 Claude Code 의 파일이고 다른 코딩 에이전트도 같은 역할의 파일을 읽습니다. AGENTS.md 는 그 파일 이름을 하나로 맞춘 공개 형식입니다. 공식 사이트는 "에이전트를 위한 README"라고 소개합니다. README 는 저장소(코드를 모아 둔 곳)에 맨 먼저 두는 안내 문서입니다.

폴더마다 AGENTS.md 를 둘 수도 있습니다. 지시가 서로 어긋나면 고치는 파일에서 가장 가까운 AGENTS.md 가 이기고 사람이 채팅으로 준 지시는 모든 파일보다 우선합니다. Codex 는 루트부터 안쪽까지 파일을 이어 붙여 함께 읽어서 겹치지 않는 바깥 규칙도 그대로 지킵니다.

Claude Code 는 v2.1.277 부터 CLAUDE.md 가 없는 저장소에서 AGENTS.md 를 읽습니다. 둘 다 있으면 CLAUDE.md 만 읽으므로, 한 파일을 같이 쓰려면 CLAUDE.md 첫 줄에 @AGENTS.md 를 적어 불러옵니다.

컨텍스트 파일이 정말 도움이 되는지 잰 연구

2026년 초 두 연구가 같은 질문을 실험했습니다. Gloaguen 외 연구진(ETH Zurich·LogicStar.ai)은 Claude Code·Codex·Qwen Code 에게 컨텍스트 파일(AGENTS.md·CLAUDE.md)이 있을 때와 없을 때 Python 저장소 과제를 맡겼습니다.

과제는 SWE-bench Lite(실제 GitHub 이슈를 고치는 과제 모음) 300개와 직접 만든 138개입니다. 성공률은 거의 그대로였습니다. 비용은 AI가 만든 파일이 평균 20% 넘게, 개발자가 쓴 파일도 최대 19% 늘렸습니다.

에이전트는 파일 속 지시를 잘 따랐습니다. Python 패키지 도구 uv 를 쓰라고 적으면 과제당 1.6번 썼고 안 적으면 거의 쓰지 않았습니다. 그런데 거의 모든 파일에 들어 있던 저장소 개요는 관련 파일을 더 빨리 찾게 해 주지 못했습니다. 따르기는 하는데 도움이 안 되는 내용이 비용만 늘린 셈입니다.

Lulla 외 연구는 다른 쪽을 쟀습니다. 저장소 10개의 실제 PR(Pull Request, 코드 변경 제안) 124건을 AGENTS.md 가 있을 때와 없을 때 돌렸습니다. 완료는 비슷했고 실행 시간과 출력 토큰이 줄었습니다.

두 결과를 겹쳐 보면 같은 결론이 나옵니다. 코드에서 알 수 없는 명령과 이 팀만의 규칙은 일을 줄여 주고 코드를 읽으면 알 수 있는 설명은 책상만 채웁니다. Gloaguen 외 연구진도 사람이 쓴 파일에는 표준과 다른 관행만 적으라고 권했습니다.

압축하면 대화는 요약되고 CLAUDE.md 는 다시 읽힙니다

책상이 한도에 가까워지면 Claude Code 는 압축(compaction)을 합니다. 먼저 오래된 도구 출력을 비우고 그래도 모자라면 대화 전체를 구조화된 요약 하나로 바꿉니다. 직접 /compact 를 쳐서 할 수도 있습니다.

무엇이 살아남는지는 들어온 길에 따라 다릅니다. 시스템 프롬프트는 그대로이고 CLAUDE.md 와 자동 메모리는 디스크(파일을 저장해 두는 컴퓨터 저장 장치)에서 다시 읽습니다. 자동 메모리는 Claude 가 지난 세션에서 알게 된 빌드 명령 같은 것을 스스로 적어 두는 노트 파일입니다.

최근에 고친 파일은 다섯 개까지 다시 읽고 대화로 오간 나머지는 요약 속 몇 줄이 됩니다. 문서는 이때 초반 대화의 자세한 지시가 사라질 수 있다고 적었습니다. 그래서 오래 지켜야 할 규칙은 대화가 아니라 CLAUDE.md 에 둡니다.

요약에 꼭 남길 것은 /compact focus on the API changes 처럼 직접 지정하거나 CLAUDE.md 에 압축 때 지킬 지시를 적어 둘 수 있습니다.

새 세션과 서브에이전트로 책상을 따로 쓰기

파일을 수십 개 읽어야 하는 조사는 서브에이전트(subagent)에게 맡깁니다. 자기 책상을 따로 쓰는 보조 에이전트로, 도서관에서 자료를 찾고 요약 메모만 들고 오는 친구와 비슷합니다.

다만 요약에서 빠진 내용은 메인 에이전트가 모릅니다. 서브에이전트도 CLAUDE.md 를 자기 책상에 다시 깔기 때문에 토큰은 사라지지 않고 다른 책상으로 옮겨 갈 뿐입니다. Anthropic 은 서브에이전트가 수만 토큰을 쓰며 탐색하고 1,000~2,000 토큰으로 줄인 요약을 돌려주는 경우가 많다고 적었습니다.

관계없는 일로 넘어갈 때는 /clear 로 새 세션을 엽니다. 깨끗한 세션에 더 나은 요청을 주는 쪽이 고친 기록이 쌓인 긴 세션보다 거의 항상 낫다고 문서는 말합니다. 비우기 전에는 노트 파일에 진행 상황을 적어 둡니다.

에이전트가 NOTES.md 나 할 일 목록에 진행 상황을 적어 두면 책상을 비운 뒤에도 그 파일을 다시 읽고 이어 갈 수 있습니다. 같은 문제를 두 번 넘게 고쳐 달라고 해도 안 되면 책상이 실패한 시도로 가득 찬 것이니 비우고 배운 점을 담아 다시 요청하라고 문서는 권합니다.

포켓몬 게임을 하던 Claude 의 노트

Anthropic 은 Claude 에게 포켓몬 게임을 시키며 노트를 쓰게 했습니다. Claude 는 수천 단계 동안 "피카츄가 목표 10레벨 가운데 8레벨을 올렸다" 같은 진행 상황과 지도, 업적을 적어 두었습니다. 책상이 비워진 뒤에도 노트를 읽고 몇 시간짜리 작업을 이어 갔다고 합니다.

모델이 좋아지면 적어 둘 것도 줄어듭니다

Anthropic 은 2026년 7월 24일 Claude 5 세대 모델(Claude Opus 5·Fable 5 등)에서 Claude Code 시스템 프롬프트를 80% 넘게 지웠는데 코딩 평가에서 잴 수 있는 손실이 없었다고 밝혔습니다. 예전 모델의 최악을 막으려고 적어 둔 규칙을 새 모델은 없이도 잘 판단한다는 설명입니다.

할 일 목록 도구인 TodoWrite 가 대표 예입니다. 언제 쓰는지 목록과 예시로 9,100자를 채웠던 설명을 한 줄 설명과 상태 세 가지(pending·in_progress·completed)로 바꿨습니다.

같은 글은 이런 방향을 함께 정리했습니다.

  • 규칙을 늘어놓는 대신 판단을 맡긴다.
  • 다 앞에 두지 않고 필요할 때 불러온다.
  • CLAUDE.md 는 저장소가 무엇인지 짧게 쓰고 토큰 대부분은 코드 속 함정에 쓴다.

책상을 치우는 일은 결국 이 질문으로 돌아옵니다. 지금 이 토큰이 다음 답을 낫게 하는가.

다음 글에서는 에이전트가 회사 이슈 트래커나 데이터베이스를 읽게 해 주는 MCP(Model Context Protocol)를 알아보겠습니다.
