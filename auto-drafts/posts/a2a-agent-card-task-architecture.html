A2A로 다른 Agent에게
일을 맡길 때 무엇이 오갈까요?

A2A(Agent2Agent)는 Agent가 다른 Agent에게 일을 맡기는 규격입니다. 맡기기 전에 상대가 내건 Agent Card를 읽고 일은 Task로 넘깁니다. 상대가 그 일을 어떤 모델과 도구로 하는지는 들여다보지 않습니다.

같은 요청을 실제 구성 요소 이름으로 다시 그리면 아래 흐름도가 됩니다. 담당자는 A2A Client인 출장 준비 Agent이고 두 업체는 A2A Server입니다. 명함은 Agent Card, 방문증은 액세스 토큰, 의뢰서는 Task, 납품물은 Artifact입니다.

A2A와 MCP가 붙는 곳

흐름도에는 규격이 두 개 나옵니다. MCP(Model Context Protocol)는 Agent가 도구와 데이터에 붙는 길이고 A2A는 Agent가 다른 Agent에게 일을 맡기는 길입니다. 한 Agent가 둘을 함께 씁니다. MCP의 Host·Client·Server 구조는 이 시리즈 6편에서 따로 그렸습니다.

MCP · Agent가 도구에 붙는 길

  • 붙는 상대도구와 데이터를 내놓는 MCP 서버. 정해진 입력을 받아 정해진 결과를 돌려준다
  • 정하는 쪽언제 어떤 도구를 부를지는 Agent의 모델이 정한다. 도구는 스스로 계획을 세우지 않는다
  • 이 예시에서출장 준비 Agent는 사내 캘린더를, 항공권 Agent는 항공사 예약 시스템을 MCP로 붙인다. 서로의 MCP 서버는 모른다

A2A · 다른 Agent에게 맡기는 길

  • 맡기는 상대자기 모델과 도구로 스스로 일하는 Agent. 다른 팀이나 다른 회사가 다른 프레임워크로 만들었을 수 있다
  • 보는 것상대가 내건 Agent Card와 주고받는 메시지뿐이다. 상대의 프롬프트, 계획, 도구 구현은 공유하지 않는다(opaque)
  • 주고받는 단위한 번에 끝나는 호출 대신 상태를 가진 Task. 몇 시간 걸리는 일도, 중간에 사람에게 되묻는 일도 담는다

Google이 2025년 4월에 발표한 A2A는 2025년 6월 Linux Foundation에 기증됐고 2026년 8월에는 MCP가 있는 Agentic AI Foundation(AAIF)으로 옮겼습니다. 2026년 4월 Linux Foundation 발표 기준으로 150곳 넘는 조직이 지원합니다. Microsoft는 Azure AI Foundry와 Copilot Studio에, AWS는 Amazon Bedrock AgentCore Runtime에 A2A를 넣었습니다.

Task가 지나는 상태와 주고받는 것

A2A에서 일의 단위는 Task입니다. 아래 이름은 2026년 3월에 나온 v1.0 명세 기준입니다. v1.0에서 message/send가 SendMessage로 바뀌는 등 0.3 버전과 달라진 이름이 많아서 예제 코드를 볼 때는 버전부터 확인합니다.

Task 상태

  • submitted접수됨. 서버가 Task를 만들고 taskId를 돌려준다
  • working상대 Agent가 자기 모델과 도구로 일하는 중이다
  • input-required · auth-required멈추고 기다린다. 클라이언트가 같은 taskId로 답이나 인증을 보내면 이어서 일한다
  • completed · failed · canceled · rejected끝난 상태다. 이어서 할 일이 있으면 같은 contextId로 새 Task를 만든다

v1.0 JSON에서는 TASK_STATE_INPUT_REQUIRED처럼 대문자 이름으로 적습니다.

주고받는 것

  • Message한 번 주고받는 말. role이 user(맡기는 쪽)나 agent(맡은 쪽)이고 Part 여러 개를 담는다
  • Part내용 한 조각. 글(text), 파일(raw · url), 구조화된 데이터(data) 가운데 하나다
  • ArtifactTask가 만든 결과물. 전자 항공권 PDF나 예약 내역 JSON처럼 Part로 이루어진다
  • 전송 방식같은 동작을 JSON-RPC 2.0, gRPC, HTTP+JSON(REST)으로 쓸 수 있다. Agent Card의 supportedInterfaces에 방식과 주소를 적는다

운영에서 먼저 정할 것이 세 가지 있습니다. 오래 걸리는 Task는 연결을 열어 두는 스트리밍 대신 푸시 알림(웹훅 POST)으로 받을 수 있습니다. v1.0부터 Agent Card에 서명(JWS)을 붙여 위조를 막을 수 있습니다. 인증한 클라이언트에게만 더 자세한 카드(extended Agent Card)를 보여 줄 수도 있습니다.
