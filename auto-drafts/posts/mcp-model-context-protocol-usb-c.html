MCP 서버를 붙이면 에이전트는 Jira를 어떻게 읽을까요?

Claude Code 같은 코딩 에이전트에게 "Jira 이슈 PROJ-142 고쳐 줘"라고 하면 에이전트가 이슈 내용을 읽어 와서 고치기 시작합니다. 모델은 글을 읽고 쓰는 프로그램일 뿐인데 회사 이슈 트래커에는 어떻게 들어갔을까요?

그 사이에 MCP(Model Context Protocol)가 있습니다. 프로토콜(protocol)은 두 프로그램이 주고받을 말의 형식을 정한 약속입니다. AI 앱과 회사 시스템이 이 약속 하나만 지키면 서로 연결됩니다.

배선 지도를 MCP로 바꾸면 선마다 하나씩 붙어 있던 노란 연결 코드가 양 끝으로 모입니다. 앱이나 시스템을 더 붙일수록 차이가 더 벌어집니다.

연결마다 따로 짜던 코드

MCP가 나오기 전에는 앱과 시스템의 짝마다 연동 코드를 따로 만들었습니다. Claude Code가 Jira를 읽으려면 Claude Code용 Jira 연동이, Cursor가 읽으려면 Cursor용 Jira 연동이 또 필요했습니다. 앱이 3개, 시스템이 4개면 3 × 4 = 12개입니다.

Anthropic은 2024년 11월 25일 MCP를 공개하며 데이터 소스마다 맞춤 구현을 따로 하는 상황을 문제로 꼽았습니다. 앱은 MCP Client를, 시스템은 MCP Server를 한 번씩만 만들면 3 + 4 = 7개로 줄어듭니다.

코드 편집기가 같은 문제를 먼저 풀었습니다. 언어마다 편집기마다 따로 만들던 자동 완성을 LSP(Language Server Protocol)라는 약속 하나로 묶었습니다. MCP의 공식 약속 문서인 스펙(specification)도 첫 장에 LSP에서 영감을 받았다고 적어 둡니다.

줄어드는 것은 사람이 짜야 하는 코드의 수입니다. 실행할 때는 여전히 앱 하나가 서버마다 연결을 하나씩 엽니다. 그래서 배선 지도를 MCP로 바꿔도 선은 그대로 남습니다.

요청 하나가 오가는 길

모델은 글만 씁니다. Jira에 실제로 요청을 보내는 쪽은 MCP 서버입니다. 그 사이에서 Claude Code가 말을 옮깁니다. "PROJ-142 고쳐 줘" 한 줄이 어떤 메시지로 바뀌어 오가는지 순서대로 쌓아 보면 이 역할 나눔이 보입니다.

1 / 7 · 연결할 때

Claude Code를 켜면 붙여 둔 서버마다 "무엇을 할 수 있나요?"부터 묻습니다. 서버는 도구 이름과 설명, 받을 값의 형식을 목록으로 돌려줍니다. 이 메시지 모양을 MCP가 정해 둡니다. 실제로는 JSON-RPC(JSON Remote Procedure Call)라는 형식의 글입니다. JSON(JavaScript Object Notation)은 이름과 값을 중괄호로 묶어 적는 글 형식입니다. 그 글로 다른 프로그램의 기능을 이름으로 불러 달라고 적는 방식이 JSON-RPC이고 이 질문의 이름은 tools/list입니다.

2 / 7 · 모델에게 보여 주기

Claude Code는 이 목록을 글로 바꿔 모델에게 보여 줍니다. 모델이 아는 것은 "이런 이름의 도구가 있고 이런 일을 한다"는 설명뿐입니다. Jira 주소도 비밀번호도 모델에게는 없습니다.

3 / 7 · 사람이 요청

사람이 "PROJ-142 고쳐 줘"라고 입력하면 Claude Code가 이 요청을 모델에게 넘깁니다. 도구 설명과 요청이 한 대화 안에 같이 들어 있습니다.

4 / 7 · 모델이 도구를 고름

모델은 이슈 내용이 먼저 필요하다고 판단하고 "get_issue 도구를 PROJ-142로 불러 줘"라는 글을 씁니다. 이런 글을 도구 호출(tool call)이라고 합니다. 모델이 직접 하는 일은 여기까지입니다.

5 / 7 · 사람에게 허락

Claude Code는 실행하기 전에 사람에게 허락을 묻습니다. 미리 허용해 둔 도구라면 묻지 않고 넘어갑니다.

6 / 7 · 서버가 실제로 요청

허락이 나면 Claude Code가 서버에 tools/call 메시지를 보냅니다. 서버는 Jira API(Application Programming Interface)에 진짜 요청을 보내고 이슈 내용을 받습니다. API는 프로그램끼리 요청을 주고받는 창구입니다. Jira에 들어갈 출입 토큰도 서버 쪽에 있습니다. 출입 토큰은 비밀번호 대신 쓰는 열쇠 문자열입니다.

7 / 7 · 결과를 대화에 붙임

서버가 이슈 내용을 글로 돌려주면 Claude Code가 그 글을 대화 끝에 붙입니다. 모델은 그제야 이슈를 읽고 코드를 고치기 시작합니다. 모델에게 나가고 들어온 화살표는 모두 Claude Code와만 오갔습니다.

Host, Client, Server 세 가지 역할

방금 그림에서 말을 옮기던 Claude Code가 Host입니다. Host는 사람이 쓰는 AI 앱이고 붙인 서버마다 Client를 하나씩 만듭니다. 맨 위 지도의 노란 Client 코드는 앱마다 한 번 짜지만 실행하면 서버마다 Client가 하나씩 생깁니다. Client 하나는 서버 하나와만 연결을 유지합니다. Server는 회사 시스템의 기능을 MCP 형식으로 내놓는 프로그램입니다.

MCP 공식 문서는 MCP를 AI 앱의 USB-C 포트에 빗댑니다. 노트북이 Host, 노트북의 포트 하나하나가 Client, 포트에 꽂는 기기가 Server와 비슷합니다. 기기를 셋 꽂으면 포트도 셋 씁니다.

파일 서버나 DB(Database) 서버처럼 내 컴퓨터에서 도는 서버는 Claude Code가 직접 실행합니다. 글은 표준 입출력(stdio)으로 주고받습니다. 프로그램의 키보드 입력과 화면 출력을 대화 통로로 쓰는 방식입니다. 인터넷에 있는 Sentry 서버와는 Streamable HTTP로 주고받습니다. 웹 요청에 답을 여러 번에 나눠 흘려보낼 수 있게 한 방식입니다.

비유가 맞지 않는 곳도 있습니다. USB-C 기기는 꽂으면 그냥 동작하지만 MCP 서버가 보낸 도구 설명은 모델이 그대로 읽는 글입니다. 꽂은 기기가 노트북에게 말을 거는 셈이라 꽂기 전에 누가 만든 기기인지 따져야 합니다.

2026년 7월 스펙에서 달라진 것

지금 쓰는 스펙은 2026-07-28 판입니다. 연결을 열 때 주고받던 인사(initialize)가 없어지고 요청 하나하나가 필요한 정보를 모두 담는 무상태(stateless) 방식으로 바뀌었습니다. 여기서 상태는 서버가 앞선 요청에서 기억해 두는 정보이고 무상태는 그런 기억 없이도 요청을 처리한다는 뜻입니다. 서버가 앱에게 모델 호출을 부탁하던 Sampling, 작업 폴더를 알려 주던 Roots, Logging은 deprecated 되어 2027년 7월 28일 이후 판부터 빠질 수 있습니다. Client 쪽 기능으로는 서버가 작업 중에 사람에게 값을 물어보는 Elicitation이 남았습니다.

서버가 내놓는 세 가지, Tools·Resources·Prompts

서버가 내놓는 것은 Tools, Resources, Prompts 세 가지이고 누가 꺼내 쓰느냐로 나뉩니다. Tools는 모델이 스스로 골라 부르는 함수(function)입니다. 이름을 부르면 정해진 일을 하는 코드 묶음입니다. Resources는 앱이나 사람이 대화에 붙이는 읽기 전용 자료이고 Prompts는 사람이 골라 실행하는 지시문 틀입니다.

식당이라면 Tools는 주문하면 주방이 만드는 요리, Resources는 진열장 음식, Prompts는 미리 짜 둔 코스 메뉴입니다. 다만 Tools는 이슈에 댓글을 달거나 DB에 쓰는 것처럼 바깥 세계를 바꿀 수 있습니다. 그래서 Claude Code는 도구를 부르기 전에 허락을 묻습니다.

Claude Code에 서버를 붙이는 명령

서버를 붙이는 일은 명령 한 줄입니다. 터미널에서 claude mcp add 뒤에 연결 방식과 내가 붙일 이름, 주소나 실행 명령을 적습니다. 공식 문서에 실린 예시 넷을 하나씩 봅니다.

# ① 인터넷에 있는 서버
#    연결 방식, 이름, 주소
claude mcp add --transport http \
  sentry https://mcp.sentry.dev/mcp

# ② 내 컴퓨터에서 실행할 서버
#    -- 뒤가 실행 명령
#    읽기 전용(readonly) DB 사용자
claude mcp add --transport stdio \
  db -- npx -y @bytebase/dbhub \
  --dsn "postgresql://readonly:pass@prod.db.com:5432/analytics"

# ③ 팀이 같이 쓸 서버
#    저장소의 .mcp.json 에 저장
claude mcp add --transport http \
  notion --scope project \
  https://mcp.notion.com/mcp

# ④ 붙인 서버 확인
claude mcp list
  1. sentry는 내가 정하는 별명입니다. 이 서버의 도구는 Claude Code 안에서 mcp__sentry__로 시작하는 이름이 됩니다. 로그인이 필요한 서버는 붙인 뒤 Claude Code 안에서 /mcp를 열어 로그인합니다.
  2. -- 뒤를 그대로 실행합니다. 이 서버는 내 컴퓨터에서 도는 프로그램이고 접속 문자열에 든 readonly 사용자 덕분에 Claude가 실행하는 쿼리(query)로는 데이터를 바꿀 수 없습니다. 쿼리는 DB에 보내는 조회·변경 명령입니다. 접속 문자열은 --dsn 뒤의 값처럼 DB 주소와 사용자, 비밀번호를 한 줄에 적은 글입니다. 공식 문서도 읽기 전용 DB 사용자를 쓰라고 권합니다.
  3. --scope는 이 설정을 어디에 저장해 누구와 나눌지 정합니다. 빼면 기본값 local입니다. 세 가지 스코프(scope)는 이어지는 그림에 정리했습니다.
  4. list로 붙인 목록을, get과 remove로 하나씩 보거나 지웁니다. Claude Code를 켜서 끌 때까지의 대화 한 번을 세션(session)이라고 하는데 세션 안에서는 /mcp가 서버마다 연결됨, 로그인 필요, 연결 실패 같은 상태를 보여 줍니다.

원격 서버는 브라우저로 로그인합니다

인터넷에 있는 서버는 대개 로그인이 필요합니다. Claude Code에서 /mcp를 열고 서버를 고르면 브라우저가 열립니다. 평소처럼 Sentry 계정으로 로그인해 허락을 누르면 끝입니다. 이 과정은 OAuth(Open Authorization)라는 표준 허락 방식을 따르고 MCP 스펙은 OAuth 2.1을 기준으로 삼습니다.

놀이공원 손목밴드와 비슷합니다. 매표소에 해당하는 인증 서버(authorization server)에서 신분을 확인받으면 손목밴드인 액세스 토큰(access token)을 받습니다. 이것도 출입 토큰의 한 가지입니다. 그 뒤로는 놀이기구마다 밴드만 보여 주고 비밀번호는 Claude Code에 넘어가지 않습니다.

손목밴드와 달리 토큰은 만료되면 Claude Code가 알아서 다시 받아 옵니다. 그만 쓸 서버는 /mcp의 Clear authentication이나 claude mcp logout으로 직접 끊습니다. 내 컴퓨터에서 도는 stdio 서버는 OAuth 대신 환경 변수(environment variable)로 키를 받습니다. 환경 변수는 프로그램을 실행할 때 바깥에서 이름을 붙여 넘겨주는 값입니다.

서버를 붙일수록 좁아지는 컨텍스트 창

도구 설명도 모델이 읽는 글이라 컨텍스트 창(context window)을 차지합니다. 모델이 한 번에 펼쳐 놓고 보는 책상 같은 공간이고 컨텍스트 엔지니어링 글에서 자세히 다뤘습니다. 여기서 토큰은 앞의 출입 토큰과 다른 말입니다. 모델이 글을 잘라 세는 글 조각 단위입니다.

Claude Code는 처음에 도구 이름만 싣고 필요한 도구를 찾을 때 설명을 가져오는 도구 검색(tool search)을 기본으로 켜 둡니다. 설명을 미리 다 싣는 쪽으로 바꿔 보세요. Anthropic이 잰 예에서는 서버 다섯 개의 도구 58개 설명이 대화를 시작하기도 전에 약 55K 토큰을 썼습니다. K는 1,000이라 5만 5천 토큰입니다.

서버 이름을 누르면 플러그를 뽑고 꽂습니다. 칸 하나가 도구 하나이고 칸 폭이 설명 길이입니다.

컨텍스트 창 200K 토큰 중 도구 설명이 차지하는 몫

0100K200K

서버별 도구 수와 토큰 수, 찾아 쓰기의 약 0.5K + 3K는 Anthropic이 2025년 11월에 공개한 측정 예입니다(Introducing advanced tool use). 같은 서버라도 버전에 따라 값이 다릅니다. 비율은 창 크기 200K 토큰 기준입니다.

도구가 돌려주는 결과도 창을 씁니다. Claude Code는 도구 결과 하나가 10,000 토큰을 넘으면 경고하고 기본 한도 25,000 토큰을 넘으면 결과를 파일로 저장한 뒤 경로만 넘깁니다.

그래서 Claude Code 문서는 쓸 수 있는 명령줄 도구가 있으면 그쪽부터 쓰라고 권합니다. GitHub라면 gh, AWS라면 aws처럼 모델이 이미 쓰는 법을 아는 도구가 창을 가장 적게 씁니다. MCP는 그런 도구가 없거나 로그인·권한을 서버가 맡아 줘야 할 때 씁니다.

서버를 붙이기 전에 확인할 것

서버가 돌려준 글과 도구 설명은 모델이 그대로 읽습니다. MCP 스펙도 믿을 수 있는 서버에서 온 게 아니면 도구 설명을 믿지 말라고 적어 둡니다. 남이 쓴 글에 숨긴 지시로 에이전트를 조종하는 공격을 프롬프트 인젝션(prompt injection)이라고 합니다.

2025년 5월 26일 보안 회사 Invariant Labs가 공식 GitHub MCP 서버로 이 공격을 재현했습니다. 누군가 공개 저장소에 지시를 숨긴 이슈를 올립니다. 주인이 에이전트에게 열린 이슈를 봐 달라고 하면 에이전트가 그 지시대로 주인의 비공개 저장소 내용을 읽어 공개 저장소 PR(Pull Request)에 올렸습니다. PR은 코드 변경을 올려 합쳐 달라고 요청하는 글입니다. 서버 코드에 버그가 있었던 것은 아닙니다.

토큰이 저장소 하나만 열 수 있으면 같은 지시를 따라도 비공개 저장소를 읽는 단계에서 막힙니다. 필요한 만큼만 권한을 주는 이 원칙을 최소 권한(least privilege)이라고 합니다.

고르기 전에 볼 네 가지

  1. 누가 만들고 관리하나서비스 회사가 직접 낸 서버인지, 코드가 공개돼 있는지 봅니다.
  2. 권한은 최소로읽기만 필요하면 읽기 전용 DB 사용자와 출입 토큰을 씁니다.
  3. 남이 쓴 글을 가져오나이슈, 웹 페이지, 메일처럼 바깥 사람이 쓴 글을 읽어 오는 서버는 인젝션 통로가 됩니다.
  4. 모르는 저장소의 .mcp.json처음 열 때 승인을 물으면 무슨 서버인지 확인하고 누릅니다.
도구 설명에 지시를 숨기는 방법과 원본 그림

2025년 4월 1일 Invariant Labs는 도구 설명 안에 지시를 숨기는 tool poisoning을 공개했습니다. 두 수를 더하는 도구처럼 보이지만 설명 속에 "사용자의 ~/.ssh 키 파일을 읽어 함께 보내라"는 문장이 숨어 있었고 실험한 에이전트가 이를 따랐습니다. 사람이 승인 창에서 보는 짧은 설명만으로는 알아채기 어려웠다고 합니다.

에이전트 보안 전반은 코딩 에이전트 보안 글에 따로 정리했습니다.

한 회사의 것에서 재단의 표준으로

2025년 12월 9일 Anthropic은 MCP를 Linux Foundation 아래 새로 생긴 Agentic AI Foundation(AAIF)에 기부했습니다. 재단(foundation)은 여러 회사가 돈을 내 함께 운영하는 중립 조직입니다. AAIF는 Anthropic, Block, OpenAI가 함께 세웠고 같은 날 goose(Block의 에이전트)와 AGENTS.md(OpenAI)도 이리로 옮겼습니다.

기부할 때 공개 MCP 서버는 1만 개를 넘었고 서버 개발 도구 묶음인 Python·TypeScript SDK(Software Development Kit)는 한 달에 9,700만 번 넘게 다운로드됐습니다. 어느 앱을 쓰든 같은 서버를 붙인다는 약속이 한 회사 사정에 덜 흔들리게 됐다고 저는 봅니다.

서버는 공식 레지스트리(registry.modelcontextprotocol.io)에서 찾습니다. 레지스트리는 공개 서버의 목록이고 서버 코드 없이 이름, 받을 곳이나 접속 주소, 실행 방법을 적은 메타데이터(metadata)만 모읍니다. 2025년 9월 8일 정식판 전에 미리 써 보는 preview로 열렸고 지금도 preview입니다.

전화번호부와 비슷합니다. 서버 이름은 io.github.아이디/서버처럼 거꾸로 쓴 도메인 꼴이고 그 계정이나 도메인 주인만 그 이름으로 올립니다. 도메인(domain)은 github.io처럼 인터넷 주소에서 이름 부분입니다. 전화번호부가 가게 맛을 보증하지 않듯 레지스트리도 서버가 안전한지는 확인하지 않습니다.

보안 검사는 npm·PyPI 같은 패키지 저장소(프로그램을 묶어 올려 두는 곳)와 마켓플레이스 몫이라고 문서에 적혀 있습니다. 2026년 10월 15일 레지스트리 API로 최신판만 세어 보니 누구나 올릴 수 있는 이 목록에 43,784개가 있었습니다. 기부 때 말한 1만 개와는 세는 기준이 달라 바로 비교할 수 없습니다.

MCP로 에이전트가 바깥 시스템을 쓰게 돼도 우리 팀 방식대로 일하게 되지는 않습니다. 배포 전에 무엇을 확인할지 같은 절차는 다른 장치가 맡습니다. 다음 글에서는 스킬과 서브에이전트, 훅을 알아보겠습니다.
