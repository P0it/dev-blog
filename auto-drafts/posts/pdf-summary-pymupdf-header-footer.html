AI Service Track · 03

논문 요약 AI가 쪽 번호부터 지우는 이유

논문 PDF를 ChatGPT나 Claude에 올리고 "요약해 줘"라고 하면 몇 초 뒤 요약이 나옵니다. 그 몇 초 사이에 AI가 받는 글은, PDF 뷰어에서 보는 반듯한 문단과 꽤 다르게 생겼습니다.

아래에 채팅 화면과, 같은 PDF에서 프로그램으로 글자를 꺼낸 결과를 나란히 놓았습니다. 요약에 학술지 이름과 쪽 번호가 끼어든 까닭이 꺼낸 글에 보입니다. 빨간 줄이 그어진 글자는 논문 내용과 상관없고 요약기를 만든다면 이것부터 걸러 내야 합니다.

01

PDF에는 문장 대신 글자를 찍을 자리가 적혀 있습니다

PDF를 열면 화면에는 반듯한 문단이 보입니다. 하지만 파일 안에 "여기부터 문단, 이건 쪽 번호" 같은 표시는 없습니다. 적혀 있는 것은 어느 좌표에 어떤 글자를 어떤 크기로 찍을지입니다.

좌표(coordinate)는 종이 위 위치를 가로·세로 두 숫자로 적은 것입니다. 그림처럼 학술지 이름도, 본문 첫 줄도, 맨 아래 쪽 번호도 똑같이 "이 자리에 이 글자"라는 명령 하나입니다.

도장 찍는 순서를 적은 쪽지와 비슷합니다. 쪽지만 봐서는 어느 도장이 제목이고 어느 도장이 쪽 번호인지 알 수 없습니다. 실제 PDF에는 글꼴·선·그림 명령도 섞여 있고 글자를 단어나 줄 단위로 묶어 두는 경우도 많습니다.

스캔한 PDF는 왜 글자가 안 나올까요?

종이를 스캐너로 찍은 PDF에는 글자 명령이 없고 쪽마다 사진 한 장만 들어 있습니다. 그래서 글자를 꺼내면 빈 문자열이 나옵니다. 이럴 때는 사진 속 글자 모양을 읽어 글자로 바꾸는 OCR(Optical Character Recognition)을 먼저 거쳐야 합니다. 마우스로 문장을 드래그해서 선택되지 않는 PDF라면 스캔본일 가능성이 큽니다.

02

그대로 꺼내면 쪽이 바뀔 때마다 잡음이 끼어듭니다

글자를 꺼내는 프로그램은 파일에 적힌 순서대로 글자를 이어 붙입니다. 그러면 1쪽 마지막 문장 다음에 1쪽 쪽 번호가 오고 이어서 2쪽 머리말이 오고 그다음에야 2쪽 본문이 옵니다.

머리말(header)은 쪽 위쪽에 반복해서 찍는 학술지 이름·논문 제목이고 꼬리말(footer)은 아래쪽의 쪽 번호 같은 글입니다. 책을 넘기는 사람에게는 길잡이지만 글을 이어 읽는 AI에게는 문장 사이에 끼어든 군말입니다.

꺼낸 글은 1쪽 → 2쪽 → 3쪽 순서로 한 줄에 이어 붙습니다.

  1. 학술지
  2. 제목
  3. 1쪽 본문
  4. 101
  1. 학술지
  2. 제목
  3. 2쪽 본문
  4. 102
  1. 학술지
  2. 제목
  3. 3쪽 본문
  4. 103
처음끝

빨간 칸이 잡음입니다. 세 쪽짜리 논문에 아홉 군데, 20쪽 논문이면 60군데가 끼어듭니다. 문장이 쪽을 넘어가면 "쓰게 / - 101 - / 농업기술연구… / 했다"처럼 한 문장이 잡음을 사이에 두고 갈라집니다.

import pymupdf

# ① PDF 파일 열기
doc = pymupdf.open("data/paper.pdf")

full_text = ""
for page in doc:
    # ② 쪽마다 글자를 꺼내 이어 붙인다
    full_text += page.get_text()

print(full_text)

03

2단 논문은 읽는 순서까지 섞일 수 있습니다

논문은 한 쪽을 왼쪽 단과 오른쪽 단으로 나눠 싣는 경우가 많습니다. 사람은 왼쪽 단을 끝까지 읽고 오른쪽 단으로 넘어갑니다. 프로그램은 그 사실을 모릅니다.

위에서 아래로 줄을 맞춰 정렬하라고 하면 왼쪽 단 한 줄, 오른쪽 단 한 줄을 번갈아 이어 붙입니다. 아래 두 그림은 같은 쪽을 두 가지로 읽은 경로와 실제로 나온 글입니다.

04

위아래를 똑같이 잘라 내면 학술지마다 결과가 다릅니다

가장 쉬운 방법은 쪽의 위아래 띠를 가리고 가운데만 꺼내는 것입니다. 책을 복사할 때 머리말 자리를 종이로 덮고 복사하는 것과 같습니다.

그런데 가리는 높이는 숫자 하나로 정해야 합니다. 아래 세 쪽은 모두 위아래 80포인트를 가렸습니다. 회색으로 덮인 띠가 가린 곳입니다.

PyMuPDF에서는 get_text(clip=…)에 꺼낼 사각형을 넘기면 이렇게 가립니다. 한 학술지의 논문만 다룬다면 이 방법으로도 충분합니다.

05

PyMuPDF 2.0은 덩어리마다 이름표를 붙여 머리말을 찾습니다

여러 학술지의 논문을 받는 요약기라면 높이 숫자 하나로는 요약에 학술지 이름이 계속 섞여 나옵니다. 높이를 사람이 정하는 대신, 쪽 모양을 보고 덩어리마다 무엇인지 맞히는 방법이 있습니다. 이것을 레이아웃 분석(layout analysis)이라고 합니다. 쪽 맨 위에 작게, 쪽마다 같은 자리에 찍힌 글이면 머리말일 가능성이 큽니다.

PyMuPDF 2.0은 이 일을 하는 분석 모델을 기본으로 품었습니다. 여기서 모델은 수많은 쪽을 보고 덩어리 종류를 맞히도록 학습한 프로그램입니다. 그림처럼 덩어리마다 page-header, text, page-footer 같은 이름표를 붙이고 우리는 이름표를 보고 뺄 것을 고릅니다. 모델이 쪽 모양을 보고 고르니, 학술지마다 높이를 맞출 필요가 없습니다.

사람이 신문을 훑어보고 "이건 광고 이건 기사"라고 가르는 것과 비슷합니다. 다만 모델은 모양만 보고 고르기 때문에 틀릴 때도 있습니다.

import pymupdf

doc = pymupdf.open("data/paper.pdf")

# ① 머리말·꼬리말을 빼고 마크다운으로
text = doc.to_markdown(header=False, footer=False)

print(text)

설치가 onnxruntime에서 멈춘다면

PyMuPDF 2.0은 레이아웃 분석 모델을 돌리려고 onnxruntime이라는 패키지를 함께 설치합니다. 막 나온 Python 판에는 이 패키지가 아직 없을 수 있습니다. 2026-10-30에 Python 3.15에서는 설치가 실패했고, 3.13으로 만든 가상 환경에서는 잘 깔렸습니다.

꺼낸 결과는 왜 눈으로 확인해야 할까요?

단 길이가 몇 줄뿐인 쪽에서는 모델이 두 단을 한 덩어리로 묶어서 "웹 서버가 기상청 날씨 자료를 3. 결과. 세 지역 밭에서 두 해 동안 매일 받아 와…"처럼 섞어 낸 적이 있습니다. 같은 쪽을 단마다 꽉 채우자 바르게 나왔습니다. 요약을 맡기기 전에 꺼낸 글을 한 번 훑어보면 이런 사고를 미리 잡을 수 있습니다.

06

요약을 시킬 때는 무엇을 뽑을지 칸으로 정해 줍니다

깨끗한 글을 얻었으면 이제 LLM(Large Language Model)에게 요약을 맡깁니다. LLM은 ChatGPT 같은 서비스 안에서 글을 읽고 쓰는 AI 모델입니다. "요약해 줘"만 보내면 부탁할 때마다 요약의 모양이 달라집니다. 어떤 때는 긴 문단 하나, 어떤 때는 목록이 나옵니다. 앞에서 못 걸러 낸 머리말을 논문 내용처럼 적기도 합니다.

그래서 실제 서비스는 무엇을 뽑을지를 미리 정합니다. 학교 독후감 양식에 "줄거리·인상 깊은 장면·느낀 점" 칸이 있는 것과 같습니다. 논문이라면 저자가 본 문제, 주장, 방법, 결과, 한계 다섯 칸이 흔히 쓰입니다.

막대 하나가 답의 한 줄입니다. 다섯 칸 양식의 진한 막대는 첫 번째 답, 점선 막대는 두 번째 답입니다. 칸이 정해져 있으면 프로그램이 칸마다 꺼내 화면에 늘어놓을 수 있습니다. 설명을 위해 그린 예시입니다.

import pymupdf
from openai import OpenAI
from pydantic import BaseModel

client = OpenAI()

# ① 요약에 꼭 들어갈 칸
class PaperSummary(BaseModel):
    problem: str        # 저자가 본 문제
    claim: str          # 저자의 주장
    method: str         # 어떻게 했나
    results: list[str]  # 주요 결과
    limits: str         # 남은 과제

def pdf_to_text(path: str) -> str:
    doc = pymupdf.open(path)
    # ② 머리말·꼬리말을 빼고 마크다운으로
    return doc.to_markdown(header=False, footer=False)
  1. 클래스(class)는 데이터의 모양을 정해 두는 틀입니다. BaseModel을 물려받은 클래스가 곧 요약 양식이 되고 칸 이름과 칸에 들어갈 값의 종류(글자 하나, 글자 목록)를 적습니다. 이런 모양 정의를 스키마(schema)라고 부릅니다.
  2. 05번 섹션에서 만든 깨끗한 글을 그대로 씁니다. 잡음을 먼저 걸러야 요약에 학술지 이름이 섞이지 않습니다.
def summarize(text: str) -> PaperSummary:
    response = client.responses.parse(
        model="gpt-6.1-sol",
        # ③ 무엇을 어떻게 뽑을지
        instructions=(
            "너는 논문을 정리하는 연구원이다. "
            "본문에 없는 내용은 지어내지 말고 '본문에 없음'이라고 써라."
        ),
        input=text,
        # ④ 답의 모양을 칸으로 고정
        text_format=PaperSummary,
    )
    # ⑤ 칸이 채워진 객체로 받는다
    return response.output_parsed

s = summarize(pdf_to_text("data/paper.pdf"))
print("문제:", s.problem)
print("주장:", s.claim)
print("방법:", s.method)
for r in s.results:
    print("결과:", r)
print("한계:", s.limits)
터미널 · 누르면 출력이 처음부터 다시 찍힙니다
$ python summarize_pdf.py 문제: 작물 생육 모형은 쓸모가 크지만 설치형 프로그램이라 농가가 쓰기 어려웠다. 주장: 모형을 웹으로 옮기면 누구나 물 주는 날을 정하는 데 쓸 수 있다. 방법: 밀 생육 모형을 웹 서버에 올리고 날씨 자료를 매일 받아 다시 계산했다. 결과: 웹 시스템의 수확량 예측이 실제 수확량과 잘 맞았다. 결과: 물 사용량이 줄었다. 한계: 다른 작물로 넓히려면 지역마다 다른 흙 자료가 필요하다.

출력은 예시 답입니다. 문장은 부를 때마다 달라지지만 칸의 이름과 개수는 바뀌지 않습니다.

  1. instructions는 모델이 지킬 규칙입니다. LLM은 그럴듯하지만 사실이 아닌 내용을 지어낼 때가 있습니다. 이것을 환각(hallucination)이라고 합니다. "없으면 없다고 써라"를 적어 두면 빈칸을 상상으로 채우는 일이 줄어듭니다.
  2. text_format에 양식 클래스를 넘기면 모델이 그 칸에 맞춘 JSON으로만 답합니다. JSON은 {"problem": "…"}처럼 이름과 값을 짝지어 적는 글 형식입니다. OpenAI는 이 기능을 Structured Outputs라고 부르고 칸이 빠지거나 이름이 바뀐 답은 나오지 않습니다.
  3. output_parsed에는 글자가 아니라 PaperSummary 객체가 들어 있어서 s.problem처럼 칸 이름으로 바로 꺼냅니다. 모델 이름 gpt-6.1-sol은 OpenAI 모델 문서(2026-10-30 확인)에 나온 이름이고 코드는 openai 3.41 기준입니다.
07

PDF 파일을 통째로 모델에 넣는 방법도 있습니다

ChatGPT에 PDF를 올리면 본문뿐 아니라 그래프와 표까지 설명해 줍니다. API(프로그램이 다른 서비스의 기능을 빌려 쓰는 창구)에서도 PDF 파일을 그대로 보내면, OpenAI가 쪽마다 꺼낸 글과 쪽 사진을 함께 모델에 넣습니다.

쪽 사진 덕분에 모델은 그래프의 선과 표의 칸까지 봅니다. 대신 사진도 토큰으로 계산되어 입력이 커집니다. 토큰은 모델이 글과 그림을 읽는 단위입니다. 서버가 꺼내 주는 글에는 머리말과 쪽 번호도 그대로 들어 있으니, 파일째 보낼 때는 지시문에 "머리말과 쪽 번호는 요약에 넣지 마라"를 적어 둡니다.

그림이 요점인 논문은 파일째로, 글 중심 논문을 많이 요약할 때는 직접 꺼낸 깨끗한 글로 보내는 쪽이 낫습니다.

import base64
from openai import OpenAI

client = OpenAI()

with open("data/paper.pdf", "rb") as f:
    data = base64.b64encode(f.read()).decode("utf-8")

response = client.responses.create(
    model="gpt-6.1-sol",
    input=[{
        "role": "user",
        "content": [
            # ① PDF 파일을 통째로
            {"type": "input_file", "filename": "paper.pdf",
             "file_data": f"data:application/pdf;base64,{data}"},
            {"type": "input_text",
             "text": "이 논문의 문제·주장·결과를 세 줄로 요약해 줘."},
        ],
    }],
)
print(response.output_text)
  1. input_file 칸에 PDF를 넣습니다. 여기서는 파일을 base64로 바꿔 실어 보냈습니다. base64는 PDF 같은 파일을 영문자와 숫자만으로 바꿔 적는 방식입니다. 같은 PDF를 여러 번 쓴다면 파일을 OpenAI 서버에 미리 올려 두는 Files API로 한 번 올리고 file_id로 가리켜도 됩니다.
쪽 사진은 얼마나 자세히 볼까요?

input_file에 detail을 low나 high로 줄 수 있습니다. 기본값 auto는 GPT-5.6 이후 모델에서 high로 동작한다고 OpenAI 문서에 적혀 있습니다. 작은 글씨 표가 많은 논문이 아니라면 low로 입력을 줄여 볼 만합니다.

08

아주 긴 문서는 나눠 요약한 뒤 합칩니다

수백 쪽짜리 보고서를 통째로 올려 요약을 받으면, 가운데 장의 내용이 요약에서 빠질 수 있습니다. 모델이 한 번에 읽는 양을 컨텍스트 창(context window)이라고 하는데, 요즘은 창이 커서 300쪽도 들어가기는 합니다.

들어간다고 고르게 읽는 것은 아닙니다. 긴 입력의 가운데에 놓인 정보를 앞이나 끝보다 잘 쓰지 못한다는 연구가 있습니다("Lost in the Middle", 2023). 그래서 긴 문서는 조각으로 나눠 따로 요약하고 그 요약들을 모아 한 번 더 요약합니다. 조각마다 처리하는 단계를 map, 모아서 줄이는 단계를 reduce라고 해서 map-reduce 요약이라고 부릅니다.

창 크기는 OpenAI 주력 모델 기준(2026-10)이고 쪽당 토큰은 Anthropic 문서의 어림값(쪽당 1,500~3,000토큰)으로 쳤습니다.

모둠 과제처럼 나눠 읽으면 조각 경계에 걸친 내용이나 앞 장을 알아야 이해되는 뒷장을 놓칠 수 있습니다. 그래서 조각을 조금씩 겹쳐 자르거나, 앞 요약을 다음 조각과 함께 넣어 차례로 다듬는 방법(iterative refinement)도 씁니다.

09

PDF 요약기를 만들기 전에 정할 네 가지

  1. 드래그해도 글자가 선택되지 않는 PDF라면 스캔본입니다. OCR부터 붙입니다.
  2. 한 학술지의 논문만 다루면 clip으로 위아래를 가려도 됩니다. 여러 곳의 PDF를 받는다면 to_markdown(header=False, footer=False)를 쓰고 꺼낸 결과를 한 번 열어 봅니다.
  3. 그래프와 표가 요점이면 PDF 파일째로, 글이 중심이고 양이 많으면 꺼낸 글로 보냅니다.
  4. 요약할 칸은 스키마로 고정합니다. 창에 들어가더라도 수백 쪽이 넘으면 나눠 요약한 뒤 합칩니다.
