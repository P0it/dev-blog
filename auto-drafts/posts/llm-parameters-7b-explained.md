> Qwen2.5-7B 를 내려받으면 15.2GB 짜리 파일 네 개가 옵니다. 그 안에 든 것은 문장도 지식도 아니고 **76억 개의 숫자**입니다. 7B·70B 라는 이름, 학습과 추론의 차이, 벡터 DB 와의 구분은 전부 이 숫자가 무엇인지에서 출발합니다.

## AI · 머신러닝 · 딥러닝 · LLM 의 포함 관계

용어부터 정리하면 이 시리즈가 편해집니다. **AI** 가 가장 넓은 말입니다. 그 안에 데이터에서 규칙을 스스로 찾아내는 **머신러닝**이 있습니다. 머신러닝 중에서 층을 여러 겹 쌓은 신경망을 쓰는 갈래가 **딥러닝**입니다. 딥러닝으로 만든 모델 가운데 글을 읽고 쓰는 데 특화된 아주 큰 모델이 **LLM**(Large Language Model)입니다.

같은 구조를 작게 만든 것을 **SLM**(Small Language Model)이라고 부릅니다. 경계는 느슨한데 대체로 수억~수십억 파라미터를 SLM 으로 봅니다. Qwen2.5-0.5B, Phi-4-mini(3.8B) 같은 모델이 여기 들어갑니다. 노트북이나 폰에서 돌리려는 목적이라 크기가 곧 정체성입니다.

## 모델 = 파라미터 묶음

머신러닝에서 **모델**은 입력을 받아 출력을 내는 함수입니다. 그 함수의 모양은 코드가 정하고 함수의 값은 **파라미터**가 정합니다. 파라미터는 학습으로 정해진 숫자 하나하나를 말합니다. 그중 입력에 곱해지는 숫자를 **가중치**(Weight), 더해지는 숫자를 **바이어스**(Bias)라고 나눠 부르는데 실무에서는 둘을 합쳐 그냥 가중치라고 부르는 일이 많습니다.

이름 뒤에 붙는 **7B·14B·70B** 의 B 는 Billion, 즉 파라미터가 몇 십억 개인지를 뜻합니다. 실제로 Hugging Face 가 Qwen2.5-7B 의 파일을 읽어 센 파라미터 수는 **7,615,616,512 개**입니다. 7B 는 반올림한 이름이고 진짜 숫자는 76억 개입니다.

## 파일을 열어 보면 나오는 것

말로만 하면 추상적이니 실제 파일을 열어 보겠습니다. Hugging Face 는 `.safetensors` 파일 안의 텐서 목록을 브라우저에서 바로 보여 줍니다.

![Qwen2.5-7B 첫 번째 safetensors 파일의 텐서 목록 — 이름·모양·정밀도](https://wzaqtubtqwpddouevwbk.supabase.co/storage/v1/object/public/post-images/2026-09-16/8b5e9037.webp)

파일 안에는 이름이 붙은 숫자 표(텐서)가 줄지어 있습니다. `model.embed_tokens.weight` 는 `[152064, 3584]` 크기, 곧 어휘 152,064 개마다 3,584 개 숫자가 붙은 표입니다. 이 표 하나만 5억 4천만 개입니다. 그 아래 `model.layers.0` 부터 `model.layers.27` 까지 같은 구조의 층이 28개 반복됩니다. 층마다 `q_proj`·`k_proj`·`v_proj`·`o_proj`·`mlp` 라는 표가 들어 있습니다. 이 이름들은 2편에서 다룰 Transformer 의 부품 이름입니다.

정밀도 칸의 **BF16** 은 숫자 하나를 2바이트로 저장한다는 뜻입니다. 76억 개 × 2바이트 ≈ **15.2GB**. 파일 목록의 총 용량과 정확히 맞습니다.

![Qwen2.5-7B 저장소 파일 목록 — safetensors 4개와 config·tokenizer](https://wzaqtubtqwpddouevwbk.supabase.co/storage/v1/object/public/post-images/2026-09-16/6dcae197.webp)

가중치 말고 같이 오는 파일도 있습니다. `config.json` 은 층 수·차원 같은 함수의 모양을 적은 686바이트짜리 설계도입니다. `tokenizer.json` 은 글자를 숫자로 바꾸는 사전이고 `generation_config.json` 은 생성 기본값입니다. 셋을 합쳐도 10MB 가 안 됩니다. **모델 크기는 사실상 가중치 크기**입니다.

## 파라미터가 많으면 왜 커지는가

파라미터 수가 늘어나는 경로는 두 가지입니다. 층을 더 쌓거나(28층 → 80층), 한 층의 폭을 넓히거나(3,584 → 8,192). 폭을 두 배로 넓히면 표의 가로세로가 함께 늘어 숫자는 네 배가 됩니다. 그래서 70B 는 7B 보다 층도 많고 폭도 넓습니다.

파라미터 하나가 2바이트를 차지하니 용량은 파라미터 수에 정비례합니다. 70B 모델은 BF16 으로 약 140GB, GPU 한 장에 들어가지 않는 크기입니다. 이 문제를 어떻게 푸는지가 4편(양자화)과 6편(여러 GPU 에 나눠 싣기)의 주제입니다.

## 학습은 숫자를 고치는 일, 추론은 숫자를 쓰는 일

**학습**(Training)은 이 76억 개 숫자를 정하는 과정입니다. 처음에는 전부 무작위 값입니다. 문장을 넣고 다음 단어를 맞히게 한 뒤 틀린 만큼 숫자를 아주 조금씩 고칩니다. 이 과정을 수조 개 토큰에 대해 반복하면 지금의 값이 됩니다. 바뀌는 것은 오직 파라미터의 값이고 모양(구조)은 그대로입니다.

**추론**(Inference)은 정해진 숫자를 읽기만 하는 과정입니다. 입력이 들어오면 저 표들에 차례로 곱하고 더해 다음 토큰 하나를 내놓습니다. 숫자를 고치지 않으니 학습보다 훨씬 쌉니다. 그래서 우리가 쓰는 서비스는 전부 추론입니다. 이 시리즈의 3~6편은 이 추론을 어떻게 빠르고 싸게 하느냐에 관한 이야기입니다.

## 파라미터와 벡터 DB 는 다른 것

"우리 회사 문서를 모델에 넣는다"는 말이 자주 헷갈리는 지점입니다. 파라미터는 학습이 끝나면 고정됩니다. 그 안에 특정 문서가 문장 형태로 들어 있지 않습니다. 학습 데이터의 통계적 흔적만 숫자에 녹아 있을 뿐입니다. 파라미터에 새 지식을 넣으려면 다시 학습(파인튜닝)해야 하고 그게 7편입니다.

**벡터 DB** 는 모델 바깥에 있는 별도 저장소입니다. 문서를 조각내 숫자 벡터로 바꿔 넣어 두고 질문이 오면 비슷한 조각을 찾아 모델에 함께 건넵니다. 모델의 파라미터는 한 개도 바뀌지 않습니다. 이 방식이 RAG 이고 8편에서 다룹니다. 둘을 한 줄로 가르면 이렇습니다.

| | 파라미터 | 벡터 DB |
|---|---|---|
| 어디에 | 모델 파일 안 | 모델 밖 별도 저장소 |
| 무엇이 | 학습으로 정해진 숫자 | 문서 조각의 임베딩 |
| 바꾸려면 | 재학습·파인튜닝 | 문서 추가·삭제 |
| 갱신 비용 | GPU 시간 | 인덱싱 몇 초 |

## 이 글에서 잡은 그림

모델 파일 = 이름 붙은 숫자 표들의 묶음입니다. 7B 는 그 숫자가 76억 개라는 뜻입니다. 학습은 그 숫자를 고치는 일이고 추론은 그 숫자를 곱해 쓰는 일입니다. 다음 편에서는 이 숫자 표들이 어떻게 문장을 읽고 다음 단어를 고르는지, Transformer 와 Attention 을 따라갑니다.
