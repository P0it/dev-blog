AI Service Track · 05

회의록 AI는 누가 말했는지 어떻게 알아낼까요?

요즘 회의 녹음 앱은 받아쓴 글을 "참석자 1", "참석자 2"처럼 말한 사람별로 나눠 보여 줍니다. 끝에는 결정 사항과 할 일을 정리한 회의록까지 만들어 줍니다.

지난 글의 받아쓰기 모델은 글만 돌려줬습니다. 이 글은 같은 41초 회의 녹음으로 화면 뒤를 따라갑니다. 목소리로 사람을 나누고 글에 이름을 붙여 Word 회의록으로 만드는 과정입니다.

왼쪽은 지난 글에서 예시 회의 녹음을 실제로 받아쓴 결과입니다. 오른쪽은 이 글 끝의 코드가 만드는 Word 파일 내용이고 결정 사항과 할 일은 예시 답입니다.

1장목소리로 사람 나누기01~04
01

먼저 녹음에서 말소리가 있는 곳을 찾습니다

녹음을 "언제 누가 말했나"로 나누는 일을 화자 분리(speaker diarization)라고 합니다. 화자는 말하는 사람입니다. 이 단계에서는 이름을 모릅니다. 대신 같은 목소리에 같은 번호를 붙입니다.

첫걸음은 말소리가 있는 곳과 조용한 곳을 가르는 일입니다. 그다음 말소리를 짧은 조각으로 자릅니다. 아래 세 줄은 같은 41초 녹음을 이 순서대로 다시 그린 것입니다.

예시 회의 녹음에서 실제로 계산했습니다. ②는 가장 큰 소리보다 35dB(소리 크기 단위) 넘게 작은 곳을 조용하다고 본 간단한 방법입니다. 실제 화자 분리 모델은 말소리를 가려내도록 학습한 모델로 이 일을 합니다. ③은 말한 구간을 1초 길이로 0.5초마다 잘라 겹친 조각 65개입니다.

말소리 구간을 찾는 일을 VAD(Voice Activity Detection, 음성 구간 검출)라고 부릅니다. 조각을 짧게 자르면 한 조각 안에 한 사람 목소리만 들어갑니다. 길게 자르면 두 사람 말이 한 조각에 섞입니다.

02

조각마다 목소리 지문을 만들어 가까운 것끼리 묶습니다

눈을 감고 반 친구들 목소리를 들으면, 이름을 몰라도 "아까 그 목소리"는 알아챕니다. 사람마다 목소리 높이와 울림이 달라서입니다. 모델은 조각마다 이런 특징을 숫자 묶음으로 바꿉니다.

이 숫자 묶음을 임베딩(embedding)이라고 부릅니다. 목소리 지문이라고 생각하면 됩니다. 비슷한 목소리면 숫자도 비슷해서 점으로 찍으면 가까이 모입니다.

점을 무리로 나누는 일을 군집화(clustering)라고 합니다. 몇 명인지 모르면 모델이 점 사이 거리를 보고 무리 수를 정하는데, 미리 알면 알려 주는 편이 정확합니다. 무리 이름은 SPEAKER_00, SPEAKER_01 같은 번호일 뿐이라 누가 서연인지는 아직 모릅니다.

03

두 사람이 동시에 말한 곳은 한 사람에게 맡깁니다

회의에서는 말이 자주 겹칩니다. 화자 분리 모델은 겹친 구간에 두 사람을 다 표시할 수 있습니다. 그런데 받아쓴 글의 낱말 하나에는 말한 사람을 한 명만 붙여야 합니다.

그래서 겹친 곳마다 한 사람만 남긴 결과를 따로 만들어 받아쓴 글과 맞출 때 씁니다. 겹친 곳의 다른 한 사람 말은 받아쓰기에서도 대개 묻혀서 제대로 적히지 않습니다.

04

pyannote로 내 컴퓨터에서 화자를 나눕니다

화자 분리를 직접 돌릴 때 가장 많이 쓰는 공개 도구는 파이썬 라이브러리 pyannote.audio입니다. 4.0 버전과 함께 나온 speaker-diarization-community-1 모델이 01~03의 단계를 한 번에 해 줍니다.

모델 파일은 Hugging Face에 있습니다. 쓰기 전에 모델 페이지에서 사용 조건에 동의하고 내 계정의 접근 토큰을 받아 둡니다. 토큰은 "이 계정이 받아 가도 된다"는 확인용 비밀번호 같은 문자열입니다.

import json, os
import torch
from pyannote.audio import Pipeline

# ① 약관에 동의한 계정의 토큰으로 모델 받기
pipeline = Pipeline.from_pretrained(
    "pyannote/speaker-diarization-community-1",
    token=os.environ["HF_TOKEN"],
)
if torch.cuda.is_available():
    pipeline.to(torch.device("cuda"))

# ② 사람 수를 알면 알려 준다
output = pipeline("meeting.wav", num_speakers=2)

# ③ 겹친 곳은 한 명만 남긴 결과
turns = output.serialize()["exclusive_diarization"]
for t in turns:
    print(f'{t["speaker"]}  {t["start"]:4.1f} ~ {t["end"]:4.1f}')
json.dump(turns, open("turns.json", "w"))
  1. torch.cuda.is_available()은 NVIDIA GPU가 있는지 묻는 줄입니다. 있으면 그쪽에서 계산해 빨라집니다. 토큰은 내 컴퓨터에만 저장해 두는 설정값인 환경 변수 HF_TOKEN에 넣어 두고 읽습니다. 코드에 직접 적으면 코드를 공유할 때 같이 새어 나갑니다. 모델의 사용 허락 조건(라이선스)은 CC-BY-4.0이라 출처를 밝히면 회사 일에도 쓸 수 있습니다.
  2. 참석자 수를 모르면 num_speakers를 빼거나 min_speakers·max_speakers로 범위만 줍니다.
  3. 결과에는 겹친 곳을 그대로 둔 것과 한 명만 남긴 것이 함께 들어 있습니다. 03번처럼 받아쓴 글과 맞출 때는 exclusive_diarization을 씁니다.

출력은 예시 회의에서 실제로 말한 구간으로 만든 예시 값입니다. 코드는 pyannote.audio 4.0.7 기준입니다.

API에 맡길 수는 없나요?

지난 글의 gpt-transcribe는 화자를 나누지 않습니다. 화자까지 붙여 주던 gpt-4o-transcribe-diarize는 2027-02-26 종료 예정입니다. pyannote를 만든 팀의 유료 서비스 pyannoteAI는 더 정확한 모델을 API로 제공합니다.

정확도는 DER(diarization error rate), 곧 녹음 시간 가운데 잘못 나눈 비율로 잽니다. community-1 모델 카드에 따르면 회의 녹음 모음 AMI에서 17.0%로, 이전 모델 3.1의 18.8%보다 낮습니다.

2장받아쓴 글에 이름 붙이기05~07
05

글 조각째로 붙이면 남의 말이 섞입니다

이제 Whisper가 준 글과 pyannote가 준 화자 구간을 시간으로 맞춥니다. 가장 쉬운 방법은 지난 글에서 본 문장 조각마다 시간이 가장 많이 겹치는 화자를 붙이는 것입니다.

두 사람 말이 한 조각에 섞이면 문제가 생깁니다. 아래는 회의 뒷부분 23~41초를 크게 늘린 그림입니다. 위 띠가 실제로 말한 사람이고 아래 띠가 받아쓴 조각에 붙은 사람입니다.

그래서 지난 글의 코드에 return_timestamps="word"를 줘서 낱말마다 시간을 받고 낱말 하나하나에 화자를 붙입니다. 서연의 지시는 서연에게 돌아왔지만 맨 앞 낱말 "그건" 하나는 여전히 도윤 쪽에 남았습니다.

06

낱말 시간이 조금만 어긋나도 경계의 낱말이 넘어갑니다

Whisper가 "그건"에 붙인 시간은 27.6~29.3초입니다. 실제로는 서연이 29초 무렵에 꺼낸 말인데, 시간이 앞으로 1초 넘게 늘어져 도윤 구간과 더 많이 겹쳤습니다.

낱말 시간을 소리에 다시 맞추는 강제 정렬(forced alignment)을 거치면 이런 어긋남이 줄어듭니다. 공개 도구 WhisperX가 이렇게 낱말 시간을 다듬은 다음 화자를 붙입니다. 그래도 말이 바뀌는 경계의 한두 낱말은 틀릴 수 있어서 회의록에는 사람이 확인할 자리를 남겨 둡니다.

07

낱말마다 겹친 시간이 가장 긴 화자를 붙입니다

05~06에서 본 규칙을 코드로 옮기면 스무 줄 남짓입니다. 입력은 낱말 시간(words.json)과 화자 구간(turns.json) 두 파일이고 출력은 말한 사람별로 묶은 줄입니다.

import json

words = json.load(open("words.json"))   # Whisper 가 준 낱말과 시간
turns = json.load(open("turns.json"))   # 화자 분리가 준 화자 구간

def speaker_of(w_start, w_end):
    # ① 낱말 구간과 화자 구간이 겹친 길이를 화자별로 더한다
    overlap = {}
    for t in turns:
        o = min(w_end, t["end"]) - max(w_start, t["start"])
        if o > 0:
            overlap[t["speaker"]] = overlap.get(t["speaker"], 0) + o
    if overlap:
        return max(overlap, key=overlap.get)
    # ② 겹친 데가 없으면 가운데 시각이 가장 가까운 구간
    mid = (w_start + w_end) / 2
    dist = lambda t: min(abs(mid - t["start"]), abs(mid - t["end"]))
    near = min(turns, key=dist)
    return near["speaker"]

# ③ 같은 화자가 이어 말한 낱말은 한 줄로 묶는다
lines = []
for w in words:
    start, end = w["timestamp"]
    spk = speaker_of(start, end)
    if lines and lines[-1]["speaker"] == spk:
        lines[-1]["text"] += w["text"]
        lines[-1]["end"] = end
    else:
        lines.append({"speaker": spk, "start": start,
            "end": end, "text": w["text"]})

for l in lines:
    print(f'[{l["start"]:5.1f}] {l["speaker"]}:{l["text"]}')
json.dump(lines, open("lines.json", "w"), ensure_ascii=False)
  1. 두 구간이 겹친 길이는 "늦게 끝난 시작"부터 "먼저 끝난 끝"까지입니다. 06번의 "그건"은 여기서 도윤 0.75초, 서연 0.25초가 나옵니다.
  2. 낱말이 화자 구간 사이의 쉼에 걸려 어느 쪽과도 겹치지 않을 때를 위한 대비입니다. 가장 가까운 구간의 화자를 붙입니다.
  3. 낱말마다 한 줄을 만들면 읽기 어려우니, 화자가 바뀔 때만 새 줄을 엽니다.

3장회의록 문서로 만들기08~10
08

번호를 이름으로 바꾸고 잘못 들은 낱말을 고칩니다

SPEAKER_00이 누구인지는 사람이 한 번 알려 줘야 합니다. 회의 녹음 앱이 "참석자 1은 누구인가요?"라고 묻는 것이 이 단계입니다. 이 글의 코드는 번호와 이름을 짝지은 표를 직접 적어 둡니다.

그다음 LLM에게 받아쓰기 오탈자만 고치게 합니다. 지난 글에서 본 "정화돈은", "슈파베이스의 사인" 같은 말입니다. 용어집을 함께 주면 무엇으로 고쳐야 할지 알기 쉽습니다.

import json
from openai import OpenAI
from pydantic import BaseModel

client = OpenAI()
NAMES = {"SPEAKER_00": "김서연", "SPEAKER_01": "박도윤"}
lines = json.load(open("lines.json"))
# ① 기계 번호를 사람 이름으로
for l in lines:
    l["name"] = NAMES[l["speaker"]]
transcript = "\n".join(f'{i}. {l["name"]}: {l["text"].strip()}' for i, l in enumerate(lines))

class Line(BaseModel):
    i: int
    text: str

class Corrected(BaseModel):
    lines: list[Line]

# ② 잘못 들은 낱말만 고친다
fixed = client.responses.parse(
    model="gpt-6.1-sol",
    instructions=(
        "회의 받아쓰기의 오탈자만 고쳐라. 말투와 뜻은 바꾸지 마라. "
        "줄 수와 번호는 그대로 둔다. 용어집: Supabase, 리뷰 분류기, 정확도."
    ),
    input=transcript,
    text_format=Corrected,
).output_parsed
for row in fixed.lines:
    lines[row.i]["text"] = row.text
  1. 번호와 이름의 짝은 회의마다 달라집니다. 앱이라면 화면에서 사용자가 고른 값을 여기에 넣습니다.
  2. responses.parse는 3편에서 본 Structured Outputs, 곧 답의 모양을 미리 정해 두고 그 모양대로만 받는 기능입니다. 답은 Corrected 모양으로 받습니다. 줄 번호를 그대로 돌려받으니, LLM이 줄을 합치거나 나눠 화자 경계를 바꿀 수 없습니다.
09

회의록 칸을 정해 두고 LLM이 채우게 합니다

회의록에 들어갈 칸을 먼저 정합니다. 제목, 요약, 결정 사항, 할 일입니다. 칸 모양을 Pydantic 클래스(파이썬으로 데이터 모양을 적는 방법)로 적어 보내면 모델은 그 모양 그대로 답하고 코드는 칸마다 Word 문서의 자리에 옮겨 적습니다.

class ActionItem(BaseModel):
    owner: str
    task: str
    due: str

class Minutes(BaseModel):
    title: str
    summary: list[str]
    decisions: list[str]
    action_items: list[ActionItem]

# ③ 회의록 칸을 채운다
minutes = client.responses.parse(
    model="gpt-6.1-sol",
    instructions="회의 기록을 읽고 회의록을 써라. 기록에 없는 내용은 쓰지 마라.",
    input="\n".join(f'{l["name"]}: {l["text"]}' for l in lines),
    text_format=Minutes,
).output_parsed

json.dump({"lines": lines, "minutes": minutes.model_dump()},
          open("minutes.json", "w"), ensure_ascii=False)
  1. action_items를 담당·할 일·기한으로 나눠 받아야 표로 옮길 수 있습니다. 한 문장으로 받으면 누가 언제까지인지 다시 뽑아야 합니다. "기록에 없는 내용은 쓰지 마라"는 없던 결정이나 담당자를 지어내지 않게 하는 한 줄입니다.
  2. python-docx는 Word 파일(.docx)을 만드는 라이브러리입니다. Table Grid는 Word에 들어 있는 기본 표 모양입니다. 코드는 python-docx 1.2.0 기준입니다.
Word 파일로 옮기는 코드 to_docx.py 보기
import json
from docx import Document

data = json.load(open("minutes.json"))
m, lines = data["minutes"], data["lines"]
doc = Document()
doc.add_heading(m["title"], level=1)
# ④ 할 일은 표로
doc.add_heading("할 일", level=2)
table = doc.add_table(rows=1, cols=3, style="Table Grid")
for cell, head in zip(table.rows[0].cells, ["담당", "할 일", "기한"]):
    cell.text = head
for a in m["action_items"]:
    row = table.add_row().cells
    row[0].text, row[1].text, row[2].text = a["owner"], a["task"], a["due"]
# (요약·결정 사항·대화 기록도 같은 방식으로 add_paragraph)
doc.save("meeting_minutes.docx")
print("저장: meeting_minutes.docx")

회의록 AI를 붙이기 전에 정할 것

  1. 녹음이 회사 밖으로 나가면 안 된다면 Whisper와 pyannote를 내 컴퓨터에서 돌립니다. 둘 다 모델 파일이 공개돼 있습니다.
  2. 참석자 수를 알면 num_speakers로 알려 줍니다. 모르면 범위만 줍니다.
  3. 화자는 문장 조각이 아니라 낱말마다 붙입니다. 말이 바뀌는 경계의 낱말은 틀릴 수 있으니 시간과 함께 남겨 사람이 확인하게 합니다.
  4. LLM에게는 오탈자 고치기와 회의록 칸 채우기만 맡기고 기록에 없는 내용은 쓰지 말라고 적습니다. 결정 사항과 할 일은 회의 참석자가 마지막에 확인합니다.
