같은 도구를 Agent마다 다시 연결해야 할까요?

사내 Agent가 세 개 있다고 해 보겠습니다. 상담 Agent, 개발 Agent, 영업 Agent가 모두 사내 위키를 검색하고 티켓 시스템을 조회합니다. 도구를 Agent마다 따로 짰다면 위키 검색 코드도 세 벌입니다. 위키 API가 바뀌면 세 곳을 다 고쳐야 합니다. 도구를 한 번 만들어 어느 Agent에서든 꽂아 쓸 수는 없을까요?

도구를 Agent마다 따로 붙이면 무엇이 문제인가요?

Agent 수 × 도구 수만큼 연결 코드가 생깁니다.

지금까지 도구는 Agent 프로그램 안에 함수로 넣었습니다. Agent가 하나일 때는 그것으로 충분합니다. Agent가 여럿이 되면 같은 도구 함수를 Agent마다 복사하게 되고 도구가 바뀔 때마다 모든 Agent를 고쳐야 합니다.

바깥 도구를 쓰고 싶을 때도 같습니다. Claude 앱이나 Cursor 같은 프로그램에 사내 위키를 붙이려면 그 프로그램이 정한 방식대로 매번 새로 연결해야 했습니다. 도구를 꽂는 방식이 프로그램마다 달랐던 것이 문제의 뿌리입니다.

MCP는 무엇을 맞춘 건가요?

도구를 내놓는 쪽과 쓰는 쪽이 주고받는 말을 하나로 정했습니다.

MCP(Model Context Protocol)는 Anthropic이 2024년 11월에 공개한 표준입니다. 도구를 내놓는 프로그램과 도구를 쓰는 프로그램이 어떤 말로 주고받을지 정해 둔 약속입니다. "가진 도구 목록을 알려 줘", "이 도구를 이 값으로 실행해 줘" 같은 요청의 모양이 정해져 있습니다.

그래서 도구를 MCP 형식으로 한 번 만들어 두면 MCP를 지원하는 프로그램 어디에서든 씁니다. 지금은 Claude 앱, ChatGPT, Cursor, VS Code 같은 앱과 LangChain·OpenAI Agents SDK 같은 프레임워크가 MCP를 지원합니다. 흔히 "AI용 USB-C"라고 부르는 이유입니다.

비유가 맞지 않는 부분도 있습니다. USB-C는 꽂기만 하면 되지만 MCP 서버는 무엇을 할 수 있는지를 글로 설명하고 LLM이 그 설명을 읽고 고릅니다. 도구 목록을 LLM이 읽고 고르는 원리는 그대로입니다.

누가 누구와 이야기하나요?

Agent 프로그램(Host) 안의 Client가 도구를 가진 Server와 이야기합니다. LLM은 Server를 직접 보지 않습니다.

MCP에는 세 역할이 있습니다. Host는 사용자가 쓰는 Agent 프로그램입니다. Claude 앱이나 우리가 짠 Agent가 Host입니다. Host 안에는 Server마다 하나씩 Client가 있어서 Server와 연결을 맡습니다. Server는 도구를 내놓는 프로그램입니다.

흐름은 지금까지와 거의 같습니다. Host가 Server에 도구 목록을 물어(tools/list) LLM에게 넘기고 LLM이 도구를 부탁하면 Host가 Server에 실행을 요청합니다(tools/call). LLM은 MCP를 모릅니다. LLM 입장에서는 도구 목록과 결과가 여느 때처럼 들어올 뿐입니다.

Server는 도구 말고 무엇을 내놓나요?

도구(Tools), 읽을거리(Resources), 프롬프트 틀(Prompts) 세 가지입니다.

이름누가 고르나예
ToolsLLM이 필요할 때 부탁위키 검색, 티켓 만들기
Resources앱이나 사용자가 골라 대화에 넣음설계 문서 파일, 오늘의 장애 목록
Prompts사용자가 골라 실행"장애 보고서 쓰기" 틀

가장 많이 쓰는 것은 Tools입니다. Resources는 파일이나 데이터처럼 읽기만 하는 것을 주소로 내놓고 무엇을 대화에 넣을지는 앱이나 사용자가 정합니다. Prompts는 자주 쓰는 지시문 틀을 내놓아 사용자가 메뉴에서 골라 쓰게 합니다.

세 가지는 누가 고르느냐가 다릅니다. 도구는 LLM이, 읽을거리는 앱이, 프롬프트 틀은 사람이 고릅니다. 앱마다 지원하는 범위가 달라서 도구만 지원하는 Host도 많습니다.

Server는 어디에서 돌아가나요?

내 컴퓨터에서 함께 띄우거나(stdio), 원격 서버로 두고 HTTP로 연결합니다.

stdioStreamable HTTP
Server 위치Host가 같은 컴퓨터에서 실행다른 서버, 인터넷 너머
주고받는 길표준 입출력HTTP 요청 (예: /mcp)
로그인필요 없음 (내 권한으로 실행)OAuth 등으로 인증
쓰는 곳내 파일·로컬 도구사내 공용 도구, 바깥 서비스

stdio는 Host가 Server 프로그램을 직접 실행하고 표준 입출력으로 주고받습니다. 내 컴퓨터의 파일을 다루는 도구에 씁니다. Streamable HTTP는 Server를 원격에 띄우고 HTTP로 연결합니다. 여러 사람이 함께 쓰는 사내 도구는 이쪽입니다.

MCP 규격은 계속 바뀌고 있습니다. 2026-07-28 개정에서는 연결마다 유지하던 세션을 없애 요청 하나하나가 따로 처리되게 했습니다. 서버를 여러 대로 늘리기가 쉬워졌습니다. 원격 Server를 연결할 때는 누가 만든 Server인지, 어떤 권한을 주는지 꼭 확인합니다. 남이 만든 MCP Server의 도구 설명과 결과도 LLM이 그대로 읽습니다.

코드로 쓰면 어떻게 되나요?

Server 목록을 적고 도구를 받아 Agent에 넘깁니다.

import asyncio
from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient

# ① 연결할 MCP Server 목록
client = MultiServerMCPClient({
    "files": {                       # 내 컴퓨터에서 함께 띄우는 Server
        "transport": "stdio",
        "command": "python",
        "args": ["files_server.py"],
    },
    "wiki": {                        # 원격 Server
        "transport": "http",
        "url": "https://mcp.example.com/wiki/mcp",
        "headers": {"Authorization": "Bearer ${WIKI_TOKEN}"},
    },
})

async def main():
    # ② 모든 Server의 tools/list 를 모아 LangChain 도구로 바꾼다
    tools = await client.get_tools()
    # ③ 나머지는 지금까지와 같다
    agent = create_agent("anthropic:claude-sonnet-5-5", tools)
    out = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "휴가 신청은 언제까지 해?"}]})
    print(out["messages"][-1].content)

asyncio.run(main())
  1. Server마다 연결 방식을 적습니다. stdio는 실행할 명령을, http는 주소와 인증 헤더를 적습니다. 실제 토큰은 환경 변수에서 읽습니다.
  2. Host 쪽 Client가 각 Server에 도구 목록을 물어 LangChain 도구로 바꿉니다. 도구 이름·설명·입력 형식은 Server가 정한 그대로입니다.
  3. MCP에서 온 도구도 직접 만든 도구와 똑같이 create_agent에 넘깁니다. LLM은 차이를 모릅니다.

코드는 langchain-mcp-adapters 0.3 기준입니다. Claude API에는 원격 MCP Server 주소를 요청에 바로 넣는 MCP connector도 있어서 원격 Server만 쓴다면 Client 코드 없이 연결할 수 있습니다.
