AI Service Track · 04

AI 받아쓰기는 왜 'Supabase'를 '슈파베이스'로 적을까요?

회의를 녹음해 받아쓰기 앱에 올리면 몇 초 뒤 시간이 붙은 글이 나옵니다. 그런데 다시 읽어 보면 처음 듣는 낱말이나 제품 이름이 엉뚱하게 적혀 있을 때가 많습니다.

아래는 41초짜리 회의 녹음을 받아쓰기 모델에 넣고 실제로 받은 결과입니다. 빨간 줄이 틀린 곳이고 손글씨가 원래 한 말입니다. 이 글은 녹음이 글이 되기까지 화면 뒤에서 일어나는 일을 따라가며 왜 이렇게 틀리는지 봅니다.

설명하려고 두 목소리로 만든 예시 회의를 OpenAI가 공개한 받아쓰기 모델 whisper-large-v3-turbo로 받아쓴 실제 결과입니다. 가운데 몇 줄은 생략했습니다. 물결 밑줄 친 곳은 07번에서 다시 보고 누가 말했는지 가려내는 일은 다음 글에서 다룹니다.

01

소리는 숫자 줄이 되고 숫자 줄은 그림이 됩니다

왜 틀리는지 보려면 모델이 소리를 어떤 모양으로 받는지부터 알아야 합니다. 말소리는 공기의 떨림이고 마이크는 이 떨림의 세기를 아주 짧은 간격으로 재서 숫자로 적습니다.

받아쓰기 모델이 쓰는 녹음은 1초에 16,000번을 잽니다. 이것을 16kHz(킬로헤르츠)라고 부릅니다. 41초 회의라면 숫자 65만 개쯤의 긴 줄입니다. 모델은 이 줄을 그대로 읽지 않고 아래처럼 그림으로 바꿔서 읽습니다.

녹음 첫 3초("오늘은 배달앱 리뷰 분류기 출시 일정을 정하겠습니다")에서 실제로 계산한 그림입니다. ③은 whisper-large-v3-turbo가 실제로 읽는 설정과 같습니다. 높낮이를 128칸으로 나누고 0.01초마다 한 줄씩 그립니다.

②의 스펙트로그램(spectrogram)은 소리를 높낮이별로 쪼개 시간 순서로 늘어놓은 그림입니다. 악보에서 위아래가 음 높이, 왼쪽에서 오른쪽이 시간인 것과 비슷합니다. 악보에는 음이 하나씩 적히지만 말소리는 여러 높이가 한꺼번에 섞여 번진 띠로 보입니다.

세로축의 Hz는 1초에 몇 번 떠는 소리인지, 곧 소리 높이입니다. 앞의 16kHz는 1초에 몇 번 재는지를 뜻하니 서로 다릅니다. 1초에 16,000번 재면 8000Hz 소리까지 담을 수 있어서 그림 위쪽 끝이 8000Hz입니다.

③의 멜(mel)은 높낮이 칸을 사람 귀가 느끼는 간격에 맞춰 다시 나눈 것입니다. 사람은 낮은 소리의 차이는 잘 듣고 높은 소리의 차이는 덜 느껴서 낮은 쪽 칸을 더 촘촘하게 둡니다.

02

모델은 그림을 보며 글자 조각을 하나씩 고릅니다

멜 스펙트로그램을 받은 모델은 글을 한 번에 쓰지 않습니다. 그림 전체를 보면서 글자 조각을 하나 고르고 고른 조각을 붙인 다음 그다음 조각을 고릅니다. 이 글자 조각을 토큰(token)이라고 부릅니다.

다음 조각을 고를 때는 그림과 함께 지금까지 쓴 글도 봅니다. ChatGPT 같은 LLM(대형 언어 모델, 글을 이어 쓰도록 학습한 큰 모델)이 다음 낱말을 고르는 방식과 같습니다. 그래서 앞에서 "배달"이라고 썼다면 다음에는 "앱"처럼 이어지기 좋은 조각이 뽑히기 쉽습니다.

모델이 한 번에 보는 그림은 30초 분량입니다. 그보다 긴 녹음은 30초짜리 창(window)으로 잘라 차례로 읽습니다. 창은 녹음 위를 미끄러지는 30초 틀입니다. 41초 회의는 창 두 개, 1시간 회의는 창 120개쯤이 됩니다.

앞 글을 힌트로 받으면 창이 바뀌어도 말투와 낱말 표기가 이어집니다. 대신 창 1에서 잘못 적은 낱말이 창 2에서도 같은 모양으로 되풀이되기 쉽습니다. 그래서 받아쓰기 라이브러리에 따라 이 이어받기를 끄는 설정을 따로 두기도 합니다.

03

처음 듣는 낱말은 귀에 익은 말로 바뀝니다

원래 한 말은 "Supabase에 쌓인"입니다. 귀에는 "수파베이스에 싸인"처럼 들리고 모델은 "슈파베이스의 사인"을 골랐습니다. 모델이 들린 소리에 맞는 후보 여럿에 점수를 매기고 그중 높은 쪽을 고르기 때문입니다.

이 점수는 확률(probability), 곧 "이 글이 맞을 가능성"입니다. 학습 때 많이 본 말일수록 점수가 높습니다. 제품 이름이나 팀 안에서만 쓰는 말은 거의 본 적이 없으니, 비슷하게 들리는 흔한 말에 밀립니다.

받아쓰기 시험에서 처음 듣는 외국 이름을 아는 말로 적어 버리는 것과 같습니다. 선생님이 칠판에 이름을 써 주면 맞힙니다. 04번에서 볼 받아쓰기 API의 keywords(꼭 맞게 적어야 할 낱말 목록)가 그 칠판입니다. 02번 순서의 "후보 조각마다 점수" 단계에서 그 낱말 쪽 점수가 올라간다고 생각하면 됩니다. 다만 모델이 뜻을 따져 고치는 것은 아니어서 힌트를 줘도 틀릴 수 있습니다.

04

API로 받아쓸 때는 gpt-transcribe에 힌트를 같이 보냅니다

API(Application Programming Interface)는 내 프로그램이 다른 회사 서비스의 기능을 빌려 쓰는 창구입니다. OpenAI는 2026년 현재 녹음 파일 받아쓰기에 gpt-transcribe를 권합니다. 예전에 쓰던 whisper-1, gpt-4o-transcribe는 2027-02-26에 서비스를 끝낸다고 공지돼 있습니다.

보내는 것은 녹음 파일과 힌트 세 가지입니다. 회의가 어떤 자리인지 적은 prompt, 꼭 그렇게 적혀야 하는 낱말 목록 keywords, 들릴 언어 목록 languages입니다.

from openai import OpenAI

client = OpenAI()

with open("meeting.m4a", "rb") as audio:
    result = client.audio.transcriptions.create(
        # ① 2026 년 권장 받아쓰기 모델
        model="gpt-transcribe",
        file=audio,
        # ② 녹음이 어떤 자리인지 한두 문장
        prompt="배달 앱 리뷰 분류기 출시 회의. 참석자 김서연, 박도윤.",
        extra_body={
            # ③ 꼭 이렇게 적혀야 하는 낱말
            "keywords": ["Supabase", "리뷰 분류기", "도윤"],
            # ④ 들릴 언어
            "languages": ["ko", "en"],
        },
    )

print(result.text)

출력은 예시 답입니다. gpt-transcribe는 받아쓴 글을 통째로 돌려주고 문장마다 시간을 붙여 주지는 않습니다.

  1. gpt-transcribe는 OpenAI가 녹음 파일 받아쓰기에 권하는 모델입니다. 값은 1분에 0.0045달러라 1시간 회의는 약 0.27달러입니다(2026-11 모델 문서 기준). 코드는 파이썬 라이브러리 openai 3.46 기준입니다.
  2. prompt에는 녹음의 배경을 문장으로 적습니다. 참석자 이름과 회의 주제를 적어 두면 비슷한 소리 가운데 맞는 쪽을 고르기 쉬워집니다.
  3. keywords가 03번의 칠판입니다. 파이썬 라이브러리(SDK)에 아직 이 칸의 이름이 없어서 정해지지 않은 값을 그대로 실어 보내는 extra_body에 담습니다. 힌트일 뿐 꼭 그대로 나온다는 보장은 없다고 문서에 적혀 있습니다.
  4. languages에 한국어와 영어를 함께 주면 "Supabase"처럼 섞여 나오는 영어 낱말을 영어로 적기 쉬워집니다. 예전의 language(언어 하나)와 함께 보내면 안 됩니다.

05

25MB를 넘는 녹음은 줄이거나 나눠서 보냅니다

받아쓰기 API는 파일 하나에 25MB까지만 받습니다. 녹음 앱이 만든 파일을 그대로 보내면 1시간 회의는 대개 이 한도를 넘습니다. 아래 막대는 같은 1시간 녹음을 형식만 바꿔 저장했을 때의 크기입니다. WAV는 소리를 줄이지 않고 그대로 담은 형식이고 MP3·M4A는 귀에 덜 들리는 부분을 덜어 내 크기를 줄인 형식입니다.

말소리는 음악보다 훨씬 적은 정보로도 알아들을 수 있습니다. 그래서 왼쪽·오른쪽 구분 없는 한 채널(mono), 16kHz, 32kbps로 줄여도 받아쓰기 품질은 거의 그대로입니다. kbps는 1초 분량의 소리를 저장하는 데 쓰는 정보량입니다. 녹음·영상 파일을 바꾸는 무료 도구 ffmpeg로 한 줄이면 됩니다.

# 한 채널 · 16kHz · 32kbps 로 줄이기
ffmpeg -i meeting.wav -ac 1 -ar 16000 -b:a 32k meeting.m4a

그래도 넘는다면 파일을 나눕니다. 말이 잠깐 끊긴 곳에서 자르고 앞 조각에서 받아쓴 끝부분을 다음 조각의 prompt에 넣으면 낱말 표기가 조각마다 달라지지 않습니다.

06

회의 내용을 밖으로 보내기 어렵다면 내 컴퓨터에서 받아씁니다

API로 받아쓰면 녹음 파일이 인터넷을 거쳐 OpenAI 서버까지 갔다가 글이 되어 돌아옵니다. 회사 회의처럼 밖으로 나가면 안 되는 녹음이라면 이 길 자체가 문제입니다.

Whisper는 모델 파일이 공개돼 있어서 내 컴퓨터로 내려받아 돌릴 수 있습니다. 모델 파일을 모아 둔 Hugging Face에서 openai/whisper-large-v3-turbo를 받아 쓰면, 녹음은 노트북 밖으로 나가지 않습니다. 요금도 들지 않고 문장마다 시간도 붙여 줍니다.

04번에서 본 whisper-1 종료는 OpenAI API 안의 모델 이름이 끝난다는 뜻입니다. 공개된 Whisper 모델 파일은 지금처럼 내려받아 쓸 수 있습니다.

대신 컴퓨터가 일을 다 합니다. 이 모델은 파라미터(parameter)가 8억 900만 개입니다. 파라미터는 모델이 학습으로 정해 둔 숫자들이고 많을수록 무겁습니다. GPU가 없으면 회의 길이보다 오래 걸릴 수도 있습니다.

import torch
from transformers import pipeline

# ① GPU 가 있으면 쓰고, 없으면 CPU
if torch.cuda.is_available():
    device = "cuda:0"
elif torch.backends.mps.is_available():
    device = "mps"
else:
    device = "cpu"

# ② 받아쓰기 파이프라인 만들기
asr = pipeline(
    "automatic-speech-recognition",
    model="openai/whisper-large-v3-turbo",
    dtype=torch.float16 if device != "cpu" else torch.float32,
    device=device,
)

# ③ 문장 조각마다 시작·끝 시간도 받는다
result = asr(
    "meeting.wav",
    return_timestamps=True,
    generate_kwargs={"language": "korean"},
)

for c in result["chunks"]:
    start, end = c["timestamp"]
    print(f"[{start:5.1f} ~ {end:5.1f}] {c['text'].strip()}")

예시 회의 녹음을 Apple 칩 노트북에서 실제로 돌린 출력입니다. 빨간 시간 두 개는 07번에서 봅니다.

  1. GPU는 그림·행렬 계산을 한꺼번에 처리하는 칩입니다. NVIDIA GPU면 cuda, Apple 칩 맥이면 mps를 씁니다. 없으면 CPU로 돌지만 많이 느립니다.
  2. 파이프라인(pipeline)은 여러 단계를 차례로 이어 붙인 작업 줄입니다. transformers 라이브러리의 pipeline은 모델 내려받기·소리를 멜 그림으로 바꾸기·글자 조각 고르기를 한 번에 해 줍니다. 녹음 파일을 읽을 때 ffmpeg를 쓰니 먼저 깔아 둡니다.
  3. return_timestamps=True면 문장 조각마다 시작·끝 초를 붙여 줍니다. "word"를 주면 낱말마다 붙습니다. 30초가 넘는 녹음은 파이프라인이 02번의 30초 창으로 나눠 읽습니다.
숫자 정밀도(dtype)와 라이브러리 버전 메모

float16은 숫자를 절반 크기로 저장해 GPU 메모리를 아끼는 설정입니다. CPU에서는 느려지거나 오류가 나서 float32를 씁니다. 코드는 transformers 5.22 기준이고 5.x부터는 예전 이름 torch_dtype 대신 dtype을 씁니다.

07

받아쓴 시간과 실제로 말한 시간은 어긋날 수 있습니다

앞 터미널의 빨간 시간 두 개를 실제 녹음과 겹쳐 보면 문제가 드러납니다. 아래에서 위쪽 줄은 두 사람이 실제로 말한 구간, 아래쪽 줄은 Whisper가 붙인 시간 조각입니다. 조각마다 번호를 붙여 터미널의 줄과 맞췄습니다.

Whisper의 시간은 낱말 하나하나를 정밀하게 잰 값이 아니라, 글을 쓰면서 함께 고른 "대략 이쯤"입니다. 둘 다 30초 창 경계 바로 앞뒤라 창을 이어 붙이는 과정과 관련 있어 보이지만 원인을 하나로 단정하기는 어렵습니다.

회의록에 시간만 적는다면 큰 문제가 아닙니다. 하지만 "누가 말했는지"를 붙이려면 이 시간을 말한 사람 구간과 맞춰야 합니다. ②처럼 두 사람 말이 한 조각에 섞이면 한 사람에게 몰아서 붙습니다. 이 맞추기는 다음 글에서 다룹니다.

08

받아쓰기를 붙이기 전에 고를 것

  1. 녹음이 회사 밖으로 나가도 되는지부터 확인합니다. 안 되면 내 컴퓨터에서 Whisper를 돌리고 괜찮으면 gpt-transcribe가 간편합니다.
  2. 팀 이름·제품 이름·사람 이름처럼 자주 틀릴 낱말을 모아 keywords와 prompt에 넣습니다. 받아쓴 결과에서 틀린 낱말을 찾으면 목록에 더해 갑니다.
  3. 파일은 한 채널·16kHz·32kbps로 줄여 25MB 안에 넣고 그래도 넘으면 말이 끊긴 곳에서 나눕니다.
  4. 회의록에 시간이나 말한 사람이 필요하다면 시간 조각을 주는 방식을 고르고 그 시간이 몇 초씩 틀릴 수 있다는 것을 감안합니다.
