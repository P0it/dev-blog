챗봇은 오늘 주가를 어디서 보고 말할까요?

어떤 챗봇은 오늘 주가를 물으면 모른다고 하고 어떤 챗봇은 방금 본 듯 숫자를 말합니다. 똑같은 모델을 써도 이런 차이가 납니다. 숫자를 가져오는 쪽이 모델이 아니라 챗봇을 만든 사람이 짜 둔 프로그램이기 때문입니다. 그 프로그램 안에서 모델 대신 일을 해 주는 함수(미리 짜 둔 명령 묶음)를 도구(tool)라고 부릅니다.

PART 1화면 뒤의 왕복: 모델은 부탁만 합니다

모델은 왜 오늘을 모를까요?

모델의 지식은 학습이 끝난 날에 멈춰 있기 때문입니다. 이 날짜를 학습 종료 시점(knowledge cutoff)이라고 부릅니다. 시험 범위까지만 공부하고 독방에 들어간 사람과 비슷합니다.

모델은 기억 속 글을 이어 쓰듯 답을 만듭니다. 그래서 오늘 주가를 물으면 모른다고 하거나, 그럴듯한 숫자를 지어내기도 합니다. 금융 질문에서 이런 지어내기(hallucination)가 심각하다는 2023년 연구도 있습니다.

모델을 더 공부시켜도 해결되지 않습니다. 독방 문틈으로 쪽지를 주고받게 하면 됩니다. 이 방식이 함수 호출(Function Calling)입니다.

질문 하나에 모델은 왜 두 번 불릴까요?

모델은 조회를 직접 하지 못하고 부탁만 적기 때문입니다. 스크롤을 내리면 질문 하나가 세 줄(화면·내 코드·모델)을 오가는 길이 차례로 켜지고 그 아래 input 목록이 한 줄씩 자랍니다.

사용자가 묻습니다

화면에 보이는 건 여기까지입니다. 이제부터 챗봇을 만드는 사람 입장에서 그 프로그램을 "내 코드"라고 부르겠습니다. 입력한 문장은 input이라는 목록의 첫 줄이 됩니다.

호출 1: 질문과 도구 설명서를 보냅니다

내 코드가 API(프로그램끼리 서로 부르는 창구)로 모델을 부릅니다. 도구는 내 코드 안에 있는 함수입니다. 모델은 그 함수를 볼 수 없어서 "이런 도구를 쓸 수 있어"라는 설명서를 함께 보냅니다.

모델은 답 대신 부탁을 적습니다

"get_stock_quote를 TSLA로 실행해 줘"라는 쪽지가 돌아옵니다. 이 쪽지가 function_call입니다. 모델은 아무것도 실행하지 않았습니다.

내 코드가 실행합니다

주가를 조회하는 건 이 순간뿐이고 값은 야후 파이낸스에서 옵니다. 결과는 function_call_output으로 목록에 붙입니다.

호출 2: 목록 전체를 다시 보냅니다

모델은 앞선 호출을 기억하지 않습니다. 질문, 쪽지, 결과를 모두 담아 새로 불러야 합니다. 여기서는 쪽지 비유가 안 맞습니다. 독방의 사람은 기다리지만 모델은 호출마다 처음부터 읽습니다.

모델이 값을 읽고 문장을 씁니다

이번에는 더 부탁할 게 없으니 답을 적습니다. 그래서 화면에는 답 하나만 보여도 모델은 두 번 불렸습니다.

코드로 옮기면 while 문 하나입니다

왕복은 모델이 더 부탁하지 않을 때까지 도는 반복문으로 끝납니다. 호출 횟수는 정해져 있지 않아서 모델이 도구를 또 부르면 세 번, 네 번이 됩니다. 아래 코드 표지 ①~⑤는 OpenAI 공식 도식의 번호와 같습니다. INSTRUCTIONS는 모델에게 주는 지시문으로, 사용자에게는 보이지 않습니다.

import sys
from openai import OpenAI
from stock_tools import tools, run_tool

client = OpenAI()
INSTRUCTIONS = ("미국 주식 도우미다. 숫자는 도구 결과에서만 가져오고 "
                "기준 시각을 함께 말한다.")

def ask(question: str) -> str:
    items = [{"role": "user", "content": question}]
    while True:
        # ①④ 목록 전체와 설명서를 보낸다
        response = client.responses.create(
            model="gpt-6.1-sol", instructions=INSTRUCTIONS,
            input=items, tools=tools)
        # ② 모델이 적은 것을 그대로 목록에 붙인다
        items += response.output
        calls = [i for i in response.output
                 if i.type == "function_call"]
        # ⑤ 부탁이 없으면 답이 나온 것이다
        if not calls:
            return response.output_text
        for call in calls:
            # ③ 내 코드가 실행하고 결과를 붙인다
            print(f"  [도구] {call.name}({call.arguments})")
            items.append(run_tool(call))

print(ask(sys.argv[1]))

버전: openai 3.46.0, 모델 gpt-6.1-sol (2026-11-05 확인)

  1. 13~15행. 첫 바퀴는 질문 한 줄, 다음 바퀴부터는 쌓인 목록 전체를 보냅니다. tools를 빼면 모델은 도구가 있는지조차 모릅니다.
  2. 17행. response.output을 통째로 붙입니다. 추론 모델(답 전에 생각 단계를 거치는 모델)은 reasoning 항목도 함께 돌려줘야 해서 function_call만 골라 붙이면 안 됩니다.
  3. 25~26행. 문자열로 온 인자를 파이썬 함수로 실행합니다. run_tool은 조금 뒤에 나옵니다.
  4. 다시 13~15행. 되돌려 보내는 호출입니다. 같은 줄이 또 실행됩니다.
  5. 21~22행. 도구 호출이 없는 응답이면 output_text에 답이 들어 있습니다.

모델은 설명서만 읽고 도구를 고릅니다

모델이 읽는 건 내가 적어 준 이름과 설명뿐이고 함수 안의 코드는 보이지 않습니다. 설명서는 JSON(프로그램끼리 주고받는 글 형식)으로 전달됩니다. 파이썬에서는 딕셔너리로 쓰면 SDK가 JSON으로 바꿔 보냅니다.

함수에 넘기는 칸을 파라미터(parameter), 칸에 넣는 실제 값을 인자(argument)라고 합니다. ticker 칸에는 티커(주식시장에서 쓰는 종목의 짧은 이름표)가 들어갑니다. 사용자가 "테슬라"라고 해도 모델이 설명서의 예를 보고 TSLA로 바꿔 넣습니다.

strict는 칸 밖에 답을 쓸 수 없는 답안지와 같습니다. 켜면 모델이 형식에 어긋난 인자를 만들지 못합니다. 조건은 모든 칸을 required에 넣고 additionalProperties를 끄는 것입니다.

도시 네 곳을 물으면 쪽지가 네 장 옵니다

모델은 쪽지를 한 번에 네 장 씁니다. 이를 병렬 호출(parallel tool calls)이라고 합니다. 쪽지마다 call_id라는 번호가 있고 결과도 같은 번호를 달아 돌려줘야 합니다. 한 장이라도 빠지면 다음 호출은 400 오류(요청이 잘못됐다는 응답)로 거절됩니다. 쪽지가 한 장뿐이라고 가정하고 하나만 처리한 코드가 흔히 이렇게 깨집니다.

call_a1 같은 번호는 예시입니다. 실제 번호는 API가 만들어 줍니다.

FUNCTIONS = {t["name"]: globals()[t["name"]] for t in tools}

def run_tool(call) -> dict:
    # ① 쪽지에 적힌 이름과 인자로 실행한다
    try:
        args = json.loads(call.arguments)
        output = FUNCTIONS[call.name](**args)
    except Exception as e:  # ② 실패도 글로 알려 준다
        output = json.dumps({"error": str(e)},
                            ensure_ascii=False)
    # ③ 같은 번호를 달아 돌려준다
    return {"type": "function_call_output",
            "call_id": call.call_id, "output": output}
  1. 모델이 적은 이름으로 함수를 찾습니다. globals()는 이 파일의 함수를 이름으로 찾는 표이고 **args는 딕셔너리를 함수 인자로 풀어 넘깁니다. 표에 없는 이름은 실행되지 않으니, 모델이 아무 코드나 돌리게 되는 일은 없습니다.
  2. 오류를 그냥 던지면 앱이 멈춥니다. 글로 돌려주면 모델이 사용자에게 사정을 설명하거나 다른 값으로 다시 시도합니다.
  3. 쪽지가 여러 장이어도 순서가 아니라 call_id로 짝을 맞춥니다.

PART 2주식 도구: 무엇을 돌려줄지가 답을 정합니다

필드 180개 중 7개만 돌려줍니다

야후 응답을 통째로 넘겨도 답은 나오지만 낭비가 큽니다. yfinance는 야후 파이낸스 값을 파이썬으로 읽어 오는 라이브러리이고 .info는 한 종목의 정보를 180개 필드(이름표가 붙은 값 한 칸)로 돌려줍니다.

모델은 글을 토큰(token)이라는 조각 단위로 읽고 요금도 토큰으로 냅니다. 게다가 도구 결과는 input 목록에 남아 왕복마다 다시 보내집니다. 그래서 답에 쓸 필드만 골라 돌려줍니다.

기준 시각도 꼭 함께 줍니다. 조회 시점은 프리마켓(정규장 전 거래 시간)이었고 385.19달러는 전날 장 마감 값이었습니다. 시각이 없으면 모델은 이걸 "지금 값"이라고 말합니다.

칸 하나가 .info 필드 하나입니다. 칠한 7칸만 씁니다. symbol, shortName, currency, currentPrice, marketCap, marketState, regularMarketTime

단위는 토큰입니다. 2026-11-05 TSLA 응답을 tiktoken(o200k_base)으로 세었습니다.

def get_stock_quote(ticker: str) -> str:
    info = yf.Ticker(ticker).info
    if "regularMarketTime" not in info:
        msg = f"{ticker} 종목을 찾지 못했습니다"
        return json.dumps({"error": msg}, ensure_ascii=False)
    # ① 180개 필드에서 답에 쓸 것만 고른다
    keep = ["symbol", "shortName", "currency",
            "currentPrice", "marketCap", "marketState"]
    result = {k: info.get(k) for k in keep}
    # ② 언제 값인지 함께 돌려준다
    when = info["regularMarketTime"]
    iso = datetime.fromtimestamp(when, tz.utc).isoformat()
    result["as_of"] = iso
    return json.dumps(result, ensure_ascii=False)

def get_stock_history(ticker: str, period: str) -> str:
    closes = yf.Ticker(ticker).history(period=period)["Close"]
    if closes.empty:
        msg = f"{ticker} 데이터가 없습니다"
        return json.dumps({"error": msg}, ensure_ascii=False)
    first, last = closes.iloc[0], closes.iloc[-1]
    # ① 표를 통째로 보내지 않고 요약한다
    return json.dumps({
        "ticker": ticker, "period": period,
        "first": {"date": str(closes.index[0].date()),
                  "close": round(float(first), 2)},
        "last": {"date": str(closes.index[-1].date()),
                 "close": round(float(last), 2)},
        "change_pct": round(float(last / first - 1) * 100, 2),
        "high": round(float(closes.max()), 2),
        "low": round(float(closes.min()), 2),
        "sessions": len(closes),
    })
  1. 계산은 코드가 끝내고 모델에게는 답만 건넵니다. 한 달치 표는 1,378토큰, 이 요약은 89토큰입니다. 모델이 나눗셈을 틀릴 위험도 함께 사라집니다.

답은 왜 한 글자씩 나올까요?

끝까지 기다리는 답답함을 없애려고 그렇게 보여 줍니다. 모델은 글을 앞에서부터 조각조각 만듭니다. 완성될 때까지 쥐고 있다가 한 번에 주느냐, 만드는 대로 흘려 주느냐의 차이입니다. 흘려 주는 방식이 스트리밍(streaming)입니다.

스트리밍을 켜도 답이 빨리 완성되지는 않습니다. 첫 글자만 빨라집니다. 도구 조회처럼 글자가 없는 시간도 있으니, 그동안 화면에 무엇을 보여 줄지도 정해야 합니다.

쪽지도 조각으로 흘러옵니다

글자뿐 아니라 쪽지도 조각으로 옵니다. 서버(요청을 받아 응답하는 컴퓨터)는 SSE(Server-Sent Events)라는 방식으로 이벤트를 하나씩 밀어 줍니다. 이벤트는 일어난 일을 알리는 짧은 메시지이고 답의 글자 조각과 인자의 글자 조각은 이름이 다릅니다.

중간에 있는 인자 조각은 온전한 JSON이 아니라서 json.loads가 실패합니다. 그림의 ✗가 그 순간입니다.

예전에는 이 조각을 직접 이어 붙이는 함수를 짰습니다. 지금은 필요 없습니다. 마지막 response.completed 이벤트에 완성된 응답이 통째로 들어 있기 때문입니다.

조각을 어디서 끊는지는 그때그때 다르며 위 끊김은 예시입니다. 완성된 값은 function_call_arguments.done과 response.completed에 실려 옵니다.

def stream_turn(items, on_tool=print):
    while True:
        stream = client.responses.create(
            model="gpt-6.1-sol", instructions=INSTRUCTIONS,
            input=items, tools=tools, stream=True)
        final = None
        for event in stream:
            if event.type == "response.output_text.delta":
                # ① 답의 글자는 바로 화면으로 흘린다
                yield event.delta
            elif (event.type == "response.output_item.added"
                  and event.item.type == "function_call"):
                # ② 도구 이름은 인자보다 먼저 온다
                on_tool(event.item.name)
            elif event.type == "response.completed":
                # ③ 완성본은 여기서 받는다
                final = event.response
        items += final.output
        calls = [i for i in final.output
                 if i.type == "function_call"]
        if not calls:
            return
        for call in calls:
            items.append(run_tool(call))
  1. yield는 값을 하나 내주고 잠시 멈추는 파이썬 문법입니다. 이 함수를 받는 쪽이 글자를 받는 대로 그립니다.
  2. 인자가 다 모이기 전에 "주가 기록 조회 중"이라고 띄울 수 있습니다. 글자 없는 시간을 메우는 자리입니다.
  3. event.response.output은 앞서 본 기본 루프의 response.output과 같은 모양입니다. 그래서 아래쪽 코드가 거의 그대로입니다.

from stream_loop import stream_turn

LABELS = {"get_stock_quote": "현재 주가 조회",
          "get_stock_history": "주가 기록 조회",
          "get_analyst_view": "애널리스트 의견 조회",
          "get_current_time": "시각 확인"}
# ① 다시 실행되어도 남는 저장소에 대화를 둔다
if "history" not in st.session_state:
    st.session_state.history = []
    st.session_state.chat = []

st.title("주식 도우미")
for role, text in st.session_state.chat:
    st.chat_message(role).write(text)

if question := st.chat_input("종목을 물어보세요"):
    st.chat_message("user").write(question)
    st.session_state.chat.append(("user", question))
    st.session_state.history.append(
        {"role": "user", "content": question})
    with st.chat_message("assistant"):
        # ② 도구 시간을 메울 상태 칸
        status = st.status("생각하는 중", expanded=True)
        def on_tool(name):

        # ③ 글자가 오는 대로 그리고 다 모은 문자열을 돌려준다

        status.update(label="조회 완료", state="complete",

    st.session_state.chat.append(("assistant", answer))

  3. write_stream은 글자를 그리고 합친 문자열을 돌려줍니다. 이 문자열은 말풍선을 다시 그릴 chat에 넣습니다. API에 보낼 history는 도구 쪽지까지 담기므로 따로 둡니다.

PART 4서비스로 낼 때: 숫자가 맞아도 끝이 아닙니다

도구가 있으면 답을 믿어도 될까요?

숫자는 믿을 근거가 생겨도, 해석은 여전히 모델의 글입니다. 그림의 답에서 칠한 숫자는 도구에서 왔고 물결 친 문장은 모델이 쓴 것입니다. 화면에서 둘을 구별해 주면 사용자가 스스로 판단할 수 있습니다.

도구를 줘도 어려운 금융 과제를 다 해내지는 못합니다. 도구를 스스로 골라 쓰는 프로그램을 에이전트(agent)라고 하는데, 금융 분석가 수준의 시험(벤치마크)에서 2026년 6월 기준 최고 성적도 세 문제 중 하나는 틀렸습니다.

뉴스 도구를 달면 남이 쓴 글이 모델 입력으로 들어옵니다. 기사나 댓글 속에 지시문을 숨겨 모델을 조종하려는 시도가 프롬프트 인젝션(prompt injection)입니다. 도구 결과는 모델이 그대로 읽으니, 그림의 빨간 문장도 지시처럼 읽힐 수 있습니다.

설명을 위해 지어낸 예시 값입니다.

도구는 꼭 내 코드에서 돌아야 할까요?

아닙니다. 검색을 켠 챗봇이 출처 링크를 달아 답할 때도 도구가 돌아갑니다. 다만 실행하는 자리가 다릅니다. 이 글의 함수는 내 앱에서 돌아서 왕복을 내가 짭니다. web_search처럼 OpenAI에 내장된 도구는 OpenAI 쪽에서 실행되어 왕복 코드가 필요 없습니다. 대신 검색 1,000회에 10달러가 붙고 무엇을 돌려줄지 내가 고르지 못합니다.

MCP(Model Context Protocol)는 데이터 회사가 도구를 서버로 열어 두는 공통 규격입니다. Alpha Vantage처럼 금융 데이터 MCP 서버를 공개한 곳이 있습니다. 다만 야후의 공식 MCP 서버는 확인하지 못했습니다.

만들기 전에 정할 세 가지

코드가 돌아가도 서비스로 내려면 이 셋은 처음부터 정해 둡니다.

데이터를 어디서 받을까yfinance는 야후와 무관한 비공식 도구이고 개인 연구·교육용을 전제합니다. 야후도 값을 다른 곳에 다시 내보내지 말라고 합니다. 서비스라면 Alpha Vantage나 Massive(옛 Polygon.io) 같은 유료 API를 씁니다.
스트림이 끊기면 어떻게 할까error 이벤트와 response.completed 없이 끝나는 경우를 처리합니다. 위 코드는 줄이느라 뺐고 이대로면 final이 None이라 오류가 납니다.
투자 조언 선을 어디에 둘까"사세요·파세요"를 말하지 않도록 지시문(instructions)에 적고 화면에도 투자 조언이 아니라고 밝힙니다. 규제는 나라마다 다르니 따로 확인합니다.
더 볼 것: tool_choice, 시세 지연, 스트림 내용 검사

tool_choice의 기본은 auto(모델이 판단)입니다. 주가 질문만 받는 앱이면 required로 지어낼 틈을 줄입니다.

이 글에서 받은 값에는 15분 지연 표시(exchangeDataDelayedBy)가 있었습니다. 요청이 많으면 YFRateLimitError도 만납니다.

스트리밍은 이미 보낸 글자를 되돌릴 수 없어서 내용 검사가 어렵다고 공식 문서도 적어 둡니다. 답을 검사해야 한다면 나눠서 보여 주는 지점을 정합니다.

그래서 그 숫자는 어디서 왔을까요?

모델은 야후 파이낸스를 본 적이 없습니다. 내 코드가 가져온 값을 읽고 문장을 썼을 뿐입니다.

챗봇의 품질은 모델만으로 정해지지 않습니다. 어떤 도구를 주고 무엇을 돌려주고 언제 값인지 적어 주느냐가 답을 정합니다.
