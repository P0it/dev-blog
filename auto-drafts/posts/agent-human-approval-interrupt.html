Agent가 결제하기 전에 사람이 확인하게 하려면 어떻게 할까요?

회사 비품을 주문하는 Agent에게 "모니터 두 대 사 줘"라고 했더니 27인치 대신 49인치 두 대가 결제됐다고 해 보겠습니다. LLM은 판단이 틀릴 수 있고 결제는 되돌리기 어렵습니다. 그렇다고 모든 단계를 사람이 확인하면 Agent를 쓰는 의미가 없습니다. 위험한 순간에만 멈추고 사람의 답을 기다리게 하는 방법을 봅니다.

확인 없이 실행하면 무엇이 문제인가요?

LLM이 틀린 판단을 그대로 실행합니다. 되돌릴 수 없는 일이면 그대로 손해입니다.

지금까지의 Agent는 LLM이 도구를 부탁하면 프로그램이 곧바로 실행했습니다. 검색이나 조회라면 틀려도 다시 하면 되지만 결제·삭제·메일 발송처럼 되돌리기 어려운 일은 한 번 틀리면 끝입니다.

사람이 확인한 뒤에 실행하게 하는 구조를 Human-in-the-loop라고 합니다. Agent의 반복 안에 사람이 들어가 있다는 뜻입니다. 위험한 도구 앞에만 멈추는 곳을 두고 나머지는 그대로 Agent에게 맡기는 것이 핵심입니다.

확인을 넣으면 어떻게 움직이나요?

결제 부탁이 오면 실행 직전에 멈추고 사람의 답을 받은 뒤에 이어 갑니다.

LLM이 결제 도구를 부탁하면 프로그램은 바로 실행하지 않고 반복을 멈춥니다. 무엇을 하려는지(도구 이름과 값)를 사람에게 보여 주고 답을 기다립니다. 이렇게 실행을 멈추는 일을 interrupt라고 합니다.

사람의 답은 보통 네 가지입니다. 그대로 승인, 값을 고쳐서 승인, 거절, 그리고 거절하면서 이유를 LLM에게 전하기입니다. 거절 이유를 전하면 LLM은 그것을 읽고 다른 상품을 찾는 등 다음 행동을 다시 고릅니다.

사람이 내일 답하면 그동안 Agent는 어디에 있나요?

상태가 저장소에 저장되어 있고 프로그램은 다른 일을 합니다. 답이 오면 그 상태를 불러와 이어 갑니다.

사람의 답은 몇 분 뒤에 도착할 수도 있고 다음 날 올 수도 있습니다. 그동안 프로그램이 반복문 안에서 기다리면 서버 자원을 붙잡게 되고 서버가 재시작되면 진행하던 일이 사라집니다.

그래서 멈출 때 지금까지의 메시지 목록과 상태를 저장소에 저장하고 요청을 끝냅니다. 앞 글에서 본 checkpointer가 이 일을 합니다. 승인이 오면 같은 대화방 번호로 저장한 상태를 불러와 멈춘 곳부터 이어 갑니다. 메모리에 저장하는 checkpointer는 서버가 꺼지면 사라지므로 서비스에서는 데이터베이스에 저장합니다.

어떤 도구에 확인을 걸어야 하나요?

되돌리기 어렵거나, 돈이 나가거나, 바깥에 보이는 일입니다.

도구확인이유
상품 검색, 주문 조회없음읽기만 함. 틀리면 다시 하면 됨
장바구니 담기없음되돌릴 수 있음
결제승인 · 수정 · 거절돈이 나감
메일·메시지 발송승인 · 수정보낸 뒤 취소 불가, 바깥에 보임
데이터 삭제승인 · 거절 (수정 불가)되돌릴 수 없음

모든 도구에 확인을 걸면 사람이 버튼만 누르는 일이 되고 결국 내용을 읽지 않고 승인하게 됩니다. 확인은 꼭 필요한 곳에만 겁니다. 금액이 일정 이상일 때만 확인하는 식으로 조건을 붙이기도 합니다.

확인 화면에는 사람이 판단할 수 있는 정보를 보여 줘야 합니다. "place_order 실행할까요?"보다 "49인치 모니터 2대, 312만 원, 배송지 본사"가 낫습니다. 누가 언제 무엇을 승인했는지는 따로 기록해 둡니다. 문제가 생겼을 때 그 기록으로 확인합니다.

코드로 쓰면 어떻게 되나요?

확인할 도구를 middleware에 적고 멈춘 실행을 사람의 답으로 이어 갑니다.

from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

agent = create_agent(
    model="anthropic:claude-sonnet-5-5",
    tools=[search_products, place_order],
    # ① 멈췄다 이어 가려면 상태를 저장할 곳이 있어야 한다
    checkpointer=InMemorySaver(),
    middleware=[HumanInTheLoopMiddleware(interrupt_on={
        # ② 결제만 확인. 검색은 그대로 실행
        "place_order": {"allowed_decisions": ["approve", "edit", "reject"]},
        "search_products": False,
    })],
)
config = {"configurable": {"thread_id": "order-301"}}

# ③ 결제 부탁이 나오면 실행하지 않고 멈춘다
result = agent.invoke(
    {"messages": [{"role": "user", "content": "모니터 두 대 사 줘."}]},
    config=config, version="v2")
for intr in result.interrupts:
    print(intr.value["action_requests"])   # 무엇을 하려는지 사람에게 보여 준다

# ④ (다음 날) 사람이 값을 고쳐 승인하면 같은 thread_id 로 이어 간다
agent.invoke(Command(resume={"decisions": [{
    "type": "edit",
    "edited_action": {"name": "place_order",
                      "args": {"product": "27인치 모니터", "count": 2}},
}]}), config=config, version="v2")
  1. 멈춘 상태를 저장할 checkpointer입니다. 예제라 메모리에 저장했습니다. 서비스에서는 Postgres 같은 저장소를 씁니다.
  2. 도구마다 확인을 걸지, 어떤 답을 허용할지 적습니다. False는 확인 없이 실행입니다.
  3. version="v2"로 부르면 결과의 interrupts에 멈춘 이유와 실행하려던 도구·값이 들어 있습니다. 이것으로 확인 화면을 만듭니다.
  4. Command(resume=...)에 사람의 답을 담아 같은 thread_id로 부릅니다. 승인은 {"type": "approve"}, 거절은 {"type": "reject"}입니다.

코드는 langchain 1.5·langgraph 1.2 기준입니다. 확인 화면은 웹 페이지든 메신저 버튼이든 서비스에 맞게 만듭니다. 그래프를 직접 그렸다면 노드 안에서 interrupt()를 부르면 같은 방식으로 멈추고 Command(resume=...)로 이어 갑니다.
