우리 회사 시스템을 MCP 서버로 열려면 무엇을 해야 할까요?

사내 티켓 시스템을 Claude 앱과 사내 Agent 모두에서 쓰게 하고 싶다고 해 보겠습니다. MCP 서버를 하나 만들면 되는데, 막상 만들려면 질문이 생깁니다. 함수를 어떻게 도구로 내놓는지, 잘 되는지 어떻게 확인하는지, 아무나 티켓을 닫지 못하게 하려면 무엇을 막아야 하는지. 티켓 서버 하나를 처음부터 만들어 보며 차례로 봅니다.

MCP 서버는 무엇을 하는 프로그램인가요?

Host가 물으면 도구 목록을 알려 주고 실행을 요청하면 함수를 실행해 결과를 돌려줍니다.

MCP 서버가 새로 하는 일은 많지 않습니다. 기존 티켓 시스템 API는 그대로 두고 그 앞에서 MCP 형식으로 도구 목록을 알려 주고 실행 요청을 받아 API를 대신 부릅니다. 결과는 LLM이 읽기 좋게 다듬어 돌려줍니다.

그래서 MCP 서버를 만드는 일은 대부분 도구 설계입니다. 도구 설계 규칙이 그대로 적용됩니다. 이름과 설명은 분명하게, 결과는 필요한 만큼만, 오류는 고칠 방법을 적어서.

함수를 어떻게 도구로 내놓나요?

함수에 데코레이터 하나를 붙입니다. 타입 힌트와 docstring이 도구 설명이 됩니다.

함수 하나 → 도구 하나
@mcp.tool() def get_ticket(ticket_id: str) -> str: """티켓 하나의 제목·상태·담당자·최근 댓글을 돌려준다. 번호를 모르면 먼저 search_tickets 로 찾는다."""
Host가 받는 도구 목록 (줄임)
{ "name": "get_ticket", "description": "티켓 하나의 제목·상태·담당자·최근 댓글을 돌려준다. …", "inputSchema": { "type": "object", "properties": { "ticket_id": { "type": "string" } }, "required": ["ticket_id"] } }

공식 Python SDK에서는 MCPServer 객체를 만들고 함수에 @mcp.tool()을 붙입니다. 함수 이름이 도구 이름, docstring이 description, 타입 힌트가 입력 형식(inputSchema)이 됩니다. LangChain의 @tool과 같은 방식입니다.

도구에는 성격을 알리는 표시(annotations)도 붙일 수 있습니다. "읽기만 한다", "되돌릴 수 없다" 같은 표시입니다. Host는 이것을 보고 위험한 도구 앞에서 사용자에게 확인을 받기도 합니다. 표시는 참고일 뿐이라 Host가 꼭 지킨다는 보장은 없습니다. 위험한 일은 서버 쪽에서도 막아야 합니다.

잘 만들었는지 어떻게 확인하나요?

MCP Inspector로 도구 목록을 보고 직접 실행해 봅니다. 그다음 실제 Host에 꽂아 LLM이 잘 고르는지 봅니다.

MCP Inspector는 MCP 서버를 띄워 놓고 브라우저에서 도구 목록을 보고 값을 넣어 실행해 보는 도구입니다. 공식 SDK에서는 mcp dev server.py 한 줄로 서버와 Inspector가 함께 뜹니다. 입력 칸은 타입 힌트에서 자동으로 만들어집니다.

Inspector에서 잘 돌아도 LLM이 도구를 잘 고르는지는 따로 봐야 합니다. Claude 앱이나 우리 Agent에 서버를 꽂고 "지난주에 내가 연 와이파이 티켓 상태 알려 줘" 같은 질문을 던져 봅니다. 엉뚱한 도구를 고르면 설명을 고칩니다. 질문 묶음을 정해 두고 고칠 때마다 다시 돌려 보면 더 좋습니다.

아무나 티켓을 닫지 못하게 하려면요?

원격 서버는 OAuth로 사용자를 확인하고 그 사용자의 권한 안에서만 도구를 실행합니다.

내 컴퓨터에서 stdio로 띄우는 서버는 내 권한으로 실행되니 로그인이 필요 없습니다. 원격 서버는 누가 부르는지 알아야 합니다. MCP 규격은 원격 서버의 인증 방식으로 OAuth를 정해 두었습니다. 사용자가 사내 계정으로 로그인하면 Host가 토큰을 받아 요청마다 붙입니다.

서버는 토큰으로 사용자를 확인하고 그 사용자의 권한 안에서만 실행합니다. 누구의 티켓인지 같은 값은 LLM이 넣게 하지 않고 토큰에서 꺼냅니다. 읽기 도구와 쓰기 도구를 나누고 토큰에 필요한 범위(scope)만 주는 것도 같은 원칙입니다.

서버를 인터넷에 열 때 하나 더 있습니다. 공식 Python SDK의 HTTP 서버는 기본으로 localhost에서 온 요청만 받도록 막혀 있어서 실제 주소로 배포하면 허용할 호스트를 직접 설정해야 합니다.

코드로 쓰면 어떻게 되나요?

서버 객체 하나, 도구 함수 몇 개, 실행 한 줄입니다.

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from mcp.types import ToolAnnotations

mcp = MCPServer("tickets")

# ① 읽기 도구: 결과는 필요한 줄만
@mcp.tool(annotations=ToolAnnotations(read_only_hint=True))
def get_ticket(ticket_id: str) -> str:
    """티켓 하나의 제목·상태·담당자·최근 댓글을 돌려준다.
    번호를 모르면 먼저 search_tickets 로 찾는다."""
    t = ticket_api.get(ticket_id)
    if t is None:
        # ② ToolError 의 글만 LLM 에게 전달된다
        raise ToolError(f"{ticket_id} 를 찾지 못했습니다. "
                        "번호는 T- 뒤 숫자 네 자리입니다.")
    return f"{t.id} · {t.title} · {t.status} · 담당 {t.owner}\n최근 댓글: {t.last_comment}"

# ③ 쓰기 도구: 되돌릴 수 없음을 표시하고, 권한은 서버가 확인한다
@mcp.tool(annotations=ToolAnnotations(destructive_hint=True))
def close_ticket(ticket_id: str, reason: str) -> str:
    """티켓을 닫는다. 닫은 티켓은 다시 열 수 없다. 사용자가 분명히 요청할 때만 쓴다."""
    user = current_user()               # 토큰에서 꺼낸 사용자
    if not user.can("tickets:close"):
        raise ToolError("이 사용자에게는 티켓을 닫을 권한이 없습니다.")
    ticket_api.close(ticket_id, reason, by=user.id)
    return f"{ticket_id} 를 닫았습니다."

if __name__ == "__main__":
    # ④ 로컬은 stdio, 공용 서버는 streamable-http
    mcp.run(transport="streamable-http", port=8000)
  1. 원본 결과의 필드 40개 가운데 LLM이 다음 행동을 고르는 데 필요한 것만 한두 줄로 돌려줍니다.
  2. 공식 SDK에서는 ToolError로 던진 글만 LLM에게 전달됩니다. 다른 예외는 "Error executing tool"로만 보입니다. 고칠 방법을 적은 글은 ToolError로 던집니다.
  3. destructive_hint는 Host에 주는 참고 표시라서 권한 확인은 서버가 직접 합니다. current_user는 요청의 OAuth 토큰에서 사용자를 꺼내는 도우미 함수입니다.
  4. HTTP로 띄우면 기본 주소는 http://localhost:8000/mcp입니다. 개발할 때는 mcp dev ticket_server.py로 Inspector와 함께 띄웁니다.

코드는 공식 MCP Python SDK mcp 2.3 기준입니다. 1.x 예제에서 보던 from mcp.server.fastmcp import FastMCP는 2.x에서 from mcp.server import MCPServer로 이름이 바뀌었습니다. 따로 만들어진 fastmcp 패키지도 있는데 공식 SDK와는 다른 프로젝트입니다.
