MCP에서 모델은 왜
서버와 직접 이야기하지 않을까요?

MCP(Model Context Protocol)는 AI 앱이 바깥 도구와 데이터에 붙는 공통 규격입니다. 서버와 메시지를 주고받는 쪽은 앱 안의 Client입니다. 모델은 앱이 건넨 도구 목록에서 고르기만 합니다. 서버마다 Client가 하나씩 따로 붙습니다.

같은 질문을 실제 구성 요소 이름으로 다시 그리면 아래 흐름도가 됩니다. 관리인은 Host 앱입니다. 기기마다 따로 이어진 전선이 Client입니다. 명판과 버튼 목록은 server/discover와 tools/list의 응답이고 출입증은 OAuth 토큰입니다.

Server와 Client가 서로 내놓는 것

도구는 Server가 내놓는 것 가운데 하나일 뿐입니다. 규격은 Server 쪽 기능 세 가지와 Client 쪽 기능을 나눠 정합니다. 무엇을 지원하는지는 Server가 server/discover 응답에 적고 Client는 요청마다 적어 보냅니다. 아래는 2026-07-28 판 기준입니다.

Server가 내놓는 것

  • Tools모델이 고르는 함수. 이름과 설명, 입력 스키마를 tools/list로 받고 tools/call로 실행한다
  • Resources파일 내용이나 DB 스키마처럼 읽어 쓰는 데이터. 앱이나 사용자가 골라 문맥에 넣는다
  • Prompts사용자가 고르는 프롬프트 틀. 앱에서는 슬래시 명령처럼 보이는 경우가 많다

규격은 tools/list 결과를 늘 같은 순서로 돌려주라고 권합니다. 모델에 보내는 도구 목록이 그대로여야 프롬프트 캐시가 잘 맞기 때문입니다.

Client가 내놓는 것

  • Elicitation처리 도중 사용자에게 물을 것이 생기면 Server가 결과 대신 input_required를 돌려준다. Client가 답을 모아 같은 요청을 다시 보낸다(MRTR, Multi Round-Trip Requests)
  • 능력 선언Client는 지원하는 기능과 확장을 요청마다 _meta에 싣는다. 양쪽 모두 상대가 선언한 기능 안에서만 주고받는다
  • Sampling · Roots2026-07-28 판에서 폐지 예고(deprecated). 모델이 필요하면 Server가 모델 API를 직접 부르고 작업 폴더는 도구 인자나 서버 설정으로 넘기라고 권한다

Logging도 같은 판에서 폐지 예고됐습니다. stdio 서버는 로그를 stderr에 쓰고 그 밖에는 OpenTelemetry를 쓰라고 합니다. 폐지 예고된 기능도 최소 12개월은 동작합니다.

서버를 원격으로 옮길 때 달라지는 것

같은 서버라도 내 컴퓨터에서 띄우는지 인터넷 너머에 두는지에 따라 전송 방식과 인증이 바뀝니다. 메시지 내용은 두 전송에서 같은 JSON-RPC입니다. 그래서 흐름도에서도 Client B 쪽에만 인증 서버가 붙어 있습니다.

전송 방식

  • stdioHost가 서버를 하위 프로세스로 띄우고 stdin과 stdout으로 한 줄에 메시지 하나씩 주고받는다. stdout에는 MCP 메시지만 써야 해서 로그는 stderr로 보낸다
  • Streamable HTTP서버가 MCP 주소 하나(예: https://example.com/mcp)를 열고 메시지마다 POST를 한 번 받는다. 응답은 JSON 하나이거나 그 요청에만 쓰는 SSE 스트림
  • 세션 없는 요청2026-07-28 판에서 Mcp-Session-Id 세션이 빠졌다. 요청마다 Mcp-Method·Mcp-Name 헤더를 함께 보내 게이트웨이가 본문을 열지 않고도 요청을 나눌 수 있다

로컬에서 HTTP로 띄울 때는 127.0.0.1에만 묶고 Origin 헤더를 검사하라고 규격에 적혀 있습니다. 다른 웹사이트가 DNS rebinding으로 내 컴퓨터의 서버를 부르는 것을 막기 위해서입니다.

인증과 오래 걸리는 작업

  • OAuth 2.1원격 서버는 리소스 서버이고 Client는 OAuth 클라이언트다. 토큰 없는 요청에 서버가 401과 메타데이터 주소를 돌려주면 Client가 인증 서버를 찾아 PKCE로 로그인 흐름을 연다
  • 토큰을 받는 대상토큰을 요청할 때 resource 매개변수에 그 서버 주소를 적는다. 서버는 자기 앞으로 발급된 토큰만 받고 받은 토큰을 다른 API에 넘기지 않는다
  • stdio 서버의 자격 증명이 흐름을 쓰지 않고 환경 변수처럼 실행 환경에서 받는다
  • Tasks공식 확장 io.modelcontextprotocol/tasks. 오래 걸리는 tools/call에 서버가 결과 대신 taskId를 돌려주면 Client가 tasks/get으로 상태(working · input_required · completed …)를 확인한다. 양쪽이 모두 선언해야 쓴다

Claude Code와 Gemini CLI는 stdio 서버와 HTTP 서버를 모두 붙이고 원격 서버의 OAuth 로그인을 지원합니다. OpenAI Responses API는 원격 서버만 붙이고 토큰을 authorization 필드로 요청마다 넘깁니다. 2026년 11월에 확인한 각 문서 기준입니다.
