Agent의 while 루프는 무엇이 멈추게 할까요?

시험 전날 조사 숙제를 한다고 해 봅니다. 책을 찾아 읽고 메모한 뒤 부족하면 다른 책을 찾습니다. 충분해지면 제출하고 시간이 다 되면 거기서 멈춥니다.

Agent 프로그램도 같은 일을 합니다. 모델을 부르고 도구(모델이 직접 못 하는 일을 대신 해 주는 우리 쪽 함수)를 실행하고 결과를 넣어 다시 모델을 부르는 과정을 되풀이합니다. 이 되풀이를 루프(loop)라고 부릅니다. 그러면 이 루프는 언제 어떻게 끝날까요?

끝나는 경우는 네 가지입니다. 모델이 답을 다 썼을 때, 바퀴 수 한도에 걸렸을 때, 답이 길이 한도에서 잘렸을 때, 모델이 답을 거절했을 때입니다. 아래 보드의 "순조로운 경우"는 답을 다 쓴 종료를, "끝나지 않는 경우"는 한도 종료를 보여 줍니다. "도구 오류 뒤 복구"는 도구가 실패해도 루프가 이어지는 모습입니다. 잘림과 거절은 뒤의 갈림길 그림에서 다룹니다.

1모델 호출messages를 보내 응답을 받습니다
→
2멈춘 이유 확인stop_reason(모델이 멈춘 이유)을 읽습니다
→
3도구 실행요청서대로 코드가 실행합니다
→
4결과 붙이기messages에 결과를 넣습니다
↓ 도구 요청이 아니면
✓끝답을 돌려주고 루프를 나갑니다
↺ 4번이 끝나면 다시 1번으로 돌아가 한 바퀴를 더 돕니다

각 칸은 모델을 한 번 부른 한 바퀴입니다. 바퀴 수는 설명을 위한 예시 값입니다. 실제 바퀴 수는 질문과 모델의 판단이 정합니다. 이 글에서 주황은 모델이 쓴 것, 초록은 코드가 실행한 것, 파랑은 사용자의 질문, 빨강은 실패나 강제 종료를 뜻합니다.

질문마다 모델을 부르는 횟수가 다릅니다

헬프데스크 Agent에게 질문 세 개를 합니다. 와이파이를 끄고 켜는 법은 도구 없이 한 번에 답합니다. 티켓 상태는 조회를 한 번 하니 모델을 두 번 부릅니다. 티켓 상태와 해결 방법을 함께 물으면 조회와 FAQ 검색을 거쳐 세 번 부릅니다.

필요한 횟수는 질문과 모델의 판단이 정합니다. 코드를 쓰는 시점에는 알 수 없으니 호출 코드를 몇 번 복사해 이어 붙일 수 없습니다. 그래서 같은 코드를 알아서 되풀이하는 루프가 필요합니다.

조사 숙제와 비슷합니다. 책을 몇 권 읽어야 할지는 숙제를 시작할 때 모릅니다. 다만 사람은 충분하다 싶으면 스스로 그만두지만 모델은 같은 검색을 되풀이할 수도 있어서 코드가 한도를 둬야 합니다.

설명을 위한 예시 장면입니다. 주황 칸은 모델을 부른 한 번이고 초록 칸은 코드가 도구를 실행한 한 번입니다.

루프 한 바퀴는 messages에 카드 두 장을 쌓습니다

모델은 앞선 호출을 기억하지 못합니다. 호출마다 처음부터 새로 읽는 계산이라서 앞 내용을 알려면 매 바퀴 messages(대화 기록 목록) 전체를 다시 보내야 합니다. 그림에서 카드가 쌓이는 순서를 확인할 수 있습니다.

모델의 응답이 카드 한 장(assistant)이 되고 도구 결과가 카드 한 장(user)이 되니 한 바퀴에 두 장이 쌓입니다. 마지막 바퀴만 도구 결과 없이 답 카드 한 장으로 끝납니다.

시작: 질문 한 장

messages에는 사용자의 질문 카드 한 장뿐입니다. 모델을 부르기 전 상태입니다.

1번째 호출

카드 한 장을 보내자 모델이 티켓 조회 요청서를 씁니다. 모델은 요청서만 쓸 뿐 실행은 코드가 합니다. 이 응답이 assistant 카드로 붙고 stop_reason은 tool_use입니다.

코드가 도구를 실행

코드가 get_ticket을 실행하고 결과를 user 카드로 붙입니다. 요청서의 번호(toolu_01A)가 결과 카드에도 적혀 둘이 짝이 됩니다.

2번째 호출

카드 세 장을 모두 보냅니다. 모델은 조회 결과를 읽고 이번에는 FAQ 검색 요청서를 씁니다.

다시 도구를 실행

FAQ 검색 결과가 user 카드로 붙습니다. 카드는 다섯 장이 됩니다.

3번째 호출

카드 다섯 장을 보내자 모델이 도구 없이 글로 답합니다. stop_reason이 end_turn이라 루프가 끝납니다.

코드 창은 좌우로 밀어서 줄 끝까지 볼 수 있습니다.

# ... import, client, MODEL, tools, run_tool 은 아래에서 본다
def run_agent(question, max_turns=8):
    # ① 대화 기록: 질문 한 장으로 시작
    messages = [{"role": "user", "content": question}]
    # ② 바퀴 수에 한도를 둔다
    for turn in range(max_turns):
        # ③ 모델 호출 한 번
        res = client.messages.create(
            model=MODEL, max_tokens=1024, tools=tools, messages=messages)
        # ④ 응답을 기록에 붙이고 멈춘 이유를 찍는다
        messages.append({"role": "assistant", "content": res.content})
        print(f"{turn + 1}번째 호출: {res.stop_reason}")
        # ⑤ 도구 요청이 아니면 끝난다
        if res.stop_reason != "tool_use":
            return "".join(b.text for b in res.content if b.type == "text")
  1. 대화 기록입니다. messages는 역할(role)과 내용(content)을 짝지은 딕셔너리(이름과 값을 짝지어 담는 Python 자료형)를 순서대로 담은 목록입니다. 처음에는 사용자 질문 한 장뿐입니다.
  2. 바퀴 수 한도입니다. while True 대신 for turn in range(max_turns)를 쓰면 최대 8번만 돌고 반드시 끝납니다. 한도를 빼면 모델이 도구를 계속 부르는 한 루프도 끝나지 않습니다.
  3. 모델 호출입니다. max_tokens는 이번 답의 길이 한도이며 토큰(모델이 글을 읽고 쓰는 단위) 수로 셉니다. Anthropic API에서는 꼭 넣어야 하는 값입니다.
  4. 응답 기록입니다. res.content는 글 조각과 도구 요청 조각이 섞인 목록입니다. 도구 요청 조각의 번호가 남도록 그대로 붙여야 결과 카드와 짝을 맞출 수 있습니다.
  5. 끝내는 조건입니다. 도구 요청으로 멈춘 게 아니면 글 조각만 이어 붙여 돌려주고 끝냅니다. 가장 단순한 종료 조건입니다.
        # ⑥ 요청서마다 도구를 실행한다
        results = []
        for block in res.content:
            if block.type != "tool_use":
                continue
            out = run_tool(block.name, block.input)
            results.append({"type": "tool_result",
                            "tool_use_id": block.id, "content": out})
        # ⑦ 결과를 user 카드 한 장에 담아 붙인다
        messages.append({"role": "user", "content": results})
    return f"{max_turns}번 안에 끝내지 못했습니다."

stop_reason이 루프의 갈림길입니다

모델의 응답에는 멈춘 이유를 적은 stop_reason이 붙습니다. 코드는 이 값을 보고 다음에 할 일을 정합니다. 루프를 계속 돌리는 값은 tool_use 하나입니다.

나머지는 모두 루프를 나가는 길인데 끝나는 모습이 다릅니다. end_turn만 정상 종료입니다. 잘림이나 거절을 정상 종료처럼 다루면 도중에 끊긴 글을 완성된 답으로 착각합니다.

응답이 도착했습니다res.stop_reason의 값마다 가는 길이 다릅니다. 길을 누르면 응답 모양과 코드가 할 일이 나옵니다.

ReAct의 생각·행동·관찰과 API 블록은 닮았습니다

        
ReAct는 Shunyu Yao 등이 2022년 10월에 arXiv에 올린 논문 「ReAct: Synergizing Reasoning and Acting in Language Models」에서 나온 방식입니다. 모델이 생각(Thought)을 쓰고 행동(Action)을 하고 관찰(Observation) 결과를 받는 과정을 되풀이합니다.

        
지금 API에서는 행동이 tool_use 블록으로, 관찰이 tool_result로 구조화돼 옵니다. 생각은 모델이 도구를 부르기 전에 글 블록을 함께 쓸 때만 보입니다. 이 대응은 논문과 문서를 맞춰 본 필자의 해석입니다.

        
누가 쓴 줄인지 칠해 보면 생각과 행동은 모델이 쓰고 관찰은 코드가 가져온 값입니다. 여기서도 모델은 도구를 직접 실행하지 않습니다.

        

      

      

        

          
ReAct 논문의 예시 (Colorado orogeny)
같은 장면을 Claude API 블록으로 쓰면

          
Thought 1동쪽 구역이 어디까지 뻗는지 알려면 먼저 이 지명을 검색해야 한다
↔
text 블록 (없을 수도 있음)먼저 이 지명을 검색해 보겠습니다.

          
Action 1Search[Colorado orogeny]
↔
tool_use 블록search {"entity": "Colorado orogeny"}

          
Observation 1The Colorado orogeny was an episode of mountain building (an orogeny) in Colorado and surrounding areas.
↔
tool_result 블록검색 결과 글 (코드가 가져와 user 카드에 담음)

        

        
왼쪽 첫 줄은 논문 부록의 첫 생각을 줄여 옮겼고 Action·Observation 줄은 원문 형식 그대로입니다. 오른쪽은 설명을 위한 예시 모양입니다. 논문의 행동 공간에는 search, lookup, finish가 있습니다.

      

    

  


  

    

      

        
다른 SDK와 tool runner

        

          
OpenAI의 Chat Completions API로 같은 루프를 짜면 뼈대는 같고 이름만 달라집니다. 이 글의 루프에서 바뀌는 곳은 표와 코드로 접어 두었습니다.


          
OpenAI로 짠 같은 루프와 달라지는 곳 보기

          

            
AnthropicOpenAI Chat Completions

            
              
멈춘 이유stop_reason == "tool_use"finish_reason == "tool_calls"

              
도구 요청서content 안의 tool_use 블록message.tool_calls 목록

              
인자input (딕셔너리)arguments (JSON 글자)

              
결과 돌려주기user 카드 한 장에 tool_result 모음요청서마다 role: "tool" 카드 한 장

              
오류 표시is_error: true전용 칸이 없어 내용 글에 적음

            
          


def run_agent(question, max_turns=8):
    messages = [{"role": "user", "content": question}]
    for turn in range(max_turns):
        res = client.chat.completions.create(
            model=MODEL, messages=messages, tools=tools)
        choice = res.choices[0]
        messages.append(choice.message)
        # 멈춘 이유: tool_calls 가 아니면 끝
        if choice.finish_reason != "tool_calls":
            return choice.message.content
        for call in choice.message.tool_calls:
            args = json.loads(call.function.arguments)  # 글자를 풀어야 함
            out = run_tool(call.function.name, args)
            messages.append({"role": "tool",
                             "tool_call_id": call.id, "content": out})
    return f"{max_turns}번 안에 끝내지 못했습니다."

            
코드는 openai 패키지 3.31 기준입니다. OpenAI의 최신 안내 문서는 Responses API 예시로 쓰여 있지만 위 코드는 Chat Completions로 짰습니다.

          

          
Anthropic SDK(Anthropic이 만든 Python 도구 모음)에는 이 루프를 대신 돌려 주는 tool runner(베타)가 있습니다. 반복 상한도 옵션으로 둡니다. 문서는 사람 승인이나 로깅이 필요하면 직접 짠 루프를 쓰라고 안내합니다. 이 글처럼 직접 짜 본 루프가 있어야 runner가 대신하는 일을 알 수 있습니다.
