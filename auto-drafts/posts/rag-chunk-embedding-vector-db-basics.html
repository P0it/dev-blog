LLM은 우리 회사 규정을 어떻게 알고 답할까요?

사내 챗봇에 "출장비 한도가 얼마야?"라고 물으면 그럴듯한 숫자가 돌아옵니다. 그런데 그 숫자는 우리 회사 규정에 없는 숫자일 수 있습니다. LLM은 우리 회사 문서를 읽고 배운 적이 없기 때문입니다. 그렇다면 사내 문서를 바탕으로 답하게 하려면 무엇이 더 있어야 할까요?

문서 없이 물어보면 어떻게 되나요?

LLM은 모르는 내용도 그럴듯하게 지어서 답합니다.

LLM이 아는 것은 학습할 때 읽은 글뿐입니다. 사내 규정, 제품 매뉴얼, 고객 계약서처럼 바깥에 공개되지 않은 문서는 읽은 적이 없습니다. 그래도 질문을 받으면 질문 다음에 올 만한 글을 쓰기 때문에 모르는 내용도 그럴듯하게 지어냅니다.

해결 방법은 단순합니다. 답에 필요한 문서 조각을 찾아서 질문과 함께 보내면 됩니다. 이렇게 검색한 내용을 붙여 답하게 하는 방식을 RAG(Retrieval-Augmented Generation)라고 합니다. 검색(retrieval)으로 보강해서 글을 쓴다(generation)는 뜻입니다.

문서를 붙이면 무엇이 달라지나요?

LLM이 붙여 준 문서를 근거로 답합니다.

LLM 자체는 바뀌지 않았습니다. 프로그램이 질문을 받으면 사내 문서에서 관련 있는 부분을 찾아 질문과 함께 보낼 뿐입니다. LLM은 받은 글 안에 답이 있으니 그것을 옮겨 씁니다.

문서를 통째로 보내면 안 되나 싶지만 사내 문서는 수천 쪽이라 context window에 들어가지 않습니다. 들어가더라도 매번 수십만 토큰을 보내면 비용이 감당되지 않습니다. 그래서 질문과 관련 있는 조각 몇 개만 골라 보내는 것이 RAG의 핵심입니다. 남은 문제는 수천 쪽에서 그 몇 조각을 어떻게 빨리 찾느냐입니다.

문서는 어떻게 조각내나요?

미리 몇백 토큰 크기로 잘라 둡니다. 이 조각을 청크라고 합니다.

검색은 질문이 올 때마다 하지만 문서를 자르는 일은 미리 한 번만 해 둡니다. 이렇게 자른 조각을 청크(chunk)라고 합니다. 보통 수백~천 토큰 정도로 자릅니다.

너무 작게 자르면 한 조각에 뜻이 다 담기지 않습니다. 너무 크게 자르면 관련 없는 내용까지 딸려 와서 토큰을 낭비합니다. 글자 수로 기계적으로 자르기보다 조항·제목·문단 같은 문서 구조를 따라 자르는 편이 낫습니다. 문장 중간에서 잘리면 앞뒤 청크 어디에도 온전한 뜻이 남지 않습니다. 그래서 앞뒤 청크를 조금씩 겹치게 둡니다.

질문과 관련 있는 청크는 어떻게 찾나요?

글을 숫자 목록으로 바꿔 두고 질문과 가까운 숫자를 찾습니다.

단어가 똑같이 들어 있는지만 보면 "숙박비 한도"와 "1박 12만 원까지"를 연결하지 못합니다. 그래서 글의 뜻을 숫자 목록으로 바꿉니다. 이 숫자 목록을 임베딩(embedding)이라고 합니다. 글을 임베딩으로 바꿔 주는 전용 모델을 임베딩 모델이라고 합니다.

뜻이 비슷한 글은 숫자 목록도 비슷하게 나옵니다. 그래서 질문을 임베딩으로 바꾼 뒤 청크 임베딩들과 얼마나 가까운지 계산하면 뜻이 통하는 청크를 찾을 수 있습니다. 가까운 정도는 보통 코사인 유사도로 잽니다. 1에 가까울수록 비슷합니다.

청크 임베딩을 담아 두고 가까운 것을 빨리 찾아 주는 저장소가 벡터 DB입니다. Chroma·pgvector·Qdrant·Pinecone 같은 제품이 있습니다. 임베딩 모델은 OpenAI·Voyage AI·Cohere 등이 제공합니다. Anthropic은 임베딩 모델을 따로 내지 않고 Voyage AI를 권합니다.

찾은 청크는 요청의 어디에 넣나요?

질문 앞에, 출처 표시를 붙여 넣습니다. 그리고 문서에 없으면 모른다고 하라고 지시합니다.

LLM에 보내는 요청 (줄임)
"system": "아래 문서만 근거로 답하라. 문서에 없으면 '규정에서 찾지 못했다'고 답하라. 답 끝에 근거 문서 이름을 적어라.", "messages": [{ "role": "user", "content": "<document source=\"출장규정 4조\"> 국내 숙박비는 1박 12만 원, 서울은 15만 원까지… </document> <document source=\"출장규정 5조\"> … </document> 질문: 국내 출장 숙박비 한도가 얼마야?" }]

청크마다 출처를 붙여 감싸 두면 LLM이 답에 "출장규정 4조"처럼 근거를 적을 수 있습니다. 사용자는 그 출처를 눌러 원문을 확인합니다. Claude API에는 문서를 넣으면 답의 문장마다 출처 위치를 붙여 주는 citations 기능도 있습니다.

system 지시의 두 번째 줄이 중요합니다. 검색이 엉뚱한 청크를 가져오면 LLM은 다시 지어내기 쉽습니다. "문서에 없으면 모른다고 답하라"는 지시가 지어내기를 크게 줄입니다.

검색이 틀리면 답도 틀립니다. 그래서 검색 품질을 따로 잽니다. 질문 수십 개와 정답 청크를 정해 두고 검색 결과 상위 몇 개 안에 정답 청크가 들어오는지 셉니다.

코드로 쓰면 어떻게 되나요?

미리 청크를 저장해 두는 부분과, 질문마다 찾아서 넣는 부분으로 나뉩니다.

import anthropic, chromadb

client = anthropic.Anthropic()
db = chromadb.PersistentClient(path="./kb")
# ① 기본 임베딩 모델로 청크를 숫자로 바꿔 저장하는 저장소
docs = db.get_or_create_collection("policies")

def ingest(chunks):          # 미리 한 번
    # ② 청크와 출처를 함께 저장한다
    docs.add(ids=[c["id"] for c in chunks],
             documents=[c["text"] for c in chunks],
             metadatas=[{"source": c["source"]} for c in chunks])

def answer(question):        # 질문마다
    # ③ 질문과 가까운 청크 3개
    hits = docs.query(query_texts=[question], n_results=3)
    context = "\n".join(
        f'<document source="{m["source"]}">{d}</document>'
        for d, m in zip(hits["documents"][0], hits["metadatas"][0]))
    # ④ 문서만 근거로, 없으면 모른다고
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=800,
        system="아래 문서만 근거로 답하라. 문서에 없으면 "
               "'규정에서 찾지 못했다'고 답하고, 끝에 근거 문서 이름을 적어라.",
        messages=[{"role": "user", "content": f"{context}\n\n질문: {question}"}],
    )
    return reply.content[0].text
  1. Chroma는 임베딩 모델을 정하지 않으면 작은 기본 모델(all-MiniLM-L6-v2)로 글을 바꿉니다. 한국어 문서가 많으면 다국어 임베딩 모델을 지정하는 편이 검색이 정확합니다.
  2. 청크마다 source를 함께 저장해야 나중에 출처를 붙일 수 있습니다. 이 함수는 문서가 바뀔 때만 다시 돌립니다.
  3. 질문도 같은 임베딩 모델로 바꿔 가장 가까운 청크 3개를 돌려받습니다. 몇 개를 가져올지는 청크 크기와 질문 종류를 보며 정합니다.
  4. 찾은 청크를 출처 표시로 감싸 질문 앞에 넣고 system에 근거 규칙을 적었습니다.

코드는 chromadb 1.5, anthropic 2.14 기준입니다. 이 구조는 질문이 오면 무조건 한 번 검색합니다. 인사말처럼 검색이 필요 없는 질문에도 검색하고 첫 검색이 빗나가도 다시 찾지 않습니다. 검색을 도구로 바꾸면 이 두 가지 문제가 해결됩니다.
