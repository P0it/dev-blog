> Cloudflare 가 9월 15일부터 AI 크롤러 기본값을 바꿉니다. 광고가 붙은 페이지에서는 학습·에이전트 용도의 크롤링이 기본으로 막히고 검색만 남습니다. 그런데 사이트가 "학습은 거부, 검색은 허용"이라고 적어도 그 구분은 크롤러가 미리 user agent 를 나눠 둔 곳에서만 성립합니다.

## 9월 15일에 바뀌는 기본값

Cloudflare 가 7월 1일에 예고한 변경이 9월 15일 발효한다고 여러 매체가 전합니다. 광고를 노출하는 페이지에서는 Training 과 Agent 로 분류된 크롤링이 기본 차단되고 Search 는 기본 허용으로 남습니다.

적용 대상은 새로 온보딩하는 도메인과 신규 고객, 그리고 기존 무료 요금제 고객입니다. 이미 설정을 잡아 둔 유료 고객의 값을 바꾸는 변경은 아닙니다. 발표 자체는 7월 1일이었고 9월 15일은 그 예고가 실제로 적용되는 날입니다.

기본값이라는 말이 여기서는 무겁습니다. 전 세계 웹 트래픽의 5분의 1 안팎이 Cloudflare 를 지나는 것으로 알려져 있습니다. 한 회사의 기본값이 바뀌면 설정 화면을 한 번도 열어 본 적 없는 사이트 수백만 개의 동작이 같이 바뀝니다.

## Content Signals 가 나눠 둔 세 칸

Cloudflare 는 2025년 9월 24일 [Content Signals Policy](https://blog.cloudflare.com/content-signals-policy/) 를 내놓으면서 크롤링 용도를 세 가지로 갈라 뒀습니다. robots.txt 에 한 줄로 적는 방식입니다.

```
User-agent: *
Content-Signal: search=yes, ai-train=no
Allow: /
```

- `search` — 검색 색인을 만들려고 가져가는 크롤링
- `ai-input` — 실시간 답변을 만들 때 본문을 넣으려고 가져가는 크롤링
- `ai-train` — 모델을 학습하거나 미세조정하려고 가져가는 크롤링

Cloudflare 의 managed robots.txt 를 켠 도메인이 약 380만 개라고 하고 그 기본 조합이 `search=yes, ai-train=no` 입니다. 어느 칸을 아예 적지 않으면 그 용도에 대해서는 허용도 거부도 하지 않은 상태로 둡니다.

여기서 한 가지를 구분해야 합니다. robots.txt 에 적는 것은 의사 표시이고 요청을 실제로 막는 것은 엣지에서 일어나는 다른 동작입니다. 두 층이 같은 세 칸을 쓰지만 성질이 다릅니다.

| | robots.txt 의 Content Signals | Cloudflare 엣지 차단 |
|---|---|---|
| 무엇인가 | 용도별 허용·거부 의사 표기 | 요청을 실제로 막는 동작 |
| 9월 15일 기본 | `search=yes, ai-train=no` | 광고 페이지에서 Training·Agent 차단 |
| 어겼을 때 | 제재 없음 | 요청이 서버에 닿지 않음 |
| 용도를 가르는 근거 | 크롤러의 자기 신고 | user agent 와 IP 검증 |
| 적용 범위 | 그 사이트 하나 | Cloudflare 를 쓰는 사이트 전체 |

## user agent 하나가 두 가지 일을 겸할 때

표의 네 번째 줄이 이번 변경의 핵심입니다. 용도를 나누려면 크롤러가 용도별로 다른 이름을 달고 와야 합니다.

문제는 Google·Apple·Microsoft 가 검색 색인과 AI 학습·응답 수집을 한 크롤러로 겸해 왔다는 점입니다. 이런 크롤러를 mixed-use 라고 부릅니다.

사이트 주인 입장에서 계산해 보면 이렇습니다. "학습은 싫고 검색은 좋다"고 적어도 한 요청이 두 용도를 동시에 채우고 있으면 그 요청을 절반만 거절할 방법이 없습니다. 남는 선택은 두 가지뿐입니다. 학습까지 받아들이고 검색 노출을 지키거나, 학습을 막으면서 검색 노출도 함께 잃거나.

그래서 [Cloudflare 의 요구](https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers/)는 사이트가 아니라 크롤러를 향합니다. 용도별로 user agent 를 나눠 두라는 것입니다. 나눠 두면 사이트가 고를 수 있고 나누지 않으면 사이트에 남는 선택지는 전부 허용과 전부 차단뿐입니다.

**선언은 사이트가 하지만 그 선언이 성립할지는 크롤러가 정합니다.** 오늘 바뀌는 기본값이 실제로 건드리는 것은 이 비대칭입니다.

## Agent 칸이 가리키는 것은 지금 읽고 있는 사람

세 칸 가운데 오해가 가장 많은 쪽은 Agent 입니다. Training 은 나중에 만들 모델을 위해 본문을 미리 가져가는 크롤링입니다. Agent 는 지금 이 순간 누군가가 자기 비서에게 "이 페이지 열어 봐"라고 시켜서 발생하는 요청입니다. 챗봇의 fetch 봇과 브라우저를 직접 조작하는 에이전트가 여기 들어갑니다.

광고가 붙은 페이지에서 Agent 를 기본 차단한다는 말은 사람이 읽으려고 보낸 요청을 돌려보낸다는 뜻이기도 합니다. 광고 수익이 걸린 매체에는 합리적인 선택입니다. 광고를 보지 않는 방문자에게 본문만 내주는 일이거든요.

개인 블로그는 사정이 다릅니다. 광고가 없으면 이 기본값은 애초에 걸리지 않습니다. 붙였다면 에이전트를 거쳐 오는 독자를 어떻게 셀지부터 정해야 합니다. 에이전트가 대신 열어 본 페이지는 방문자 수에 잡히지 않습니다. 인용은 되는데 트래픽은 안 잡히는 구간이 이미 생겼습니다.

## 봇 비중 숫자가 측정마다 갈리는 이유

이 논의에는 "봇이 사람을 넘어섰다"는 문장이 거의 항상 붙습니다. 그런데 공개된 수치를 나란히 놓으면 폭이 큽니다.

| | Cloudflare 발표 | Imperva Bad Bot Report 2026 | Cloudflare Radar |
|---|---|---|---|
| 자동 트래픽 비중 | 약 57% | 약 53% | 약 35% |
| 무엇을 셌나 | 일부 호스팅 사이트의 HTML 요청 | 앱·API 호출을 포함한 전체 트래픽 | 네트워크 전체 측정 |
| 기준 시점 | 2026년 | 2025년 | 2026년 8월까지 28일 |

세 숫자는 평균 낼 대상이 아닙니다. 세는 대상이 다르기 때문입니다. HTML 요청만 세면 이미지·API 를 많이 호출하는 사람 쪽 트래픽이 빠지면서 봇 비중이 올라갑니다. 네트워크 전체를 재면 내려갑니다.

같은 회사가 낸 두 숫자가 57%와 35%로 갈린다는 사실이 이 표에서 가장 중요합니다. 기본값을 정당화하는 근거로는 대개 큰 쪽이 인용됩니다. 내 사이트에 실제로 무엇이 들어오는지는 내 접근 로그에만 적혀 있습니다.

## 인프라 한 곳이 기본값을 정할 때

반대 시각도 분명합니다. 정책 연구 쪽에서는 이 변경을 게이트키핑의 확대로 봅니다. 지금까지 크롤링 규칙은 사이트마다 따로 정했습니다. 완벽하지는 않아도 분산돼 있었고 한 회사가 웹 전체에서 특정 크롤러를 한 번에 막을 수는 없었습니다. Cloudflare 가 차단 목록을 직접 관리하고 주기적으로 갱신하는 구조에서는 무엇을 학습용으로 볼지 판정하는 권한도 한곳에 모입니다.

이 비판은 타당합니다. 다만 반대쪽 사정도 같이 봐야 공평합니다. 개인이 운영하는 사이트가 수십 개 크롤러의 정책을 따로 관리하는 일은 현실적이지 않습니다. 기본값이 없으면 사실상의 기본값은 전부 허용이 됩니다. 그건 중립이 아닙니다. 아무것도 정하지 않은 상태가 크롤러 쪽에 유리하게 기울어 있을 뿐입니다.

제 판단은 이렇습니다. 걸리는 지점은 기본값의 존재보다 **그 기본값을 누가 바꿀 수 있느냐**입니다. 무료 요금제 고객에게 새 기본이 적용되고 설정을 잡아 둔 유료 고객은 그대로라는 구성이 설정 화면을 들여다볼 여력이 있는 쪽과 없는 쪽을 가릅니다.

## 개인 블로그가 먼저 정할 것

이 관점에서 보면 개인 블로그 운영자가 확인할 것은 세 가지로 좁혀집니다.

- **내 사이트가 이 기본값의 적용 대상인지.** 최근에 붙였거나 무료 요금제를 쓰고 있으면 대상입니다.
- **`ai-train` 과 `ai-input` 은 다른 칸이라는 것.** 학습에 쓰이는 것을 거부하는 결정과 실시간 답변에 인용되는 것을 거부하는 결정은 같은 결정이 아닙니다.
- **내 robots.txt 에 지금 무엇이 적혀 있는지.** managed robots.txt 를 켜 뒀다면 내가 적지 않은 줄이 들어와 있습니다.

Cloudflare 를 쓰지 않는 사이트도 이 결정에서 빠지지는 않습니다. Content Signals 표기는 공개된 형식이라 robots.txt 에 직접 적어 넣을 수 있습니다. 다만 적어 넣는다고 집행되지는 않습니다. 그 줄은 요청을 막지 않습니다. 의사를 밝힐 뿐입니다. 집행까지 원하면 CDN 이나 서버 앞단에서 user agent 와 IP 를 확인해 직접 막아야 합니다.

학습 거부는 감정적으로 쉬운 선택입니다. 대가 없이 내 글로 모델을 학습시키는 일에 반대하는 쪽이 자연스럽거든요. 그런데 `ai-input` 까지 함께 막으면 답변형 검색에서 인용될 통로가 닫힙니다. AI 도구를 거친 유입은 아직 전체 웹 트래픽의 1%에도 못 미치는 것으로 집계되지만 2024년 집계와 견주면 자릿수가 달라졌습니다. 방문자 수가 크지 않은 기술 블로그일수록 이쪽에서 걸릴 여지가 큽니다.

그래서 9월 15일에 실제로 정해지는 것은 AI 학습에 찬성하느냐 반대하느냐가 아닙니다. 내 글이 어디까지 읽히길 바라는지를 세 칸으로 나눠 적어 두는 일입니다. 적어 두지 않으면 기본값이 대신 적습니다.
