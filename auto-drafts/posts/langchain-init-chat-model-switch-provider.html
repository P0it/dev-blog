GPT를 Claude로 바꾸는 데 필요한 코드 한 줄, LangChain 첫걸음

해외여행을 갈 때 멀티 어댑터를 챙깁니다. 콘센트 모양은 나라마다 달라도 어댑터를 끼우면 같은 충전기를 그대로 씁니다.

Agent 프로그램도 비슷한 상황을 만납니다. 모델을 서비스하는 회사(provider)마다 요청 모양이 달라서 회사를 바꾸려면 호출 코드를 고쳐야 합니다. LangChain은 이 사이에 끼우는 어댑터 역할을 하는 프레임워크(framework, 자주 쓰는 뼈대를 미리 만들어 둔 도구 묶음)입니다. 그러면 모델을 바꿀 때 정말 한 줄만 고치면 될까요?

대부분은 그렇습니다. 바꾸는 곳은 모델 이름 문자열 하나입니다. 다만 어댑터가 콘센트 모양만 맞춰 줄 뿐 전압까지 바꿔 주지는 않는 것처럼, 문자열만 바꿔서는 안 되는 경우도 있습니다. 보드에서 직접 바꿔 봅니다.

모델 회사

temperature는 답을 고를 때의 무작위 정도를 정하는 값이고 0에 가까울수록 같은 답을 내려 합니다.

모델 이름 문자열 하나가 클래스를 고릅니다

        
init_chat_model에 "회사:모델" 모양의 문자열을 넘기면 LangChain이 콜론 앞의 회사 이름을 보고 알맞은 클래스를 만들어 줍니다. 회사마다 따로 만들어진 클래스가 있기 때문입니다.

        
그 클래스는 회사별 패키지 안에 있어서 해당 패키지를 설치해야 합니다. API 키는 환경변수(프로그램 밖에서 넘겨주는 설정값)에 둡니다. 모델 이름은 바뀌지 않는 고정 이름을 쓰라고 LangChain 레퍼런스가 권합니다.

        
이 구조 덕분에 나머지 코드는 어느 회사의 클래스인지 몰라도 됩니다. 어느 클래스든 같은 invoke가 있어서 부르는 쪽 코드는 그대로입니다.

클래스·패키지·환경변수 이름은 langchain 1.4와 각 회사 패키지 기준입니다. 모델 이름은 예시입니다.

# pip install -U "langchain[anthropic]"
from langchain.chat_models import init_chat_model

# ① 회사와 모델을 문자열로 고른다
model = init_chat_model("anthropic:claude-sonnet-5-5")
# ② OpenAI로 바꾸려면 이 줄만 바꾼다

  1. 모델을 만드는 한 줄입니다. 콜론 앞이 회사이고 뒤가 모델 이름입니다. 회사 패키지는 미리 설치해 둡니다(OpenAI는 "langchain[openai]"). 모델 이름은 예시이며 실제로는 회사 문서의 최신 이름을 씁니다.
    2. 
  
  2. 회사를 바꾸는 방법입니다. 줄 하나만 바꾸면 되고 이 파일의 나머지 코드는 건드리지 않습니다. API 키는 ANTHROPIC_API_KEY나 OPENAI_API_KEY처럼 회사별 환경변수에서 읽습니다.
    3. 


        

      

    

  


  

    

      
메시지는 말한 사람의 이름표를 붙인 쪽지입니다

      
단톡방에서 누가 한 말인지는 이름표로 구분합니다. 모델에 보내는 대화도 쪽지마다 역할(role) 이름표가 붙어 있습니다. LangChain에는 이름표별로 클래스가 네 개 있습니다. 클래스 대신 이름표와 내용을 짝지은 딕셔너리(이름과 값을 짝지어 담는 Python 자료형)로 써도 같은 뜻으로 받아 줍니다.

      

        
이름표클래스로 쓰면딕셔너리로 쓰면

        
system
SystemMessage 모델이 어떻게 행동할지와 상황을 알려 줍니다
{"role": "system", "content": "너는 IT 헬프데스크 상담원이다."}

        
user
HumanMessage 사용자가 한 말입니다
{"role": "user", "content": "T-1042 티켓 어떻게 됐어요?"}

        
assistant
AIMessage 모델이 쓴 응답이며 글과 도구 요청, 부가 정보가 들어 있습니다
{"role": "assistant", "content": "조회해 보겠습니다."}

        
tool
ToolMessage 도구를 실행한 결과입니다
{"role": "tool", "tool_call_id": "…", "content": "부품 대기"}

      

      
설명을 위한 예시 문구입니다. 이 글의 코드는 읽기 쉬운 딕셔너리 모양을 씁니다. 다만 비유가 맞지 않는 곳도 있습니다. 단톡방 이름표는 사람이 보려는 표시이지만 role은 모델이 누구 말인지 읽는 데 쓰는 값입니다.

같은 질문에 두 회사 모델이 답한 예시를 정리한 값입니다. response_metadata에는 이보다 많은 항목이 들어갑니다.

      

      

        
응답에는 글만 있지 않습니다

        
모델의 응답은 글 한 줄이 아니라 AIMessage 객체입니다. 객체(object)는 값 여러 개를 이름을 붙여 한 덩어리로 묶은 것입니다. content_blocks는 글과 도구 요청을 같은 모양의 조각 목록으로 정리한 것이고 tool_calls는 모델이 부른 도구 요청 목록이며 usage_metadata는 토큰 수입니다. 그림에서 초록 칸은 어느 회사 모델이든 모양이 같습니다. 주황 칸은 회사가 보내 준 원래 정보를 그대로 담은 곳이라 이름이 다릅니다.

        
모델이 답을 멈춘 이유를 적은 값의 이름은 회사마다 달라서 Anthropic은 stop_reason 이고 OpenAI는 finish_reason입니다. 이 이름 차이는 여기 response_metadata 안에 남아 있습니다. LangChain은 글과 도구 요청과 토큰 수를 맞춰 줍니다. 멈춘 이유는 아직 회사 이름 그대로입니다.

  1. 호출 한 줄입니다. invoke는 메시지 목록을 보내고 응답이 다 만들어질 때까지 기다렸다가 AIMessage 하나를 돌려줍니다. 메시지 목록은 위의 딕셔너리 모양을 그대로 넘깁니다.
    2. 
  
  2. 응답을 열어 보는 곳입니다. content는 글이고 usage_metadata는 입력과 출력 토큰 수입니다. response_metadata에는 멈춘 이유를 포함한 회사 원본 정보가 들어서 회사에 따라 키 이름이 다릅니다.
    3. 


        

      

    

  


  

    

      

        
invoke는 한 번에 stream은 조금씩 batch는 여러 개를 한꺼번에

        

          
호출 방식은 세 가지입니다. invoke는 답이 다 만들어진 뒤 한 번에 받습니다. stream은 답이 만들어지는 대로 조각(chunk)을 받아 바로 화면에 찍을 수 있습니다. batch는 질문 여러 개를 동시에 보내고 답을 목록으로 받습니다.

          
세 가지 모두 어느 회사 모델이든 이름과 사용법이 같습니다. 아래에서 같은 질문을 세 방식으로 보내고 첫 글자가 보이는 때와 끝나는 때를 비교해 봅니다.

          
0.0초

        

      

      

        

          
invoke
첫 글자 2.4초 · 끝 2.4초 (다 만들어진 뒤 한꺼번에)

          
stream
첫 글자 0.3초 · 끝 2.4초 (만들어지는 대로)

          
batch (질문 2개)
차례로 보내면 4.8초
첫 결과 2.4초 · 끝 2.4초 (동시에 보내서 목록으로)

        

        
설명을 위한 예시 시간입니다. 답이 완성되는 데 2.4초가 걸린다고 가정했고 줄 전체는 4.8초를 뜻합니다. 검은 표시는 첫 글자가 보이는 때입니다. 실제 시간은 모델과 네트워크에 따라 다릅니다.

      

      

        

          


# ⑤ 조각이 오는 대로 찍는다
for chunk in model.stream(messages):
    print(chunk.content, end="|")
# ⑥ 조각을 더하면 하나의 메시지가 된다
full = None
for chunk in model.stream(messages):
    full = chunk if full is None else full + chunk
# ⑦ 질문 여러 개는 한 번에 보낸다
answers = model.batch([messages_a, messages_b])

모델을 런타임에 바꾸고 싶다면

          

            
설정에서 모델 이름을 읽어 실행 중에 바꾸려면 configurable_fields를 씁니다. 모델을 만들 때 이름을 비워 두고 호출할 때 넘깁니다. 샘플링 파라미터는 모델마다 허용 여부가 달라서 코드에 박아 두지 말고 모델별 설정에 둡니다.


# ⑧ 모델을 비워 두고 바꿀 수 있는 항목만 연다
model = init_chat_model(
    configurable_fields=("model", "model_provider"))
# ⑨ 호출할 때 모델을 고른다
res = model.invoke(messages, config={"configurable": {
    "model": "gpt-5.5", "model_provider": "openai"}})

            
    
              
  1. 바꿀 수 있는 항목을 정해 둡니다. 모델 이름을 비워 두면 model과 model_provider가 호출 때 정해지는 항목이 됩니다. 문서는 모든 항목을 여는 "any"를 보안상 위험하다고 경고합니다.
    2. 
              
  2. 호출할 때 고릅니다. config에 고른 값을 넘기면 그 모델로 호출합니다. 값은 설정 파일이나 사용자 선택에서 가져올 수 있습니다.

→

→
            
메시지 목록채워진 쪽지 두 장

모델prompt | model

          

          
LangChain 1.x에서는 Agent를 만들 때 create_agent를 권합니다. 예전의 LLMChain 같은 낡은 체인은 langchain-classic 패키지로 옮겨졌습니다. 이 시리즈는 create_agent를 쓰는 쪽으로 갑니다.

          
ChatPromptTemplate 예시 보기


from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "너는 IT 헬프데스크 상담원이다."),
    ("user", "{question}"),
])
messages = prompt.invoke({"question": "T-1042 티켓 어떻게 됐어요?"})
res = (prompt | model).invoke({"question": "T-1042 티켓 어떻게 됐어요?"})

            
첫 호출은 메시지 목록(ChatPromptValue)을 돌려줄 뿐 모델을 부르지 않습니다. prompt | model은 틀을 채운 뒤 모델에 넘기는 한 줄입니다.

          

        

      

    

  


  

    

      

        
한 줄로 바뀌는 것과 안 바뀌는 것

        

          
LangChain은 호출 모양을 맞춰 줍니다. 모델의 성격까지 맞춰 주지는 않습니다.

          

            
LangChain이 맞춰 줌

              
요청system 자리, max_tokens 채우기

              
응답content, content_blocks, usage_metadata

              
호출invoke, stream, batch

            
직접 확인할 것

              
모델 설정temperature·top_p·top_k를 받는지

              
원본 정보stop_reason과 finish_reason 이름

              
모델 이름회사 문서의 최신 이름

          

          
모델을 바꿀 때는 문자열을 바꾼 뒤 샘플링 파라미터, 멈춘 이유 이름, 모델이 허용하는 설정을 한 번 확인하면 됩니다. 다음 글에서는 모델이 정해진 모양의 데이터로 답하게 하는 Structured Output을 알아보겠습니다.
