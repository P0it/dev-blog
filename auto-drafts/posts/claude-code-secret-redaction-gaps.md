> 9월 29일 공개된 Claude Code v2.1.285 는 비밀 값이 새어 나간 세 건을 함께 고쳤습니다. 마스킹과 업로드 제외가 무엇을 기준으로 판단하는지, 그 기준을 빠져나가는 값은 어떤 모양인지 공식 문서에서 확인해 정리했습니다.

에이전트가 이상하게 동작한 세션을 `/feedback` 으로 보내거나 디버그 로그를 그대로 붙여 동료에게 물어본 적이 있을 것입니다. 그럴 때 로그에 찍힌 DB 접속 문자열을 보면 비밀번호 부분이 가려져 있습니다.

그 표시를 그대로 믿어도 될까요? v2.1.285 의 수정 목록을 보면 그렇지 않은 경우가 있었습니다. URL 안 비밀번호에 `@` 가 들어 있으면 그 일부가, `%40` 으로 적혀 있으면 전부가 가려진 로그와 트랜스크립트에 남아 있었습니다. `postgres://admin:pa%40ss@db.internal:5432/app` 처럼 적어 둔 접속 문자열이 여기에 해당합니다. Claude Code 가 비밀 값을 무엇을 기준으로 가리는지 알면, 어떤 값이 그 기준을 빠져나가는지 넘기기 전에 확인할 수 있습니다.

## 가려진 로그에 남아 있던 URL 비밀번호

변경 목록의 문장은 짧습니다.

> Fixed redacted logs and transcripts showing part of a URL password that contains `@`, or all of it when the URL writes its `@` as `%40`

`@` 는 URL 에서 사용자 정보 구간과 호스트를 가르는 구분자입니다. 비밀번호 안에 같은 문자가 들어가면 문자열만 보고 경계를 정하기 어려워지거든요. `%40` 은 그 `@` 를 퍼센트 인코딩으로 적은 표기라 모양이 한 번 더 달라집니다. 같은 비밀번호인데 어떻게 적었는지에 따라 일부만 가려지거나 아예 가려지지 않은 것입니다.

대상도 같이 볼 만합니다. 로그만 적혀 있지 않고 트랜스크립트가 함께 적혀 있습니다. 트랜스크립트는 대화 기록이라 `/feedback` 이나 세션 품질 설문으로 Anthropic 에 올라갈 수 있고 `~/.claude/projects/` 아래에 평문으로도 남습니다. 기본 보관 기간은 30일이고 `cleanupPeriodDays` 로 바꿉니다.

## 자격증명 파일을 이름으로 걸러내는 방식

나머지 두 건은 `/ultrareview` 쪽입니다. `/code-review ultra` 로 브랜치를 검토하면 Claude Code 가 저장소 상태를 묶어 클라우드 샌드박스에 올립니다. 커밋되지 않은 변경과 스테이징된 변경도 함께 올라갑니다.

공식 문서는 이때 자격증명이나 키처럼 보이는 이름의 파일을 따로 다룬다고 적어 뒀습니다. 예로 든 것은 `.env` 파일, Terraform 의 `*.tfvars` 파일, 그리고 `id_rsa` 나 `*.pem` 같은 키 파일입니다. 이런 파일의 커밋되지 않은 변경은 업로드에서 빠지고 Claude Code 가 빠뜨린 파일 이름을 알려 줍니다. 세션은 각 파일의 커밋된 버전으로 시작하고 커밋된 것이 없으면 그 파일 없이 시작합니다.

판단 기준이 파일 이름이라는 점이 v2.1.285 가 고친 두 건의 배경입니다. 하나는 확장자 앞에 콜론이 든 이름입니다. 변경 목록이 든 예는 `server:8443.key` 이고 이 파일의 커밋되지 않은 변경이 업로드에 들어갔습니다. 다른 하나는 백업이나 편집기 표시가 여럿 붙은 파일·폴더 이름이 자격증명 검사에서 빠진 것입니다.

두 건 모두 값의 내용과는 관계가 없습니다. 같은 개인 키를 `server.key` 로 두면 걸러지고 `server:8443.key` 로 두면 올라갔습니다.

## 제외 규칙이 적용되는 범위

이 규칙에는 조건이 두 가지 더 붙습니다.

첫째는 운영체제입니다. 문서는 macOS, Linux, WSL 세 환경을 명시합니다. Windows 네이티브 환경은 그 문장에 들어 있지 않으니 그 환경에서 쓴다면 따로 확인하는 편이 안전합니다. 변경 목록에도 `/ultrareview` 업로드 수정이 WSL 항목과 Windows 항목으로 나뉘어 올라와 있습니다. 이 부분은 환경마다 처리가 다릅니다.

둘째는 적용 대상입니다. 제외되는 것은 **커밋되지 않은 변경**입니다. 이미 커밋한 `.env` 는 저장소 상태에 들어 있고 세션은 그 커밋된 버전으로 시작합니다. 자격증명을 실수로 커밋해 둔 저장소라면 이름 기반 제외가 도와주지 않습니다. 커밋 기록을 정리하는 쪽이 먼저입니다.

같은 제외 규칙을 따르는 다른 명령이 `claude --cloud` 입니다. git 리모트가 없는 저장소나 Claude GitHub App 이 설치되지 않은 저장소에서 실행하면 로컬 저장소를 묶어 클라우드 세션에 직접 올립니다. 문서는 이 번들에 모든 브랜치의 전체 저장소 히스토리와 추적되는 파일의 커밋되지 않은 변경이 들어간다고 적었습니다. 추적되지 않는 파일은 포함되지 않습니다. 과거 커밋에 자격증명이 들어 있다면 그 히스토리가 함께 올라간다는 뜻입니다.

번들 업로드 자체를 피하는 선택지도 있습니다. 공식 문서는 풀 리퀘스트를 검토할 때(`/code-review ultra <PR 번호>`)는 샌드박스가 저장소를 호스트에서 직접 클론하므로 기기에서 올라가는 것이 없다고 적었습니다. 커밋되지 않은 변경이 신경 쓰이는 저장소라면 브랜치를 먼저 push 하고 PR 번호로 검토하는 편이 확실합니다.

## 오류 보고와 설문 업로드가 가리는 값

알려진 패턴으로 판단하는 구조는 `/ultrareview` 만의 것이 아닙니다. 세션 기록이 기기를 떠나는 방법마다 가리는 값과 보관 기간이 다르게 적혀 있습니다.

![Claude Code 가 설치·인증·요청·텔레메트리·피드백으로 외부와 주고받는 연결을 실선과 점선으로 구분해 그린 다이어그램](https://wzaqtubtqwpddouevwbk.supabase.co/storage/v1/object/public/post-images/2026-09-29/5ee61135.svg)

공식 문서의 데이터 흐름도는 필수 연결을 실선으로, 선택이거나 사용자가 시작하는 흐름을 점선으로 구분해 뒀습니다. 텔레메트리와 피드백이 점선 쪽에 있습니다. 세 방법을 항목별로 비교하면 아래와 같습니다.

| | 세션 품질 설문의 트랜스크립트 업로드 | 오류 보고 | `/feedback` 보고 |
|---|---|---|---|
| 무엇이 나가는가 | 대화·서브에이전트 트랜스크립트와 디스크의 세션 로그 파일 | Claude Code 내부의 오류 메시지와 스택 트레이스 | 대화 기록과 코드 |
| 가린다고 적힌 값 | 알려진 API 키·토큰 패턴 | 알려진 비밀·파일 경로·이메일 주소 패턴 | 문서에 별도 표기 없음 |
| 그대로 올라가는 값 | 소스 코드·파일 내용·그 밖의 대화 내용 | 문서에 별도 표기 없음 | 코드를 포함한 대화 기록 |
| 보관 기간 | 최대 6개월 | 문서에 별도 표기 없음 | 5년 |
| 끄는 방법 | `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` | `DISABLE_ERROR_REPORTING=1` | `DISABLE_FEEDBACK_COMMAND=1` |

세 줄에서 "알려진 패턴" 이라는 말이 반복됩니다. 알려지지 않은 모양의 비밀 값은 이 단계에서 걸러지지 않습니다. 서드파티 제공자를 쓰거나 Anthropic 자격증명이 없는 환경이라면 `/feedback` 이 보고서를 전송하지 않고 `~/.claude/feedback-bundles/` 아래 로컬 아카이브로 쓰는데 이때 가리는 값도 알려진 API 키·토큰 패턴입니다.

세 가지를 한 번에 끄는 변수도 있습니다. `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 을 설정하면 비필수 트래픽이 함께 멈춥니다. 다만 WebFetch 의 도메인 안전 검사는 이 변수와 무관하게 동작하고 설정의 `skipWebFetchPreflight` 로 따로 끕니다.

마스킹이 적용되지 않는다고 문서가 분명히 적어 둔 곳도 있습니다. 힙 스냅샷입니다. 트러블슈팅 문서는 `.heapsnapshot` 파일에 프로세스 안의 모든 문자열이 들어가고 거기에는 대화 전체와 자격증명이 포함된다고 적었습니다. 공개 이슈에 첨부하거나 공유하지 말라는 경고가 함께 붙어 있습니다. 성능 문제를 신고할 때는 대화 내용과 자격증명이 들어 있지 않은 `-diagnostics.json` 만 첨부하라고 안내합니다.

## MCP 서버 이름에 들어온 터미널 이스케이프

같은 릴리스에는 방향이 반대인 수정도 한 줄 있습니다. `claude mcp list` 와 `claude mcp get`, 그리고 `claude mcp remove`·`login`·`logout` 의 not-found 오류가 MCP 서버 이름과 값에 든 줄바꿈과 터미널 이스케이프 시퀀스를 그대로 출력하던 것을 고쳤습니다.

앞의 세 건이 내보낼 값을 가리지 못한 것이라면 이쪽은 받아 온 문자열을 화면에 그대로 쓴 것입니다. 빠져나간 이유는 같습니다. 문자열의 모양을 확인하지 않고 지나갔습니다.

MCP 서버 목록은 저장소에 체크인하는 설정 파일에 들어갑니다. 공식 문서도 직접 만든 서버나 신뢰하는 제공자의 서버를 쓰라고 권합니다. Anthropic 이 디렉터리에 올릴 때 검토는 하지만 개별 MCP 서버를 보안 감사하거나 관리하지는 않는다고도 적어 뒀습니다. 이름과 값이 곧 터미널에 찍히는 문자열이라면 그 목록을 볼 때 확인할 것이 하나 늘어납니다.

## 세션을 넘기기 전에 확인할 것

여기까지 보면 Claude Code 의 비밀 값 보호는 값을 읽고 판단하는 구조가 아닙니다. 알려진 패턴과 파일 이름에 맞으면 가리고 어긋나면 지나갑니다. 규칙이 촘촘해질수록 어긋나는 모양은 줄어들지만 없어지지는 않습니다. v2.1.285 가 고친 세 건이 그 경계에 있던 예입니다.

그래서 화면에서 값이 가려져 보인다는 것만으로 그대로 넘겨도 된다고 판단하기는 어렵습니다. 로그나 세션을 남에게 넘기기 전에 볼 것을 정리하면 이렇습니다.

- 접속 문자열의 비밀번호에 `@` 나 `%40` 같은 퍼센트 인코딩이 들어 있는지 확인합니다. 있으면 직접 지운 뒤 넘깁니다.
- `/ultrareview` 를 실행하기 전에 자격증명 파일 이름이 문서가 든 형태에 맞는지 봅니다. 확장자 앞 콜론이나 편집기 백업 표시가 붙어 있으면 이름을 고칩니다.
- 그 파일이 이미 커밋돼 있지 않은지 확인합니다. 커밋돼 있으면 이름 기반 제외는 적용되지 않습니다.
- 실행 직전 Claude Code 가 알려 주는 "업로드에서 빠뜨린 파일" 목록을 실제로 읽습니다.
- Windows 네이티브 환경이라면 제외 규칙이 문서에 적힌 세 환경에 들어 있지 않다는 점을 감안합니다.
- 클라우드 세션을 공유할 때는 공개 범위를 먼저 봅니다. Max·Pro 계정의 Public 공유는 저장소 접근 확인이 기본으로 켜져 있지 않습니다. 문서도 세션에 비공개 저장소의 코드와 자격증명이 들어 있을 수 있으니 공유 전에 확인하라고 적었습니다.

버전을 올리는 것으로 해결되는 항목이기도 합니다. 세 건 모두 v2.1.285 에서 고쳐졌으니 그보다 낮은 버전을 쓰고 있다면 올리는 것이 먼저입니다. 다만 다음 릴리스에서 같은 종류의 수정이 또 올라올 가능성은 남아 있습니다. 가려 주는 기능을 신뢰 경계로 쓸지, 값이 애초에 로그에 들어가지 않게 할지는 그다음 판단입니다.
