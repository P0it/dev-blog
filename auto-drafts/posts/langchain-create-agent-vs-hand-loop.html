직접 짠 Agent 반복문은 LangChain 어디에 들어 있을까요?

지금까지 Agent를 반복문 40줄로 직접 짰습니다. 그런데 Agent 예제를 찾아보면 대부분 LangChain의 create_agent 한 줄로 시작합니다. 그 한 줄은 우리가 짠 40줄과 무엇이 같고 무엇이 다를까요? 프레임워크를 쓰면 무엇을 덜 짜고 무엇은 여전히 직접 정해야 할까요?

create_agent는 무엇을 대신해 주나요?

우리가 짠 반복문을 통째로 대신합니다. 도구 목록과 지시만 넘기면 됩니다.

LangChain은 LLM 앱을 만들 때 반복해서 짜는 부분을 모아 둔 Python·JavaScript 프레임워크입니다. 그중 create_agent는 지금까지 직접 짠 Agent 반복문을 그대로 대신합니다. LLM을 부르고 응답이 도구 부탁이면 함수를 실행해 결과를 붙입니다. 답이 오면 멈춥니다.

우리가 넘기는 것은 세 가지입니다. 어떤 모델을 쓸지, 어떤 도구 함수를 줄지, 어떤 지시를 줄지. 판단은 여전히 LLM이 하고 반복문을 짜는 일만 LangChain으로 넘어간 것입니다.

직접 짠 코드의 어느 줄이 어디로 갔나요?

반복문·실행·결과 붙이기는 사라지고 도구 정의는 함수 하나로 줄어듭니다.

직접 짠 코드LangChain에서
input_schema를 손으로 쓴 도구 목록@tool을 붙인 함수. 타입 힌트가 스키마, docstring이 description
for 반복문과 stop_reason 확인create_agent 안
tool_use 블록을 읽고 함수 실행create_agent 안
is_error로 실패 돌려주기기본 동작 (예외를 결과 글로 돌려줌)
반복 횟수 한도middleware(ModelCallLimitMiddleware)
대화가 길어지면 요약middleware(SummarizationMiddleware)

도구를 정의하는 방식이 가장 많이 달라집니다. 직접 짤 때는 이름·설명·JSON Schema를 딕셔너리로 썼습니다. LangChain에서는 평범한 Python 함수에 @tool을 붙이면 함수 이름이 도구 이름, docstring이 설명, 타입 힌트가 입력 형식이 됩니다.

그래서 docstring이 곧 LLM이 읽는 도구 설명입니다. 함수에 붙이는 짧은 메모라고 여기고 대충 쓰면 LLM이 도구를 잘못 고릅니다. 언제 쓰는지까지 적는 규칙은 그대로입니다.

모델을 바꾸려면 얼마나 고쳐야 하나요?

모델 이름 문자열 하나만 바꿉니다.

직접 짠 코드는 Claude API 형식에 맞춰져 있어서 OpenAI 모델로 바꾸려면 요청을 만드는 부분과 응답을 읽는 부분을 다 고쳐야 합니다. 도구 부탁이 tool_use 블록으로 오느냐, tool_calls 목록으로 오느냐부터 다릅니다.

LangChain은 모델 이름 앞에 회사 이름을 붙인 문자열 하나로 모델을 고르고 응답을 같은 모양의 메시지로 바꿔 돌려줍니다. 함수로 모델 객체를 따로 만들고 싶으면 init_chat_model을 씁니다. 그래서 모델 하나가 장애일 때 다른 회사 모델로 돌리는 일도 쉬워집니다.

다만 기능까지 같아지지는 않습니다. prompt caching 표시처럼 한 회사에만 있는 기능은 그 회사용 옵션으로 따로 넘겨야 합니다. 모델마다 도구를 고르는 솜씨도 다릅니다. 모델을 바꾼 뒤에는 같은 질문 몇 개로 다시 확인합니다.

반복문 중간에 내 코드를 끼우고 싶으면요?

middleware를 씁니다. LLM을 부르기 전후, 도구를 실행하기 전후에 코드를 끼웁니다.

직접 짠 반복문에는 반복 한도, 대화 줄이기, 오류 처리 같은 코드를 if 문으로 직접 넣었습니다. create_agent는 반복문이 안에 숨어 있으니 그 자리에 코드를 끼우는 방법이 따로 필요합니다. 그것이 middleware입니다.

LangChain에는 자주 쓰는 middleware가 미리 들어 있습니다. 대화 요약, 모델 호출 한도, 도구 호출 한도, 사람 승인, 개인정보 가리기, 모델 장애 시 다른 모델로 넘기기 같은 것들입니다. 필요한 것을 목록으로 넘기면 순서대로 끼워집니다. 우리 서비스에만 필요한 규칙은 함수 하나로 직접 middleware를 만들어 끼웁니다.

그럼 직접 짜는 법은 왜 배웠나요?

프레임워크가 무엇을 대신하는지 알아야 문제가 생겼을 때 어디를 볼지 알기 때문입니다.

LangChain을 쓰면 Agent를 빨리 만들 수 있지만 안에서 무슨 일이 일어나는지는 보이지 않습니다. Agent가 같은 도구를 계속 부르거나 비용이 갑자기 늘었을 때, 반복문과 메시지 목록이 어떻게 생겼는지 알면 원인을 찾기 쉽습니다. 메시지 목록에 무엇이 쌓였는지, stop_reason이 무엇이었는지를 보면 됩니다.

LangChain을 쓰지 않는 선택도 흔합니다. Anthropic은 "가장 단순한 방법으로 시작하라. LLM API를 직접 쓰면 몇 줄로 되는 경우가 많다"고 권합니다. 반복문이 단순하면 직접 짜고 middleware와 여러 회사 모델이 필요해지면 프레임워크를 씁니다. Claude Agent SDK나 OpenAI Agents SDK처럼 회사가 만든 Agent 도구도 있습니다.

코드로 쓰면 어떻게 되나요?

도구 함수 하나와 create_agent 호출 하나입니다.

from langchain.agents import create_agent
from langchain.agents.middleware import (
    ModelCallLimitMiddleware, SummarizationMiddleware)
from langchain.tools import tool

# ① docstring 이 도구 설명, 타입 힌트가 입력 형식이 된다
@tool
def search_menu(query: str) -> str:
    """주문 앱에서 메뉴를 검색한다. 가게 이름, 가격, 맵기를 돌려준다."""
    return menu_api.search(query)

agent = create_agent(
    # ② 회사:모델 문자열 하나로 모델을 고른다
    model="anthropic:claude-sonnet-5-5",
    tools=[search_menu, place_order],
    system_prompt="너는 음식 주문 도우미다. 주문 전에 가게와 가격을 확인한다.",
    # ③ 반복문 중간에 끼울 코드
    middleware=[
        ModelCallLimitMiddleware(run_limit=10),
        SummarizationMiddleware(model="anthropic:claude-haiku-5-5",
                                trigger=("tokens", 60_000),
                                keep=("messages", 20)),
    ],
)

# ④ 메시지 목록을 넘기고, 끝난 메시지 목록을 돌려받는다
result = agent.invoke(
    {"messages": [{"role": "user", "content": "떡볶이 1인분 시켜 줘."}]})
print(result["messages"][-1].content)
  1. 직접 짤 때 손으로 쓰던 input_schema를 query: str이라는 타입 힌트에서 만들어 줍니다. menu_api와 place_order는 예시라 정의를 줄였습니다.
  2. "openai:gpt-5.5"로 바꾸면 나머지 코드를 고치지 않고 OpenAI 모델로 돌아갑니다.
  3. 한 번 실행에 모델을 10번 넘게 부르면 멈추고 대화가 6만 토큰을 넘으면 최근 20칸만 남기고 나머지를 요약합니다. 요약은 값싼 모델에 맡겼습니다.
  4. result["messages"]에는 도구 부탁과 결과를 포함한 전체 메시지 목록이 들어 있습니다. 마지막 칸이 LLM의 답입니다.

코드는 langchain 1.5 기준입니다. 예전 예제에서 보던 AgentExecutor나 create_react_agent는 옛 방식이라 새 코드에는 create_agent를 씁니다. create_agent는 안에서 LangGraph라는 그래프 실행기로 돌아갑니다.
