LLM의 답을 프로그램이 그대로 믿고 써도 될까요?

고객 문의를 읽고 배송·환불·기타 가운데 하나로 나눠 담당 부서로 넘기는 프로그램을 만든다고 해 보겠습니다. LLM에게 "분류해서 JSON으로 답해"라고 시켰는데, 어떤 날은 JSON 앞에 "네, 분류 결과입니다!"가 붙어서 옵니다. 프로그램은 그 자리에서 멈춥니다. 사람이 읽기에는 멀쩡한 답이 왜 프로그램에서는 깨질까요?

사람에게 좋은 답이 프로그램에는 왜 문제가 되나요?

프로그램은 정해진 모양의 데이터만 읽을 수 있기 때문입니다.

프로그램이 LLM의 답을 쓰려면 문장에서 값을 꺼내야 합니다. 위 예에서 필요한 것은 "배송"이라는 값 하나인데, 답에는 인사말과 마크다운 코드 표시까지 섞여 있습니다. JSON을 읽는 함수는 첫 글자부터 JSON이어야 읽을 수 있어서 바로 오류를 냅니다.

프롬프트에 "JSON만 답해"라고 더 세게 적으면 대부분은 지킵니다. 하지만 하루에 만 건을 처리하면 그중 몇 건은 형식이 어긋나고 그때마다 문의가 길을 잃습니다. 프로그램이 읽을 답은 대부분 맞는 형식으로는 부족합니다.

형식을 지키게 하는 방법에는 무엇이 있나요?

프롬프트로 부탁하기, 도구로 강제하기, structured output 세 가지입니다. 뒤로 갈수록 확실합니다.

지시에 "JSON만, 이 형식으로 답해"라고 적습니다. 가장 쉽지만 보장은 없습니다.

classify 도구를 하나 만들고 tool_choice로 그 도구를 반드시 쓰게 합니다. 답이 도구의 입력 형식으로 옵니다. strict를 켜면 형식이 보장됩니다.

응답 형식 자리에 JSON Schema를 걸어 둡니다. API가 스키마에 맞는 JSON만 나오도록 막아 줍니다.

도구로 강제하는 방법은 도구를 데이터를 받는 그릇으로 쓰는 것입니다. tool_choice로 classify 도구를 지정하면 LLM은 답 대신 그 도구의 입력 형식에 맞춘 부탁을 씁니다. 프로그램은 실제로 무언가를 실행하지 않고 부탁에 담긴 값을 데이터로 꺼내 씁니다.

structured output은 응답 자체에 형식을 거는 방법입니다. Claude API는 output_config의 format에, OpenAI는 response_format(Responses API에서는 text.format)에 JSON Schema를 넣습니다. API가 모델이 토큰을 고르는 단계에서 스키마에 맞지 않는 토큰을 막기 때문에 모양이 틀린 JSON은 나오지 않습니다.

스키마는 어떻게 만드나요?

Python에서는 Pydantic 클래스로 만들면 스키마와 검사를 한 번에 얻습니다.

Pydantic 클래스
class Inquiry(BaseModel): model_config = ConfigDict(extra="forbid") category: Literal["배송", "환불", "기타"] urgent: bool summary: str = Field(description="한 문장 요약")
Inquiry.model_json_schema() 가 만든 스키마 (줄임)
{ "type": "object", "properties": { "category": { "enum": ["배송", "환불", "기타"], "type": "string" }, "urgent": { "type": "boolean" }, "summary": { "type": "string", "description": "한 문장 요약" } }, "required": ["category", "urgent", "summary"], "additionalProperties": false }

Pydantic은 Python 클래스로 데이터의 모양을 적는 라이브러리입니다. 클래스에서 JSON Schema를 만들 수 있고(model_json_schema), 들어온 JSON이 그 모양에 맞는지 검사할 수도 있습니다(model_validate_json).

Literal로 고를 수 있는 값을 정하면 스키마에 enum으로 들어가서, LLM이 "배송 문의"처럼 목록에 없는 값을 쓰지 못합니다. Field의 설명도 스키마에 들어가 LLM이 읽습니다. extra="forbid"는 정하지 않은 칸을 받지 않겠다는 뜻입니다. 스키마에는 additionalProperties: false로 들어갑니다.

structured output이 받아 주는 스키마에는 제약이 있습니다. 모든 칸을 required로 두고 additionalProperties를 false로 두라고 요구하거나, 숫자 범위·문자열 길이 같은 일부 조건을 지원하지 않기도 합니다. 지원하지 않는 조건은 받은 뒤 검사 단계에서 따로 확인합니다.

형식이 맞으면 내용도 믿어도 되나요?

아닙니다. 값이 말이 되는지는 프로그램이 따로 검사합니다.

structured output은 JSON의 모양을 보장할 뿐 값이 옳은지는 보장하지 않습니다. 형식이 맞는다고 내용까지 맞는 것은 아닙니다. 요약 칸이 빈 문자열이거나 배송 문의를 환불로 잘못 나누는 일은 여전히 생깁니다.

그래서 프로그램은 받은 JSON을 한 번 더 검사합니다. 빈 값, 범위를 벗어난 숫자, 서로 맞지 않는 칸을 확인하고 문제가 있으면 무엇이 틀렸는지 적어 다시 묻습니다. 다시 묻는 횟수에는 한도를 두고 넘으면 사람이 처리하는 대기열로 보냅니다.

structured output을 써도 예외가 있습니다. 답이 max_tokens에 걸려 JSON이 중간에 잘리거나, 모델이 요청을 거절하면(refusal) 스키마에 맞지 않는 답이 옵니다. 그래서 stop_reason을 먼저 확인한 뒤에 검사합니다.

코드로 쓰면 어떻게 되나요?

스키마를 건 요청 하나와, 검사에 실패하면 다시 묻는 반복문입니다.

from typing import Literal
import anthropic
from pydantic import BaseModel, ConfigDict, Field, ValidationError

client = anthropic.Anthropic()

# ① 데이터의 모양
class Inquiry(BaseModel):
    model_config = ConfigDict(extra="forbid")
    category: Literal["배송", "환불", "기타"]
    urgent: bool
    summary: str = Field(description="문의를 한 문장으로 요약")

def classify(text: str, retries: int = 2) -> Inquiry | None:
    messages = [{"role": "user", "content": f"다음 문의를 분류하세요.\n\n{text}"}]
    for _ in range(retries + 1):
        reply = client.messages.create(
            model="claude-sonnet-5-5", max_tokens=512, messages=messages,
            # ② 응답 형식에 JSON Schema 를 건다
            output_config={"format": {"type": "json_schema",
                                      "schema": Inquiry.model_json_schema()}},
        )
        # ③ 잘린 답·거절은 검사 전에 거른다
        if reply.stop_reason != "end_turn":
            return None
        raw = reply.content[0].text
        try:
            # ④ 모양과 값을 검사한다
            result = Inquiry.model_validate_json(raw)
            if not result.summary.strip():
                raise ValueError("summary 가 비어 있습니다")
            return result
        except (ValidationError, ValueError) as e:
            # ⑤ 틀린 이유를 붙여 다시 묻는다
            messages += [
                {"role": "assistant", "content": raw},
                {"role": "user", "content": f"형식 오류: {e}. 고쳐서 다시 답하세요."},
            ]
    return None  # 한도를 넘으면 사람이 처리하도록 넘긴다
  1. 고를 수 있는 값은 Literal, 설명은 Field로 적었습니다. 이 클래스 하나가 스키마도 되고 검사기도 됩니다.
  2. output_config의 format에 스키마를 넣었습니다. 모델은 이 모양에 맞는 JSON만 만들 수 있습니다.
  3. 답이 잘렸거나 거절됐으면 스키마를 지키지 못했을 수 있으니 검사하지 않고 넘깁니다.
  4. model_validate_json이 모양을 검사하고 그 아래 줄이 스키마로 적기 어려운 조건(빈 요약)을 검사합니다.
  5. 틀린 답과 이유를 대화에 붙여 다시 부릅니다. LLM은 자기가 쓴 답과 무엇이 틀렸는지를 보고 고칩니다. 횟수 한도를 넘으면 None을 돌려 사람에게 넘깁니다.

코드는 anthropic 2.14와 pydantic 2.14 기준입니다. OpenAI SDK에서는 client.responses.parse(model=..., input=..., text_format=Inquiry)처럼 Pydantic 클래스를 바로 넘기면 SDK가 스키마를 만들고 결과를 output_parsed에 클래스로 돌려줍니다.
